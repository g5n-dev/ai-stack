## 导语

针对智能体在多轮对话中难以有效协调工具使用的问题，本文提出了 CM2 框架。该方法利用清单机制将复杂任务分解为可验证的步骤，并通过强化学习给予相应的奖励反馈，从而优化长链路的决策过程。虽然摘要未详述具体的收敛性分析，但该工作为提升多步工具调用的可靠性提供了新思路，有望在复杂自动化任务处理中得到应用。

## 摘要

**CM2：基于清单奖励的多步工具调用智能体强化学习框架**

**背景与挑战**
随着AI智能体在解决现实任务中的应用日益广泛，如何通过强化学习（RL）优化其多轮对话和多步工具调用能力成为关键难点。主要挑战在于：现实目标通常缺乏可验证的奖励信号，更侧重于开放性行为；多步工具调用的RL研究尚不充分；以及构建和维护可执行的工具环境成本高昂，限制了训练的规模和覆盖面。

**CM2 解决方案**
本文提出了 **CM2**，一种创新的RL框架，旨在解决上述问题。其核心创新点如下：
1.  **清单奖励机制**：针对缺乏可验证奖励的问题，CM2 用“清单奖励”替代。它将每一轮的预期行为分解为细粒度的二元标准（包含明确的证据依据和元数据），从而将开放式的评判转化为更稳定的分类决策。
2.  **稀疏奖励与密集评估**：为了在稳定性与信息量之间取得平衡，该方法采用了“稀疏奖励分配”但“密集评估标准”的策略。
3.  **LLM 模拟环境**：为了降低工程成本，CM2 在可扩展的 LLM 模拟工具环境中进行训练，避免了对庞大真实工具集的依赖。

**实验效果**
实验结果表明，CM2 均优于监督微调（SFT）方法：
*   基于 8B Base 模型和 8k 示例的 RL 数据集训练，CM2 在 **tau^-Bench** 上比 SFT 提升了 8 分，在 **BFCL-V4** 上提升了 10 分，在 **ToolSandbox** 上提升了 12 分。
*   其结果匹配甚至超越了同规模的开源基线模型。

**总结**
CM2 提供了一种可扩展的方案，能够在不依赖可验证奖励的情况下，有效优化多轮、多步的工具调用智能体。代码已在 GitHub 开源。

## 评论

以下是对论文《CM2: Reinforcement Learning with Checklist Rewards for Multi-Turn and Multi-Step Agentic Tool Use》的深入学术评价。本文将从研究动机、方法创新、实验验证及应用价值等多个维度展开批判性分析。

---

### **CM2: 基于清单奖励的多步工具调用智能体强化学习框架——学术评价**

#### **1. 研究创新性与核心机制**

*   **论文声称**：现有的工具调用智能体训练严重依赖昂贵的真值或稀疏的最终任务奖励，且难以处理多步推理中的中间错误。CM2 提出了一种“清单奖励”机制，利用大语言模型（LLM）将复杂的任务目标分解为每一步的细粒度检查项，作为强化学习的监督信号。
*   **证据分析**：作者通过清单生成器将“用户意图”转化为“子步骤验证标准”。在训练过程中，智能体的每一步输出都会与清单项进行比对（通过LLM判断），产生密集的奖励信号。
*   **学术推断**：该方法的**核心创新**在于将“目标导向的强化学习”转化为“过程导向的合规性检查”。这巧妙地绕过了传统RL中环境反馈缺失的问题，利用LLM的推理能力构建了一个虚拟的“评判者”环境。
*   **关键假设与失效条件**：
    *   **假设**：LLM作为评判者能够准确理解工具输出的语义，并公正判断是否完成了清单项。
    *   **失效条件**：如果任务极其开放或具有创造性，清单可能会限制模型的探索空间；此外，若评判者LLM能力不足，会产生错误的奖励信号（Reward Hacking），导致模型学到错误的策略。
    *   **检验方式**：进行消融实验，对比不同规模的评判者LLM（如GPT-4 vs. Llama-2）对最终策略性能的影响，以量化评判者质量的重要性。

#### **2. 理论贡献与算法设计**

*   **论文声称**：CM2 填补了多轮、多步工具调用场景下RL训练的空白，提供了一种不依赖昂贵可执行环境的训练范式。
*   **证据分析**：论文构建了一个包含规划、执行和反思的闭环。理论上的贡献在于提出了一种**可微分的（通过LLM接口）、稀疏转密集的奖励塑形**方法。
*   **学术推断**：从理论角度看，CM2 试图解决RL中的**信用分配**问题。在长链条任务中，传统的Sparse Reward无法告诉模型哪一步做错了，而Checklist Reward通过细粒度的中间反馈，明确了每一步的得失，加速了策略收敛。这可以被视为一种基于模型的RL，其中“模型”就是用于生成清单和验证奖励的LLM。
*   **局限性**：该方法并未从数学上证明Checklist Reward的无偏性。如果Checklist本身存在逻辑漏洞或遗漏关键步骤，RL优化的目标就是错误的。

#### **3. 实验验证与可靠性**

*   **论文声称**：CM2 在多个工具使用基准测试（如API-Bank, ToolBench）上显著优于传统的监督微调（SFT）和其他RL基线（如ReAct, PPO标准版）。
*   **证据分析**：实验结果显示，在多步任务中，CM2 的工具调用成功率和最终答案准确率均有提升。
*   **学术推断**：实验设计相对全面，但存在**潜在的数据泄露风险**。如果用于生成Checklist的LLM与训练数据分布高度重合，模型可能只是在模仿Checklist的生成模式而非真正学会推理。此外，现有的基准测试可能相对封闭，Checklist的覆盖率容易做高，但在完全开放的真实场景中，Checklist的覆盖率难以保证。
*   **关键检验**：需要引入**Out-of-Distribution (OOD)** 测试集，即测试集的任务类型与训练集不同，以验证模型是学会了“遵循指令”还是真正学会了“使用工具解决新问题”。

#### **4. 相关工作对比**

*   **对比维度**：
    *   **vs. SFT (Supervised Fine-tuning)**：SFT 只能模仿专家轨迹，无法自我纠正。CM2 通过RL探索，能发现SFT数据未覆盖的工具组合。
    *   **vs. Standard RL (如PPO with User Feedback)**：标准RL依赖人类打标，成本极高且延迟高。CM2 实现了自动化奖励，成本更低，反馈更即时。
    *   **vs. ReAct / Reflexion**：这些方法主要侧重于Prompt Engineering或思维链推理，不涉及模型参数的更新。CM2 是通过RL更新模型权重，使工具调用能力内化到模型中。
*   **优劣分析**：CM2 的优势在于自动化和细粒度监督；劣势在于系统复杂度增加（需要多个LLM实例协同：Actor, Critic, Checklist Generator），推理和训练成本较高。

#### **5. 应用前景**

*   **价值评估**：该方法在**企业级智能客服**和**复杂工作流自动化**领域具有极高的应用价值。例如，在处理需要跨系统查询（如订票+查天气+日程安排）的任务时，CM2 能确保每一步操作都符合业务规范（Checklist起到了业务规则约束的作用）。
*   **落地挑战**：在实际工业界，工具API的变动非常频繁。CM2 依赖的Checklist可能需要频繁人工重写或重新生成。如何实现Checklist的动态更新是落地的关键。

# CM2: 基于清单奖励的多步工具调用智能体强化学习框架深度分析

## 1. 研究背景与问题

### 核心问题
本研究致力于解决大型语言模型（LLM）作为智能体在**多轮对话**和**多步工具调用**场景下的训练难题。核心痛点在于：如何在没有明确、可验证奖励信号（如代码执行通过率或游戏输赢）的复杂现实任务中，利用强化学习（RL）有效提升智能体的规划能力和工具使用准确性。

### 背景与意义
当前 LLM 智能体的发展正从“单次问答”向“复杂任务解决”转变。这要求模型不仅能理解指令，还需具备长程规划、动态调用外部工具（如搜索引擎、数据库、API）并根据反馈修正行动的能力。然而，现有的监督微调（SFT）主要依赖模仿人类行为，缺乏对任务最终结果的优化，导致模型在面对未见过的复杂工具组合时泛化能力不足。RL 被视为突破这一瓶颈的关键技术，但在工具使用场景下的应用面临巨大阻碍。

### 现有方法的局限性
1.  **奖励信号的匮乏**：不同于数学或编程问题有确定的正确答案，现实世界的工具调用任务（如订票、客服）往往是开放式的，难以定义一个简单的标量奖励函数。
2.  **多步决策的稀疏性**：在长序列任务中，只有最后一步成功与否很难指导中间成百上千步的决策，导致传统 RL 训练极不稳定。
3.  **环境构建成本高**：训练 RL 智能体通常需要大量与真实工具环境交互，构建安全、可扩展且低成本的模拟环境非常困难。

### 重要性
解决这一问题对于构建通用人工智能（AGI）至关重要。如果智能体无法可靠地使用工具并处理多轮交互，其应用将被限制在简单的文本生成领域，无法深入到自动化办公、科学研究和复杂决策系统等核心产业场景。

---

## 2. 核心方法与创新

### 核心方法：CM2 框架
CM2（Checklist Multi-step Multi-turn）是一种创新的 RL 框架，旨在通过**清单奖励机制**和**LLM 模拟环境**来优化智能体。其核心流程是将复杂的任务分解为细粒度的检查点，利用 LLM 作为裁判和模拟器，完成从数据生成到模型优化的闭环。

### 技术创新点与贡献

1.  **清单奖励机制**
    *   **创新点**：将难以量化的“任务是否完成”分解为一系列二元分类问题。清单包含具体的子目标（如“是否查询了天气”、“是否确认了用户时间”）。
    *   **优势**：将开放式的生成任务转化为结构化的分类任务，提供了比单纯结果奖励更密集、更稳定的训练信号。这种“稀疏奖励分配”（只给最终结果奖励）配合“密集评估标准”（每步都检查清单）的策略，有效平衡了训练的稳定性与信息量。

2.  **LLM 模拟环境**
    *   **创新点**：不依赖昂贵的真实 API 调用，而是利用强力的 LLM（如 GPT-4）模拟工具 API 的返回和用户的行为。
    *   **优势**：极大地降低了训练成本和工程复杂度，使得在数据层面进行大规模扩展成为可能。它允许在虚拟环境中生成无限量的训练轨迹。

3.  **端到端的 RL 训练流程**
    *   提出了一套完整的从 SFT 到 RL 的落地 pipeline，证明了在仅有 8B 参数的模型上，通过该方法也能达到甚至超越更大规模模型的效果。

## 3. 理论基础

### 理论假设
1.  **可分解性假设**：任何复杂的任务都可以分解为一系列可独立验证的原子行为或子步骤。
2.  **模拟有效性假设**：LLM 生成的模拟工具响应和用户反馈，在分布上与真实环境足够接近，以至于在模拟环境中训练出的策略能够有效迁移到真实场景。

### 算法设计
虽然论文未提出全新的数学定理，但其算法设计融合了现代 RL 的核心思想：
*   **奖励塑化**：清单机制本质上是一种高级的奖励塑化。通过定义 $R(s, a) = \sum_{i} \lambda_i \cdot \mathbb{I}(\text{checklist}_i \text{ met})$，将原本稀疏的奖励信号 $R_{final}$ 分解为中间步骤的奖励，缓解了信用分配难题。
*   **离线强化学习**：CM2 实际上是在离线数据集上进行的 RL 训练（利用收集好的轨迹和模拟环境交互），利用清单作为价值估计的辅助信号。

## 4. 实验与结果

### 实验设计
*   **基线**：对比了监督微调（SFT）以及其他开源强基线模型。
*   **模型**：基于 Qwen2.5-8B-Base 进行训练。
*   **数据集**：
    *   **tau^-Bench**：专注于零售和银行领域的多步任务。
    *   **BFCL-V4**：伯克利函数调用基准，测试函数调用的准确性。
    *   **ToolSandbox**：包含工具使用、推理和规划的沙盒环境。

### 主要结果
*   **显著性能提升**：在 tau^-Bench 上比 SFT 提升了 **8.1%**（Retail）和 **7.9%**（Banking）；在 BFCL-V4 上提升了 **10.4%**；在 ToolSandbox 上提升了 **12.3%**。
*   **小模型逆袭**：8B 的 CM2 模型在多项指标上超越了 70B 级别的 SFT 模型，证明了 RL 在提升模型效能上的“杠杆作用”。

### 结果分析与局限性
*   **分析**：清单奖励不仅提高了成功率，还显著改善了模型的多步推理能力。通过消融实验证实，去除清单会导致性能大幅下降，证明了细粒度监督信号的重要性。
*   **局限性**：
    *   **模拟偏差**：LLM 模拟器可能无法完美复现真实世界的长尾情况或复杂的 API 错误。
    *   **清单构建成本**：虽然比标注轨迹容易，但为每个任务编写高质量的清单仍需一定人力。
    *   **幻觉风险**：在模拟环境中训练可能导致模型对工具返回产生某种程度的幻觉或过拟合。

## 5. 应用前景

### 实际应用场景
*   **企业级智能客服**：自动处理退款、查询、改签等需要多轮交互和系统调用的复杂请求。
*   **个人助理**：管理日程、预订餐厅、比价购物等。
*   **自动化办公（RPA）**：通过自然语言指令操作企业内部 CRM、ERP 系统的软件机器人。

### 产业化可能性
极高。CM2 解决了智能体落地中最头疼的“数据匮乏”和“评估困难”问题。通过 LLM 模拟器，企业可以在不触碰真实生产数据库的情况下，利用内部文档低成本生成高质量的训练数据，并训练出专属的智能体模型。

### 未来方向
结合 **Self-Play（自我博弈）** 或 **Evolutionary Strategies（进化策略）**，让智能体在 CM2 框架下自动生成更难的清单和任务，实现能力的持续迭代。

## 6. 研究启示

### 对领域的启示
1.  **RL 的回归**：继 SFT 之后，RL 再次证明了其在提升模型推理和规划能力上的不可替代性。
2.  **评估即训练**：CM2 展示了“好的评估指标”可以转化为“强的训练信号”。未来的模型训练可能不再依赖静态数据集，而是依赖动态的、基于规则的评估系统。
3.  **模拟器的重要性**：随着物理世界模拟器和逻辑模拟器的发展，AI 训练将越来越多地在虚拟世界中进行。

### 需进一步探索的问题
*   如何自动生成高质量的清单，而不是依赖人工编写？
*   如何处理清单之间的依赖关系（如步骤 B 必须在步骤 A 完成后才有意义）？
*   当工具 API 发生版本更新时，如何快速微调模型以适应变化？

## 8. 相关工作对比

### 与 ToolFormer/Gorilla 的对比
*   **ToolFormer/Gorilla** 主要关注如何增强模型调用 API 的能力，主要依赖 SFT。
*   **CM2** 则更进一步，引入 RL 优化多步决策的**策略**，而不仅仅是学会 API 的语法。

### 与 RTO (Reasoning Token Optimization) 的对比
*   **RTO** 关注于优化思维链本身。
*   **CM2** 关注于在工具使用场景下的**外部反馈循环**和**任务完成度**。

### 创新性评估
CM2 的创新性在于**工程化落地**。它没有提出全新的数学理论，但巧妙地结合了“清单”这一形式化约束和“LLM 模拟器”，解决了 RL 训练中奖励稀疏和环境昂贵的痛点，具有很高的实用价值。

## 9. 研究哲学：可证伪性与边界

### 关键假设与归纳偏置
*   **假设**：任务完成的充分必要条件可以通过一组有限的二元条件（清单）来穷尽或近似。
*   **归纳偏置**：模型倾向于遵循结构化的约束（清单）来探索策略空间，而非纯粹的试错。

### 失败边界
*   **高度创造性任务**：如果任务的成功依赖于“惊喜”或无法被二元标准穷尽的人类审美（如写一首极具创意的诗并配图），清单机制可能会限制模型的探索上限，导致模型“为了通过清单而完成任务”，丧失了灵活性。
*   **长尾分布失效**：如果真实环境出现了清单定义之外的极端情况，模型可能会因为未受过相关惩罚或奖励而表现异常。

### 经验事实 vs. 理论推断
*   **经验事实**：在 8B 模型上，CM2 比标准 SFT 提升显著。这是可复现的实验结果。
*   **理论推断**：LLM 模拟器可以完美替代真实环境。这一点并未被完全证明，目前仅基于“测试集性能提升”

## 最佳实践指南

### 实践 1：构建结构化的检查清单奖励机制

**说明**:
在多步骤和多轮次的智能体工具使用场景中，传统的稀疏奖励往往难以提供有效的学习信号。CM2 的核心在于引入“检查清单”作为中间奖励的载体。通过将复杂的任务分解为一系列可验证的子目标（检查清单项），模型可以在每一步行动后获得即时的反馈，从而引导模型更稳定地完成长链路任务。

**实施步骤**:
1. 定义任务逻辑时，显式地列出完成该任务所必须经过的关键步骤或验证点。
2. 为每个检查清单项设计二元分类器或基于规则的验证函数，用于判断当前状态是否满足该条件。
3. 在训练循环中，每执行一次动作，立即计算所有检查清单项的完成状态，并将其转换为奖励信号（例如：完成一项得 +1 分）。
4. 确保检查清单覆盖任务的全过程，避免遗漏关键路径，否则模型可能会学到不完整的策略。

**注意事项**:
检查清单的设计必须具备可验证性，避免引入需要人工主观判断的模糊标准，以确保奖励信号的客观性和自动化训练的可行性。

---

### 实践 2：采用基于轨迹的最优行为监督

**说明**:
单纯的强化学习在复杂的工具使用场景中探索效率较低。CM2 方法强调利用专家演示轨迹来辅助训练。通过在训练初期或混合训练过程中引入专家数据，可以规范智能体的行为模式，使其更快地掌握正确的工具调用顺序和参数设置。

**实施步骤**:
1. 收集高质量的专家轨迹数据，包含观察、思考、工具调用和最终结果。
2. 在强化学习训练开始前，先进行监督微调（SFT），使模型具备基本的工具使用能力。
3. 在强化学习阶段，使用混合数据集（专家轨迹 + Agent 交互轨迹）进行训练，或者使用离线强化学习算法（如 CQL）来利用专家数据防止策略偏离。
4. 定期评估模型生成轨迹与专家轨迹的相似度，以监控训练效果。

**注意事项**:
专家数据的质量直接决定了模型能力的上限。如果专家数据中包含错误的工具调用或逻辑漏洞，模型会学习并放大这些错误。

### 实践 3：实施多轮次与长链路的训练策略

**说明**:
单轮工具调用往往无法解决复杂问题。CM2 针对多轮次交互进行了优化，要求模型具备记忆能力和上下文理解能力。在训练中，需要特别关注长序列的梯度消失和爆炸问题，以及多轮交互中的状态追踪。

**实施步骤**:
1. 在构建训练环境时，设计需要多次工具调用才能解决的复杂任务（例如：先查询天气，再根据天气查询建议，最后预订行程）。
2. 使用支持长上下文的 Transformer 架构（如使用 RoPE 或 FlashAttention 技术），确保模型能处理长序列的历史记录。
3. 在奖励函数设计中，引入对“轮次效率”的惩罚或奖励，鼓励模型用最少的轮次完成任务，避免无效的循环调用。
4. 实施“课程学习”，从简单的单步任务开始训练，逐步过渡到复杂的多轮次任务。

**注意事项**:
长链路训练容易导致“灾难性遗忘”，即模型在学习新任务时忘记了旧任务。建议使用经验回放池来保存各类任务的样本。

### 实践 4：设计细粒度的工具调用反馈

**说明**:
工具调用的结果（无论是成功还是失败）是模型学习的重要信号。CM2 方法强调不仅要看工具是否被调用，还要看调用的参数是否正确以及返回的结果是否被有效利用。反馈机制应包含工具执行状态、参数正确性校验和结果相关性打分。

**实施步骤**:
1. 建立工具 API 的严格校验层，对模型生成的参数进行类型和范围检查。
2. 当工具调用发生错误（如参数缺失、类型错误）时，给予负奖励，并将错误信息作为特殊的 Observation 返回给模型，让其学习如何纠错。
3. 对于工具返回的文本结果，使用语义匹配模型判断该结果是否有助于推进任务，并给予相应的奖励。
4. 记录工具调用的频率分布，防止模型对特定工具产生过度依赖或完全忽略某些工具。

**注意事项**:
错误处理机制必须健壮。如果环境因为错误的工具调用而直接崩溃，训练将无法继续。应确保所有异常都能被捕获并转化为负反馈。

## 常见问题


### 1: 什么是 CM2，它主要解决了什么问题？

1: 什么是 CM2，它主要解决了什么问题？

**A**: CM2 (Checklist for Multi-step and Multi-turn) 是一种用于训练智能体使用工具的强化学习框架。它主要解决了当前大型语言模型（LLM）在复杂任务中面临的两个核心问题：一是现有的微调方法难以有效处理多轮、多步骤的工具使用场景；二是传统的奖励模型（如基于成对比较的奖励）无法细致地捕捉复杂任务中的中间步骤是否正确执行。CM2 通过引入“清单奖励”机制，将复杂的任务分解为细粒度的子目标，从而提供更精确的监督信号，显著提升了模型在长链路任务中的表现。

---



### 2: CM2 中的“清单奖励”是如何运作的？

2: CM2 中的“清单奖励”是如何运作的？

**A**: 清单奖励是 CM2 方法的核心组件。其运作流程如下：
1.  **离线阶段**：在训练开始前，系统会利用 GPT-4 等高性能模型对训练数据进行逆向分析，为每个轨迹生成一份“清单”。这份清单包含了完成该任务所需的关键步骤或子目标。
2.  **在线评估**：在强化学习训练过程中，当智能体执行工具调用的中间步骤时，奖励模型会根据预先生成的清单检查当前步骤是否符合要求。
3.  **信号反馈**：如果智能体的行为与清单中的子目标匹配，它会获得正向奖励；反之则获得惩罚。这种机制使得模型能够获得比仅看最终结果更密集、更具体的反馈，从而加速收敛并提高准确性。

---



### 3: CM2 与传统的 RLHF（基于人类反馈的强化学习）在工具使用任务上有什么区别？

3: CM2 与传统的 RLHF（基于人类反馈的强化学习）在工具使用任务上有什么区别？

**A**: 传统的 RLHF 通常依赖于人类标注员对模型生成的最终输出进行比较（例如，输出 A 是否比输出 B 更好），这种稀疏的奖励信号在多步骤工具使用中效果有限，因为模型很难知道最终错误是发生在哪一步。
相比之下，CM2 采用了基于结果的奖励模型，并结合了细粒度的清单检查。主要区别在于：
1.  **粒度**：RLHF 通常针对最终结果，而 CM2 针对中间过程。
2.  **客观性**：CM2 的清单基于工具执行的客观结果（如 API 返回的数据是否正确提取），减少了人类主观判断的不确定性。
3.  **效率**：清单提供了一种自动化的、可扩展的方式来生成密集奖励，而不需要人类对每一个中间步骤进行标注。

---



### 4: CM2 的训练流程包含哪些具体阶段？

4: CM2 的训练流程包含哪些具体阶段？

**A**: CM2 的训练流程主要分为三个阶段：
1.  **监督微调（SFT）**：首先使用专家演示数据对基础模型进行微调，使其具备基本的工具调用和对话能力。
2.  **清单生成**：利用强大的教师模型（如 GPT-4）分析 SFT 数据，提取出完成每个任务的关键步骤，形成验证清单。
3.  **强化学习（RL）**：使用 PPO（近端策略优化）或 ReMax 等算法训练策略模型。在此阶段，模型在环境中执行动作，奖励模型根据清单和执行结果给出奖励，从而优化模型的多步决策能力。

### 5: CM2 方法在实验中的表现如何，有哪些具体的提升？

5: CM2 方法在实验中的表现如何，有哪些具体的提升？

**A**: 根据论文报告，CM2 在多个工具使用基准测试中取得了显著的性能提升。
1.  **ToolBench**：在多个子任务上，CM2 训练出的 7B 模型在生成率（Pass Rate）上显著优于基线模型（如仅经过 SFT 的模型或使用标准 RM 训练的模型）。

3.  **长尾任务**：在需要更多步骤的复杂任务中，CM2 的优势尤为明显，因为清单机制能够有效防止模型在长链条中过早偏离正确路径。

### 6: CM2 方法是否适用于所有类型的工具使用场景？

6: CM2 方法是否适用于所有类型的工具使用场景？

**A**: 虽然 CM2 在实验中表现出色，但它主要针对的是**可分解的、多步骤的**工具使用任务。对于某些极其简单、单步即可完成的任务，CM2 的清单生成机制可能显得过于繁琐，带来的收益有限。此外，CM2 的效果在很大程度上依赖于“清单”的质量。如果任务本身非常模糊，或者很难定义明确的中间步骤（例如某些极具创造性的开放性任务），生成高质量的清单可能会面临挑战。然而，对于绝大多数涉及 API 调用、代码执行或检索增强生成的实际应用场景，CM2 都是非常适用的。
