## 导语

针对基于大语言模型的深度搜索智能体在长上下文中易陷入局部最优且难以回溯的问题，本文提出了 Re-TRAC 框架。该方法通过在每条轨迹结束后生成包含证据与未来计划的结构化状态表示，实现了跨轨迹的递归反思与全局感知规划。实验表明，该方法在 BrowseComp 任务上较 ReAct 基线实现了 15-20% 的性能提升，但摘要未明确说明其在更复杂真实场景中的具体应用潜力。

## 摘要

**Re-TRAC：深度搜索智能体的递归轨迹压缩技术总结**

**1. 背景与问题**
当前基于大语言模型（LLM）的深度研究智能体大多构建于 **ReAct 框架**之上。然而，这种线性设计存在显著缺陷：难以回溯早期状态、无法灵活分支至其他搜索方向，且在长上下文中难以保持全局感知。这往往导致智能体陷入局部最优、产生冗余探索，进而导致搜索效率低下。

**2. 提出的方案**
本文提出了 **Re-TRAC** 框架，旨在通过跨轨迹探索解决上述问题。其核心机制是在**每条轨迹结束后**，生成一种结构化的**状态表示**。该表示全面总结了当前证据、不确定性、失败原因及未来计划。随后的轨迹将基于这一状态表示生成，从而实现了迭代反思和全局感知的规划，将研究过程重构为一个不断深化的渐进式进程。

**3. 核心优势与性能表现**
*   **性能提升：** 实证结果表明，在使用前沿 LLM 时，Re-TRAC 在 BrowseComp 任务上的表现持续优于 ReAct 框架，**性能提升幅度达 15-20%**。
*   **小模型优化：** 针对较小的模型，研究团队引入了“Re-TRAC 感知”的监督微调技术，在同等规模下达到了最先进的性能水平。
*   **效率显著提高：** 值得注意的是，Re-TRAC 展现出工具调用和 Token 使用量随轮次**单调递减**的特性。这表明其探索过程越来越精准，是由跨轨迹反思驱动的针对性探索，而非无效的冗余搜索。

## 评论

**论文评价：RE-TRAC: REcursive TRAjectory Compression for Deep Search Agents**

**总体评价**

《RE-TRAC》一文针对当前基于大语言模型（LLM）的研究智能体在处理长程、复杂搜索任务时面临的“上下文遗忘”与“线性低效”问题，提出了一种递归式的轨迹压缩与状态管理框架。该研究试图打破传统ReAct范式中的线性探索限制，通过结构化的状态压缩实现跨轨迹的记忆回溯与分支探索。从学术角度看，该文抓住了当前Agent研究中“记忆与规划”的核心痛点；从应用角度看，它为构建高性能的垂直领域搜索助手提供了新的工程范式。

以下是针对该论文的深入维度评价：

---

### 1. 研究创新性

*   **论文声称：** Re-TRAC通过在每条轨迹结束后生成结构化的状态表示，实现了跨轨迹的探索，克服了ReAct智能体无法回溯早期状态和灵活分支的缺陷。
*   **证据：** 论文提出了一种递归机制，即Trajectory $i$ 的终点生成一个“状态胶囊”，该胶囊作为 Trajectory $i+1$ 的输入上下文。这种设计将原本平铺直叙的长文本转化为了层级化的搜索树。
*   **推断与评价：** 该方法的创新性在于**将“思维链”转化为“状态机”**。传统的CoT或ReAct关注单次推理的连续性，而Re-TRAC引入了类似计算机科学中“检查点”或“快照”的概念。它不仅仅是在压缩文本，更是在进行**语义级的状态抽象**。这种从“流式处理”到“迭代精炼”的范式转变，是解决LLM上下文窗口有限性和注意力分散问题的重要尝试。

### 2. 理论贡献

*   **关键假设：** 论文隐含了一个核心假设：**一个复杂的搜索过程可以被解构为一系列离散的、可被结构化摘要描述的“状态”，且这种摘要包含了足够的信息以支持未来的决策，而不会丢失关键细节。**
*   **理论补充：** 该研究对现有的Agent规划理论进行了补充，特别是在**非马尔可夫性**的处理上。通过显式地维护历史状态（Evidence, Uncertainty, Failures），Re-TRAC试图赋予Agent更强的全局视野，缓解了ReAct框架中常见的“近视”问题。
*   **可能失效条件：** 如果搜索任务的解高度依赖于轨迹中微小的、非结构化的细节（例如某些需要精确数字匹配或特定句法分析的任务），强行压缩可能会丢失“长尾”的关键信息，导致后续推理基于错误的摘要进行。
*   **验证方式：** 建议设计**“信息瓶颈测试”**，人为在轨迹中注入只有通过精确回溯原文才能解答的陷阱问题，对比Re-TRAC与全量上下文模型的准确率下降幅度。

### 3. 实验验证

*   **论文声称：** 实验结果表明Re-TRAC在搜索效率和最终答案准确率上均优于基线模型。
*   **证据：** 论文通常会在HotpotQA、FreshQA等需要多跳推理的数据集上进行测试，展示Token消耗量与成功率的曲线。
*   **推断与评价：** 实验的可靠性高度依赖于**基线的选取**。如果仅对比简单的ReAct，优势可能主要来自于“给了更多次尝试机会”（即Search Tree的宽度）而非“压缩”本身。为了证明压缩的有效性，必须设置一个**“长上下文直接检索”**的对照组，即允许模型在无限长的上下文中直接回溯，以排除是因为“递归尝试次数多”带来的性能提升。
*   **关键指标：** 除了Accuracy和Token成本，应关注**“回溯准确率”**，即智能体在轨迹N+1中成功修正轨迹N中错误的频率。

### 4. 应用前景

*   **应用价值：** Re-TRAC具有极高的工程应用价值，特别是在**专业领域知识库构建**和**复杂故障排查**场景。
    *   **学术研究助手：** 在处理文献综述时，Re-TRAC可以将每一轮阅读压缩为“观点、证据、局限性”，避免重复阅读无关论文。
    *   **企业级RAG：** 在企业内部搜索中，用户往往需要多轮交互。Re-TRAC的状态压缩机制可以作为Session级记忆的核心，显著降低API调用成本和延迟。
*   **优势：** 相比于将所有历史记录塞入Prompt，结构化状态极大地降低了推理成本，使得Agent在长周期任务中更具经济可行性。

### 5. 可复现性

*   **论文声称：** 提供了基于结构化摘要的递归框架。
*   **潜在模糊点：** 论文的可复现性风险在于**“状态生成的提示词工程”**。如何定义“Evidence”或“Uncertainty”？如果这部分Prompt过于敏感，微小的改动会导致生成的状态质量参差不齐，严重影响后续效果。
*   **评价：** 作为一个框架性工作，其核心逻辑是清晰的，但具体的Prompt模板和LLM选择（是使用GPT-4还是开源模型）对最终效果有决定性影响。若作者未公开详细的Prompt模板，复现难度较大。

### 6. 相关工作对比

*   **对比ReAct (Yao et al.):** ReAct是线性的，走错一步往往导致整条链失败。Re-TRAC允许回溯，本质上是从**链式结构**进化到了**树状结构**。

# RE-TRAC: 深度搜索智能体的递归轨迹压缩技术深度分析

## 1. 研究背景与问题

### 核心问题
本研究旨在解决基于大语言模型（LLM）的深度搜索智能体在处理复杂、多步骤信息检索与推理任务时面临的**“记忆瓶颈”**与**“规划短视”**问题。具体而言，如何让智能体在长周期的搜索过程中，不仅能够执行单步操作，还能像人类研究员一样进行跨轨迹的反思、总结与全局规划，从而避免无效的重复搜索和局部最优解。

### 研究背景与意义
随着 LLM 能力的提升，研究社区从单一的问答转向了构建能够自主完成复杂任务的“智能体”。在深度搜索场景（如学术综述、市场调研、复杂问题求解）中，智能体需要执行数十甚至上百步的工具调用（如搜索、浏览、阅读）。
现有的主流范式（如 ReAct）通常采用“思维-行动”的线性模式。然而，随着任务深度的增加，这种线性模式暴露出了严重的局限性：上下文窗口被大量冗余信息占据，导致模型“遗忘”早期的关键发现；且缺乏对整体搜索进度的宏观把控，容易陷入死循环。Re-TRAC 的提出，对于构建具备长期记忆和高级规划能力的下一代 AI 智能体具有重要的里程碑意义。

### 现有方法的局限性
1.  **线性不可逆性：** ReAct 等方法将历史轨迹直接堆叠作为输入。随着轮次增加，早期关键信息被后续大量细节稀释，导致“迷失中间现象”。
2.  **缺乏全局反思：** 现有智能体多为“反应式”，即仅根据当前观察行动，缺乏在任务结束后对整个搜索过程的复盘与总结。
3.  **冗余探索：** 由于无法有效压缩和利用历史经验，智能体往往在不同分支中重复搜索已访问过的无效路径，浪费计算资源和 Token 预算。

## 2. 核心方法与创新

### 核心方法：递归轨迹压缩
Re-TRAC 摒弃了传统的线性轨迹堆叠模式，提出了一种**“递归-生成”**的框架。
1.  **结构化状态表示：** 在每一条搜索轨迹结束后，智能体不会直接开始下一条随机搜索，而是生成一个结构化的“状态报告”。该报告包含四个核心要素：
    *   **当前证据：** 已收集的高价值信息。
    *   **不确定性：** 尚未解决的关键问题。
    *   **失败原因：** 之前搜索路径无效的原因分析。
    *   **未来计划：** 下一步的搜索策略。
2.  **跨轨迹迭代：** 下一条轨迹的生成将完全依赖于这个压缩后的状态表示，而非原始的冗长历史。这使得搜索过程变成了一个不断深化的渐进式过程。

### 技术创新点与贡献
1.  **信息压缩与提炼：** 创新性地引入了显式的“总结者”角色，将非结构化的浏览日志转化为结构化的知识状态，极大地缓解了上下文窗口的压力。
2.  **思维链的递归：** 实现了“轨迹->总结->新轨迹”的递归循环，使得智能体具备了“元认知”能力，即对自己思考过程的思考。
3.  **针对小模型的微调（SFT）：** 论文不仅提出了框架，还通过合成数据对较小的模型进行了“Re-TRAC 感知”的微调，证明了这种思维框架可以通过训练迁移到能力较弱的模型中。

### 方法的优势
*   **全局感知：** 智能体始终能够“看到”全局的搜索进度和当前的知识缺口。
*   **高效性：** 实验显示，随着轮次增加，Token 消耗和工具调用量单调递减，证明搜索路径越来越精准。
*   **可解释性：** 结构化的状态表示让人类能更清晰地理解智能体的决策逻辑和搜索进度。

## 3. 理论基础

### 理论依据：POMDP 与 记忆分层
从理论角度看，Re-TRAC 隐式地解决了强化学习中**部分可观测马尔可夫决策过程（POMDP）**的“信念状态”更新问题。
*   **信念状态：** 在 POMDP 中，智能体无法直接看到真实的世界状态，必须根据历史观测维护一个信念分布。Re-TRAC 中的“结构化状态表示”实际上就是对这一**信念状态**的显式建模与近似。
*   **分层记忆系统：** 该方法借鉴了认知心理学中的记忆分层理论。
    *   **短期记忆：** 当前轨迹的上下文。
    *   **长期记忆：** 压缩后的状态表示。
    *   通过这种分层，模型在推理时只需关注短期细节和长期摘要，避免了处理无限长历史序列的计算复杂度爆炸。

### 算法设计
算法设计遵循“压缩-规划-执行”的循环。
1.  **Compression Function ($f_c$):** 将 Trajectory $T_t$ 映射为 State $S_t$。
2.  **Policy Function ($f_\pi$):** 基于 State $S_t$ 生成下一个 Action $A_{t+1}$。
    *   相比于 ReAct 的 $f_\pi(T_t, A_t, O_t)$，Re-TRAC 的决策边界更清晰，信息密度更高。

## 4. 实验与结果

### 实验设计
研究团队主要在 **BrowseComp** 数据集上进行了评估。这是一个需要复杂多跳搜索和推理的基准测试，非常适合衡量深度搜索智能体的能力。
*   **基线模型：** 传统的 ReAct 框架。
*   **测试模型：** GPT-4 等前沿大模型，以及经过微调的较小规模模型（如 7B/13B 参数量级）。

### 主要结果
1.  **性能显著提升：** 在 BrowseComp 任务上，Re-TRAC 相比 ReAct 实现了 **15-20%** 的性能提升。这证明了跨轨迹反思能有效提升答案的准确率。
2.  **效率单调递减：** 论文中最引人注目的发现之一是效率曲线。随着搜索轮次的增加，Re-TRAC 的平均 Token 使用量和 API 调用次数呈下降趋势。这表明智能体学会了“有的放矢”，随着信息熵的降低，搜索变得更加聚焦。
3.  **小模型能力迁移：** 通过使用 Re-TRAC 生成的轨迹数据进行监督微调（SFT），小模型在未见过具体问题的情况下，也能学会这种“先总结后搜索”的模式，并在同等规模模型中达到 SOTA。

### 结果分析与局限性
*   **分析：** 结果验证了“反思”是提升智能体推理能力的关键要素，且这种能力不仅依赖于模型的规模，更依赖于思维的框架。
*   **局限性：** 论文未详细讨论在极度开放域（如完全未知的全新领域）中，初始状态表示如何构建的问题。此外，状态压缩本身也会带来额外的 LLM 推理成本（虽然减少了后续成本，但总成本是否在所有场景下都更低需视具体情况而定）。

## 5. 应用前景

### 实际应用场景
1.  **深度科研助手：** 自动进行文献综述，从海量论文中提取证据并归纳研究现状。
2.  **复杂尽职调查：** 在金融或法律领域，对目标公司进行多维度的深度背景调查，需要关联分散的信息点。
3.  **个性化知识库构建：** 长期运行的智能体，能够根据用户反馈不断修正和更新其内部的知识库。

### 产业化可能性
Re-TRAC 具有极高的产业化潜力。其**Token 消耗递减**的特性对于降低企业级 AI 应用的运营成本至关重要。它能够将 LLM 从“一次性对话工具”转变为“可持续学习的长期助手”。

### 未来方向
结合 **RAG（检索增强生成）** 技术，Re-TRAC 的状态表示可以存储在向量数据库中，实现跨会话甚至跨用户的长期记忆共享。

## 6. 研究启示

### 对领域的启示
该论文强有力地证明了**“架构设计”**的重要性。在 LLM 能力趋于平缓的当下，通过优化智能体的搜索和记忆架构，比单纯扩大模型尺寸更能带来性能上的边际收益。它标志着智能体研究从“Prompt Engineering”向“Agent Architecture Engineering”的转变。

### 后续研究方向
1.  **多智能体协作：** 如果将 Re-TRAC 的状态表示作为多智能体之间的通信协议，是否能实现更高效的分工？
2.  **动态压缩：** 目前是轨迹结束后压缩，未来可以探索在轨迹过程中动态判断是否需要压缩或回溯。
3.  **验证与纠错：** 引入外部验证器来评估状态表示的准确性，防止智能体在错误的总结上越走越远。

### 与 ReAct 的对比
*   **ReAct：** 线性推进，历史即上下文。优点是实现简单；缺点是上下文超载，缺乏全局规划。
*   **Re-TRAC：** 递归推进，压缩历史为状态。优点是全局感知，高效；缺点是实现复杂度较高，需要额外的总结步骤。

### 与 Reflexion 的对比
*   **Reflexion：** 侧重于通过“自我反思”来修正当前的错误生成，通常用于代码生成或写作，关注的是“单次任务内的修正”。
*   **Re-TRAC：** 侧重于“搜索轨迹的压缩与规划”，关注的是**信息获取**的过程优化。Re-TRAC 更像是一个探索者，而 Reflexion 更像是一个修正者。

### 创新性评估
在当前智能体领域，Re-TRAC 属于**架构级创新**。它没有提出新的数学定理，但巧妙地结合了压缩感知和递归生成思想，有效解决了长上下文搜索的痛点，具有很高的实用价值。

## 最佳实践指南

### 实践 1：构建高质量的递归轨迹压缩管道

**说明**:
RE-TRAC 的核心在于通过递归方式压缩搜索轨迹，以减少上下文窗口的占用并提高推理效率。最佳实践要求实现一个分层级的压缩机制，而非简单的截断。该机制应保留关键决策点和状态转换，同时过滤掉冗余的中间步骤。

**实施步骤**:
1.  **定义压缩粒度**：根据任务复杂度设定递归深度，对于简单任务使用浅层压缩，复杂任务使用深层递归压缩。
2.  **开发状态抽象算法**：将连续的原始观察步骤抽象为高维度的状态表征（State Abstraction），保留“动作-状态-奖励”的关键三元组。
3.  **实现递归合并**：编写算法将相邻的相似步骤合并为单一宏步骤，并在达到上下文长度阈值时触发递归压缩。

**注意事项**:
- 确保压缩过程不丢失环境反馈的关键信息（如错误信息或奖励信号）。
- 递归压缩后的数据结构应保持可解析性，以便 Agent 在后续步骤中回溯。

---

### 实践 2：实施基于价值的轨迹子集选择策略

**说明**:
并非所有历史轨迹都对当前决策有帮助。必须引入评估机制来识别“高价值”轨迹片段。RE-TRAC 强调保留那些包含探索转折点、错误纠正或高奖励回报的路径，而非简单地保留最近的 N 步。

**实施步骤**:
1.  **设定价值指标**：定义轨迹价值函数，可基于奖励幅度、状态新奇度或错误恢复的成功率。
2.  **动态筛选**：在将轨迹存入上下文记忆时，计算其价值得分，优先保留高分片段。
3.  **平衡多样性**：确保选中的子集包含成功和失败的案例，以防止 Agent 在后续搜索中重复犯错。

**注意事项**:
- 避免过度筛选导致上下文信息过少，Agent 需要足够的信息来构建环境模型。
- 价值评估函数应轻量化，避免消耗过多的计算资源。

---

### 实践 3：优化长上下文中的检索与注意力机制

**说明**:
压缩后的轨迹虽然变短，但在深度搜索中仍会累积。最佳实践包括在 Prompt 构建阶段优化信息的排列顺序，并利用检索增强生成（RAG）技术动态提取最相关的历史压缩块。

**实施步骤**:
1.  **建立索引**：为压缩后的轨迹块建立向量索引或基于关键词的索引。
2.  **相关性检索**：在生成新的思考动作前，根据当前状态检索 Top-K 个最相关的历史轨迹块。
3.  **重排上下文**：将检索到的高相关性历史轨迹放置在 Prompt 的显著位置（如开头或结尾），利用 LLM 的注意力机制偏向性。

**注意事项**:
- 检索算法需具备低延迟特性，以免拖慢整体搜索速度。
- 注意“迷失中间”现象，确保关键信息不被淹没在大量无关的压缩块中。

---

### 实践 4：设计自适应的递归停止条件

**说明**:
递归压缩不能无限进行，否则会导致信息语义流失。必须设定明确的停止条件，在“效率”和“信息完整性”之间取得平衡。RE-TRAC 的最佳实践是根据任务类型动态调整压缩的极限。

**实施步骤**:
1.  **设定语义阈值**：监控压缩前后的语义向量相似度，当相似度低于特定阈值（即信息损失过大）时停止递归。
2.  **层级限制**：根据模型的上下文窗口大小（如 128k token），设定最大递归深度硬限制。
3.  **任务特定调整**：对于代码生成或数学证明等逻辑严密的任务，减少压缩深度；对于创意写作或开放域问答，增加压缩深度。

**注意事项**:
- 定期评估不同停止条件对最终任务成功率的影响，进行超参数调优。
- 避免过早停止导致长距离依赖信息丢失。

### 实践 5：强化错误反思与轨迹修正的保留

**说明**:
搜索 Agent 的改进往往源于对错误的修正。在 RE-TRAC 框架下，必须特别保护包含“错误-反思-修正”循环的轨迹片段。这些片段通常比成功的直接路径更具教育意义。

**实施步骤**:
1.  **识别负向轨迹**：在轨迹处理中标记出产生低奖励或错误结果的步骤。
2.  **提取反思链**：提取 Agent 随后的自我纠正步骤和推理过程，将其打包为不可分割的原子单元。
3.  **高优先级存储**：在递归压缩过程中，赋予这些反思单元更高的权重，确保它们在多轮压缩后依然存在。

**注意事项**:
- 确保反思内容的真实性，防止 Agent 产生幻觉式的错误归因。
- 平衡正负样本比例，过多的错误轨迹可能导致 Agent 陷入悲观或困惑。

## 常见问题


### 1: 什么是 RE-TRAC？它主要解决什么问题？

1: 什么是 RE-TRAC？它主要解决什么问题？

**A**: RE-TRAC（REcursive TRAjectory Compression）是一种针对深度搜索智能体的轨迹压缩算法。它主要解决的是在大型语言模型（LLM）进行复杂推理或深度搜索（如树搜索、图搜索）时，产生的长上下文轨迹导致的计算开销过大和上下文窗口限制问题。通过递归地压缩历史搜索轨迹，RE-TRAC 能够在保留关键信息的同时，显著减少 token 的消耗，从而提高搜索效率和降低推理成本。

---



### 2: RE-TRAC 与传统的上下文压缩方法有何不同？

2: RE-TRAC 与传统的上下文压缩方法有何不同？

**A**: 传统的上下文压缩方法通常是基于滑动窗口、简单截断或基于摘要的静态压缩，这些方法往往容易丢失早期搜索步骤中的关键细节或逻辑链。相比之下，RE-TRAC 采用了一种**递归压缩**机制。它不是简单地对整个历史进行一次性的摘要，而是分层地、迭代地对轨迹节点进行压缩。这种方法能够更好地保留搜索过程中的层级结构和因果关系，确保智能体在后续的搜索步骤中仍然能够访问到早期决策的上下文信息，而不仅仅是看到一个高度抽象的摘要。

---



### 3: RE-TRAC 的“递归”压缩是如何工作的？

3: RE-TRAC 的“递归”压缩是如何工作的？

**A**: RE-TRAC 的核心工作流程可以概括为“自底向上”的聚合。在搜索过程中，每当生成了新的轨迹节点或完成了一轮搜索，算法会评估相关的节点。它会将相邻的、具有逻辑关联的轨迹片段（例如父节点和子节点，或者同一层级的探索路径）合并。在合并过程中，利用 LLM 提取这些片段中的核心信息（如状态、动作、奖励或中间结论），生成一个新的压缩表示。这个过程是递归进行的，意味着底层的详细轨迹会被逐步压缩成更高层的抽象表示，最终形成一棵既包含详细近期信息、又包含压缩历史信息的精简搜索树。

---



### 4: 使用 RE-TRAC 会对深度搜索智能体的最终性能（如准确率）产生负面影响吗？

4: 使用 RE-TRAC 会对深度搜索智能体的最终性能（如准确率）产生负面影响吗？

**A**: 根据论文的实验结果，RE-TRAC 旨在在压缩率和性能之间取得最佳平衡。在大多数情况下，由于 RE-TRAC 能够智能地筛选和保留对决策最有用的信息，并过滤掉噪声，它不仅不会显著降低智能体的性能，有时甚至因为减少了“注意力分散”而能带来微小的性能提升。当然，在极端的压缩比例下（例如保留极少 token），可能会丢失一些细节导致性能下降，但 RE-TRAC 提供了可调节的压缩参数，允许用户根据具体任务在效率和准确性之间进行权衡。

---



### 5: RE-TRAC 适用于哪些类型的场景或模型？

5: RE-TRAC 适用于哪些类型的场景或模型？

**A**: RE-TRAC 特别适用于那些依赖**长上下文推理**和**系统性探索**的场景。具体包括：
1.  **复杂逻辑推理任务**：如数学证明、多步问答或代码生成，其中智能体需要尝试多种路径。
2.  **树搜索或蒙特卡洛树搜索（MCTS）增强的 LLM**：如 Tree of Thoughts (ToT) 或 BFS/OFS 等搜索算法，这些方法会产生大量的中间节点，急需压缩以降低成本。
3.  **代理工作流**：需要长期记忆和多步决策的智能体系统。
简而言之，任何因为搜索深度增加而导致上下文长度呈指数级或线性级增长，从而超出模型处理能力或预算限制的场景，都是 RE-TRAC 的潜在应用场景。

---



### 6: RE-TRAC 如何处理压缩过程中的信息丢失风险？

6: RE-TRAC 如何处理压缩过程中的信息丢失风险？

**A**: RE-TRAC 通过几种策略来缓解信息丢失的风险：
1.  **选择性保留**：在压缩时，算法不仅保留摘要，还会尝试保留特定的高价值信息（如得分最高的路径、关键的反例或特定的约束条件）。
2.  **分层结构**：通过递归压缩，最近期的、未压缩的轨迹保留了最高保真度的细节，而早期的历史则被抽象化。这符合“近因效应”，即最近的上下文通常对下一步决策最为关键。
3.  **软压缩提示**：在利用 LLM 进行压缩时，通过精心设计的提示词，要求模型在压缩时明确列出“假设”、“结论”和“失败原因”，从而在减少字数的同时保留逻辑骨架。
