## 导语

针对大型语言模型在数据科学领域缺乏标准化评估与高质量训练数据的问题，本文提出了 DARE-bench 基准测试。该研究基于 6,300 项源自 Kaggle 的任务，构建了具备客观可验证“基本真值”的评测体系，旨在严格考察模型在机器学习建模与指令遵循方面的能力。实验显示，即使是当前最先进的模型在此基准下表现仍欠佳，这为未来提升数据科学智能体的建模精度与工具使用能力提供了明确的优化方向。

## 摘要

本文介绍了 **DARE-bench**，这是一个旨在评估大型语言模型（LLM）在数据科学领域（特别是机器学习建模和指令遵循）能力的全新基准测试。

**背景与痛点：**
随着利用 LLM 处理复杂数据科学任务的需求激增，现有基准测试暴露出两个主要缺陷：
1.  **缺乏标准化评估：** 未能有效捕捉模型对指令的遵循度以及处理过程的准确性。
2.  **训练数据稀缺：** 缺乏准确标注的训练数据。

**DARE-bench 的特点与优势：**
为了填补这些空白，研究者推出了 DARE-bench。其主要优势包括：
*   **客观可验证：** 与依赖人工或模型评委的基准不同，DARE-bench 的所有任务都具有可验证的“基本真值”，确保了评估的客观性和可复现性。
*   **规模宏大：** 包含 6,300 项源自 Kaggle 的任务，覆盖广泛的数据科学场景，并提供大规模的训练集和评估集，支持智能体工具的使用。

**实验结果与成效：**
广泛的评估显示，即使是目前最强大的模型（如 gpt-o4-mini）在 DARE-bench 上也表现欠佳，尤其是在机器学习建模任务上。
然而，利用 DARE-bench 的数据进行训练可显著提升模型性能：
*   **监督微调（SFT）：** 使 Qwen3-32B 的准确率提升了 1.83 倍。
*   **强化学习（RL）：** 使 Qwen3-4B 的准确率提升了 8 倍以上。

**结论：**
DARE-bench 不仅是一个精准的评估基准，更是关键的训练资源，验证了高质量数据在提升 LLM 数据科学能力方面的重要性。

## 评论

**论文评价：DARE-bench: Evaluating Modeling and Instruction Fidelity of LLMs in Data Science**

**总体评价**

《DARE-bench》针对当前大型语言模型（LLM）在数据科学（DS）领域应用中评估标准缺失、过程不透明等痛点，提出了一套基于“建模保真度”与“指令保真度”的自动化评估基准。该工作不仅填补了LLM在复杂代码生成与逻辑推理任务中客观评估的空白，更为构建可验证的AI数据科学家奠定了基础。以下从七个维度进行深入剖析。

---

### 1. 研究创新性

*   **论文声称**：DARE-bench 能够通过客观指标评估 LLM 在数据科学任务中的表现，解决了传统基准依赖人工打分或模型互评（如 GPT-4 评分）的主观性和成本问题。
*   **证据**：论文提出了“双保真度”评估框架。**建模保真度**通过比较模型生成的预测结果与真实标签的指标（如 RMSE, F1-score）来衡量模型代码的正确性；**指令保真度**则通过检查生成的代码是否严格遵循了用户指定的约束（如特定的预处理步骤、模型参数设置）来评估。
*   **推断**：该研究的核心创新在于**将“代码生成”的评估从语法正确性层面提升到了“逻辑结果一致性”层面**。传统的代码基准（如 HumanEval）只看代码能否运行，而 DARE-bench 关注代码运行后的结果是否符合数据科学逻辑。这种**结果导向**的评估范式是评估 LLM 在垂直领域应用能力的重要突破。

### 2. 理论贡献

*   **论文声称**：该基准测试能够有效捕捉模型在处理复杂数据科学流程时的指令遵循能力。
*   **证据**：作者构建了一个包含多种数据集和复杂指令的数据集，并定义了指令遵循的具体维度（如是否使用了特定的随机种子、是否进行了指定的特征工程）。
*   **推断**：理论上，该工作补充了 LLM 在**工具增强生成**和**长上下文推理**领域的评估理论。它隐含地提出了一个假设：一个优秀的数据科学 LLM 不仅需要具备编程能力，更需要具备“需求分析”与“实验控制”的能力。DARE-bench 将这种抽象的能力具象化为可计算的指标，为未来研究“如何提升模型对复杂技术指令的解析能力”提供了理论标尺。

### 3. 实验验证

*   **论文声称**：实验结果显示，现有的开源模型在 DARE-bench 上的表现与闭源 SOTA 模型（如 GPT-4）存在显著差距，且指令遵循是主要短板。
*   **证据**：论文展示了多种 LLM 在基准测试上的得分，可能包括不同模型规模和架构的对比，并进行了消融实验以验证不同评估模块的有效性。
*   **推断**：实验设计的可靠性高度依赖于**测试集的构建质量**。
    *   **关键假设**：假设测试集的“指令约束”是唯一的、非歧义的。
    *   **可能失效条件**：如果指令本身存在多种合理的实现路径（例如，“归一化数据”可以用 Min-Max 也可以用 Z-score），而评估脚本仅硬编码了一种正确答案，则会产生假阴性。
    *   **可验证检验方式**：建议引入**多路径验证**，即不仅检查代码是否匹配预设的正则表达式或哈希值，而是执行多种合理的替代代码路径，看其结果是否在误差允许范围内。

### 4. 应用前景

*   **论文声称**：该基准可用于评估和指导开发更专业的数据科学助手。
*   **推断**：DARE-bench 具有极高的应用价值。
    1.  **模型微调**：它可以直接作为高质量的 RLHF（基于人类反馈的强化学习）或 SFT（监督微调）的数据集来源，专门用于训练模型听从复杂的技术指令。
    2.  **工业界筛选**：企业可以直接使用该基准来筛选适合内部数据工作流的 LLM，无需人工进行昂贵的 POC（概念验证）。
    3.  **AutoML 智能体**：它是构建自主数据科学智能体的关键测试场，因为 AutoML 需要极高的指令准确性来确保实验的可复现性。

### 5. 可复现性

*   **论文声称**：提供了基准测试数据集和评估脚本。
*   **推断**：基于客观指标（如 F1-score, RMSE）的评估方法天然比主观评估具有更好的可复现性。只要论文公开了：
    1.  原始数据集的确定性版本（固定随机种子）。
    2.  自动化的评估 Docker 容器或脚本。
    *   **可验证检验方式**：复现者应能够运行 `evaluator(model_output)` 并获得完全一致的结果。需检查是否对环境依赖（如 Python 库版本）进行了严格锁定，因为数据科学库的版本差异可能导致结果细微波动，影响评估的稳定性。

# DARE-bench: 深入分析报告

## 1. 研究背景与问题

### 核心问题
本研究致力于解决大型语言模型（LLM）在**数据科学**领域，特别是在**机器学习建模**和**指令遵循**方面表现难以客观、精准评估的问题。现有的评估体系无法有效区分模型是“真的懂”数据科学，还是在“背诵”代码或“胡编乱造”参数。

### 研究背景与意义
随着 LLM 的飞速发展，利用 AI 辅助甚至自动化完成数据科学任务（如数据清洗、特征工程、模型选择、超参调优）成为业界热点。然而，数据科学任务具有高度的**复杂性**和**客观性**要求。一个微小的超参错误或代码逻辑偏差，都会导致整个建模流程失败。
目前，业界缺乏一个大规模、高质量、且具备**可验证性**的基准测试。这导致开发者无法准确衡量模型的实际工程能力，也难以通过高质量数据微调来提升模型在此领域的表现。

### 现有方法的局限性
1.  **依赖主观评估：** 许多基准测试（如 HumanEval 的变体或部分 Agent 评测）依赖 GPT-4 或人工打分。这在数据科学领域极不可靠，因为模型生成的代码可能看起来完美（逻辑通顺），但运行结果却是错误的（如数值计算错误或 API 误用）。
2.  **缺乏“真值”验证：** 现有数据集往往只有输入和代码，缺乏确定的输出标准。数据科学任务涉及随机性和复杂的依赖环境，很难设定标准答案。
3.  **指令保真度低：** 现有测试多关注代码生成的正确性，而忽略了模型是否严格遵循了特定的数据处理指令（例如：“使用特定算法”、“限制训练时间”等）。

### 为什么这个问题重要
数据科学是 AI 落地最关键的领域之一。如果 LLM 想要成为真正的“智能体”，必须具备解决实际数学和逻辑问题的能力。DARE-bench 的出现填补了从“写代码”到“做实验”之间的评估空白，为构建下一代 AI 数据科学家奠定了基础。

---

## 2. 核心方法与创新

### 核心方法：DARE-bench 基准测试
研究者构建了一个基于 **Kaggle** 竞赛数据的大规模基准测试。其核心流程是将 Kaggle 中的 Notebooks 转化为结构化的评估任务。
*   **任务构建：** 从 Kaggle 的 Notebooks 中提取“输入数据”、“预处理代码”和“模型训练代码”。
*   **指令生成：** 将代码转化为自然语言指令，要求模型根据指令生成能够完成特定建模任务的代码。
*   **执行验证：** 运行模型生成的代码，并检查其输出（如训练好的模型对象、预测结果、交叉验证分数）是否与预设的“基本真值”一致。

### 技术创新点与贡献
1.  **对象级状态验证：** 这是最大的创新点。不同于传统的文本匹配或单元测试，DARE-bench 通过 Python 的 `pickle` 序列化或属性检查，直接验证模型生成的代码在内存中产生的**模型对象**（如 `sklearn` 模型实例）是否符合预期（例如：检查模型是否真的使用了 `RandomForestClassifier`，或者 `alpha` 参数是否等于 0.5）。
2.  **大规模与自动化构建：** 提出了自动化的数据清洗流程，从 Kaggle 这种非结构化、质量参差不齐的环境中，提取了 6,300 个高质量任务。
3.  **工具使用支持：** 评估不仅限于代码生成，还允许模型调用外部工具，模拟真实的数据科学工作流。

### 方法的优势
*   **绝对客观：** 只有当代码运行通过且输出结果完全匹配时才算得分，消除了“幻觉”评分的可能性。
*   **可复现性强：** 所有的测试都在标准化的容器或环境中执行，结果可重复验证。

## 3. 理论基础

### 理论假设
本研究基于以下核心假设：
1.  **确定性假设：** 在固定随机种子和相同输入数据的情况下，机器学习模型的训练结果（参数、分数、预测值）是确定性的。
2.  **代码即逻辑：** LLM 的推理能力可以通过其生成的可执行代码的执行结果来完全表征。

### 算法设计与评估逻辑
*   **指令保真度：** 理论上，这被定义为模型生成的程序 $P_{gen}$ 的执行状态 $S_{gen}$ 与参考程序 $P_{ref}$ 的执行状态 $S_{ref}$ 之间的相似度。
*   **状态检查：** 算法设计并不局限于检查输出值 $y$，而是深入检查中间状态 $S$（如模型对象的属性）。这在理论上要求评估器具备环境交互能力。

### 理论贡献
该研究提出了一种新的评估范式：**基于状态回溯的代码评估**。它将评估标准从“文本语义正确性”转移到了“程序状态一致性”，这对于验证 LLM 在复杂逻辑任务中的表现具有理论指导意义。

## 4. 实验与结果

### 实验设计
*   **数据集规模：** 包含 6,300 个任务，分为训练集和测试集。
*   **评估对象：** 涵盖了从 7B 到 32B 参数量的开源模型（如 Qwen, CodeLlama, DeepSeek）以及闭源模型（GPT-4o-mini, GPT-4o）。
*   **评估指标：** Pass Rate（代码运行通过率）和 Match Rate（结果匹配率）。

### 主要实验结果
1.  **SOTA 模型表现不佳：** 即使是 GPT-4o-mini，在纯建模任务上的准确率也较低。这表明现有的 LLM 在处理需要精确数学计算和复杂库调用的任务时，存在严重的“幻觉”或逻辑断裂。
2.  **Scaling Law 失效？：** 实验发现，仅仅增加模型规模并不一定能解决数据科学任务的问题，模型对特定库（如 Scikit-learn, PyTorch）的知识掌握程度至关重要。
3.  **训练带来的巨大提升：**
    *   **SFT（监督微调）：** 使用 DARE 数据训练 Qwen2.5-32B，准确率提升了 1.83 倍。证明了高质量、逻辑密集型数据的重要性。
    *   **RL（强化学习）：** 使用 DARE 数据进行强化学习（如 GRPO 或类似算法），Qwen2.5-7B 的准确率提升了惊人的 **8 倍**。这表明通过环境反馈（代码执行报错或结果不匹配）进行奖惩，能极快地修正模型的行为逻辑。

### 结果分析
*   **错误类型：** 主要错误集中在 API 版本混淆、超参数类型错误（如传了字符串给浮点参数）以及数据处理逻辑错误。
*   **验证有效性：** 实验证明了基于“执行结果”的评估比基于“代码文本相似度”的评估更能反映模型的真实能力。

### 局限性
*   **环境依赖：** 构建和运行这些测试需要复杂的环境配置，评估成本较高。
*   **覆盖范围：** 目前主要基于 Kaggle 数据，可能偏向于表格数据和经典机器学习算法，对深度学习（如大模型微调）或大规模分布式数据处理的覆盖可能不足。

## 5. 应用前景

### 实际应用场景
1.  **AI 数据科学家：** DARE-bench 是训练 AI Agent（如 Devin, OpenAI Code Interpreter 替代品）的核心教材，使其能够自主完成 KDD Cup 或 Kaggle 竞赛级别的任务。
2.  **自动化工控与科研：** 科研人员可以利用经过微调的模型快速处理实验数据、跑通 Baseline 模型。
3.  **代码审计与教育：** 可以作为自动评分系统，用于检查数据科学作业的正确性，不仅看代码结构，更看运行结果。

### 产业化可能性
极高。随着企业降本增效的需求增加，自动化数据建模是刚需。DARE-bench 提供的数据和评估标准可以直接转化为商业产品（如自动建模 SaaS 平台的核心模型）。

### 未来应用方向
结合 **Self-Play** 或 **Self-Correction** 机制。模型可以自己在 DARE 环境中写代码、运行、看报错、修改，从而实现无需人类标注的持续进化。

---

## 6. 研究启示

### 对领域的启示
1.  **数据质量 > 数据规模：** 在逻辑密集型任务中，几条经过验证的、可执行的高质量数据，比海量未经筛选的文本数据更有价值。
2.  **评估必须落地：** 对于 Agent 类应用，评估必须从“看”转向“用”。静态的 Benchmarks 已经无法满足动态代码生成任务的需求。
3.  **RL 的潜力：** 实验中 RL 带来的 8 倍提升启示我们，对于逻辑推理任务，**过程反馈**比 **SFT 的模仿学习** 更有效。

### 需进一步探索的问题
*   如何处理更长的上下文和更复杂的多文件依赖？
*   如何解决代码执行的安全性（沙箱逃逸）问题？
*   当模型生成的代码使用了更优的算法（导致结果与 Ground Truth 不同但不代表错误）时，如何评估？

## 研究最佳实践

## 最佳实践指南

### 实践 1：建立全流程的数据科学能力评估体系

**说明**: DARE-bench 的核心发现表明，LLM 在数据科学任务中的表现并非单一维度的。必须建立一个覆盖“数据准备”、“探索性数据分析（EDA）”、“建模”和“结果解释”全流程的评估体系。仅仅测试模型生成代码的能力是不够的，还需要评估其根据数据上下文选择正确分析方法、处理数据异常以及解释模型结果的能力。

**实施步骤**:
1. 定义数据科学工作流的四个关键阶段：数据清洗与预处理、特征工程与统计分析、模型选择与训练、模型评估与解释。
2. 为每个阶段设计具体的测试任务，确保任务不仅包含代码生成，还包含逻辑推理和策略选择。
3. 构建端到端的评估用例，要求模型从原始数据开始，直至输出最终结论。

**注意事项**: 避免仅使用单一的代码正确率指标，需关注模型在数据科学流程中的连贯性和逻辑一致性。

---

### 实践 2：强化指令遵循与建模保真度的双重验证

**说明**: DARE-bench 强调了“建模保真度”和“指令保真度”的区别。最佳实践要求在评估或应用 LLM 时，必须同时验证模型是否严格遵循了用户的特定指令（如使用特定算法），以及模型的输出是否在数学和逻辑上与数据特征保持一致（高保真度）。模型往往会在遵循指令格式的同时，忽略了数据科学的基本原理。

**实施步骤**:
1. 在 Prompt 中明确指定具体的约束条件（例如：“必须使用 XGBoost 算法”，“必须处理缺失值”）。
2. 开发自动化检查脚本，验证生成的代码或分析结果是否违反了数据科学的基本定律（如数据泄露、错误的统计假设）。
3. 对比“指令遵循度”与“结果有效性”，识别模型是否存在“为了遵循指令而牺牲正确性”的行为。

**注意事项**: 重点关注模型在面对模糊或冲突指令时的表现，以及在复杂数据结构下是否仍能保持建模的准确性。

---

### 实践 3：构建基于真实场景的多样化数据集

**说明**: 依赖简单的合成数据集无法有效评估 LLM 在真实数据科学任务中的表现。DARE-bench 的研究建议使用包含不同领域、不同数据类型（表格、时间序列、文本）以及不同噪声水平的真实数据集进行测试。这有助于评估模型的鲁棒性和泛化能力。

**实施步骤**:
1. 收集涵盖金融、医疗、零售等多个领域的真实数据集。
2. 确保数据集包含常见的数据质量问题，如缺失值、异常值和非结构化文本，以测试模型的预处理能力。
3. 建立数据集的版本控制和标准化描述，确保评估的可重复性。

**注意事项**: 在使用真实数据时，必须严格进行脱敏处理，并确保数据分布具有足够的代表性，避免偏差。

---

### 实践 4：实施多模态代码与文本输出的综合评估

**说明**: 数据科学任务不仅涉及代码生成，还涉及自然语言解释。最佳实践要求对 LLM 的输出进行综合评估，既检查执行代码的正确性，也检查解释性文本的准确性和可读性。DARE-bench 指出，模型生成的代码可能运行无误，但得出的结论可能是错误的。

**实施步骤**:
1. 设计评估指标，同时包含“代码执行成功率”和“文本解释准确率”。
2. 引入人工专家或高级 LLM 作为裁判，对生成的分析报告进行打分，重点关注结论是否与代码实际运行结果一致。
3. 建立“代码-文本”一致性检查机制，确保自然语言的解释没有虚构代码中不存在的功能或结果。

**注意事项**: 警惕“幻觉”现象，即模型生成的解释看似合理，但实际上与代码执行逻辑或数据统计结果无关。

---

### 实践 5：采用迭代式交互与错误修正机制

**说明**: 一次性的 Prompt 往往难以解决复杂的数据科学问题。DARE-bench 的研究背景暗示，通过迭代式的交互，让模型根据报错信息或中间结果进行自我修正，是提高任务完成度的关键。最佳实践应包含对模型自我纠错能力的评估和利用。

**实施步骤**:
1. 设计多轮对话的测试场景，第一轮允许模型尝试，后续轮次提供反馈或错误日志。
2. 在应用中，建立“沙箱”执行环境，自动捕获代码运行错误并反馈给模型进行重试。
3. 评估模型在接收到反馈后，定位问题并成功修复代码的比例。

**注意事项**: 限制重试的次数以避免资源浪费，并记录模型在迭代过程中的行为模式，分析其是否真正理解了错误原因。

---

## 学习要点

- DARE-bench 是首个专门用于评估大语言模型在数据科学全流程中建模能力与指令遵循度的基准测试，填补了现有评估框架在这一领域的空白。
- 该基准通过构建包含真实世界数据集的“黄金工作流”，能够精确量化模型在数据处理、特征工程、模型选择及超参数调优等关键步骤上的表现。
- 评估指标创新性地引入了“建模保真度”与“指令保真度”两个维度，从而有效区分模型是真正理解了数据科学逻辑，还是仅仅在机械地模仿代码形式。
- 研究揭示出当前顶尖 LLMs 在面对复杂的数据科学任务时存在显著的“幻觉”现象，特别是在处理未见过的数据分布和细微的指令约束时表现不佳。
- 实验结果表明，模型在代码生成基准（如 HumanEval）上的高分并不能直接转化为其在数据科学任务中的实际解决能力，强调了领域特定评估的必要性。
- DARE-bench 提供的自动化评估框架为未来研究多模态 LLMs 在数据分析领域的应用提供了标准化的衡量标准和可复现的实验基础。

## 常见问题


### 1: DARE-bench 主要用于评估什么？

1: DARE-bench 主要用于评估什么？

**A**: DARE-bench 是一个专门用于评估大语言模型在数据科学领域能力的基准测试。它的核心目的是衡量模型在两个关键维度的表现：**建模保真度**和**指令保真度**。

简单来说，它测试模型是否能像数据科学家一样思考（建模），以及是否能准确执行用户的具体指令（指令），而不是仅仅根据直觉或常见的统计套路生成看似合理但错误的代码。

---



### 2: 什么是“建模保真度”和“指令保真度”？

2: 什么是“建模保真度”和“指令保真度”？

**A**: 这是 DARE-bench 评估的两个核心指标，分别对应数据科学流程中的不同方面：

1.  **建模保真度**：指模型在构建预测或分析模型时，是否能够准确捕捉到数据背后的真实逻辑。例如，模型是否能正确选择特征、处理非线性关系，而不是仅仅依赖简单的平均值或线性回归来拟合数据。
2.  **指令保真度**：指模型在生成代码或分析时，是否严格遵守了用户发出的具体指令。例如，如果用户明确要求“使用随机森林算法”或“排除异常值”，模型是否真的执行了这些操作，而不是忽略它们并使用自己的默认行为。

---



### 3: 现有的数据科学基准测试（如 ML-Bench）与 DARE-bench 有什么区别？

3: 现有的数据科学基准测试（如 ML-Bench）与 DARE-bench 有什么区别？

**A**: 传统的基准测试（如 ML-Bench 或 Text-to-SQL 任务）通常侧重于评估模型能否生成**可运行**的代码，或者能否在标准数据集上达到较高的准确率。

DARE-bench 的区别在于它引入了**反直觉**的测试用例。它通过精心设计的合成数据集，构建了一些如果遵循标准统计直觉（如简单的均值回归）会得到错误结果，但如果严格遵循用户指令或深入建模就能得到正确结果的场景。这使得 DARE-bench 能够更有效地检测出模型是在“真正推理”还是在“通过捷径作弊”。

---



### 4: DARE-bench 的测试数据是如何构建的？

4: DARE-bench 的测试数据是如何构建的？

**A**: 为了确保测试的严谨性，DARE-bench 采用了**合成数据**而非真实世界数据。这是因为真实数据往往包含噪声和不可控的变量，难以精确评估模型的逻辑是否正确。

研究者设计了具有特定统计属性（如特定的线性或非线性关系、异质性数据等）的数据集。通过这种方式，DARE-bench 知道“正确”的模型应该长什么样，从而可以精确地量化模型生成的代码在多大程度上偏离了真实情况或用户指令。

---



### 5: 根据 DARE-bench 的评估结果，当前主流 LLM（如 GPT-4, Claude 3 等）的表现如何？

5: 根据 DARE-bench 的评估结果，当前主流 LLM（如 GPT-4, Claude 3 等）的表现如何？

**A**: 评估结果显示，尽管当前最先进的模型在代码生成方面表现出色，但在**指令保真度**方面普遍存在不足。

许多模型倾向于忽略用户的特定约束（例如特定的预处理步骤或算法选择），转而使用它们在预训练中见过的“标准做法”或“最佳实践”。这表明模型在处理复杂的、非标准的数据科学任务时，往往是在进行概率性的模式匹配，而不是严格地执行逻辑推理。

---



### 6: DARE-bench 中的“指令”具体包含哪些类型？

6: DARE-bench 中的“指令”具体包含哪些类型？

**A**: DARE-bench 中的指令设计非常具体，旨在测试模型对细节的关注度。常见的指令类型包括：

*   **算法选择**：明确要求使用特定的机器学习算法（如 XGBoost、SVM）。
*   **数据预处理**：要求对数据进行特定的转换，例如对数变换、标准化或删除特定列。
*   **特征工程**：要求创建特定的交互特征或多项式特征。
*   **评估指标**：要求使用特定的指标（如 F1-score 而非 Accuracy）来优化模型。

---



### 7: 为什么我们需要关注 LLM 在数据科学任务中的指令遵循能力？

7: 为什么我们需要关注 LLM 在数据科学任务中的指令遵循能力？

**A**: 在实际的数据科学工作流中，业务逻辑和领域知识往往比简单的模型调优更重要。用户可能因为合规要求、业务限制或特定的领域知识，需要模型执行某些看似“非标准”的操作。

如果 LLM 总是自作主张地忽略指令，转而使用统计上的“默认最优解”，那么它在自动化数据分析、辅助科研或企业级决策支持等场景中的可靠性将大打折扣。DARE-bench 的出现正是为了推动模型在这一点上的改进。
