# 技术实现原理

### 1. 底层机制：In-Context Learning
该仓库的 Prompt 基于大模型的**上下文学习**能力。
- **原理**：在不改变模型权重的情况下，通过将精心设计的指令作为输入，利用注意力机制引导模型聚焦于特定的语义空间。
- **标准化结构**：库中的 Prompt 实际上是 `[Role] -> [Context] -> [Instruction] -> [Constraint] -> [Output Format]` 结构的标准化实例。

### 2. Prompt 设计模式
虽然没有代码，但 Prompt 编写遵循特定的**工程化设计模式**：
1.  **Persona Pattern (角色模式)**：使用 `I want you to act as a...` 句式，激活模型在训练数据中关于该角色的关联知识权重。
2.  **Few-Shot Pattern (少样本模式)**：在指令中嵌入具体的输入输出示例，以规范模型的生成格式。
3.  **Constraint Pattern (约束模式)**：通过明确的负面约束（如“不使用缩写”、“不解释代码”），限制模型的生成边界，提高输出的精确度。

```python
def process_prompts(prompt_list):
    """
    批量处理ChatGPT提示词，添加统一的前缀和后缀
    :param prompt_list: 提示词列表
    :return: 处理后的提示词列表
    """
    prefix = "请用中文回答以下问题："
    
    processed = []
    for prompt in prompt_list:
        # 去除首尾空格并添加前后缀
        formatted = f"{prefix} {prompt.strip()} {suffix}"
        processed.append(formatted)
    
    return processed

# 测试示例
```

```python
# 示例2：提示词质量评估
def evaluate_prompt_quality(prompt):
    """
    评估单个提示词的质量（简单评分系统）
    :param prompt: 待评估的提示词
    :return: 质量评分(0-100)和改进建议
    """
    score = 100
    suggestions = []
    
    # 检查长度
    if len(prompt) < 10:
        score -= 20
        suggestions.append("提示词过短，建议补充更多细节")
    
    # 检查是否包含关键要素
    if "请" not in prompt and "帮我" not in prompt:
        score -= 10
        suggestions.append("建议添加礼貌用语")
    
    # 检查是否有明确目标
    if not any(word in prompt for word in ["生成", "分析", "解释", "创建"]):
        score -= 15
        suggestions.append("建议明确指定任务类型")
    
    return max(score, 0), suggestions

# 测试示例
test_prompt = "写个故事"
print(evaluate_prompt_quality(test_prompt))
```

```python
    动态生成角色扮演提示词
    :param role: 扮演的角色
    :param task: 需要完成的任务
    :param style: 回复风格（专业/幽默/简洁）
    :return: 完整的角色扮演提示词
    """
    style_templates = {
        "专业": "请用专业术语和严谨逻辑回答",
        "幽默": "请用轻松幽默的方式回答",
        "简洁": "请用最简练的语言回答"
    }
    
    prompt = f"""
    你现在是一位{role}。
    你的任务是：{task}
    回复风格要求：{style_templates.get(style, "专业")}
    
    请始终保持角色设定，不要出戏。
    """
    
    return prompt.strip()

# 测试示例
print(generate_roleplay_prompt(
    role="资深Python工程师",
    task="解释装饰器的工作原理",
    style="幽默"
))
```

## 最佳实践

## 提示词工程最佳实践

### 1. 角色定义
在提示词开头明确指定AI的角色或身份（如“你是一位资深Python工程师”），有助于模型精准理解任务背景并调整输出风格。
*   **实施**：使用“你是一位[角色]”的句式，简要描述该角色的专业领域。
*   **注意**：角色定义应具体且与任务强相关，避免使用过于宽泛的描述。

### 2. 任务拆解
将复杂任务分解为清晰的步骤（3-7个为宜），使用编号列表组织内容。
*   **实施**：利用“首先”、“其次”、“最后”等逻辑词串联步骤，明确每步的输入输出。
*   **注意**：确保步骤间逻辑连贯，无歧义或重复。

### 3. 示例引导
*   **实施**：使用“示例：”标记，提供2-3个典型场景，并附带“请按此格式处理”的指令。
*   **注意**：示例需简洁且格式严格一致，避免包含干扰信息。

### 4. 格式约束
明确指定回答的格式（如Markdown表格、JSON代码块），确保结果易于解析。
*   **实施**：在提示词末尾使用“请以[格式]输出”指令，必要时提供模板。

### 5. 负向约束
明确限制回答的范围、长度或风格，防止模型产生幻觉或无关内容。
*   **实施**：使用“不要包含...”、“不超过X字”等否定或量化约束。
*   **注意**：约束条件需具体可衡量，且相互之间不冲突。

### 6. 迭代优化
将提示词视为持续迭代的产品，根据输出质量不断调整。
*   **实施**：建立个人提示词库，记录有效模式和常见问题，针对性修改并测试。
*   **注意**：优秀提示词往往需要多次微调，需保持耐心。

### 7. 上下文管理
在多轮对话中，确保AI理解当前任务与历史信息的关联。
*   **实施**：使用“基于上文总结...”等引导语，简要重述关键信息。
*   **注意**：引用应精简，仅保留与当前任务直接相关的上下文。

## 性能优化建议

## 性能优化建议

### 优化 1：启用 GitHub Pages 缓存

**说明**: 静态资源（如 CSS、JS、图片）可以通过浏览器缓存减少重复加载时间，提升页面响应速度。

**实施方法**:
1. 在 `index.html` 中为静态资源添加 `Cache-Control` 头（如 `max-age=31536000`）。
2. 使用 GitHub Actions 自动部署时，确保静态资源路径包含哈希值（如 `main.a1b2c3.js`）。

**预期效果**: 减少重复加载时间 50%-70%。

---

### 优化 2：压缩静态资源

**说明**: 压缩 HTML、CSS、JS 文件可减少传输数据量，加快页面加载速度。

**实施方法**:
1. 使用工具如 `html-minifier`、`cssnano` 或 `terser` 压缩文件。
2. 在 GitHub Actions 中添加压缩步骤（如 `actions/minify-action`）。

**预期效果**: 文件大小减少 20%-40%，加载时间缩短 10%-30%。

---

### 优化 3：使用 CDN 加速

**说明**: 将静态资源托管到 CDN（如 Cloudflare 或 jsDelivr）可利用边缘节点加速全球访问。

**实施方法**:
1. 将静态资源上传到 CDN 或使用 GitHub Pages 的 CDN 集成。
2. 替换资源链接为 CDN 地址（如 `https://cdn.jsdelivr.net/gh/user/repo/file.js`）。

**预期效果**: 全球访问延迟降低 30%-50%。

---

### 优化 4：优化图片资源

**说明**: 图片通常是页面中最大的资源，优化图片可显著减少加载时间。

**实施方法**:
1. 使用现代格式（如 WebP）替代 PNG/JPEG。
2. 通过工具（如 `imagemin` 或 `sharp`）压缩图片。
3. 为图片添加 `width` 和 `height` 属性以避免布局抖动。

**预期效果**: 图片大小减少 50%-70%，页面加载时间缩短 20%-40%。

---

### 优化 5：减少 HTTP 请求数

**说明**: 合并 CSS/JS 文件或使用内联资源可减少 HTTP 请求数，降低延迟。

**实施方法**:
1. 将多个 CSS/JS 文件合并为一个（如 `bundle.js`）。
2. 对小文件（如关键 CSS）使用内联方式（`<style>` 或 `<script>`）。

**预期效果**: 请求数减少 50%-80%，首屏加载时间缩短 10%-20%。

---

### 优化 6：预加载关键资源

**说明**: 通过 `<link rel="preload">` 预加载关键资源（如字体或关键 CSS）可提前加载并减少阻塞。

**实施方法**:
1. 在 `index.html` 中添加预加载标签：
   ```html
   <link rel="preload" href="critical.css" as="style">
   <link rel="preload" href="font.woff2" as="font" crossorigin>
   ```
2. 确保预加载资源路径正确。

**预期效果**: 首屏渲染时间缩短 15%-30%。
