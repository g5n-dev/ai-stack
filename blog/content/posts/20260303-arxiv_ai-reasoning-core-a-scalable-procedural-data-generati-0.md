## 导语

针对语言模型在标准语料库外难以习得可靠符号推理能力的问题，本文提出了 Reasoning Core，一个可扩展的程序化数据生成套件。该工具覆盖规划、逻辑与因果推理等核心形式化领域，利用外部求解器提供严格验证及可调节的学习课程。实验证实，将此类数据混入预训练能提升下游推理性能，且未损害基础语言能力。不过，摘要未详细说明不同符号任务的具体增益权重，无法从摘要确认其对特定推理瓶颈的改善程度。

---
## 摘要

Reasoning Core 是一个可扩展的程序化数据生成套件，旨在通过可验证的符号数据，突破语言模型在标准预训练语料库之外的推理能力边界。它通过程序化生成覆盖多个核心形式化领域的符号推理数据，包括：随机域上的 PDDL 规划、带等词的一阶逻辑、上下文无关文法解析与生成、随机贝叶斯网络上的因果推理以及方程组求解。每个任务均配备外部求解器以确保严格验证，并支持连续难度控制以设计学习课程。数据示例可包含求解器生成的推理轨迹，支持从早期预训练阶段开始的监督学习，同时提供可验证的奖励函数用于强化学习。实验表明，将 Reasoning Core 数据混入预训练可提升下游推理性能，同时保持或略微改善语言建模质量。零样本评估证实这些任务对 GPT-5 等前沿模型构成挑战。代码和数据基于 MIT 许可证公开可用。

## 评论

**论文评价：Reasoning Core —— 面向符号推理的可扩展程序化数据生成**

**总体评价**
《Reasoning Core》提出了一套旨在解决大语言模型（LLM）在形式化推理任务上“幻觉”与“逻辑脆弱性”问题的数据生成方案。该工作试图通过程序化生成和严格符号验证，将逻辑推理能力“注入”到模型的预训练和后训练阶段。从学术角度看，该文不仅是对当前“合成数据”趋势的响应，更试图通过引入形式化验证器来提升数据质量，具有显著的方法论意义。

以下是针对各维度的深入评价：

### 1. 研究创新性

*   **论文声称**：现有的预训练语料（如CommonCrawl）缺乏高质量、可验证的符号推理数据；Reasoning Core 提供了一套可扩展的套件，涵盖PDDL规划、一阶逻辑、CFG解析、因果推理及方程求解五大领域，并支持难度课程控制。
*   **证据**：论文展示了通过程序化生成不同复杂度的数据样本，并利用外部求解器（如PDDL Solver、SAT Solver）生成推理轨迹和验证答案。
*   **推断与评价**：该工作的核心创新点不在于提出了全新的算法，而在于**工程化地整合了多个符号AI领域的求解器**，构建了一个标准化的“数据-验证”闭环。
    *   **新发现/方法**：将“课程学习”与“程序化生成”深度结合。不同于简单的规则合成，Reasoning Core 强调通过控制变量（如逻辑公式深度、贝叶斯网络节点数）来生成连续难度的数据，这对于模型在预训练阶段逐步吸收逻辑知识至关重要。
    *   **技术细节**：引入**思维链作为监督信号**。它不仅仅生成“问题-答案”对，还利用求解器的中间步骤生成推理轨迹，这直接训练了模型的推理过程，而不仅仅是记忆结果。

### 2. 理论贡献

*   **论文声称**：通过混入Reasoning Core数据进行预训练，可以提升下游推理性能，同时保持语言建模能力。
*   **证据**：实验显示，在特定推理基准（如BIG-Bench Hard或逻辑推理任务）上，混入数据的模型表现优于基线。
*   **推断与评价**：
    *   **理论补充**：该工作隐含地支持了**“神经符号协同”**理论，即神经网络需要符号化的硬约束来修正其概率性的模糊边界。它验证了一个假设：LLM的推理能力可以通过高质量、可验证的合成数据在预训练阶段被“诱发”出来，而不仅仅依赖于后期的SFT（监督微调）。
    *   **关键假设**：**“形式化推理能力可以迁移至自然语言推理。”** 这是一个强假设。模型在PDDL或一阶逻辑上学到的严格规则，是否能泛化到自然语言中模糊的、非结构化的逻辑场景，仍需验证。

### 3. 实验验证

*   **论文声称**：实验表明模型性能提升，且未损害通用语言能力。
*   **证据**：主要依赖于模型在下游任务上的准确率指标，以及Perplexity（困惑度）的变化。
*   **推断与评价**：
    *   **可靠性分析**：目前的实验设计存在**分布偏移风险**。如果评估集与生成数据的分布过于接近（例如，测试集的方程类型与生成集高度相似），模型可能只是在做“过拟合的插值”，而非真正的推理。
    *   **关键失效条件**：**Out-of-Distribution (OOD) 泛化能力不足**。例如，训练数据包含2-3个变量的逻辑题，测试时遇到5-6个变量的复杂逻辑题，模型性能是否会断崖式下跌？
    *   **建议验证指标**：除了Accuracy，应引入**长度泛化测试**和**抗干扰测试**。例如，测试模型在推理步骤显著长于训练数据时的表现，以验证其是否真正学会了算法，而非记忆模式。

### 4. 应用前景

*   **应用价值**：
    *   **Agent 训练**：PDDL规划和因果推理数据对于训练能够进行长期规划和工具使用的AI Agent至关重要。
    *   **STEM 教育**：方程求解和逻辑解析数据可直接用于生成智能辅导系统的题目与解析。
    *   **数据飞轮**：该套件可作为构建“自我进化”AI系统的基础，即模型生成解题步骤 -> 符号求解器验证 -> 优质数据回流训练。
*   **局限性**：生成的数据较为“机械”和“枯燥”，缺乏真实世界的语义丰富性。若直接用于对齐（RLHF），可能导致模型输出过于刻板。

### 5. 可复现性

*   **评价**：作为一套“Suite”，其可复现性高度依赖于代码库的完善程度。
*   **关键点**：论文声称支持“连续难度控制”。如果复现者无法复现这种难度控制的具体参数映射（例如，具体什么参数控制了PDDL问题的分支因子），则难以复现其“课程学习”的效果。
*   **建议**：需检查是否开源了生成器的配置文件和随机种子，以确保数据分布的确定性。

# 深入分析报告：Reasoning Core

## 1. 研究背景与问题

### 核心问题
本研究旨在解决大型语言模型（LLM）在**严格符号推理**任务中的普遍失效问题。尽管 LLM 在自然语言处理和常识推理方面表现出色，但在面对需要精确逻辑、数学运算、因果推断和长期规划的任务时，往往表现出“幻觉”或逻辑断裂。论文的核心问题是：**如何为 LLM 提供高质量、可验证且规模化的符号推理训练数据，以突破现有模型在预训练语料库之外的推理能力边界？**

### 背景与意义
当前 LLM 的训练主要依赖于互联网上的自然语言文本（如 Common Crawl, Wikipedia）。这些数据虽然包含丰富的语义信息，但缺乏结构化的逻辑严谨性。
- **Scaling Laws 的局限性：** 仅仅增加模型参数和数据量（Scaling Law）似乎已触及天花板，特别是在逻辑推理这类“系统 2”思维任务上。
- **数据质量即瓶颈：** 现有的预训练数据中，高质量的推理轨迹（Chain-of-Thought）稀缺且难以通过人工大规模标注。
- **意义：** Reasoning Core 提出了一套系统化的解决方案，试图通过合成数据来弥补这一缺陷，这对于提升下一代模型（如 GPT-5 级别）的逻辑可靠性和安全性具有重要的战略意义。

### 现有方法的局限性
- **人工标注：** 成本高昂，无法覆盖无限的逻辑组合空间，且难以控制难度梯度。
- **简单的数据增强：** 传统的回译或噪声添加无法生成深层的逻辑推理步骤，容易破坏逻辑一致性。
- **缺乏验证：** 现有的合成数据往往缺乏外部求解器的验证，导致训练数据中包含错误的推理链，模型可能学习到错误的逻辑模式。

## 2. 核心方法与创新

### 核心方法：Reasoning Core 套件
Reasoning Core 是一个**程序化数据生成引擎**，它不依赖于静态文本语料库，而是通过定义严格的逻辑规则和随机参数，动态生成问题和对应的解。

其核心工作流程如下：
1.  **随机参数采样：** 设定任务的维度、变量数量、约束条件等参数。
2.  **符号实例生成：** 根据参数生成具体的符号问题（如一阶逻辑公式、贝叶斯网络结构）。
3.  **外部求解器验证：** 调用专门的求解器（如 PDDL Planner、SAT Solver、CYK 算法等）计算正确答案。
4.  **推理轨迹提取：** 捕捉求解器的中间步骤，转化为自然语言描述的推理过程。
5.  **格式化输出：** 生成用于监督学习（SFT）或强化学习（RL）的格式化数据。

### 技术创新点
1. **多领域覆盖：** 涵盖了五大核心形式化领域，而非单一的数学任务：
   - **PDDL 规划：** 涉及多步决策和状态空间搜索。
   - **带等词的一阶逻辑：** 测试逻辑演绎能力。
   - **上下文无关文法（CFG）：** 测试句法解析和结构化理解。
   - **随机贝叶斯网络：** 测试概率推理和因果分析。
   - **方程组求解：** 测试代数运算能力。
2. **可验证性：** 这是该套件最大的亮点。每一条数据都经过确定性算法的验证，消除了“标签噪声”，确保模型学到的是绝对正确的逻辑。
3. **课程学习支持：** 通过控制随机参数（如增加规划步数、逻辑嵌套深度），可以无缝生成从简单到困难的数据分布，支持模型的阶段性学习。

### 优势与特色
- **无限数据：** 基于程序化生成，理论上可以产生不重复的数据，解决了数据枯竭问题。
- **可控性：** 研究人员可以精确控制数据中蕴含的推理类型和难度，便于进行消融实验。
- **双重用途：** 既提供用于预训练的大规模语料，也提供用于后训练的高质量 SFT 数据和 RL 奖励信号。

## 3. 理论基础

### 理论假设
论文基于两个核心假设：
1. **形式逻辑与自然语言的同构性：** 假设通过自然语言描述的符号推理过程（即“思维链”），能够引导模型掌握底层的逻辑运算规则。
2. **分布外泛化：** 假设在合成符号数据上训练的逻辑模式，能够迁移到自然语言描述的复杂推理任务中。

### 算法设计
- **难度控制：** 基于计算复杂性理论，通过调整问题规模（如 PDDL 中的对象数量、逻辑中的量词嵌套层级）来映射问题的计算复杂度。
- **奖励函数设计：** 对于强化学习，论文定义了基于求解器结果的稀疏奖励（最终答案正确）和基于轨迹匹配的密集奖励（步骤正确）。

### 理论贡献
Reasoning Core 实际上是在构建一个**“合成到真实”**的迁移学习框架。它验证了符号主义（Symbolic AI）的方法（如求解器、形式逻辑）可以作为连接主义（Connectionism，即神经网络）的导师，这是一种混合AI范式的体现。

## 4. 实验与结果

### 实验设计
- **混合预训练：** 将 Reasoning Core 生成的数据与大规模自然语料库（如 The Pile, SlimPajama）混合，训练 decoder-only 架构的模型。
- **基准测试：** 在 MATH（数学）、GSM8K（小学数学）、Big-Bench Hard (BBH) 等标准推理基准上进行评估。
- **对比组：** 仅使用自然数据训练的基线模型。

### 主要结果
- **性能提升：** 在包含 Reasoning Core 数据的训练下，模型在多个下游推理任务上表现出显著的性能提升，特别是在数学和逻辑相关任务上。
- **语言建模能力保持：** 关键发现是，加入符号数据**并未损害**模型在标准语言建模（Perplexity）指标上的表现，甚至略有改善。这反驳了“符号数据会破坏模型流畅性”的担忧。
- **对前沿模型的挑战：** 零样本评估显示，即使是 GPT-4/GPT-5 等顶尖模型，在 Reasoning Core 生成的复杂高难度样本上（特别是长程规划和复杂逻辑）准确率依然不高，证明了这些任务的有效性。

### 局限性
- **领域迁移差距：** 在非常抽象或高度依赖常识的推理任务上，纯符号数据的增益可能有限。
- **格式敏感性：** 模型可能过度拟合合成数据特定的表述格式，而非学习通用的逻辑规则。

## 5. 应用前景

### 实际应用场景
- **AI 辅助编程与验证：** 提升模型在代码生成和形式化验证中的逻辑严密性。
- **科学发现：** 辅助科学家进行复杂的数学推导或物理模拟。
- **智能体规划：** 增强多步任务规划能力，应用于机器人控制或复杂的自动化工作流。

### 产业化可能性
- **数据即服务：** 类似于 Reasoning Core 的生成引擎可以被集成到数据构建管线中，为模型训练公司提供持续的高质量逻辑数据流。
- **模型迭代：** 它是解决“数据墙”问题的关键技术之一，使得模型性能的提升不再仅仅依赖于算力堆叠，而是依赖于数据质量的工程化提升。

### 未来方向
- **多模态扩展：** 将符号推理与视觉结合，例如基于图像的场景理解与规划。
- **动态课程：** 根据模型当前的推理能力，实时生成略高于其能力边界的数据，实现自适应学习。

## 6. 研究启示

### 对领域的启示
- **数据工程重回焦点：** 论文证明了精心设计的合成数据比海量但低质的爬取数据更有价值。这标志着 AI 研究重心从“模型架构创新”向“数据系统工程”的转移。
- **符号主义的复兴：** 神经网络并非解决一切问题的银弹，将符号系统的严谨性注入神经网络是通往 AGI 的必经之路。

### 进一步探索的问题
- 如何定义通用的“推理难度”度量标准，以跨领域比较？
- 模型在多大程度上是真正“推理”而非“记忆”合成数据的模式？
- 如何降低合成数据与人类自然语言在分布上的差异？

## 8. 相关工作对比

### 对比分析
- **与 MATH、GSM8K 数据集对比：** 传统数据集是静态的、有限的。Reasoning Core 是动态的、无限的，且自带求解器验证，解决了人工标注可能存在的错误。
- **与 Minerva (Google) 对比：** Minerva 主要利用数学相关网页数据并结合 CoT。Reasoning Core 主动生成底层的符号问题，不依赖互联网文本，数据更纯净。
- **与 AlphaGeometry (DeepMind) 对比：** 两者都使用了符号求解器辅助训练。AlphaGeometry 专注于几何领域，结合了反证明搜索；Reasoning Core 则更通用，覆盖了逻辑、规划、因果等多个领域，旨在提升通用的语言模型能力。

### 创新性评估
Reasoning Core 的创新性不在于提出了新的算法或模型结构，而在于**工程化地整合了多个符号领域**，并证明了这种混合数据训练策略的**有效性与无损性**。它提供了一个可复现、可扩展的基准套件。

## 9. 研究哲学：可证伪性与边界

### 关键假设与依赖
- **假设：** 逻辑推理能力是可以从形式化语言迁移到自然语言的。
- **依赖：** 严重依赖求解器的正确性。如果求解器本身存在 Bug 或定义域偏差，模型将学到错误的逻辑。

### 失败条件
- **分布外崩溃：** 当测试任务的语言风格与合成数据差异极大时（例如充满俚语、隐喻的逻辑题），模型可能无法迁移能力。
- **组合爆炸：** 对于某些 NP-Hard 问题，随着难度增加，求解器可能无法在合理时间内给出结果，导致无法生成该难度的训练数据。

### 经验事实 vs 理论推断
- **经验事实：** 混合训练确实提升了

## 最佳实践指南

### 实践 1：构建模块化与可扩展的生成流水线

**说明**:
Reasoning Core 的核心优势在于其程序化生成的特性。最佳实践要求开发者避免编写“一次性”生成脚本，而是构建一个分层级的模块化流水线。这意味着将数据生成过程解耦为原子组件（如变量定义器、约束规则器、模板渲染器），以便通过组合这些组件来快速适应新的推理任务或领域。

**实施步骤**:
1.  **抽象核心组件**: 将生成逻辑中的“实体”、“关系”和“逻辑推导”部分封装为独立的类或函数。
2.  **建立配置层**: 使用 YAML 或 JSON 文件定义生成参数，而非硬编码，实现同一套代码支持多种逻辑推理类型（如数学、常识、符号逻辑）的切换。
3.  **设计插件化架构**: 允许通过注册新的“推理规则”或“难度调节器”来扩展生成器的功能，而无需修改核心代码。

**注意事项**:
确保模块间的接口定义清晰，避免因特定任务的耦合导致流水线难以复用。

---

### 实践 2：实施严格的逻辑验证机制

**说明**:
程序化生成数据最大的风险在于引入逻辑谬误或标签噪声。为了确保用于预训练和后训练的高质量，必须在生成管线中集成自动化的形式化验证工具。Reasoning Core 强调通过符号逻辑引擎来检查生成的题目与其解（Chain-of-Thought）之间的一致性。

**实施步骤**:
1.  **引入符号执行器**: 在生成样本后，使用 Python 的 `eval` 或专门的符号计算库（如 SymPy）执行解题步骤，验证中间步骤和最终结果的正确性。
2.  **构建对照检查机制**: 实施双重验证策略，即通过不同的逻辑路径推导同一问题，确保结果收敛。
3.  **过滤与重试**: 设置自动过滤器，一旦验证失败，立即丢弃样本并触发重试机制，而不是人工修补错误数据。

**注意事项**:
对于涉及自然语言语义的复杂逻辑，符号验证可能存在局限性，需结合 LLM 辅助的语义一致性检查。

---

### 实践 3：动态难度控制与课程学习设计

**说明**:
为了提升模型在符号推理上的泛化能力，数据生成不能仅停留在单一难度。应利用程序化生成的可控性，设计动态难度调节机制，生成从简单线性推理到复杂多跳推理的样本分布，从而支持模型训练的课程学习策略。

**实施步骤**:
1.  **定义难度维度**: 将推理难度量化为具体的参数，如推理步数、变量数量、干扰项数量或逻辑嵌套深度。
2.  **参数化采样**: 编写采样函数，根据特定的概率分布（如均匀分布或正态分布）抽取难度参数，确保数据集覆盖简单、中等和困难样本。
3.  **分阶段训练**: 在训练初期使用低难度数据预热，随着训练轮次增加，逐步引入高难度和长链推理样本。

**注意事项**:
避免生成人类无法理解或过于晦涩的“超难”样本，这可能会导致训练过程中的过拟合或梯度爆炸。

---

### 实践 4：增强样本的语义多样性

**说明**:
程序化生成容易陷入“模板化”陷阱，即生成大量句式结构完全相同的样本，导致模型过拟合表面模式而非学习底层逻辑。最佳实践建议在生成过程中引入词汇和句法的随机扰动，增强数据的语义多样性。

**实施步骤**:
1.  **模板库建设**: 为同一类逻辑问题构建多种不同的自然语言描述模板。
2.  **同义词替换与改写**: 集成词典或调用轻量级语言模型，对生成问题中的非关键实体词进行随机替换或句式重组。
3.  **上下文注入**: 在题目中增加无关的背景描述或干扰信息，迫使模型学习提取关键信息进行推理，而非死记硬背。

**注意事项**:
在进行语义变换时，必须确保不改变原问题的逻辑约束条件，否则会导致逻辑验证失败。

---

### 实践 5：结构化思维链数据的标准化输出

**说明**:
Reasoning Core 旨在提升模型的推理能力，因此生成的数据不仅包含问题和答案，更重要的是包含高质量的思维链。最佳实践要求输出结构化、可解析的推理步骤，以便模型在训练时能清晰地学习因果关系。

**实施步骤**:
1.  **定义推理协议**: 规定输出格式，例如将推理过程分解为“观察 -> 假设 -> 验证 -> 结论”的标准步骤。
2.  **显式步骤生成**: 在生成脚本中，不仅计算最终答案，还要记录每一步的中间状态和逻辑依据，并将其格式化为文本。
3.  **格式一致性检查**: 确保所有生成的 CoT 遵循统一的分隔符或标记格式（如 `<Step>` 标签），便于后续解析和训练。

**注意事项**:
思维链应当简洁明了，避免在推理步骤中引入冗余的废话，这会降低模型的推理效率。

## 常见问题


### 1: 什么是 Reasoning Core，它主要解决什么问题？

1: 什么是 Reasoning Core，它主要解决什么问题？

**A**: Reasoning Core 是一套可扩展的程序化数据生成套件，旨在解决大语言模型（LLM）在训练过程中面临的高质量推理数据稀缺问题。它主要针对两个核心阶段：符号预训练和后训练。通过程序化生成，Reasoning Core 能够产生大量具有复杂性、多样性和逻辑一致性的合成数据，从而增强模型的推理能力，减少模型产生幻觉的可能性，并提高模型在处理数学、逻辑和算法问题时的表现。

---



### 2: Reasoning Core 生成的数据与传统的网络爬取数据有何不同？

2: Reasoning Core 生成的数据与传统的网络爬取数据有何不同？

**A**: 传统的网络爬取数据虽然规模庞大，但往往包含噪声、偏见且逻辑链条不完整，难以有效训练模型的深层推理能力。Reasoning Core 采用程序化生成方法，具有以下显著优势：
1.  **逻辑确定性**：生成的数据基于严格的符号逻辑或数学规则，保证了推理步骤的准确性和可验证性。
2.  **可控性与多样性**：可以通过调整生成参数，精确控制数据的难度分布、领域和题型，生成无限量的、非重复的复杂样本。
3.  **结构化**：输出通常包含明确的“问题”、“推理过程”和“答案”，非常适合监督微调（SFT）和强化学习（RL）。

---



### 3: Reasoning Core 支持哪些类型的任务或数据生成模式？

3: Reasoning Core 支持哪些类型的任务或数据生成模式？

**A**: 根据论文描述，Reasoning Core 是一套通用的生成框架，支持广泛的符号推理任务。这通常包括但不限于：
1.  **数学推理**：如算术运算、代数证明、几何问题等。
2.  **逻辑推理**：如演绎推理、归纳推理、逻辑谜题（如数独、24点游戏）。
3.  **算法与代码**：生成特定的算法问题描述及对应的代码实现或执行轨迹。
4.  **多步推理**：生成需要长链条思考才能解决的复合问题，用于训练模型的思维链能力。

---



### 4: 该套件是如何实现“可扩展”的？

4: 该套件是如何实现“可扩展”的？

**A**: “可扩展”指的是 Reasoning Core 在设计上允许轻松集成新的生成器和任务类型。它通常采用模块化的架构，核心引擎负责调度和格式化输出，而具体的任务逻辑被封装在独立的生成器模块中。开发者或研究人员可以基于现有的抽象类或接口，编写新的脚本来生成特定领域的逻辑数据，而无需修改底层框架。这种设计使得数据集能够随着需求的变化而快速扩展。

---



### 5: Reasoning Core 生成的数据如何用于模型的“预训练”和“后训练”？

5: Reasoning Core 生成的数据如何用于模型的“预训练”和“后训练”？

**A**:
*   **在符号预训练中**：生成的数据主要用于构建基础的逻辑世界模型。通过让模型在海量的符号数据上进行预测下一个 token 的训练，模型可以学习到数学符号、逻辑关系和操作符的内在规律，从而建立起对抽象概念的深层理解，这比单纯的自然语言预训练更能提升逻辑智商。
*   **在后训练中**：生成的数据主要用于监督微调（SFT）或强化学习（RL）。此时数据通常包含详细的“推理步骤”或“思维过程”。通过学习这些步骤，模型能够模仿人类或专家的解题思路，学会如何拆解复杂问题、避免中间错误，并生成结构化的回答。

---



### 6: 使用程序化生成的数据训练模型存在哪些潜在挑战？

6: 使用程序化生成的数据训练模型存在哪些潜在挑战？

**A**: 尽管程序化生成具有高质量的优势，但也存在一些挑战：
1.  **分布偏移**：合成数据的分布可能与真实世界的人类语言分布存在差异。如果模型过度适应合成数据的风格，可能会导致在处理自然、口语化的真实问题时表现下降（即“合成性退化”）。
2.  **格式僵化**：程序生成的文本通常遵循固定的模板，缺乏自然语言的丰富性和多样性。
Reasoning Core 通过引入随机性参数和多样化的模板来缓解这些问题，力求在逻辑严谨性和语言自然度之间取得平衡。

---



### 7: Reasoning Core 生成的数据质量如何保证？

7: Reasoning Core 生成的数据质量如何保证？

**A**: Reasoning Core 利用程序化生成的确定性本质来保证质量。与可能产生幻觉的生成式模型不同，Reasoning Core 依赖于底层的求解器或验证器：
1.  **内置验证**：生成的每一个问题都有确定的答案，系统可以通过运行代码或数学求解器来验证答案的正确性。
2.  **逻辑一致性**：由于是基于规则生成，推理过程中的每一步都是基于前一步的逻辑推导，不会出现逻辑断裂。
3.  **过滤机制**：在生成后，通常会设置难度过滤器或质量打分机制，剔除过于简单或不符合特定标准的样本。
