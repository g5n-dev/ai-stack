## 核心结论

来源作者以一个 Java 程序员连续五周的真实项目实践为背景，讨论 AI 时代程序员能力结构的变化。项目产出了 Python 版品牌 AI 可见性测量工具、基于 Java/Spring 的 MCP server、六篇分析文章，以及包含 rules、agents、hooks 的 Agent 工程环境。代码约有 90% 由 Claude Code 完成，但项目中的关键决策、错误归因、责任确认和长期积累仍由人承担。

作者据此提出三个层次的工作能力：

- 定义层：把现实中的模糊问题转化为 spec，并设计 eval。
- 验证层：检查代码与测试结果背后的结论是否成立，识别“测试通过但归因错误”的情况，并对结果签名。
- 拥有层：积累领域上下文、数据资产、客户关系和跨季度时间序列。

被明显压缩的是将清晰需求翻译为代码的中间环节。来源没有据此断言程序员整体消失，而是强调挂载方式发生变化：产出由谁签名、资产由谁拥有，以及人类如何与 Agent 协作并设置质量闸门。

## 能力机制

项目采用“spec → TDD → review → 签名”的协作链路。12 个任务全部采用 TDD，形成 44 个测试；代码审查又修正了 4 个 Important 问题。Agent 可以执行既定 spec，也可以发现畸形请求，但不能独立判断业务归因是否正确。

一次典型问题是：Java 版将某模型“不联网”错误地归因到更大范围，而 Python 版实际请求正常。两个 Agent 分别工作时无法自动获知对方做过什么，最终依靠作者对历史工作的记忆完成交叉核验。这说明单元测试验证的是代码行为，Agent 产出是否持续变好，则需要针对 Agent 行为建立 eval。来源明确将 eval 视为下一优先级。

作者还将长期记忆与分发视为 Agent 难以替代的部分。季度测量形成的连续时间序列依赖持续投入，不能仅靠一次上下文窗口获得；文章发布、社群经营和陌生人沟通同样未被 Agent 覆盖。

## 快速开始

来源没有提供可直接执行或可核验的命令，因此不应虚构安装、启动或调用步骤。根据文中已验证的工作方式，可按以下顺序组织一个真实项目：

1. 先明确问题域、测量范围、分类方式与内容目标，并将其写成 spec。
2. 将 spec 拆成任务，以 TDD 推进实现，同时保留测试与代码审查。
3. 为每个阶段设置人工确认点，核对代码、测试、现象和结论是否属于同一范围。
4. 对不同模块或 Agent 的结果进行交叉检查，特别核对失败原因和适用范围。
5. 为 Agent 行为建立 eval，用于比较不同周期的产出质量，而不是只看代码测试是否通过。
6. 将季度重复测量、客户关系和署名内容作为长期资产持续积累。

以上属于依据来源经验整理的工程建议，不是来源提供的自动化脚本。密钥处理同样无法从来源确认具体命令；如项目需要访问 API，只能使用环境变量承接凭据，不应写入日志或示例配置。

## 适用边界

该方法适合需要长期积累、结果必须可归责、且包含跨模块验证的真实项目，尤其适用于需要同时运行多个 Agent、维护多个版本或持续进行周期测量的工作。

来源中的实践规模有限：两个开源仓库、六篇文章、基于 720 条真实 AI 问答形成的分析内容，以及累计约 210 次阅读。作者也明确指出，分发效果仍不理想，咨询转化为零。因此，不能根据这些结果推导商业有效性或普遍市场表现。

来源还强调，Agent 无法承担法律身份、银行账户和违约责任，也无法独立处理支付条件、合作模式、凭据泄漏后的平台重置等现实接口。涉及合规、财务、身份与对外承诺的环节仍需人工负责。

对于只包含明确需求转换、常规编码和局部测试的任务，来源所描述的多层验证与长期积累机制未必具有相同收益。关于“被压缩岗位”“规则工程半年内形成红海”等内容属于作者判断，不应当作已经得到行业数据验证的结论。

## 核验清单

- Spec 是否明确说明问题、范围、分类方式和验收标准，而不是仅描述预期代码？
- 关键决策能否追溯到领域理解，而非完全来自模型生成？
- 测试通过后，是否再次核对结论、适用范围和失败归因？
- 不同 Agent、模块或语言版本之间是否做过交叉验证？
- 是否为 Agent 行为建立周期性 eval，并能比较本周与上周的产出质量？
- 代码审查中发现的 Important 问题是否得到记录和修复？
- API 凭据是否避免进入日志，泄漏后的重置责任是否明确？
- 对外发布、法律承诺、财务安排和身份相关操作是否保留人工确认？
- 季度数据、领域知识、客户关系和署名内容是否被持续保存？
- 自动化范围是否仅覆盖可验证的执行工作，而未替代结论签名和责任归属？
- 评估项目效果时，是否区分代码测试、Agent 行为质量、内容分发与实际转化？
- 引用本文结论时，是否只陈述来源记录的事实，并将作者判断单独标注？
