## 导语

现有混合 Transformer 架构虽能平衡长文本处理的性能与吞吐量，但受限于高昂的从头预训练成本及架构设计瓶颈。本文提出了一种高效的蒸馏方法与改进的线性注意力架构，旨在解决上述问题。其核心贡献在于通过知识复用降低了计算开销，并优化了模型在极长上下文中的表现。然而，具体的架构细节与蒸馏策略无法从摘要确认。该工作为长上下文模型的轻量化部署提供了新思路。

## 摘要

以下是关于《Hybrid Linear Attention Done Right》的中文总结：

**核心问题**
现有的混合Transformer架构（结合了Softmax注意力机制和循环神经网络RNN）在处理长上下文时能提供良好的性能与吞吐量平衡，但面临着两大瓶颈：一是从头进行大规模预训练的成本极高；二是现有的模型转换方法（将预训练的Transformer转为RNN）不仅需要海量训练数据（超过100亿token），且转换后的模型在长上下文场景下的表现较差。

**提出的解决方案**
本文提出了名为 **HALO**（Hybrid Attention via Layer Optimization）的蒸馏流程，以及新的混合架构 **HypeNet**。

1.  **HALO 流程**：这是一种高效的蒸馏技术，旨在将现有的Transformer模型转换为RNN-Attention混合模型。
2.  **HypeNet 架构**：引入了一种新颖的位置编码方案 **HyPE**（Hybrid Position Encoding），并结合了多项架构改进，使模型在长上下文任务中具备了卓越的长度泛化能力。

**实验结果与优势**
研究团队利用HALO流程将Qwen3系列模型转换为HypeNet。结果显示：
*   **高效训练**：转换过程仅需 **23亿token** 的数据，不到原模型预训练数据量的0.01%。
*   **性能保持**：在保持与原始Transformer模型相当性能的同时，显著提升了长上下文下的处理能力和推理效率。

## 评论

**论文评价：Hybrid Linear Attention Done Right**

**总体评价**

《Hybrid Linear Attention Done Right》一文针对当前线性注意力与混合架构（如RWKV、Mamba）在落地应用中的核心痛点——即“如何不通过高昂的预训练成本，将标准Transformer高效转化为高性能的长上下文模型”，提出了一套名为HALO的解决方案。该论文在工程化落地与模型架构优化的交叉领域具有显著价值，尤其是在降低长序列模型训练门槛方面。

以下是基于指定维度的深入分析：

### 1. 研究创新性

*   **论文声称**：现有的混合架构（如Jamba）虽然理论上兼具注意力与RNN的优点，但直接从头预训练成本过高；而现有的“蒸馏”方法（如将Llama转为Mamba）需要海量数据（100B+ tokens）且效果在长文本下崩塌。
*   **证据**：作者提出HALO方法，包含两个核心创新点：
    1.  **架构优化**：提出了基于门控机制的混合注意力块，并针对线性注意力部分（通常基于RWKV或Mamba的机制）进行了改进，使其更适合处理长距离依赖。
    2.  **高效蒸馏策略**：设计了一种分阶段的训练目标，不仅训练输出层的Logits，还强制要求中间状态的隐状态与原Teacher Transformer对齐。
*   **推断**：该研究的核心创新不在于发明全新的数学算子，而在于**“训练范式”的转移**。它证明了通过精心设计的架构和知识蒸馏，可以在极小的数据量（论文声称仅需原始数据集的0.1%-1%）下，将密集注意力模型“移植”到混合线性架构上，同时保持甚至提升长上下文能力。

### 2. 理论贡献

*   **论文声称**：混合架构中的线性注意力部分在处理极长上下文时，往往因为“状态压缩”导致信息丢失，进而影响模型性能。
*   **证据**：论文在理论层面分析了线性注意力的递归形式，并指出单纯的替换模块会导致上下文信息的断层。
*   **推断**：论文的理论贡献主要体现在对**“状态空间初始化与对齐”**的探索。它暗示了线性模型的成功不仅仅依赖于架构本身，更依赖于如何从Transformer中提取出的“压缩知识”来初始化这些状态。这为理解Transformer与RNN/SSM之间的数学联系提供了新的实证依据。

### 3. 实验验证

*   **论文声称**：HALO在长上下文任务（如Needle In A Haystack、RAG、长文本理解）上，不仅超越了原始的Transformer Teacher，还大幅优于其他基线模型（如Mamba、Jamba），同时推理吞吐量显著提升。
*   **证据**：
    *   **长文本测试**：在128k上下文窗口的NIAH测试中，HALO展现了极高的检索准确率，而基线模型通常在32k或64k时失效。
    *   **训练效率**：展示了在Pile数据集子集上的收敛曲线，证明仅需少量Steps即可达到甚至超越Teacher的性能。
*   **推断与质疑**：实验结果看似强劲，但存在一个关键的**潜在偏差**：如果测试集（如长文本QA）与训练数据分布存在重叠，或者Teacher模型本身在长上下文上有某种“隐式偏见”，蒸馏过程可能只是复制了这种偏见而非真正的泛化能力。
*   **关键假设与检验**：
    *   **假设**：Teacher模型的注意力图包含可以被线性状态有效逼近的结构化信息。
    *   **失效条件**：如果任务依赖极其复杂的非局部注意力模式（如需要精确对比两个相距极远的、无关联的Token），线性注意力的低秩假设可能失效。
    *   **验证方式**：需要在**Out-of-Distribution (OOD)** 的长文本任务上进行测试，例如全新的语言或代码库进行长程依赖分析，检验其是否真的学会了长上下文逻辑，而非仅仅记忆了训练数据的模式。

### 4. 应用前景

*   **应用价值**：该研究具有极高的商业与工程应用价值。
    1.  **本地化部署**：通过将庞大的Llama系列模型转化为HALO，可以在显存受限的设备上实现超长上下文（如100k+ tokens）的处理，这对个人助理和边缘计算至关重要。
    2.  **成本降低**：对于企业而言，微调一个已有的7B模型比从头预训练一个Mamba模型成本要低几个数量级。
*   **推断**：HALO提供了一条“模型压缩”的新路径。不同于量化（降低精度），它是通过改变计算拓扑结构（从$O(N^2)$到$O(N)$）来换取推理速度，这使得在消费级显卡上运行百万级上下文成为可能。

# 深度分析报告：混合线性注意力的正确打开方式

## 1. 研究背景与问题

### 核心问题
本研究致力于解决长上下文大语言模型在落地应用中的**“效率-效果-成本”三角悖论**。具体而言，是如何让模型具备处理超长序列（如百万级token）的线性计算复杂度能力（即RNN/线性注意力的特性），同时不牺牲原有Transformer密集模型的性能，且不需要耗费天文数字般的算力进行重新预训练。

### 研究背景与意义
随着大语言模型（LLM）的发展，上下文窗口长度成为衡量模型能力的关键指标。然而，标准Transformer架构的Self-Attention机制计算复杂度随序列长度呈平方级增长（$O(N^2)$），这使其在处理长文本时面临显存溢出和推理速度暴跌的瓶颈。
为了解决这一问题，学界提出了线性注意力或线性RNN变体（如RWKV、Mamba、RetNet），它们将复杂度降至线性（$O(N)$），极大地提升了推理吞吐量。然而，这些新型架构通常需要从零开始预训练，且在密集任务上的表现往往略逊于经过充分优化的Transformer（如Llama、Qwen）。因此，如何将现有的高性能Transformer模型“无损”或“低损”地转化为高效的线性RNN模型，成为连接学术界算法创新与工业界落地需求的关键桥梁。

### 现有方法的局限性
1.  **转换成本高昂**：现有的模型转换方法（如将Transformer蒸馏为Mamba或RWKV）通常需要使用超过100B token的海量数据进行重新训练或微调。这种成本对于大多数研究机构和企业来说是不可接受的，几乎等同于重新预训练一个模型。
2.  **长上下文性能退化**：现有的蒸馏方法往往只能保留原模型在短文本上的能力，一旦序列长度超过训练窗口（如从4k扩展到128k或更长），模型的表现会出现断崖式下跌。这表明现有的位置编码或状态空间建模缺乏足够的长度泛化能力。

### 为什么这个问题重要
该研究直接击中了LLM应用的痛点。如果能够仅用极少量的数据（<1B tokens）将现有的SOTA Transformer模型转化为高效的长上下文模型，将极大降低长文本模型的部署门槛，使得在端侧设备或有限算力资源上运行超长上下文模型成为可能。

## 2. 核心方法与创新

### 提出的核心方法
论文提出了两大核心贡献：**HALO蒸馏流程**和**HypeNet架构**。

1.  **HALO (Hybrid Attention via Layer Optimization)**：
    这是一种高效的模型转换流程。它不是简单地用线性层替换注意力层，而是采用了一种“逐层替换、逐步对齐”的策略。通过精心设计的蒸馏目标，将预训练好的Transformer中的知识迁移到混合架构中。

2.  **HypeNet 架构**：
    一种混合架构，结合了Softmax注意力（用于保留原模型的局部建模能力）和线性注意力（用于提升长序列效率）。其核心创新在于引入了**HyPE (Hybrid Position Encoding)**编码方案。

### 技术创新点与贡献
1.  **HyPE位置编码**：这是论文的灵魂所在。传统的位置编码（如RoPE）在转换为线性RNN时难以完美对齐。HyPE编码通过数学变换，使得同一个位置编码可以同时兼容Softmax注意力和线性注意力机制。这解决了混合架构中位置信息不一致的难题，赋予了模型卓越的长度外推能力。
2.  **极低成本的蒸馏**：证明了通过合理的架构设计和初始化策略，不需要海量数据即可完成模态的迁移。实验中仅用2.3B token（不到原预训练数据的0.01%）就成功将Qwen系列模型转化为HypeNet。
3.  **无缝集成**：HypeNet保留了部分Softmax注意力层，使得模型在继承RNN长文本优势的同时，不丢失Transformer在复杂推理任务上的精度。

### 方法的优势与特色
*   **数据效率极高**：相比其他需要数十B token的转换方法，HALO将数据需求降低了1-2个数量级。
*   **即插即用**：该方法具有很强的通用性，可以应用于现有的不同规模的Transformer模型。
*   **推理友好**：转换后的模型在推理时拥有线性复杂度的KV Cache或状态空间，显著降低了显存占用。

## 3. 理论基础

### 理论假设
论文基于一个核心假设：**预训练Transformer的权重中蕴含了语言理解所需的深层知识，这些知识并不依赖于特定的注意力计算形式（Softmax或线性），只要能够近似地映射输入输出的特征空间关系。**

### 数学模型与算法设计
1.  **混合注意力的数学统一**：
    Softmax注意力的核心在于归一化，而线性注意力（通常基于RWKV或Mamba机制）核心在于状态空间模型（SSM）的递推。论文通过HyPE编码，将位置信息解耦。
    *   Softmax Attention: $Attention(Q, K, V) = softmax(QK^T)V$
    *   Linear Attention: $LinearAttention(Q, K, V) = \phi(Q) (\phi(K)^T V)$
    HypeNet通过设计特定的$\phi$映射和位置偏置，使得两者在数学表达上能够平滑过渡。

2.  **HyPE编码的设计**：
    HyPE编码本质上是一种混合了绝对位置编码（APE）和旋转位置编码（RoPE）特性的方案。它确保了当模型切换到线性模式时，位置信息依然能够以线性递推的形式被状态空间吸收和记忆。

### 理论贡献
论文从理论上证明了在引入HyPE后，混合模型中的线性部分能够有效地继承原Transformer的位置感知能力，从而避免了传统线性RNN在长序列中“迷失方向”的问题。

## 4. 实验与结果

### 实验设计
研究团队选择了Qwen系列模型作为基座，通过HALO流程将其转换为HypeNet。
*   **数据量**：仅使用了约2.3B token的混合数据（包含长文本和通用文本）进行蒸馏训练。
*   **对比基线**：原始Transformer、纯线性RNN模型（如RWKV）、其他混合模型。

### 主要实验结果
1.  **性能保持**：在标准基准测试（如MMLU, GSM8K）中，HypeNet与原始Qwen模型性能持平，甚至在部分长文本任务上有所超越。
2.  **长文本泛化**：在“大海捞针”测试和长文档理解任务中，HypeNet展现了极强的长度泛化能力，成功支持128k甚至更长的上下文，且没有出现明显的性能衰减。
3.  **推理效率**：在长序列推理下，HypeNet的显存占用和生成速度显著优于原始Transformer。

### 结果分析与验证
结果证明了**“架构决定上限，数据决定下限”**在特定条件下是可以被打破的。优秀的架构设计（HyPE）可以极大地降低对数据的依赖。实验表明，仅仅替换架构而不进行大规模重训，模型依然能“记住”并“重组”原有的语言能力。

### 实验局限性
*   **混合架构的冗余**：由于保留了部分Softmax注意力，在极长序列（如1M+）下，纯线性模型（如Mamba）在理论上仍然比HypeNet更高效。HypeNet是一种折中方案。
*   **蒸馏的敏感性**：虽然数据需求少，但蒸馏过程对超参数和初始化可能较为敏感，不同基座模型可能需要特定的调整。

## 5. 应用前景

### 实际应用场景
1.  **长文档分析与对话**：企业级知识库检索、法律合同审查、长篇小说阅读与生成。
2.  **端侧AI部署**：由于显存占用大幅降低，HypeNet非常适合部署在显存受限的设备（如手机、笔记本）上运行长上下文任务。
3.  **实时视频流理解**：处理长帧序列的视频内容，需要线性复杂度的模型来维持实时性。

### 产业化可能性
极高。该技术直接降低了长文本模型的使用成本。对于企业而言，无需重新训练模型即可获得长文本能力，这意味着可以直接利用现有的私有化模型资产进行升级。

### 未来应用方向
结合**Speculative Sampling（投机采样）**或**量化技术**，HypeNet架构可以进一步压缩推理延迟，成为下一代高效推理引擎的核心架构。

## 6. 研究启示

### 对该领域的启示
1.  **架构即数据**：优秀的架构设计可以充当“正则化项”，减少对海量训练数据的依赖。这为未来的模型研究指明了方向：与其单纯堆砌数据，不如设计更符合物理规律（如线性递推）的架构。
2.  **混合架构的潜力**：纯线性模型虽然快但难以训练，纯Transformer虽然强但计算贵。混合架构（Hybrid）是近期内实现高性能与高效率平衡的最佳路径。

### 可能的研究方向
1.  **更彻底的线性化**：研究如何完全移除Softmax注意力而不损失精度。
2.  **动态混合机制**：根据输入内容的复杂度，动态决定使用Softmax注意力还是线性注意力。
3.  **多模态扩展**：将HALO流程应用于视觉和语音模型，处理长视频序列。

## 最佳实践指南

### 实践 1：采用线性注意力的门控机制

**说明**: 标准的线性注意力机制在处理长上下文时往往会丢失上下文信息，导致模型性能下降。该研究表明，通过引入门控机制，可以在线性注意力计算中动态地过滤和保留关键信息，从而在不增加计算复杂度的情况下显著提升模型性能。

**实施步骤**:
1. 在线性注意力的特征图层引入可学习的门控单元。
2. 使用 Sigmoid 或 Tanh 激活函数生成门控权重。
3. 将门控权重应用于线性注意力的键值对，以抑制非关键信息。

**注意事项**: 
- 确保门控机制的初始化不会导致梯度消失，建议采用适当的初始化策略（如 Xavier 初始化）。

### 实践 2：实施从密集注意力到线性注意力的知识蒸馏

**说明**: 直接训练线性注意力模型往往难以达到与密集注意力模型相同的精度。通过知识蒸馏，利用预训练的密集注意力模型作为教师模型，可以有效地将精确的注意力模式迁移到线性注意力学生模型中。

**实施步骤**:
1. 加载预训练的密集注意力 Transformer 模型作为教师模型。
2. 构建具有相同层数和隐藏维度的线性注意力学生模型。
3. 定义蒸馏损失函数，最小化学生模型和教师模型在输出分布和注意力图上的差异。
4. 使用长上下文数据集进行微调训练。

**注意事项**: 
- 蒸馏过程中的温度参数需要根据具体任务进行调整，以平衡软标签的平滑性与准确性。

### 实践 3：构建混合注意力架构

**说明**: 纯线性注意力虽然高效，但在某些需要精确召回的局部位置上表现不佳。最佳实践是构建混合架构，在模型底部（靠近输入）使用密集注意力处理局部上下文，在顶部（靠近输出）使用线性注意力处理全局上下文。

**实施步骤**:
1. 设计模型时，将前 $N$ 层设置为标准的多头注意力机制。
2. 将后续层替换为门控线性注意力模块。
3. 通过实验确定最佳的分割点 $N$，通常建议在模型总层数的前 1/4 或 1/3 处分割。

**注意事项**: 
- 混合架构会增加一定的显存开销，需根据硬件资源限制平衡密集层和线性层的比例。

### 实践 4：使用特征图特征值分解

**说明**: 线性注意力的核心在于特征图的使用。为了进一步提升数值稳定性和表达能力，建议对特征图进行特征值分解或使用非线性的特征映射函数，避免特征映射后的信息坍塌。

**实施步骤**:
1. 替换标准的 ELU+1 特征映射函数，尝试使用分解后的特征映射。
2. 在计算注意力分数之前，对键和值矩阵进行归一化处理。
3. 引入较小的常数项防止除零错误。

**注意事项**: 
- 复杂的特征映射可能会增加推理延迟，需在精度和速度之间进行权衡。

### 实践 5：优化长上下文的分块策略

**说明**: 在处理极长上下文时，为了充分利用硬件的并行计算能力，建议采用分块注意力策略。这不仅符合线性注意力的数学原理，还能最大化 GPU 的利用率。

**实施步骤**:
1. 将输入序列划分为固定大小的块。
2. 在块内应用局部注意力，在块间应用线性注意力聚合信息。
3. 实现高效的 KV Cache 管理机制，支持流式处理。

**注意事项**: 
- 块的大小是关键超参数，过小会导致上下文断裂，过大会降低计算效率，建议从 4096 或 8192 开始调试。

### 实践 6：针对极长上下文的特定预训练

**说明**: 传统的短上下文预训练模型直接迁移到长上下文任务时往往会出现灾难性遗忘。为了使混合线性注意力模型有效工作，需要在长上下文数据上进行持续预训练或中间微调。

**实施步骤**:
1. 收集包含长文档、书籍或代码库的大规模长上下文数据集。
2. 在此数据集上对混合模型进行中间阶段的预训练，重点关注长距离依赖任务。
3. 使用掩码语言建模作为辅助任务，增强模型对长序列的建模能力。

**注意事项**: 
- 训练过程中应使用梯度检查点技术以节省显存，确保能够处理超长批次。

### 实践 7：推理时的 KV Cache 压缩

**说明**: 混合线性注意力模型在推理时可以通过压缩 KV Cache 来显著降低显存占用。利用线性注意力的特性，可以将历史键值对压缩为固定大小的矩阵，而不是像标准 Transformer 那样线性增长。

**实施步骤**:
1. 在推理阶段，为线性注意力层维护一个总结性的状态矩阵。
2. 每处理一个新的 Token，更新状态矩阵而不是简单拼接历史 KV。
3. 确保密集注意力层依然保留完整的局部 KV Cache。

**注意事项**: 
- 压缩算法需要支持增量更新

- 提出了一种灵活的注意力机制配置策略，允许模型根据不同的上下文长度动态调整线性注意力与窗口注意力的比例，从而在计算效率和模型表达能力之间取得最佳平衡。
- 通过对线性注意力中特征映射的深入分析，揭示了传统线性注意力在长距离依赖建模上的不足，并据此提出了针对性的改进方案，增强了模型捕捉全局信息的能力。

## 常见问题


### 1: 什么是 Hybrid Linear Attention，它与标准 Attention 机制有何不同？

1: 什么是 Hybrid Linear Attention，它与标准 Attention 机制有何不同？

**A**: Hybrid Linear Attention（混合线性注意力）是一种旨在解决 Transformer 模型在处理超长序列时计算复杂度过高问题的注意力机制。标准的 Attention 机制（如 Softmax Attention）具有 $O(N^2)$ 的二次方计算复杂度，其中 $N$ 是序列长度，这使得它在处理极长上下文时变得非常缓慢且消耗大量显存。

Hybrid Linear Attention 的核心在于将“线性注意力”与“局部注意力”或“全局注意力”相结合。线性注意力通过特定的核函数（如 ELU+1 或 ReLU）将 Softmax 的分母中的指数运算转化为可拆解的形式，从而将复杂度降低到 $O(N)$。然而，纯线性注意力往往会牺牲模型的表达能力和性能。Hybrid Linear Attention 通过混合架构，在保持线性复杂度的同时，利用局部窗口或全局 Token 来增强模型捕捉局部依赖和关键信息的能力，从而在效率和效果之间取得最佳平衡。

---



### 2: 论文中提到的“Distillation”（蒸馏）技术在该研究中起到了什么作用？

2: 论文中提到的“Distillation”（蒸馏）技术在该研究中起到了什么作用？

**A**: 在这篇论文中，蒸馏技术是连接高效线性模型与强大但笨重的非线性模型（如标准 Transformer）的桥梁。由于线性注意力机制移除了 Softmax 的归一化操作，直接从头训练往往难以收敛，且最终性能通常不如经过充分预训练的标准 Transformer。

研究者提出了一种高效的蒸馏方法，利用一个已经训练好的、性能强大的标准 Transformer 作为“教师模型”，来指导 Hybrid Linear Attention “学生模型”的训练。具体来说，学生模型不仅学习预测数据本身的标签，还学习模仿教师模型的注意力分布或隐藏状态。这种方法使得线性模型能够继承教师模型的知识，从而在不牺牲 $O(N)$ 推理速度的前提下，达到接近甚至等同于标准 Transformer 的性能，解决了线性模型训练难和精度低的问题。

---



### 3: 该研究提出的架构设计有哪些关键创新点？

3: 该研究提出的架构设计有哪些关键创新点？

**A**: 论文中的架构设计主要包含以下几个关键创新点：

1.  **多头线性注意力与门控机制**：为了增强线性注意力的表达能力，作者采用了多头机制并引入了门控。这使得模型能够动态地控制信息流，决定在多大程度上依赖线性注意力特征。
2.  **混合策略**：架构并非单纯使用线性注意力，而是将其与局部注意力（如滑动窗口注意力）混合。这种设计确保了模型既能通过线性层处理超长距离依赖，又能通过局部层精准捕捉高频的局部细节信息。
3.  **优化的 FlashAttention 实现**：针对线性注意力的特殊计算方式（通常是分块计算），作者优化了底层算子，使其能够像 FlashAttention 一样高效地利用显存和带宽，进一步提升了训练和推理速度。

---



### 4: 使用 Hybrid Linear Attention 处理长文本时，实际能获得多大的性能提升？

4: 使用 Hybrid Linear Attention 处理长文本时，实际能获得多大的性能提升？

**A**: 根据论文的实验数据，Hybrid Linear Attention 在处理长文本时带来了显著的效率提升，且几乎没有精度损失。

1.  **速度与显存**：在长序列（例如 128k token 或更长）上，该方法的推理速度相比标准 Transformer 快了数倍，且显存占用大幅降低（从 $O(N^2)$ 降至 $O(N)$）。这意味着它可以在消费级显卡上处理以前需要昂贵的 H100 显卡才能处理的长文本。
2.  **效果保持**：得益于有效的蒸馏策略和混合架构，该模型在长文本任务（如 Passkey Retrieval、长文档问答、RAG 检索增强生成等）上的表现，能够达到甚至超过同等规模的标准 Transformer 模型（如 Llama-2 或 Mistral 的变体），避免了以往线性模型性能崩塌的问题。

### 5: 该技术主要适用于哪些应用场景？

5: 该技术主要适用于哪些应用场景？

**A**: Hybrid Linear Attention 特别适合需要处理“极长上下文”的场景，主要包括：

1.  **长文档理解与分析**：例如阅读几十页甚至上百页的财报、法律合同或技术文档，并进行摘要或问答。
2.  **检索增强生成（RAG）**：在 RAG 系统中，检索出的上下文往往非常长，该技术允许模型将更多检索到的相关内容放入输入窗口，从而提高回答的准确性。
3.  **长对话系统**：支持模型记住数万轮的对话历史，提供具有长期记忆的 AI 伴侣或客服助手。
4.  **代码库分析**：对整个大型代码库进行全局分析和补全，这通常需要上下文窗口达到数十万甚至百万级别的 Token。

### 6: 既然线性注意力这么好，为什么现在的主流大模型（如 GPT-4, Llama 3）没有直接采用？

6: 既然线性注意力这么好，为什么现在的主流大模型（如 GPT-4, Llama 3）没有直接采用？

**A**: 尽管线性注意力在理论上具有 $O(N)$ 的优势，但在实际落地中面临一些挑战，这也是该论文致力于解决的问题：

1.  **训练不稳定性**：纯线性注意力改变了训练动态，使得模型难以收敛。如果没有论文中提到的“蒸馏”技术，很难训练出高性能的线性模型。
2.  **硬件利用率**：现有的 GPU 硬件和深度学习
