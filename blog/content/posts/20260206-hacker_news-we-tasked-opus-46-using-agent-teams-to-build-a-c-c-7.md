# 示例1：词法分析器 - 将源代码分解为Token
import re

class Lexer:
    """简单的C语言词法分析器，用于识别关键字、标识符、数字和符号"""
    
    # 定义Token类型
    TOKEN_SPEC = [
        ('NUMBER',   r'\d+'),              # 整数
        ('ASSIGN',   r'='),                # 赋值符号
        ('END',      r';'),                # 语句结束
        ('ID',       r'[A-Za-z]\w*'),      # 标识符
        ('OP',       r'[+\-*/]'),          # 运算符
        ('SKIP',     r'[ \t]+'),           # 空白字符（跳过）
        ('MISMATCH', r'.'),                # 其他字符
    ]
    
    def __init__(self):
        # 编译正则表达式
        self.tok_regex = '|'.join(f'(?P<{pair[0]}>{pair[1]})' for pair in self.TOKEN_SPEC)
        self.re_prog = re.compile(self.tok_regex)
    
    def tokenize(self, code):
        """将输入的代码字符串转换为Token列表"""
        tokens = []
        for mo in self.re_prog.finditer(code):
            kind = mo.lastgroup
            value = mo.group()
            if kind == 'SKIP':
                continue  # 跳过空格
            elif kind == 'MISMATCH':
                raise RuntimeError(f'无法识别的字符: {value}')
            tokens.append((kind, value))
        return tokens

# 测试
lexer = Lexer()
code = "int a = 10 + 5;"
print(lexer.tokenize(code))
# 输出: [('ID', 'int'), ('ID', 'a'), ('ASSIGN', '='), ('NUMBER', '10'), ('OP', '+'), ('NUMBER', '5'), ('END', ';')]
```

# 示例2：语法分析器 - 构建抽象语法树(AST)

class ASTNode:
    """抽象语法树节点基类"""
    pass

class BinOp(ASTNode):
    """二元运算节点 (如: a + b)"""
    def __init__(self, left, op, right):
        self.left = left   # 左操作数
        self.op = op       # 运算符
        self.right = right # 右操作数
    
    def __repr__(self):
        return f"({self.left} {self.op} {self.right})"

class Num(ASTNode):
    """数字节点"""
    def __init__(self, token):
        self.value = int(token[1])
    
    def __repr__(self):
        return str(self.value)

def parse_expression(tokens):
    """简单的递归下降解析器，解析加减乘除表达式"""
    # 处理乘除（优先级高）
    def parse_factor():
        if tokens[0][0] == 'NUMBER':
            val = Num(tokens[0])
            tokens.pop(0)
            return val
        # 这里省略了括号和变量的处理
    
    node = parse_factor()
    
    while tokens and tokens[0][1] in ('*', '/'):
        op = tokens[0][1]
        tokens.pop(0)
        node = BinOp(node, op, parse_factor())
    
    # 处理加减（优先级低）
    while tokens and tokens[0][1] in ('+', '-'):
        op = tokens[0][1]
        tokens.pop(0)
        node = BinOp(node, op, parse_factor())
        
    return node

# 测试
tokens = [('NUMBER', '10'), ('OP', '*'), ('NUMBER', '2'), ('OP', '+'), ('NUMBER', '3')]
ast = parse_expression(tokens)
print(f"生成的AST结构: {ast}")
# 输出: ((10 * 2) + 3)
```

## 最佳实践指南

### 实践 1：构建多智能体协作架构

**说明**: 利用 Opus 4.6 的 Agent Teams 功能，将复杂的 C 编译器构建任务分解为多个子系统。不要试图用单个 Prompt 完成所有工作，而是通过定义不同的角色（如词法分析专家、语法分析专家、代码生成专家）来模拟真实的软件开发团队结构，实现模块化开发。

**实施步骤**:
1. 定义智能体角色：为预处理、词法分析、语法分析、语义分析、代码生成及优化器分配专门的角色。
2. 设置通信协议：明确各 Agent 之间的输入输出格式（如 AST 的中间表示格式）。
3. 建立管理机制：设立一个“项目经理”Agent 负责统筹进度和合并代码。

**注意事项**: 确保各 Agent 的上下文窗口足够大，或通过外部文件系统传递中间产物，避免 Token 限制导致的信息丢失。

---

### 实践 2：采用增量式开发与验证策略

**说明**: 编译器是一个逻辑严密的系统，试图一次性生成完整代码极易导致失败。最佳实践是遵循“最小可行性产品”原则，先实现一个能处理极简单代码（如返回整数的 main 函数）的子集，再逐步扩展 C 语言标准的支持范围。

**实施步骤**:
1. 定义 T 型测试集：从最基础的 `int main() { return 0; }` 开始。
2. 分阶段迭代：第一阶段仅实现词法和语法树生成；第二阶段实现简单的中间代码生成；最后实现目标代码生成。
3. 每个阶段必须通过上一阶段的测试集才能继续。

**注意事项**: 严禁在基础功能（如基本的加减法）未通过测试前，就尝试实现复杂特性（如指针算术或宏定义）。

---

### 实践 3：建立自动化测试与自我修正闭环

**说明**: AI 生成的代码可能包含逻辑错误或边界情况漏洞。必须构建一个自动化测试流水线，让 AI 生成的代码能够立即接受标准测试用例的检验，并将错误信息反馈给 Agent Team 进行自我修正。

**实施步骤**:
1. 准备标准测试集：使用 gcc 或 clang 编译的输出作为“金标准”，对比 Opus 生成的编译器输出。
2. 封装测试脚本：编写 Shell 或 Python 脚本，自动运行编译并比对二进制输出或汇编结果。
3. 错误反馈循环：将测试失败的 Log 作为 Prompt 的一部分重新输入给 Agent，要求其定位并修复 Bug。

**注意事项**: 对于浮点运算或未定义行为，需要明确测试的容忍度，避免因微小的实现差异导致测试失败。

---

### 实践 4：规范中间表示（IR）的设计

**说明**: Agent Teams 之间的协作高度依赖于数据接口。设计一套清晰、文本化且易于 LLM 理解的中间表示（如类 JSON 格式或自定义汇编语言），是连接前端（解析）和后端（生成）的关键。

**实施步骤**:
1. 定义 IR 结构：确定是使用三地址码、SSA（静态单赋值）形式还是其他格式。
2. 文档化接口：在 System Prompt 中明确 IR 的具体字段和含义。
3. 验证 IR 转换：编写专门的解析器，确保前端生成的 IR 能被后端正确读取。

**注意事项**: IR 设计应尽量简单明了，过于复杂的 IR 结构会增加 Agent 生成代码时的出错率。
