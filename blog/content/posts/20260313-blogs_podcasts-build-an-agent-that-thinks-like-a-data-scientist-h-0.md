## 最佳实践指南

### 实践 1：构建可复用的工具生成机制

**说明**:
与其为每个特定任务硬编码工具，不如构建一个能够根据上下文动态生成工具的系统。这种“元工具”方法允许 Agent 在遇到新问题时，能够编写、验证并存储自己的代码片段或函数作为可复用工具。这模仿了数据科学家建立个人代码库的过程，极大地提高了长期效率。

**实施步骤**:
1. 建立一个沙箱环境，允许 Agent 安全地执行生成的代码。
2. 设计一个接口，让 Agent 能够将验证成功的代码片段注册为可调用函数。
3. 实施版本控制或哈希机制，以避免重复生成相同的工具。

**注意事项**:
必须严格限制生成的工具的权限（如禁止网络访问或文件写入），以防止安全漏洞。

---

### 实践 2：实施迭代式自我修正循环

**说明**:
数据科学家很少在第一次尝试就写出完美的代码。Agent 应该具备“尝试-失败-分析错误-修复”的能力。这意味着系统不仅要执行任务，还要能够解析报错信息、回溯逻辑，并自主调整策略，而不是在遇到错误时立即停止。

**实施步骤**:
1. 在执行逻辑中嵌入 Try-Catch 块，将错误信息返回给 LLM。
2. 设计提示词，要求 Agent 在遇到错误时必须提出假设的修复方案，而不是盲目重试。
3. 限制最大重试次数，防止陷入无限循环。

**注意事项**:
需要区分“数据错误”和“代码逻辑错误”，针对不同类型的错误设计不同的修正策略。

### 实践 3：将复杂任务分解为可管理的子任务

**说明**:
面对复杂的数据分析问题，直接生成最终解决方案往往会导致幻觉或逻辑跳跃。最佳实践是指导 Agent 像资深数据科学家一样思考：先进行探索性数据分析（EDA），再定义特征，最后建模。通过链式思考将大任务拆解为小步骤。

**实施步骤**:
1. 强制 Agent 在生成代码前先生成执行计划。
2. 设置中间检查点，在每个子步骤完成后验证输出是否符合预期。
3. 允许 Agent 根据上一步的结果动态调整下一步的计划。

**注意事项**:
计划不应过于死板，需要保留一定的灵活性以应对数据分析中的意外发现。

### 实践 4：建立严格的验证与测试协议

**说明**:
自动生成的代码可能包含微妙的 Bug 或逻辑缺陷。在将任何分析结果或工具投入使用之前，必须通过自动化测试。这包括单元测试（针对生成的函数）和数据完整性检查（针对分析结果）。

**实施步骤**:
1. 要求 Agent 在生成核心逻辑的同时生成断言或测试用例。
2. 在沙箱中运行测试用例，只有通过测试的代码才被部署。
3. 对比输出数据的统计特性（如均值、分布）与预期是否相符。

**注意事项**:
测试数据的覆盖面至关重要，应包含边缘情况以验证代码的鲁棒性。

### 实践 5：优化上下文感知与记忆管理

**说明**:
数据科学项目是连续的，且依赖大量的历史信息。为了达到高性能，Agent 需要能够访问之前的分析结果、失败的尝试和特定的领域知识。利用向量数据库或长上下文窗口来维护这种“项目记忆”。

**实施步骤**:
1. 将之前的对话历史、生成的代码和错误日志存储在检索系统中。
2. 在执行新任务前，检索相关的历史工具和上下文。
3. 动态过滤上下文，只保留与当前任务最相关的信息，以控制 Token 消耗。

**注意事项**:
需注意上下文窗口的 Token 限制，定期总结或压缩旧信息，避免超出模型处理能力。

---

### 实践 6：设计领域特定的提示词模板

**说明**:
通用的提示词往往无法产生高质量的数据科学代码。使用包含特定库（如 Pandas, Scikit-learn）最佳实践的模板，可以显著提升代码质量。这相当于给 Agent 提供了一位“资深导师”的指导。

**实施步骤**:
1. 在系统提示词中明确指定代码风格和必须使用的库。
2. 提供常见数据分析任务（如数据清洗、可视化）的代码示例作为少样本学习。
3. 强制要求输出包含解释性注释，便于后续的调试和复用。

**注意事项**:
模板需要定期更新，以适应数据分析库的版本迭代和新特性的引入。
