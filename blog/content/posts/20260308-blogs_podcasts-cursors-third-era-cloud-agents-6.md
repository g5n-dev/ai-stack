## 最佳实践指南

### 实践 1：构建上下文感知的提示词工程

**说明**: 在 Cursor 的 Cloud Agents 时代，Agent 不再仅仅是补全代码，而是能够理解整个代码库和云端上下文。构建高质量的提示词需要包含明确的技术栈描述、具体的业务逻辑目标以及预期的文件结构，以便 Agent 能够准确调用云端知识库进行推理。

**实施步骤**:
1. 在项目根目录创建 `cursor-rules.txt` 或 `prompt.md` 文件，明确定义项目的技术栈（如 React, FastAPI 等）和编码规范。
2. 使用 `@` 符号明确引用 Agent 需要读取的具体文件或文件夹，限制其搜索范围，减少幻觉。
3. 在对话中采用“角色-任务-约束”的框架，例如：“作为资深架构师（角色），重构 API 层（任务），保持现有接口不变（约束）”。

**注意事项**: 避免模糊的指令，例如“优化代码”，应具体指出是优化性能、可读性还是安全性。

---

### 实践 2：利用 Composer 功能进行多文件重构

**说明**: Cloud Agents 的核心优势之一是处理跨文件的复杂变更。利用 Composer（Cmd+I / Ctrl+I）功能，可以让 Agent 一次性规划并修改多个相互关联的文件，而不是单文件逐个修补，这能保证架构的一致性。

**实施步骤**:
1. 打开 Composer 面板，输入高层次的需求，例如“将用户认证逻辑从本地迁移到 OAuth 2.0”。
2. 在 Agent 生成计划后，检查其预览的 `diff`，确认涉及的所有文件（如 models, controllers, config）。
3. 点击“Accept”接受全部变更，或选择部分文件进行逐步应用。

**注意事项**: 在进行大规模重构前，务必确保代码仓库已提交，以便在 Agent 引入非预期逻辑时能够快速回滚。

---

### 实践 3：建立本地与云端知识的闭环验证

**说明**: 虽然 Cloud Agents 拥有强大的云端推理能力，但生成的代码可能不完全符合本地环境的具体配置或边缘情况。最佳实践是将 Agent 视为“初级工程师”，必须建立“生成-验证-修正”的闭环。

**实施步骤**:
1. 让 Agent 生成代码后，不要直接复制粘贴，而是先使用 Cursor 的内置 Diff 视图逐行审查。
2. 运行本地的 Linting 工具和单元测试。
3. 如果测试失败，将错误信息直接反馈给 Agent，并附加相关日志，要求其基于错误信息进行修正。

**注意事项**: 不要盲目信任 Agent 生成的依赖库版本，需检查其与项目现有依赖的兼容性。

---

### 实践 4：精细化权限控制与敏感数据保护

**说明**: Cloud Agents 需要将代码上下文发送到云端进行处理。在处理包含 API 密钥、数据库凭证或专有算法的项目时，必须严格控制发送给 Agent 的上下文范围，防止数据泄露。

**实施步骤**:
1. 使用 `.cursorignore` 文件（类似于 `.gitignore`），明确排除 `.env`、`secrets.yaml`、`config/prod` 等敏感文件。
2. 在 `.env.local` 或 Cursor 设置中，关闭“Privacy Mode”以外的敏感数据自动上传选项（如果可用）。
3. 定期审查 Agent 的聊天历史，确保没有意外粘贴敏感数据。

**注意事项**: 即使是脱敏的数据，如果组合起来具有特定模式，也可能存在泄露风险，务必在源头上隔离敏感文件。

---

### 实践 5：定义清晰的测试驱动开发（TDD）工作流

**说明**: Cloud Agents 非常适合编写测试用例和测试数据。最佳实践是要求 Agent 先生成测试，再生成功能代码，或者利用 Agent 来验证现有代码的覆盖率。

**实施步骤**:
1. 在要求编写新功能时，附加指令：“请先为该功能生成单元测试，使用 Jest/Pytest”。
2. 让 Agent 运行测试并观察失败结果，这有助于 Agent 理解预期的行为边界。
3. 一旦测试通过，要求 Agent 检查是否有边缘情况未覆盖，并补充测试用例。

**注意事项**: Agent 生成的测试可能过于理想化（Happy Path），需人工添加异常处理和边界条件的测试指令。

---

### 实践 6：利用 Agent 进行技术债务的文档化

**说明**: 除了编写代码，Cloud Agents 还是优秀的文档助手。利用其对代码库的理解能力，可以自动生成或更新 README、API 文档以及内联代码注释，特别是针对遗留系统中的“技术债务”。

**实施步骤**:
1. 选中复杂的遗留代码模块，询问 Agent：“请分析这段代码的逻辑，并生成详细的流程图描述和注释”。
2. 要求 Agent 列出代码中潜在的 Bug 风险或不符合现代最佳实践的地方（即技术债务清单）。
3. 根据生成的清单，制定重构计划。

**注意事项**: 生成的文档可能存在冗余，需要人工进行精简和格式调整，以符合团队的文档规范。
