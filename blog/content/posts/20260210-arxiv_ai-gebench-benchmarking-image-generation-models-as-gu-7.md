## 导语

随着图像生成技术的发展，利用用户指令预测未来图形用户界面（GUI）状态已成为可能，但现有基准主要关注通用领域的视觉保真度，缺乏针对 GUI 场景中状态转换与时间一致性的评估。为此，本文提出了 GEBench，这是一个旨在填补这一空白的综合性基准。该基准可能包含特定的评估指标或数据集设计，但具体的评估维度和实验结果无法从摘要确认。这项工作有望为 GUI 自动化生成与交互系统的性能评估提供新的参考标准。

## 摘要

**GEBench：GUI 图像生成模型的基准测试**

**背景与问题**
随着图像生成模型的进步，利用用户指令预测未来图形用户界面（GUI）状态成为可能。然而，现有基准主要关注通用领域的视觉保真度，缺乏针对 GUI 场景中状态转换和时间连贯性的评估。

**GEBench 介绍**
为填补这一空白，本文推出了 GEBench，这是一个用于评估 GUI 生成中动态交互和时间连贯性的综合基准。
*   **数据规模：** 包含 700 个精心策划的样本。
*   **覆盖范围：** 涵盖 5 个任务类别，涉及单步交互、多步轨迹（现实与虚构场景）以及定位点。

**评估指标：GE-Score**
为了进行系统性评估，研究团队提出了 GE-Score，这是一种新型的五维度评估指标，涵盖：
1.  目标达成度
2.  交互逻辑
3.  内容一致性
4.  UI 合理性
5.  视觉质量

**主要发现**
对当前模型的广泛评估表明：
1.  **长期能力弱：** 模型在单步转换上表现尚可，但在维持长交互序列的时间连贯性和空间定位方面存在显著困难。
2.  **关键瓶颈：** 图标解释、文本渲染和定位精度是当前技术的主要瓶颈。

**意义**
该工作为构建高保真生成式 GUI 环境的未来研究提供了评估基础和改进方向。代码已在 GitHub 开源。

## 评论

**论文评价：GEBench: Benchmarking Image Generation模型在GUI环境中的基准测试**

**总体评价**

《GEBench: Benchmarking Image Generation Models as GUI Environments》针对图像生成模型在图形用户界面（GUI）交互场景中的应用，提出了一个全新的评估基准。该研究切中了当前多模态大模型与生成式AI在具身智能和自动化交互领域的痛点，即从静态图像生成向动态、逻辑驱动的场景生成转变。论文通过构建特定领域的数据集和评估指标，试图量化模型对GUI状态转换的理解能力。

以下是基于学术与应用视角的深入评价：

### 1. 研究创新性

*   **论文声称：** 现有的通用图像生成基准（如MSCOCO、ImageNet）仅关注视觉保真度，无法有效评估GUI生成中的功能逻辑和时间连贯性；GEBench填补了这一空白，首次系统性地将GUI交互作为图像生成任务进行基准化。
*   **证据：** 论文构建了包含700个样本的GEBench，覆盖了单步交互、多步轨迹（现实/虚构）及定位点5大类任务，并提出了结合视觉相似度（CLIP）与功能逻辑的GE-Score评估指标。
*   **学术评价：** **创新点显著，具有细分领域的开创性。** 将GUI视为一种“环境”而非单纯的“图像”，视角独特。现有的图像生成评估多关注美学质量，而GEBench强制模型理解“点击按钮A会导致状态B”的因果逻辑，这是将生成模型引入智能体决策的关键一步。
*   **推断：** 该研究可能启发后续工作将“视频生成”或“世界模型”的评估思路下沉到具体的UI交互领域，强调生成内容的“可用性”而非仅仅是“好看”。

### 2. 理论贡献

*   **论文声称：** 提出了GE-Score，旨在综合评估生成图像的视觉质量和结构准确性。
*   **证据：** GE-Score被设计为包含CLIP Score（语义对齐）和结构相似性指标（虽然摘要未详述，通常指像素级或特征级的结构匹配）。
*   **学术评价：** **理论增量有限，主要是应用层面的理论整合。** 论文并未提出新的生成模型架构或新的损失函数理论，而是贡献了评估理论。其核心挑战在于如何量化“功能正确性”。
*   **关键假设与失效条件：**
    *   **假设：** 视觉上的相似性（CLIP Score）能够有效代理GUI功能的正确性。即：如果生成的界面看起来像真实的，那么它就是功能正确的。
    *   **可能失效：** 在GUI中，视觉极相似但功能完全不同的情况比比皆是（例如：两个颜色完全一样的“提交”和“取消”按钮，或者一个被禁用的按钮）。仅靠视觉相似度无法捕捉这种语义层面的细微差别。
    *   **验证方式：** 建议引入基于LLM的视觉裁判或OCR工具，检测生成界面中的文本内容和控件状态（如是否可点击），以验证视觉指标与功能逻辑的一致性。

### 3. 实验验证

*   **论文声称：** 在GEBench上对主流生成模型（如Stable Diffusion系列、DALL-E 3等或基于ControlNet的变体）进行了评估，揭示了现有模型在处理GUI动态性时的不足。
*   **证据：** （基于摘要推断）实验应展示了模型在单步交互上表现尚可，但在多步轨迹和虚构场景生成上出现逻辑断裂或视觉漂移。
*   **学术评价：** **实验设计的针对性很强，但数据规模是短板。** 700个样本对于基准测试而言相对较小，容易导致过拟合或统计显著性不足。
*   **推断：** 现有的生成模型（如SD3或DALL-E 3）在处理“多步轨迹”时，可能会因为缺乏对UI状态机的显式建模，导致生成结果出现“幻觉”，例如凭空创造出不存在的按钮。
*   **可靠性检验：** 需要检查数据集的划分是否包含了足够多样的UI风格（Material Design, iOS, Fluent OS等），以及是否包含了长尾的边缘情况。

### 4. 应用前景

*   **应用价值：** **极高。** 该研究直接服务于AI Agent（智能体）和自动化测试领域。
    1.  **AI辅助设计：** 设计师可以通过自然语言描述交互流程，模型直接生成中间态UI原型。
    2.  **自动化UI测试：** 在测试中，可以利用生成模型预测点击后的界面状态，并与实际开发出的APP进行比对，用于发现逻辑Bug。
    3.  **训练数据合成：** 为训练GUI理解模型提供合成数据，解决真实交互数据稀缺的问题。

### 5. 可复现性

*   **分析：** 论文提出了明确的基准和指标，通常意味着会开源数据集和评估代码。
*   **潜在问题：** GUI生成高度依赖于提示词的工程。如果论文没有详细披露用于微调或推理的Prompt模板，复现结果可能会有较大波动。此外，700个样本的人工标注标准（如：什么是“合理的下一帧”）如果不清晰，也会影响基准的权威性。

# GEBench：GUI 图像生成模型的基准测试深度解析

## 1. 研究背景与问题

### 核心问题
该研究致力于解决**如何利用图像生成模型构建高保真、可交互的图形用户界面（GUI）仿真环境**这一核心问题。具体而言，它探索了当前的生成模型（如扩散模型）是否能够根据用户的操作指令（如“点击设置按钮”），准确地预测出下一帧的 GUI 状态，从而模拟真实软件的运行逻辑。

### 背景与意义
- **AI 智能体的需求爆发**：随着大语言模型（LLM）和视觉语言模型（VLM）的发展，能够自主操作计算机和手机软件的智能体成为研究热点。训练这些智能体需要大量的交互数据，而真实环境存在成本高、速度慢、安全性低（不可逆操作）等问题。
- **生成式仿真的潜力**：理想的解决方案是构建一个“生成式环境”，即由模型根据动作生成下一帧界面。这不仅能提供无限的训练数据，还能加速智能体的训练循环。
- **从静态到动态的跨越**：目前的图像生成模型多擅长生成静态、高质量的单一图像，但 GUI 本质上是动态的、状态机驱动的系统。将生成模型应用于 GUI 仿真，是对模型逻辑推理和时空连贯性能力的极大考验。

### 现有方法的局限性
- **评估基准缺失**：现有的图像生成基准（如 COCO, ImageNet）或 GUI 理解基准（如 Widget Captioning）主要关注静态视觉质量或简单的检测任务，缺乏对**“状态转换”**、**“交互逻辑”**和**“时间连贯性”**的评估。
- **模型能力未测**：业界尚不清楚 SOTA（最先进）的图像生成模型在处理需要精确像素定位（如点击特定按钮）和保持文本/图标一致性（如滑动后文字不乱码）的 GUI 任务时，其瓶颈究竟在哪里。

### 问题重要性
该研究的重要性在于它为“生成式 GUI”这一新兴方向设立了标尺。如果生成模型能够通过此类基准测试，意味着我们可以低成本构建虚拟的操作系统环境，这对 AI Agent、自动化测试、UI 设计辅助等领域具有革命性意义。

## 2. 核心方法与创新

### 核心方法：GEBench 框架
论文提出了 **GEBench**，这是一个专门针对 GUI 生成任务设计的综合基准测试框架。它包含两个核心组成部分：
1.  **结构化数据集**：包含 700 个精心筛选的样本，覆盖 5 种不同类型的任务（单步交互、多步轨迹等），旨在测试模型在不同复杂度下的表现。
2.  **多维评估指标（GE-Score）**：提出了一套全新的五维评估体系，结合了自动化指标（如 CLIP Score）和基于 VLM（视觉语言模型）的自动化评估，以替代昂贵的众包人工评估。

### 技术创新点与贡献
- **任务细粒度分类**：将 GUI 生成任务细分为单步预测、多步轨迹预测（现实/虚构）和锚点定位。这种分类法有助于诊断模型在短期记忆与长期规划上的不同表现。
- **VLM 驱动的自动化评估**：传统的图像生成评估（如 FID）无法判断“按钮是否被正确点击”。作者创新性地利用强大的多模态大模型（如 GPT-4V）作为“裁判”，通过 Prompt 工程让 VLM 检查生成的图像是否符合指令要求（例如：检查“设置菜单是否已打开”）。这解决了 GUI 逻辑难以量化评估的难题。
- **瓶颈定位分析**：不仅给出了分数，还深入分析了失败案例，指出了当前模型在**图标解释**、**文本渲染**和**定位精度**上的具体缺陷。

### 方法的优势与特色
- **针对性强**：完全聚焦于 GUI 领域的特有问题（如文本清晰度、控件状态变化）。
- **可扩展性**：评估流程自动化，无需人工介入即可快速对新模型进行基准测试。
- **诊断性**：GE-Score 的五个维度（目标达成、交互逻辑、一致性、合理性、视觉质量）能像体检报告一样指出模型的具体短板。

## 3. 理论基础

### 理论基础与假设
该研究基于以下理论假设：
1.  **世界模型假设**：即图像生成模型隐式地学习了对物理世界（在此处为数字世界 GUI）的因果理解。假设模型能够理解“点击”与“界面跳转”之间的因果映射关系。
2.  **多模态对齐**：假设视觉特征与文本指令在潜在空间中是对齐的，因此可以通过计算 CLIP Score 或 VLM 的 Logit 来判断生成内容与指令的一致性。

### 算法设计
虽然没有提出全新的生成模型架构，但在评估算法上设计了 **GE-Score**：
$$ GE\text{-}Score = \mathcal{E}(I_{gen}, I_{gt}, \text{Instr}) $$
其中 $\mathcal{E}$ 是综合评估函数，包含：
- **视觉质量**：使用 FID (Fréchet Inception Distance) 或 CLIP Score。
- **逻辑与一致性**：使用 VLM (Vision-Language Model) 进行二元分类或打分。

### 理论贡献分析
论文的理论贡献在于**形式化了 GUI 生成的评估空间**。它证明了传统的像素级损失函数（如 L1/L2 Loss）和感知损失（如 LPIPS）不足以衡量 GUI 交互的正确性，必须引入高层语义理解（VLM）来评估“功能性”是否达成。

## 4. 实验与结果

### 实验设计
- **数据集构建**：从 Android 和 iOS 等主流移动应用中收集数据，涵盖电商、社交、工具等类别。包含“真实轨迹”（基于真实操作录制）和“虚构轨迹”（基于不存在的操作，测试模型泛化能力）。
- **基准模型**：选取了当前主流的图像生成模型作为基线，包括基于 SDXL 的微调模型、基于指令的生成模型等。
- **评估指标**：主要使用提出的 GE-Score，并对比了不同模型在五个维度上的表现。

### 主要结果
1.  **单步尚可，多步崩塌**：现有模型在单次交互（如点击一次）的生成上表现尚可，但在多步连续交互中，错误会累积，导致界面出现严重的逻辑混乱（如出现乱码、控件消失）。
2.  **定位精度不足**：模型难以精确理解像素级的坐标指令（如“点击坐标 (100, 200)”），生成的交互反馈往往偏离预期位置。
3.  **文本与图标是短板**：生成的界面中，文字经常出现 OCR 错误，图标变形严重。这表明通用生成模型对 GUI 中高频出现的细粒度语义元素理解不足。

### 结果验证与局限性
- **验证**：通过消融实验验证了 GE-Score 中各个维度的必要性；通过人工抽样验证了 VLM 评估结果与人类判断的高度一致性。
- **局限性**：
    - **数据规模较小**：700 个样本相比通用数据集仍然较小，可能存在偏差。
    - **评估器的偏差**：依赖 VLM（如 GPT-4V）作为裁判，而 VLM 本身可能存在视觉幻觉或理解偏差，导致评分不完美。

## 5. 应用前景

### 实际应用场景
1.  **AI Agent 训练场**：这是最直接的应用。GEBench 可以筛选出能够构建逼真 GUI 环境的生成模型，为手机控制 Agent（如 AutoGPT, iPhone 的 Siri 相关功能）提供低成本的训练环境。
2.  **自动化 UI 测试**：在设计阶段，利用生成模型预测 UI 流程的可行性，提前发现设计逻辑漏洞。
3.  **原型生成与辅助设计**：设计师输入草图或指令，模型快速生成高保真的交互原型。

### 产业化可能性
- **高**。随着大模型在端侧应用的发展，对能够理解和生成 GUI 的模型需求极大。GEBench 提供了筛选这些模型的标尺。
- **挑战**：目前的模型在文本渲染上仍未达到商用级标准（必须 100% 准确），这是产业落地前必须解决的技术障碍。

### 未来应用方向
- **视频生成 GUI**：从单帧生成转向短视频生成，模拟更流畅的动画效果。
- **个性化 GUI**：根据用户习惯实时生成和调整界面布局。

## 6. 研究启示

### 对领域的启示
该论文揭示了**“视觉生成”与“逻辑仿真”之间的鸿沟**。它告诉社区，仅仅提高图像分辨率或美学质量是不够的，GUI 生成需要模型具备极强的**结构化理解能力**和**像素级精确控制能力**。

### 可能的研究方向
1.  **Layout-Guided Generation**：结合更强的布局控制算法，强制模型遵守 GUI 的网格结构。
2.  **Text Encoder 的优化**：针对 GUI 中的文本和图标进行专项优化，解决渲染乱码问题。
3.  **交互一致性建模**：引入 RNN 或 Transformer 机制，专门处理长序列的状态记忆问题。

在 **High**。它开辟了一个新的评估子领域，将生成模型的评估从“美学”推向了“逻辑功能性”。

## 研究最佳实践

## 最佳实践指南

### 实践 1：构建基于渲染的确定性评估环境

**说明**:
传统的图像生成评估依赖静态数据集（如 ImageNet），忽略了生成内容作为交互环境的潜力。GEBench 的核心在于将图像生成模型视为可渲染的 GUI 环境。最佳实践要求开发者放弃仅对生成图像进行像素级对比的做法，转而构建一个基于渲染引擎的评估框架。该框架应能接收生成模型的输出（如布局、分割图或直接渲染的 RGB 图像），并将其转换为可交互的场景，以测试视觉-语言模型（VLM）或智能体在生成环境中的感知与推理能力。

**实施步骤**:
1. 定义环境接口：建立一套标准接口，将生成模型的输出（如语义分割图、深度图）映射为模拟环境中的对象属性。
2. 集成渲染引擎：集成轻量级渲染器（如 PyGame 或基于 Web 的渲染引擎），将生成结果实时转换为可视化的 GUI 界面。
3. 状态管理：实现环境状态管理，确保生成的图像不仅是静态展示，而是包含可交互对象（如按钮、图标）的动态状态。

**注意事项**:
- 确保渲染过程的确定性，以便在复现实验时，生成模型输出的微小变化能被准确捕捉。
- 避免过度依赖复杂的物理引擎，重点应放在视觉元素的逻辑交互上，而非物理仿真。

---

### 实践 2：采用多模态大模型作为“裁判”

**说明**:
在评估生成的 GUI 环境时，人工标注成本高昂且主观性强。最佳实践是利用强大的多模态大模型（MLM）或视觉-语言模型（VLM）作为自动化评估器。这些模型能够“看”到生成的界面，并根据自然语言指令判断界面是否符合功能要求、布局是否合理以及元素是否对齐。这种方法比传统的 FID 或 CLIP 分数更能反映生成内容的可用性和语义一致性。

**实施步骤**:
1. 选择基座模型：选用当前性能领先的闭源（如 GPT-4o）或开源（如 LLaVA）VLM 作为评估基座。
2. 设计评估提示词：构建详细的 Prompt 模板，指导模型从视觉保真度、文本可读性和布局逻辑性三个维度进行打分。
3. 结果校准：使用少量人工标注的“黄金标准”数据集，校准 VLM 的打分尺度，确保其与人类判断具有高度相关性。

**注意事项**:
- 注意 VLM 可能存在的幻觉问题，对于具体的文本识别错误，应结合 OCR 工具进行二次验证。
- 定期更新评估模型，以利用最新 VLM 的视觉理解能力。

---

### 实践 3：实施分层级的评估指标体系

**说明**:
单一的分数无法全面衡量 GUI 生成质量。GEBench 强调分层级评估，将指标分为像素级、感知级和功能级。最佳实践是建立一套金字塔式的指标体系：底层关注图像质量和文本清晰度（OCR 准确率），中层关注视觉美学和布局合理性，顶层关注功能正确性（如生成的按钮是否在正确的位置）。这种分层能帮助开发者精准定位模型的短板。

**实施步骤**:
1. 定义层级指标：明确 Level 1（像素/文本）、Level 2（感知/布局）、Level 3（功能/交互）的具体计算方式。
2. 自动化流水线：建立自动化流水线，依次运行 OCR 检测、CLIP 相似度计算和 VLM 逻辑验证。
3. 综合报告：生成可视化报告，展示模型在不同层级上的表现雷达图，而非单一的标量分数。

**注意事项**:
- 不同层级的指标可能存在冲突（例如，高保真度可能牺牲功能性），需要根据应用场景设定权重。
- 确保层级间的依赖关系正确（例如，只有文本可读，才能评估功能正确性）。

---

### 实践 4：建立可控的文本到图像生成工作流

**说明**:
GEBench 涉及将文本指令（如“创建一个包含登录按钮的窗口”）转化为图像。最佳实践要求优化生成工作流，以提高模型对复杂空间指令的遵循能力。这不仅仅是提示词工程，还包括对生成模型进行微调或使用 ControlNet 等结构化控制工具，以确保生成的 GUI 元素位置精确、文本渲染准确。

**实施步骤**:
1. 指令结构化：将自然语言指令解析为结构化的数据格式（如 JSON），明确指定元素类型、位置和属性。
2. 条件生成控制：引入 ControlNet 或 T2I-Adapter 等工具，利用边缘检测、深度图或分割图来约束生成过程，确保布局不崩坏。
3. 迭代优化：建立反馈循环，如果 VLM 评估发现布局错误，自动调整输入的 ControlNet 条件或提示词进行重绘。

**注意事项**:
- 文本渲染是当前扩散模型的弱项，建议在生成后引入专门的文本修正模块或通过字体叠加技术优化。
- 控制信号的强度需要仔细调整，以免过度约束导致生成内容缺乏多样性。

## 学习要点

- GEBench 是首个将图像生成模型评估视为图形用户界面（GUI）环境交互任务的创新基准，旨在解决传统静态评估方法无法捕捉模型动态推理能力的问题。
- 该基准通过模拟真实用户与 AI 绘图软件的交互流程，构建了包含 450 个高质量提示词、多轮对话及迭代编辑的自动化测试数据集。
- 提出了一套基于视觉语言模型（VLM）的自动化评估框架，能够从指令遵循、视觉质量和编辑保真度三个维度对生成结果进行细粒度打分。
- 研究揭示了当前最先进的图像生成模型（如 DALL-E 3 和 Stable Diffusion）在处理复杂、多轮 GUI 交互指令时仍存在显著性能瓶颈，尤其是在局部编辑指令上表现不佳。
- 通过引入 GUI 交互范式，该工作为未来开发具备更强指令遵循能力和动态交互性的下一代智能绘图代理奠定了重要的数据与评估基础。

## 常见问题


### 1: GEBench 的核心定义是什么，它与传统的图像生成基准测试有何不同？

1: GEBench 的核心定义是什么，它与传统的图像生成基准测试有何不同？

**A**: GEBench（GUI Environment Benchmark）是一个用于评估图像生成模型在图形用户界面（GUI）环境下表现的基准测试。传统的图像生成基准测试（如 COCO）主要关注生成图像的保真度（Fidelity）和文本-图像对齐度，即评估图像的质量及其与文字描述的匹配程度。

GEBench 的不同之处在于引入了“交互性”和“环境”的概念。它不再将模型仅视为静态内容生成工具，而是将其作为用户可以通过自然语言指令进行交互的“环境”。在该基准测试中，用户指令不仅是描述图像内容，而是类似于操作软件界面的命令（例如“点击按钮”、“移动窗口”）。GEBench 旨在评估模型遵循复杂指令、保持多轮交互中状态一致性以及理解 GUI 逻辑的能力。

---



### 2: GEBench 主要评估图像生成模型的哪些具体能力？

2: GEBench 主要评估图像生成模型的哪些具体能力？

**A**: GEBench 主要关注以下三个维度的能力：

1.  **指令遵循与布局控制**：评估模型根据具体指令（涉及空间位置、物体属性修改）精确修改图像内容的能力。例如，用户要求“将左上角的图标移到右下角”时，模型能否准确执行这一空间变换。
2.  **多轮对话与状态一致性**：这是 GEBench 的评估重点。在多轮交互中，模型必须基于上一轮生成的图像状态进行修改，而不是每次都重新生成一张全新的图像。这要求模型具备处理上下文信息的能力。
3.  **GUI 逻辑与语义理解**：评估模型是否理解基本的 GUI 元素（如按钮、窗口、菜单）及其功能。例如，当用户发出“关闭弹窗”指令时，模型应移除弹窗元素，而非随机改变图像颜色。

---



### 3: GEBench 数据集是如何构建的，包含什么样的数据？

3: GEBench 数据集是如何构建的，包含什么样的数据？

**A**: GEBench 的数据构建通常基于现有的 GUI 截图或合成界面，主要包含以下几类数据：

1.  **初始状态图像**：一系列作为交互起点的 GUI 界面截图。
2.  **成对的指令与目标**：对于每个初始状态，数据集提供了一系列指令以及对应的理想输出结果。这些指令通常涉及编辑操作（添加/删除元素）、移动操作（改变布局）和属性修改（改变颜色/大小）。
3.  **多轮对话历史**：为了测试状态一致性，数据集中包含了模拟用户工作流的对话序列。每一轮的输入都依赖于上一轮的输出，用于测试模型基于历史上下文进行生成的能力。

---



### 4: GEBench 使用什么指标来评估模型的性能？

4: GEBench 使用什么指标来评估模型的性能？

**A**: 由于传统的图像生成指标（如 FID）难以准确衡量“指令遵循”和“部分修改”的准确性，GEBench 通常采用以下评估方式：

1.  **视觉问答（VQA）模型辅助评估**：利用视觉大模型（如 GPT-4V）作为裁判。向 VQA 模型展示生成的图像和原始指令，通过问答形式判断指令是否被正确执行（例如：“图标是否移动到了右下角？”）。
2.  **像素级/特征级相似度**：计算生成图像与 Ground Truth 在特定区域的相似度，但这通常作为辅助指标，因为 GUI 生成允许一定的非关键区域视觉差异。
3.  **成功率**：统计在多轮交互中，模型能够完全符合所有指令并保持环境稳定的比例。

---



### 5: 现有的主流图像生成模型（如 Midjourney, DALL-E 3, Stable Diffusion）在 GEBench 上的表现如何？

5: 现有的主流图像生成模型（如 Midjourney, DALL-E 3, Stable Diffusion）在 GEBench 上的表现如何？

**A**: 根据相关研究显示，现有的主流模型在 GEBench 上面临挑战，表现存在局限性。主要问题包括：

1.  **缺乏状态记忆**：大多数模型（如 SDXL 或 Midjourney）是无状态的。在多轮交互中，如果用户只说“把那个按钮变红”，模型往往无法定位到上一轮生成图像中具体的目标位置，导致生成随机图像或无法定位目标。
2.  **指令执行不精确**：模型在处理复杂的空间和逻辑指令时（如精确的像素级移动或层级关系调整），容易出现执行偏差或错误的修改。
3.  **过度重绘**：当用户要求修改局部时，模型倾向于重绘整个图像，导致未修改部分的细节发生变化，破坏了 GUI 环境的稳定性。
