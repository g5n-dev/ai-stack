## 核心结论

这是一个面向前端开发者的 Chrome 调试辅助插件，通过在页面运行时自动捕获控制台报错，将错误信息、堆栈、页面上下文组装为结构化提问供 AI 诊断。代码量约 400 行，核心解决手动复制报错信息效率低、提问质量差的问题。插件使用 Shadow DOM 隔离 UI 样式，通过 background service worker 转发 AI 请求以绕过 CORS 限制。

## 能力机制

插件捕获四类信号：console.error、console.warn、未捕获异常、Promise rejection。每条报错提供三个操作：生成结构化提问并复制、展开完整堆栈、直连 AI 诊断。

生成的结构化提问包含错误信息、调用堆栈、页面 URL、报错类型、触发次数及合并状态。AI 直连诊断通过 background service worker 转发请求，避免 content script 直接 fetch 被页面 CORS 拦截。

去重机制基于报错级别和内容，相同报错合并为一条，触发次数累加。路由变化监听通过注入脚本劫持 history.pushState 和 history.replaceState 实现，面板检测到 URL 变化后自动清空列表。

UI 整体置于 Shadow DOM，避免污染页面样式；悬浮徽章显示总触发次数，支持拖拽定位并记忆位置。

## 快速开始

配置清单：在 manifest.json 的 content_scripts 中声明 `world: "MAIN"` 使脚本运行在页面主环境，声明 `run_at: "document_start"` 确保尽早注入。

AI 直连诊断：打开面板的「API 设置」，填写 OpenAI 兼容接口的 base 地址、key、model 三个字段，保存后即可对任意报错使用「AI 直连诊断」。

## 适用边界

该工具定位为开发阶段辅助，不适用于生产环境监控。四类场景提问模板可参考插件内置速查表：TypeError 类询问数据链断裂位置、Promise rejection 类询问缺失的 catch、跨域类询问后端配置与预检问题、React 重渲染类询问 state 与 effect 依赖。

作者建议积累报错后可用于完善 ESLint 规则、单元测试覆盖和 CI 检查，将单次报错转化为防御性改进机会。

## 核验清单

内容脚本需正确配置 `world: "MAIN"` 才能捕获页面 console 输出。堆栈截断上限需设置充足，建议不低于 6000 字符。内容去重逻辑需同时匹配报错级别与具体内容。路由变化监听需在注入脚本中劫持原生 history 方法而非在 content script 中监听。AI 请求需经 background service worker 转发，content script 直接 fetch 会触发 CORS 拦截。面板使用 display: flex 布局时，hidden 属性可能失效，需额外强制规则。
