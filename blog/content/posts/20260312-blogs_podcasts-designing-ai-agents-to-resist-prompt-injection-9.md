## 摘要

**核心概念：提示注入与社会工程学**
*   **提示注入**：攻击者通过精心设计的输入（如恶意指令），试图绕过AI的原始设定，使其执行非预期的操作。
*   **社会工程学**：攻击者通过欺骗手段（如伪装身份或制造紧迫感），诱骗AI泄露敏感信息或执行有害任务。

**ChatGPT 的防御策略**

为了确保AI智能体的安全，ChatGPT采取了多层防御措施，主要集中在以下两个方面：

1.  **约束危险行为**
    *   **权限控制与沙箱机制**：严格限制智能体的操作权限，将其置于隔离的“沙箱”环境中运行。这防止了智能体执行对系统有害的命令（如删除文件或修改核心配置）。
    *   **工具使用限制**：仅允许智能体访问完成任务所必需的最小工具集，避免滥用高风险功能。
    *   **输入与输出过滤**：对用户输入和模型输出进行实时监控，识别并拦截潜在的恶意指令或代码注入。

2.  **保护敏感数据**
    *   **数据隔离**：确保智能体在工作流中处理的数据（如用户隐私信息、机密文档）与外部环境严格隔离，防止被恶意提示提取。
    *   **上下文窗口管理**：防止攻击者通过“越狱”或特定的提示技巧，从智能体的长期记忆或上下文窗口中窃取系统提示词或训练数据中的敏感信息。
    *   **最小化数据暴露**：智能体仅被授予访问特定数据的权限，而非全面的数据库访问权，从而减少潜在的数据泄露风险。

**总结**
设计安全的AI智能体需要建立“深度防御”体系。通过在架构层面实施严格的权限隔离、过滤机制以及数据保护策略，ChatGPT能够有效抵御外部攻击，确保智能体在执行复杂任务时的安全性与可靠性。

# 技术分析：设计抗注入攻击的 AI 智能体

## 1. 核心观点

文章主张在构建自主 AI 智能体时，必须通过系统架构层面的工程约束来保障安全性，而非依赖大语言模型（LLM）自身的对齐能力。核心设计理念是将高风险操作（如系统指令执行、数据修改）与用户输入进行逻辑解耦，并引入严格的权限隔离机制。这种架构旨在从根本上防御提示注入和社会工程学攻击，确保智能体在处理不可信输入时不会执行非预期动作。

## 2. 关键技术要点

### 2.1 基础概念
-   **提示注入**：攻击者通过输入特定的恶意指令（如“忽略之前的指令...”），试图劫持模型控制权。
-   **权限隔离**：将模型推理环境与实际执行环境分离，限制模型的操作范围。
-   **人机协作审查**：在执行不可逆操作前，引入人工确认环节。

### 2.2 实现原理
1.  **指令与数据分离**
    -   **原理**：在底层上下文中物理隔离开发者指令与用户内容，防止模型混淆指令边界。
    -   **实现**：利用特定的标记结构（如 XML 标签）包裹系统指令，强制模型区分“元指令”和“数据”。

2.  **工具调用的间接化**
    -   **原理**：LLM 不直接生成可执行代码（如 SQL 或 Shell），而是输出结构化的中间表示（如函数调用签名）。
    -   **实现**：构建中间解析层。LLM 输出类似 `search_web(query="...")` 的指令，后端代码负责参数校验与实际执行。LLM 仅接收执行结果，不直接持有数据库连接句柄。

3.  **上下文隔离与清洗**
    -   **原理**：对外部输入（如网页内容、文件）进行预处理。
    -   **实现**：在将外部内容注入模型前，标记其为“不可信来源”，并指示模型仅提取信息，禁止执行其中的指令。

### 2.3 防御难点与对策
-   **难点**：复杂的逻辑陷阱和角色扮演（“越狱”）可能绕过基于规则的防御。
-   **对策**：实施**二次确认机制**。对于高风险操作（如发送邮件、删除文件），系统强制要求必须经过人类用户的确认才能执行。此外，可要求模型在执行前进行“自我批判”，以核对行为是否符合安全策略。

### 2.4 架构创新
-   **沙箱执行环境**：类似代码解释器的设计，将代码执行限制在隔离的临时容器中。即使 LLM 生成了恶意代码，也无法逃逸至宿主服务器或访问未授权数据。
-   **最小权限原则**：智能体仅被授予完成特定任务所需的最小数据访问权限，而非拥有整个系统的 Root 权限。

## 最佳实践指南

### 实践 1：严格的输入验证与清洗

**说明**:
这是防御提示注入的第一道防线。所有来自用户或外部来源的输入（包括文本、文件、URL）都应被视为不可信的。清洗过程旨在识别并移除可能试图操纵模型行为的恶意字符或模式，例如系统指令覆盖标记或特定的分隔符。

**实施步骤**:
1. 建立允许字符和格式的白名单，严格限制输入长度。
2. 扫描并过滤常见的提示注入模式（如 "Ignore previous instructions" 或 "###" 等分隔符）。
3. 对输入进行编码或转义，防止特殊字符被解释为代码或指令。

**注意事项**:
不要仅依赖黑名单过滤，因为攻击者可以通过同音词、隐形字符或混淆技术绕过规则。应结合白名单机制使用。

### 实践 2：利用人机交互回路

**说明**:
对于高风险操作（如发送电子邮件、删除数据、执行交易），不要完全依赖 AI 的自主判断。引入人工审核环节，确保 AI 生成的内容或执行的操作在最终生效前经过人类管理员的确认。

**实施步骤**:
1. 识别系统中的“关键操作”，并为这些操作配置人工审批流程。
2. 在 AI 生成响应后，向用户或管理员展示摘要，并要求明确授权（如点击按钮）。
3. 记录所有未执行的敏感操作请求，用于后续的安全审计。

**注意事项**:
避免设计成“自动批准”的交互模式。如果用户过于频繁地批准请求，可能会产生“自动点击”习惯，从而降低安全性。

### 实践 3：实施特权通道分离

**说明**:
将系统指令与用户输入通过不同的通道或 API 参数传递。现代大模型通常支持区分“系统消息”和“用户消息”。系统消息应具有更高的优先级，且模型应被训练为优先遵循系统消息，即使被用户指令明确要求覆盖。

**实施步骤**:
1. 在 API 调用中，将核心角色定义和行为规则放在 System 参数中，而不是拼接到 User 参数中。
2. 明确告知模型区分开发者指令和用户输入的界限。
3. 定期测试模型是否严格遵守 System 消息的层级，防止被越狱。

**注意事项**:
并非所有模型都能完美遵守这种分离，因此这必须与其他防御措施（如输出过滤）结合使用。

### 实践 4：输出语义分析与过滤

**说明**:
不仅要在输入端设防，还要在输出端进行检测。使用辅助模型或规则集来分析 AI 的最终响应，判断其是否包含被攻击者诱导生成的有害内容、泄露的敏感信息或非预期的指令执行结果。

**实施步骤**:
1. 在最终响应返回给用户之前，通过一个轻量级分类器进行扫描。
2. 检查输出是否包含内部系统提示词的泄露或格式异常。
3. 如果检测到异常输出，立即阻断并返回通用的错误信息，避免泄露具体的过滤原因。

**注意事项**:
输出检测可能会增加延迟。对于实时性要求极高的应用，需在安全性和性能之间寻找平衡。

### 实践 5：限制工具与函数的访问权限

**说明**:
如果 AI Agent 具备调用外部工具（如数据库、API、文件系统）的能力，必须实施最小权限原则。攻击者通过提示注入可能会试图调用这些工具来执行恶意操作，因此必须严格限制工具的参数和范围。

**实施步骤**:
1. 为 AI Agent 分配专用的 IAM 角色，仅授予完成任务所必需的最小权限。
2. 在函数调用层面增加参数校验，例如限制 SQL 查询只能为 SELECT 语句，或限制 URL 必须为特定域名。
3. 禁止或限制执行任意代码或系统命令的工具访问。

**注意事项**:
不要依赖 AI 自行生成安全的参数（如“只查询安全的数据”），必须在代码层面强制执行权限检查。
