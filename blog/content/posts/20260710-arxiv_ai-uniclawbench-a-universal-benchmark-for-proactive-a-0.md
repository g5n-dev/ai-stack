## 导语

现有代理评估基准多在沙箱或单一任务设定下进行，能力混杂导致失败根因难以定位。本文提出 UniClawBench，围绕技能使用、探索、长上下文推理、多模态理解与跨平台协调五项核心能力构建 400 条双语真实任务，并在实时 Docker 环境中实现闭环评估，旨在分离基座模型与框架设计的贡献。基准代码与数据已公开，可为后续代理系统研发提供统一、可复现的评测平台。

## 摘要

#### 背景
随着大语言模型和多模态模型的快速发展，出现能够在日常工具和真实环境中主动帮助用户的代理系统。现有基准多在沙箱环境、单一任务、单轮评价下进行，且任务分类混合多种能力，难以定位失败根因。

#### UniClawBench 目标
构建首个能力驱动的基准，用于评估在动态真实场景中的主动代理。

#### 核心能力
围绕五项基础能力设计：① 技能使用；② 探索；③ 长上下文推理；④ 多模态理解；⑤ 跨平台协调。

#### 任务规模
基于上述能力设计 400 条双语（中文‑英文）真实任务，覆盖多种日常操作场景。

#### 评估方式
- 在实时 Docker 容器中运行代理，获取细粒度、逐步完成检查点，而非静态答案。
- 采用闭环评估策略：执行代理（完成任务），隐藏监督代理（检查进度），用户代理（模拟多轮人类反馈），保证评分标准不泄露。

#### 模型‑框架解耦
在多种代理框架下对当前最先进的模型进行统一评估，以分离基座模型能力与框架设计对性能的影响。

#### 开放资源
基准、代码已公开于 GitHub，方便后续研究。

- **缺乏闭环反馈**：传统评测依赖人工打分或一次性答案，无法模拟用户在多轮交互中的真实反馈。

##### 本文定位
- **目标**：提出首个能力驱动的通用基准 **UniClawBench**，在真实 Docker 容器中评估代理的主动性与多能力协同。

#### 核心方法
##### 能力驱动的任务设计
1. **技能使用**：代理需调用预定义工具或 API 完成子目标。

3. **长上下文推理**：跨越多轮交互记忆关键状态。

5. **跨平台协调**：在多个应用或系统之间切换与同步。

##### 评估框架
- **实时 Docker 容器**：代理在真实系统上执行，保证行为与实际环境一致。
- **细粒度检查点**：记录每一步的状态转换，便于定位错误来源。
- **闭环评估**：
  - **执行代理**：完成任务；
  - **隐藏监督代理**：检查进度并提供内部反馈；
  - **用户代理**：模拟人类用户的自然语言回复。

#### 理论基础
- **主动代理理论**：代理在不确定环境中需具备**感知‑规划‑执行‑反馈**循环。

#### 关键假设、潜在失效条件与可证伪方式
- **关键假设**
  1. Docker 环境能够完整模拟真实日常工具的行为。
  2. 隐藏监督代理的反馈能够近似人类用户的真实满意度。
  3. 双语任务的质量足够平衡，不偏向某一语言。

- **潜在失效条件**
  - **环境不匹配**：若真实系统的 API 或 UI 与 Docker 镜像不一致，评估结果将失效。
  - **监督代理偏差**：若隐藏监督代理的检查逻辑不够鲁棒，可能误判成功/失败。
  - **任务设计偏差**：任务覆盖可能仍不足以代表所有真实场景（如高频异常处理）。

- **可证伪方式**
  - **交叉平台验证**：在同一批任务上部署到真实云服务器或实体设备，比较完成率差异。
  - **人工评审**：邀请人类用户在相同任务上与代理对比，检验用户代理的满意度预测是否可信。
  - **语言平衡实验**：使用机器翻译与原生语言并行任务，检验语言差异对性能的影响。
