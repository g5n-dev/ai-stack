# 示例 1：使用 Gemini 进行智能文本摘要
# 解决问题：自动提取长文章的核心观点，节省阅读时间
import google.generativeai as genai

def summarize_article(api_key, article_text):
    """
    使用 Gemini API 对长文本进行摘要
    :param api_key: 你的 Google API 密钥
    :param article_text: 需要摘要的文章内容
    :return: 摘要后的文本
    """
    genai.configure(api_key=api_key)
    model = genai.GenerativeModel('gemini-2.0-flash-exp')
    
    prompt = f"请将以下文章内容总结为一段简短的中文摘要（不超过100字）：\n\n{article_text}"
    
    try:
        response = model.generate_content(prompt)
        return response.text
    except Exception as e:
        return f"生成摘要时出错: {e}"

import google.generativeai as genai

def chat_bot_interaction(api_key, user_message, chat_history=None):
    """
    进行具有上下文记忆的多轮对话
    :param api_key: 你的 Google API 密钥
    :param user_message: 用户当前输入的消息
    :param chat_history: 之前的对话历史列表
    :return: (模型回复, 更新后的历史记录)
    """
    genai.configure(api_key=api_key)
    model = genai.GenerativeModel('gemini-2.0-flash-exp')
    
    if chat_history is None:
        chat_history = []

    convo = model.start_chat(history=chat_history)
    response = convo.send_message(user_message)
    
    return response.text, convo.history

### 1：初创公司构建智能客户支持系统

 1：初创公司构建智能客户支持系统

**背景**:
一家处于快速扩张期的 SaaS 初创公司，其用户群随着产品功能的增加而迅速扩大。然而，由于缺乏足够的人力资源，客服团队面临着巨大的压力，无法及时响应所有用户的咨询，尤其是在非工作时间。

**问题**:
传统的客服机器人只能处理简单的关键词匹配，经常无法理解用户的真实意图，导致转人工率高，响应时间长。此外，整理用户反馈并将其转化为产品改进意见的过程完全依赖人工，效率低下且容易遗漏关键信息。

**解决方案**:
利用 Gemini 3.1 Pro 的长上下文理解和多模态能力，构建了一个新一代的智能客服助手。该助手不仅能够阅读和理解公司长达数百页的复杂技术文档，还能根据用户上传的截图或错误日志进行综合分析，直接给出解决方案或代码修复建议。

**效果**:
客服团队的工单处理量减少了 60%，因为大部分常见和中级的技术问题现在由 AI 准确解决。同时，系统自动将用户对话中的痛点提炼成结构化的产品反馈报告，帮助产品团队每周节省约 10 小时的会议整理时间，极大地提升了产品迭代的速度。

## 最佳实践指南

### 实践 1：采用结构化提示词工程


**实施步骤**：
1.  **定义角色**：明确 AI 的身份（例如：“你是一位资深的 Python 架构师”）。
2.  **明确任务**：清晰描述需要完成的具体工作。
3.  **设定约束**：列出禁止或必须包含的内容（例如：“不要使用任何外部库”）。
4.  **指定格式**：规定输出的结构（例如：“请以 Markdown 表格形式输出”）。

**注意事项**：保持逻辑层级清晰，避免指令过于冗长导致重点分散。

---

### 实践 2：实施思维链引导

**说明**：对于复杂的逻辑推理或代码生成任务，直接要求结果可能导致模型产生“幻觉”。引导模型展示中间推理步骤，可以有效提高最终结果的正确率。

**实施步骤**：
1.  在提示词中添加“请一步步思考”或“让我们逐步分析这个问题”。
2.  要求模型在给出最终答案前，先列出关键假设或推导过程。
3.  对于代码任务，要求先解释算法逻辑再生成代码。

**注意事项**：思维链会消耗更多的输出 Token，需在成本和精度之间取得平衡。

---

### 实践 3：利用系统指令进行行为固化

**说明**：利用 Gemini API 的 `system_instruction` 功能，将核心的安全边界、风格指南或角色定义与用户提示词分离，可以确保在整个对话 Session 中保持一致性，并增强对“越狱”尝试的防御能力。

**实施步骤**：
1.  将“安全策略”和“回复风格”写入 `system_instruction` 参数。
2.  确保系统指令简明扼要，优先级高于用户指令。
3.  在多轮对话中，保持系统指令不变，仅更新 User 和 Model 内容。

**注意事项**：系统指令并非绝对物理隔离，仍需通过测试验证其对诱导性指令的防御能力。

---

### 实践 4：配置合理的生成参数

**说明**：针对特定任务调整 `temperature`、`top_p` 和 `top_k` 等参数至关重要。不同的温度设定对模型的创造性和稳定性影响明显。

**实施步骤**：
1.  **创意/发散性任务**：将 `temperature` 设置在 0.7 - 1.0 之间。
2.  **代码/逻辑/精确提取任务**：将 `temperature` 设置为 0 - 0.3，以确保结果的一致性。
3.  调整 `max_output_tokens` 以确保模型有足够的空间完成长文本生成，避免截断。

**注意事项**：极低的温度可能导致模型输出过于死板或陷入重复循环。

---

### 实践 5：建立检索增强生成 (RAG) 机制

**说明**：尽管 Gemini 3.1 Pro 拥有较大的上下文窗口，但通过 RAG 技术将外部最新或私有文档作为上下文传入，可以极大减少幻觉，提高回答的可信度。

**实施步骤**：
1.  将外部知识库切分为合适的文本块。
2.  根据用户查询检索最相关的 Top-K 文本块。
3.  将检索到的内容填充到提示词的“上下文”部分，并明确指示模型“仅依据以下提供的上下文回答”。

**注意事项**：必须明确指示模型如果上下文中没有答案，应回答“不知道”，而不是编造答案。

---

### 实践 6：应用 JSON 模式进行结构化输出

**说明**：利用 API 的 JSON 模式约束，可以强制模型输出符合特定 Schema 的 JSON 对象，从而省去繁琐的后续文本清洗工作，便于直接集成到程序逻辑中。

**实施步骤**：
1.  定义清晰的 JSON Schema（包含字段名、类型、嵌套结构）。
2.  在 API 调用中声明 `response_mime_type` 为 `application/json`。
3.  在提示词中提供 JSON 示例或详细的 Schema 定义。

**注意事项**：复杂的嵌套 Schema 可能会导致模型偶尔出错，建议在后端增加 JSON 校验和重试机制。

---

### 实践 7：多模态输入的预处理与对齐

**说明**：Gemini 3.1 Pro 原生支持多模态输入（文本、图像、音频、视频）。为了获得最佳分析效果，需要对非文本输入进行适当的预处理和对齐。

**实施步骤**：
1.  **图像处理**：对于高分辨率图像，考虑先进行压缩或裁剪以突出重点区域，减少 Token 消耗。
