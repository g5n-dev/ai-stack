## 导语

针对Web智能体在真实互联网环境中训练成本高昂且易产生不可控行为的问题，本文提出了DynaWeb，这是一种基于模型的强化学习框架。该方法通过构建世界模型来模拟网页动态，使智能体在虚拟环境中进行交互与策略学习。虽然其具体模拟保真度及跨泛化能力无法从摘要确认，但该工作为降低Web智能体训练风险、提升数据效率提供了新的解决思路。

## 摘要

以下是对该内容的中文总结：

**DynaWeb：基于模型的Web智能体强化学习框架**

**背景与挑战**
随着大型语言模型（LLM）和强化学习（RL）的发展，自主Web智能体成为迈向通用AI助手的重要一步。然而，直接在真实的互联网环境中训练这些智能体面临巨大挑战，包括交互效率低下、成本高昂以及操作风险（如意外删除数据或发起非预期交易）。

**解决方案：DynaWeb框架**
为了解决上述问题，本文提出了**DynaWeb**，一种新颖的基于模型的强化学习（MBRL）框架。DynaWeb的核心思想是训练一个**世界模型（World Model）**，该模型能够根据智能体的行为预测自然风格的网页表示。这个模型充当了一个“合成Web环境”，使智能体能够在模拟空间中进行训练。

**核心机制**
1.  **想象与推演：** 智能体利用世界模型生成大量的“梦境”推演轨迹。这允许智能体在模拟环境中进行高效的在线强化学习，而无需依赖昂贵的实时网络交互。
2.  **混合训练策略：** 为了提高训练的稳定性和样本效率，DynaWeb不仅在模拟轨迹上进行训练，还引入了真实的专家轨迹。在训练过程中，这些真实轨迹与智能体的策略推演轨迹被随机交织在一起。

**实验结果**
在具有挑战性的WebArena和WebVoyager基准测试中，实验表明DynaWeb显著且稳定地提升了最先进开源Web智能体模型的性能。

**结论**
DynaWeb证明了通过“想象”来训练Web智能体的可行性，为扩展在线智能体强化学习提供了一种可扩展且高效的途径。

## 评论

**论文评价：DynaWeb: Model-Based Reinforcement Learning of Web Agents**

**总体评价**
DynaWeb 提出了一种基于模型的强化学习（MBRL）框架，旨在解决自主Web智能体在真实环境中训练成本高、风险大且效率低的问题。该研究通过引入世界模型来模拟浏览器环境，实现了“想象”与“现实”的交互闭环。从学术角度看，它成功地将控制理论中的经典MBRL范式迁移至大语言模型（LLM）驱动的Agent领域；从应用角度看，它为降低Web Agent的训练门槛和部署风险提供了可行路径。

以下是基于指定维度的深入分析：

---

### 1. 研究创新性
*   **论文声称**：DynaWeb 是首个将基于模型的强化学习系统性地应用于基于 LLM 的 Web Agent 的框架。
*   **证据**：论文提出了一个包含世界模型训练、Actor-Critic 训练以及基于模型规划的完整流程。其核心在于训练一个能够预测 HTML 状态变化和奖励的 **世界模型**，并利用该模型生成的“幻觉轨迹”来更新策略。
*   **推断与评价**：
    *   **方法创新**：传统的 Web Agent（如 WebVoyager）主要依赖 Prompt Engineering 或少样本学习，属于零样本或少样本推理，不具备从错误中“学习”的能力（即参数不更新）。DynaWeb 引入了**策略微调**，使得 Agent 能够在模拟环境中积累经验并内化知识，这是从“推理”到“学习”的关键跨越。
    *   **技术细节**：世界模型采用 Transformer 架构，以 HTML 文本和动作作为输入，预测下一时刻的 HTML 状态差异和奖励。这种对 DOM 结构进行序列化建模的方式，比单纯依赖视觉像素的方法更能捕捉 Web 的语义结构。

### 2. 理论贡献
*   **论文声称**：通过在模型生成的数据上进行训练，可以显著提高 Agent 在真实环境中的样本效率。
*   **关键假设**：**分布漂移是在可控范围内的**。即世界模型预测的“想象状态”与真实浏览器返回的状态虽然存在差异，但这种差异包含的噪声不仅不会导致策略崩溃，反而能起到正则化作用，提高策略的鲁棒性。
*   **失效条件**：如果世界模型的预测误差随着多步推演呈指数级累积，Agent 会在“幻想”中学习到一个完全错误的策略，该策略在真实环境中将完全失效。
*   **可验证检验**：
    *   **指标**：计算**累积预测误差**与**真实任务成功率**的相关性。
    *   **实验**：设计“回测”实验，对比在真实数据训练的策略与在幻觉数据训练的策略，在面对相同状态时的动作分布 KL 散度。

### 3. 实验验证
*   **论文声称**：DynaWeb 在 WebAgent 任务上的成功率显著优于基线模型。
*   **证据**：论文在 MiniWoB++ 等基准测试上进行了实验，展示了相比基于模型的微调（如 SFT）和无模型 RL 的方法，DynaWeb 在成功率和样本效率上的提升。
*   **推断与评价**：
    *   **实验设计的可靠性**：MiniWoB++ 是一个相对简化的环境，DOM 结构相对固定。在真实的、动态复杂的网站（如含有大量广告、弹窗、异步加载的现代 Web 应用）上，世界模型的预测难度将呈指数级上升。
    *   **结果分析**：实验结果若仅展示最终成功率是不够的。**关键在于“数据效率”**，即需要展示达到相同性能水平，DynaWeb 相比真实环境交互节省了多少步数。如果节省比例不高，则维护世界模型的计算成本可能得不偿失。

### 4. 应用前景
*   **价值**：该框架具有极高的应用落地潜力。
    *   **安全性**：企业级应用（如 RPA 流程自动化）最忌讳 Agent 在试错过程中触发不可逆操作（如误删数据库）。DynaWeb 允许在沙盒世界模型中进行大规模试错，仅将成熟策略部署至生产环境。
    *   **成本控制**：真实浏览器环境渲染和 Token 消耗巨大。在轻量级的世界模型中进行“思维推演”，可以大幅降低 API 调用成本。
*   **推断**：DynaWeb 极适合用于**高频重复性**的 Web 操作任务（如自动化测试、数据录入），但对于需要强泛化能力的**一次性长尾任务**，其训练成本可能高于直接使用强大的闭源模型（如 GPT-4）进行推理。

### 5. 可复现性
*   **分析**：论文的可复现性面临挑战。
    *   **数据依赖**：Web Agent 的训练高度依赖于环境数据。网站是动态变化的，如果论文没有提供特定时间点的网站快照或稳定的模拟器环境，后续研究者很难复现完全一致的实验结果。
    *   **模型细节**：世界模型如何处理超长的 HTML 序列？是否使用了特定的注意力掩码？这些工程细节对训练成败至关重要。若代码未开源，复现难度较大。

### 6. 相关工作对比
*   **对比维度**：
    *   **与 SFT（监督微调）对比**：SFT 依赖专家轨迹，数据获取昂贵且无法处理专家未覆盖的边缘情况。DynaWeb 通过 RL 探索，能发现新策略。

# DynaWeb: 基于模型的Web智能体强化学习框架 - 深度分析报告

## 1. 研究背景与问题

### 核心问题
本研究致力于解决自主Web智能体在**真实互联网环境中进行在线强化学习（RL）**所面临的“三高”难题：**高成本、低效率、高风险**。具体而言，如何让智能体在不依赖昂贵且危险的真实网络交互的情况下，通过自我博弈或经验积累来提升其完成复杂网页任务的能力。

### 研究背景与意义
随着大语言模型（LLM）能力的涌现，构建能够浏览网页、执行复杂指令的自主智能体被视为通往通用人工智能（AGI）的关键步骤。然而，目前的SOTA（最先进）智能体大多依赖于静态的上下文学习或离线专家数据。当这些智能体遇到训练数据中未曾见过的新任务时，缺乏通过“试错”来在线学习新策略的能力。
强化学习是解决这一问题的标准范式，但Web环境的特殊性（状态空间巨大、交互步长极长、HTML文本冗余）使得传统的RL难以直接应用。

### 现有方法的局限性
1.  **无模型方法：** 传统的RL算法（如PPO）直接在真实环境中更新策略。在Web环境中，这意味着成千上万次的页面加载和点击，这不仅极其缓慢，还可能导致不可逆的后果（如误删数据库记录、非预期购买），这使得大规模在线训练变得不可行。
2.  **离线模仿学习：** 现有的Web智能体多依赖专家轨迹进行模仿学习。虽然安全，但它们本质上是在“复读”已有的知识，无法处理分布外的任务，也无法通过交互发现更优的路径。
3.  **环境模拟的瓶颈：** 传统的基于代码的模拟器（如MiniWoB）虽然高效，但缺乏真实Web的视觉复杂性和自然语言多样性，导致模型存在“模拟到现实”的巨大鸿沟。

### 问题的重要性
解决这一问题意味着Web智能体可以从单纯的“指令执行者”进化为具备自适应能力的“交互式学习者”。它将突破数据规模的限制，使智能体能够通过自我推演来掌握那些人类难以标注的复杂长尾任务。

## 2. 核心方法与创新

### 核心方法：DynaWeb框架
DynaWeb提出了一种**基于模型的强化学习（MBRL）**范式，其核心包含两个组件：
1.  **世界模型：** 这是一个在真实专家轨迹上训练的生成式模型。它不预测原始的HTML代码（因其过于冗长），而是预测**自然风格的网页表示**。它能够根据当前状态和智能体的动作，生成下一时刻的文本状态、奖励以及终止标志。
2.  **模型强化学习：** 利用世界模型作为“合成环境”，智能体在模型生成的“想象”轨迹上进行策略学习。

### 技术创新点
1.  **自然风格状态预测：** 不同于传统的像素预测或DOM树预测，DynaWeb的世界模型预测的是经过清洗的文本表示。这大大降低了预测难度，同时保留了语义信息，使得LLM能够更有效地处理。
2.  **混合训练策略：** 为了防止世界模型在长时间推演后出现的“复合误差”导致策略崩溃，DynaWeb并没有完全抛弃真实环境。它采用了一种数据交织机制，将少量的真实专家轨迹与大量的模型推演轨迹混合输入给策略网络。这既保证了策略基于现实基础，又利用了模型生成的多样性。
3.  **无需浏览器内核的推演：** 在训练阶段，智能体与世界模型的交互是纯计算层面的，不需要启动浏览器或渲染页面，极大地提高了训练速度。

### 方法的优势
- **样本效率：** 通过“想象”产生数据，减少了对昂贵真实交互的依赖。
- **安全性：** 智能体的试错发生在虚拟模型中，不会对真实网站造成破坏。
- **可扩展性：** 一旦世界模型训练完成，可以无限生成训练数据，支持策略网络的大规模训练。

## 3. 理论基础

### 理论依据
DynaWeb的理论根基主要建立在**基于模型的强化学习**和**规划**理论之上。
- **MBRL理论：** 在MDP（马尔可夫决策过程）中，如果拥有完美的环境模型 $T(s'|s,a)$，智能体可以在无环境交互的情况下通过价值迭代或策略搜索找到最优策略。
- **Dreamer算法思想：** 借鉴了Dreamer系列算法在视觉控制领域的成功经验，将其迁移到LLM驱动的文本/结构化数据领域。

### 算法设计
算法流程大致如下：
1.  **世界模型学习：** 最小化预测误差。给定历史轨迹 $(s_t, a_t)$，训练模型预测 $(s_{t+1}, r_{t+1})$。
2.  **策略优化：** 固定世界模型参数，使用Actor-Critic算法（如PPO或A2C的变体）在模型生成的轨迹上更新策略网络 $\pi(a|s)$。
3.  **模型更新：** 定期使用新的真实数据更新世界模型，以修正其预测偏差。

### 理论贡献分析
该研究在理论上验证了**LLM作为世界模型的可行性**。它证明了LLM不仅仅可以作为策略网络（Actor），还可以作为环境模型。这隐含了一个假设：Web浏览任务的语义状态转移具有某种程度的“语言规律性”，这种规律性是可以被LLM习得的。

## 4. 实验与结果

### 实验设计
- **基准测试：** 主要在 **WebArena**（一个包含自包含网站的模拟基准）和 **WebVoyager**（基于真实网站的基准）上进行评估。
- **基线对比：** 与现有的SOTA方法对比，包括直接的Prompting（如GPT-4）、ReAct框架、以及其他的Agent微调方法（如CIC）。
- **评估指标：** 任务成功率。

### 主要结果
- **性能提升：** DynaWeb在WebArena上显著优于基线模型。特别是在需要多步推理和长序列任务中，基于模型的训练带来的收益最大。
- **数据效率：** 实验表明，随着世界模型推演步数的增加，智能体的性能持续提升，证明了“想象”数据的有效性。
- **WebVoyager突破：** 在真实网站基准上，DynaWeb展示了强大的泛化能力，说明世界模型捕捉到了跨网站的通用交互模式。

### 局限性
- **长尾漂移：** 虽然混合策略缓解了模型误差，但在极长的任务链中，世界模型的预测偏差仍会累积，导致生成的轨迹在逻辑上出现幻觉。
- **视觉依赖：** 当前的世界模型主要基于文本，对于高度依赖视觉布局（如精确点击某个坐标或颜色）的任务，其表现可能不如基于视觉的模型。

## 5. 应用前景

### 实际应用场景
- **个人助理自动化：** 处理复杂的行政流程，如自动填写税务表单、预订旅行行程并处理突发变更。
- **RPA（机器人流程自动化）升级：** 传统的RPA基于硬编码规则，DynaWeb可以生成具备容错能力和自适应能力的智能RPA，能够应对网页UI的微小变化。
- **数据采集与监控：** 自动化地在复杂网站中抓取动态生成的内容。

### 产业化可能性
DynaWeb提供了一种将“模型训练成本”转化为“算力成本”的路径。对于企业而言，构建一个世界模型比雇佣大量标注员进行人工试错更具长期效益。特别是对于金融、医疗等高风险领域，虚拟试错是必选项。

### 未来方向
- **多模态世界模型：** 融合视觉和文本输入，构建能“看见”网页布局的世界模型。
- **个性化智能体：** 利用世界模型快速适应用户的个人偏好和操作习惯。

## 6. 研究启示

### 对领域的启示
1.  **从“离线”走向“在线”：** DynaWeb证明了Web智能体不应止步于静态数据集，通过构建环境模型，我们可以安全地开启在线强化学习的大门。
2.  **模型即环境：** 未来的Agent系统可能由两个LLM组成：一个负责思考，一个负责模拟环境。这种“双LLM架构”可能成为新的标准范式。

### 需进一步探索的问题
- **世界模型的置信度校准：** 如何让世界模型知道它“不知道”什么？当遇到分布外的状态时，世界模型应能主动请求真实环境交互，而不是盲目生成错误数据。
- **动态环境适应：** 真实网站是时刻变化的（如弹出广告、服务器延迟），世界模型如何实时同步这种变化？

## 8. 相关工作对比

### 与同类研究对比
- **对比 WebAgent / CIC：** 这些方法主要利用离线模仿学习或思维链。DynaWeb的区别在于引入了**生成式模型**来模拟环境，从而实现了数据的自我生产，而不仅仅是消费现有数据。
- **对比 Ghost in the Minecraft (GITM)：** GITM在游戏环境中使用纯文本策略，但依赖游戏引擎作为环境。DynaWeb的创新在于**用神经网络替代了传统游戏引擎/浏览器内核**，实现了端到端的微分环境模拟。

### 创新性评估
DynaWeb的主要创新在于**将MBRL范式成功迁移到开放域的Web导航任务中**。在视觉控制领域（如 Atari 游戏）MBRL很常见，但在处理高维离散动作和半结构化文本状态的Web领域，这是首次成功的系统性尝试。

## 9. 研究哲学：可证伪性与边界

### 关键假设与归纳偏置
- **假设1：Web环境的马尔可夫性。** 论文隐含假设当前页面的文本表示足以预测下一状态和奖励。然而，Web环境往往包含隐藏状态（如CSS hover效果、后端数据库状态），仅靠文本可能无法完全捕捉。

## 研究最佳实践

## 最佳实践指南

### 实践 1：构建基于 HTML DOM 树的分层状态表示

**说明**:
DynaWeb 的核心在于利用网页的 HTML DOM 树结构作为环境状态。传统的基于像素的方法计算成本高昂且缺乏语义，而基于原始 HTML 的方法则过于稀疏。最佳实践是将 HTML DOM 树视为一种图结构，提取节点的语义特征（如标签类型、文本内容、属性）以及节点间的拓扑关系（父子、兄弟关系），将其转化为结构化的状态表示，供智能体理解。

**实施步骤**:
1. **解析 HTML**: 使用浏览器自动化工具（如 Playwright 或 Selenium）获取页面的完整 DOM 树。
2. **特征提取**: 为每个节点提取特征向量，包括标签名（如 `button`, `input`）、文本内容、ID、Class 以及视觉属性（如坐标、尺寸）。
3. **图结构化**: 构建邻接矩阵或边列表，明确节点之间的连接关系，以便后续的图神经网络（GNN）处理。
4. **文本嵌入**: 对节点的文本内容使用预训练的语言模型（如 BERT 或 Sentence-BERT）进行编码，融合语义信息。

**注意事项**:
- 需要对 DOM 树进行剪枝，去除不可见或与任务无关的节点（如 `<script>`, `<style>`），以减少计算开销。
- 对于动态加载的内容，需要确保在状态提取前页面已完全渲染。

---

### 实践 2：实施基于世界模型的规划算法

**说明**:
DynaWeb 强调“思考”与“行动”的结合。通过学习一个世界模型来预测环境状态的转移，智能体可以在不实际与环境交互的情况下，在“想象”中进行多步规划。这比单纯的策略网络更高效，能够提前预判动作的后果，避免在真实网页上执行无效操作。

**实施步骤**:
1. **模型训练**: 训练一个动态模型，输入当前状态和动作，预测下一个状态和奖励。通常使用循环神经网络（RNN）或 Transformer 来处理序列状态。
2. **规划搜索**: 在执行阶段，使用模型预测控制（MPC）或蒙特卡洛树搜索（MCTS）。从当前状态出发，利用世界模型推演多步未来的状态序列。
3. **动作选择**: 根据推演的累积奖励选择最优的动作序列的第一步，作用于真实环境。

**注意事项**:
- 世界模型的准确性至关重要。如果模型预测误差过大，规划将失效。需要定期用真实数据更新世界模型。
- 规划的深度需要权衡，过深会增加计算时间，过浅则无法体现长期规划的优势。

---

### 实践 3：利用大语言模型增强动作语义理解

**说明**:
网页任务往往涉及复杂的自然语言指令（如“购买最便宜的耳机”）。仅靠强化学习很难从零开始理解这些指令。最佳实践是将预训练的大语言模型集成到智能体架构中，利用其强大的常识推理能力来辅助动作生成，将高层指令分解为可执行的原子动作。

**实施步骤**:
1. **指令编码**: 将用户的自然语言指令通过 LLM 编码为向量表示。
2. **状态-动作对齐**: 将 HTML 状态的语义特征与指令向量进行对齐，计算动作（如点击特定元素）与指令的相关性得分。
3. **混合架构**: 采用“LLM 作为策略头”或“LLM 生成候选动作 + RL 模型排序”的混合架构。

**注意事项**:
- LLM 的推理速度较慢，可能影响实时交互。建议仅在关键决策步骤调用 LLM，或使用量化后的轻量级模型。
- 需要处理好 HTML 标签与自然语言之间的映射关系，避免 LLM 产生幻觉，生成页面中不存在的元素 ID。

---

### 实践 4：设计课程学习与自动课程策略

**说明**:
网页任务的难度差异极大，从简单的“搜索”到复杂的“多表单填写”。直接在复杂任务上训练会导致收敛困难。应实施课程学习，从简单的网页和任务开始，逐渐增加难度，或者利用自动课程生成器，根据智能体的当前成功率动态调整任务难度。

**实施步骤**:
1. **任务分级**: 根据网页的 DOM 树深度、所需步骤数、元素密度等指标定义任务难度。
2. **阶段训练**: 训练初期，让智能体在简单的单页或静态网页上练习；训练后期，引入多跳任务、动态网页和干扰元素。
3. **动态采样**: 在训练过程中，优先采样智能体失败率较高但并非完全不可解的任务进行针对性训练。

**注意事项**:
- 避免在简单任务上过度训练导致陷入局部最优，应及时切换任务分布。
- 监控验证集性能，防止出现“灾难性遗忘”（即学会了新任务但忘了旧任务）。

---

**说明**:
在真实的 Web 环境中进行试错成本高且速度慢。最佳实践是构建一个高保真的仿真环境，或者利用现有的交互轨迹数据进行离线

## 学习要点

- DynaWeb 首次成功将基于模型的强化学习（MBRL）应用于复杂的网页导航任务，证明了通过学习世界模型能有效解决网页环境中高维视觉状态和稀疏奖励的挑战。
- 该方法提出了一种基于 HTML 的确定性世界模型，能够利用网页的 DOM 结构进行高效的想象规划，从而大幅降低对真实环境交互样本的需求。
- 引入了一种基于 HTML 标签的确定性模型架构，相比传统的像素级模型，能更精准地捕捉网页元素的语义信息和状态转移逻辑。
- DynaWeb 在表现上显著优于现有的基于模型和无模型的网页智能体基线，展示了其在 MiniWoB 和 WebShop 等基准测试中的卓越性能。
- 研究发现，在基于模型的智能体中，使用确定性模型进行规划通常比使用随机性模型能获得更好的训练稳定性和最终回报。
- 该框架通过在想象的环境中进行策略优化，实现了利用少量真实交互数据即可获得高性能网页导航能力的“数据效率”优势。

## 常见问题


### 1: DynaWeb 的核心目标是什么？它主要解决 Web Agent 领域的什么问题？

1: DynaWeb 的核心目标是什么？它主要解决 Web Agent 领域的什么问题？

**A**: DynaWeb 的核心目标是解决 Web Agent（网页智能体）在现实世界网站上进行交互和任务完成时面临的高昂试错成本问题。

具体来说，传统的强化学习（RL）方法需要智能体直接在真实网站上通过大量的“试错”来学习策略，这不仅效率低下，还可能导致不可逆的错误操作（如误删数据、下单购买等），且非常耗时。DynaWeb 引入了**基于模型的强化学习**和**世界模型**的概念，通过在从网页 HTML 结构自动生成的模拟环境中进行大量的“想象”和离线训练，从而减少对真实环境交互的依赖，显著提高学习效率和最终的成功率。

---



### 2: DynaWeb 是如何构建其训练环境的？它需要人工设计模拟器吗？

2: DynaWeb 是如何构建其训练环境的？它需要人工设计模拟器吗？

**A**: DynaWeb 不需要人工设计模拟器，这是其一大亮点。它采用了一种**数据驱动**的方法来构建环境。

DynaWeb 利用真实网站的 HTML DOM（文档对象模型）树作为输入。它并不依赖预定义的游戏引擎或复杂的物理模拟器，而是将 HTML 结构视为环境的“状态”。通过分析大量的静态 HTML 数据，DynaWeb 能够学习网页的结构规律和元素之间的动态关系。基于这些数据，它可以生成模拟的网页状态，让智能体在这个由数据驱动的虚拟空间中进行规划和学习，从而避免了人工构建模拟器的高昂成本。

---



### 3: DynaWeb 与传统的 Web Agent 方法（如基于微调的大模型方法）有何区别？

3: DynaWeb 与传统的 Web Agent 方法（如基于微调的大模型方法）有何区别？

**A**: 主要区别在于学习机制和交互方式：

1.  **学习机制**：传统的基于微调的方法（如 Flan-U-PaLM 等）通常属于行为克隆，它们模仿专家的轨迹，但缺乏对环境后果的预测能力。而 DynaWeb 使用强化学习（特别是基于模型的 RL），它不仅模仿，还通过世界模型学习“如果我采取这个动作，网页会变成什么样”，从而具备更强的规划和泛化能力。
2.  **交互成本**：传统方法在训练时通常需要大量的在线交互数据来微调，或者仅仅依赖静态数据而无法处理动态变化。DynaWeb 通过世界模型在离线状态下进行大量的“自我博弈”或“想象”，极大地降低了对真实网站实时交互的需求。

---



### 4: 什么是 DynaWeb 中的“世界模型”，它是如何工作的？

4: 什么是 DynaWeb 中的“世界模型”，它是如何工作的？

**A**: 在 DynaWeb 中，世界模型是一个能够预测环境变化的神经网络。它的作用是学习 Web 环境的动力学模型。

具体工作流程是：世界模型接收当前的网页状态（HTML 的表示）和智能体计划执行的动作，然后预测**下一个**网页状态以及该动作带来的奖励。通过这种方式，智能体不需要真正点击网页，就可以在脑海中预演动作的结果。DynaWeb 利用这个模型进行“模型预测控制”或生成想象轨迹来训练策略网络，从而使得智能体在面对未见过的网站时，也能更准确地预测操作后果。

---



### 5: DynaWeb 在处理网页元素时采用了什么样的表示方法？

5: DynaWeb 在处理网页元素时采用了什么样的表示方法？

**A**: DynaWeb 采用了**基于文本的 HTML 表示方法**，而不是依赖视觉像素截图。

虽然许多现代 Web Agent 使用视觉模型（如看截图），但 DynaWeb 论证了 HTML 结构本身包含了丰富的语义信息。它将 HTML DOM 树解析为文本序列，利用 Transformer 架构来处理这些文本。这种方法的优势在于能够直接利用大语言模型（LLM）强大的上下文理解能力，捕捉网页的深层结构和逻辑，同时也比纯视觉方法在处理长滚动页面或复杂 DOM 结构时更具优势。

6: DynaWeb 的实验效果如何？在哪些基准测试上进行了验证？

**A**: 根据论文报告，DynaWeb 在多个具有挑战性的 Web Agent 基准测试中取得了最先进（SOTA）的结果。

主要验证平台包括 **MiniWoB++** 和 **WebShop**。
