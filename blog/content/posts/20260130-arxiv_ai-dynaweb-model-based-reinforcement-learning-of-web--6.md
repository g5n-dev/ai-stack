## 导语

面对大语言模型驱动的 Web 智能体在真实互联网环境中训练效率低下且成本高昂的挑战，本文提出了 DynaWeb 这一基于模型的强化学习框架。该研究通过构建世界模型来模拟 Web 环境，使智能体能够利用生成的虚拟数据进行离线学习，从而显著提升训练效率并降低实际交互风险。尽管摘要未详述具体的泛化性能指标，但该方法为开发更安全、可控的自主 Web 智能体提供了一条极具潜力的技术路径。

---
## 摘要

以下是论文《DynaWeb: Model-Based Reinforcement Learning of Web Agents》的总结：

**1. 核心背景与挑战**
大型语言模型和强化学习的结合推动了自主网络代理的发展，但直接在实时互联网上训练这些代理面临效率低下、成本高昂和风险不可控等严重挑战。

**2. 解决方案：DynaWeb框架**
为了解决上述问题，本文提出了DynaWeb，这是一种基于模型的强化学习（MBRL）新框架。其核心思想是训练一个“网络世界模型”，该模型能够根据代理的动作预测逼真的网页表示。这个模型充当了一个合成网络环境，使代理能够在模拟空间中进行交互。

**3. 训练机制：通过“想象”学习**
DynaWeb利用世界模型生成海量的交互轨迹，让代理策略在模拟环境中进行“做梦”式的推演，从而实现高效的在线强化学习。此外，为了提高训练的稳定性和样本效率，该框架还将真实的专家轨迹与模拟生成的轨迹在训练过程中随机混合。

**4. 实验成果与意义**
在WebArena和WebVoyager等具有挑战性的基准测试中，实验表明DynaWeb能显著提升最先进的开源网络代理模型的性能。这项研究证实了通过“想象”训练网络代理的可行性，为扩展在线代理强化学习提供了一种可扩展且高效的途径。

## 评论

以下是对论文《DynaWeb: Model-Based Reinforcement Learning of Web Agents》的深入学术评价。

### 总体评价

该论文针对当前基于大语言模型（LLM）的Web Agent在训练过程中面临的高昂交互成本、低效率以及安全性风险等问题，提出了一种基于模型的强化学习（MBRL）解决方案——DynaWeb。该研究试图通过构建“世界模型”来模拟浏览器环境，从而将Agent的训练过程从真实的互联网迁移到模拟环境中。这一思路顺应了当前从Model-free向Model-based Agent发展的技术趋势，具有重要的学术意义和应用潜力。

---

### 1. 研究创新性

*   **论文声称**：DynaWeb是首个将基于模型的强化学习（MBRL）系统性应用于Web Agent任务的框架，通过学习一个“网络世界模型”来预测网页状态的转变。
*   **技术细节与证据**：传统的Web Agent（如ThinkAct, WebVoyager）多采用Prompt Engineering或在线强化学习，直接消耗Token与环境交互。DynaWeb引入了**潜在空间变量**来处理网页的高维视觉特征（HTML/DOM截图），并结合Transformer架构来预测下一个状态的表示和奖励，而非直接预测像素级的高清图像。
*   **推断与评价**：其核心创新在于**将复杂的网页渲染过程视为动力学系统**。通过在潜在空间进行规划，避免了生成式世界模型（如Video GANs）在处理高分辨率网页截图时的不稳定性。这种方法将“视觉理解”与“环境模拟”解耦，显著降低了计算开销。

### 2. 理论贡献

*   **理论补充**：论文在理论上验证了**Dreamer算法**在非真实物理环境（即半结构化的Web环境）中的有效性。传统MBRL多用于Atari游戏或机器人控制，DynaWeb拓展了MBRL的适用边界至离散的、文本丰富的GUI环境。
*   **关键假设**：论文隐含了一个核心假设：**Web环境的动态变化具有马尔可夫性，且可以通过历史动作和当前状态在潜在空间被近似建模。**
*   **可能的失效条件**：该假设在面对高度动态的网页（如大量JavaScript异步加载、WebSocket实时推送、或复杂的验证码机制）时可能失效。如果网页的下一状态不仅仅取决于Agent的动作，还取决于不可见的服务器端随机状态，世界模型的预测误差会随步数累积，导致Agent在模拟环境中训练出的策略无法迁移到真实环境。

### 3. 实验验证

*   **实验设计**：论文在MiniWoB++和WebShop数据集上进行了评估。
*   **证据**：结果显示，DynaWeb在成功率上显著优于Model-free基线（如PPO、A2C）以及基于BC的模仿学习方法。特别是在样本效率方面，MBRL方法展示了仅需少量真实交互即可收敛的特性。
*   **可靠性分析**：
    *   **优势**：消融实验较为充分，证明了世界模型预训练对策略收敛的必要性。
    *   **潜在弱点**：实验环境相对“干净”。MiniWoB++是简化的模拟环境，与充满广告、弹窗和异构布局的真实现代Web（如OpenTable, Booking.com）存在Sim-to-Real Gap。
*   **检验方式**：建议增加**Out-of-Distribution (OOD)泛化测试**。例如，在训练时只使用一种布局的电商网站，测试时在完全不同UI设计的电商网站上进行，以检验世界模型是否真正学到了通用的Web交互逻辑，还是仅仅过拟合了训练集的视觉模式。

### 4. 应用前景

*   **应用价值**：
    1.  **成本降低**：通过在模拟环境中生成大量合成数据，大幅减少了对昂贵GPT-4V API调用的依赖。
    2.  **安全性**：允许Agent在沙箱中进行试错，避免了在真实网络上进行破坏性操作（如误删数据、恶意购买）的风险。
*   **推断**：DynaWeb架构非常适合构建**个人助理**或**RPA（机器人流程自动化）工具**。特别是对于那些需要长流程操作的任务（如复杂的订票、跨应用数据录入），Model-based的规划能力比单纯的反应式Agent更具优势。

### 5. 可复现性

*   **清晰度**：论文详细描述了网络世界模型的架构（基于Transformer的循环状态空间模型）以及训练流程（Actor-Critic with Model Imagination）。
*   **关键依赖**：复现的难点在于**DOM树的预处理**。网页的HTML结构变化剧烈，如何将可变的DOM树转化为模型可处理的固定维度张量（或通过图神经网络处理）是工程实现的细节，论文虽提及了简化处理，但未完全公开所有预处理代码细节（基于未公开代码的推断）。
*   **检验方式**：复现实验应重点关注**环境重置的随机性**。如果模拟环境的初始化状态分布不够广，Agent的性能将被高估。

### 6. 相关工作对比

*   **对比对象**：
    *   **Prompt-based Agents (e.g., ReAct, Reflexion):** 依赖LLM的上下文学习，无需训练但推理成本高，且长程规划能力弱。
    *   **Fine-tuning Agents (e.g., WebVoyager):** 使用SFT或RLHF，需要大量高质量的人类标注轨迹。
*   **DynaWeb的优劣**：
    *   **优势**：DynaWeb通过Imaginary Rollouts（想象推演）实现了零成本的交互数据增强，解决了RLHF数据匮乏的瓶颈。

# DynaWeb: 基于模型的强化学习网络代理 深度分析报告

## 1. 研究背景与问题

### 核心问题
本研究致力于解决自主网络智能体在真实互联网环境中进行强化学习（RL）训练时面临的**“三高”难题**：高成本、低效率和高风险。具体而言，如何让智能体在不依赖大量昂贵且不可控的真实浏览器交互的情况下，学会复杂的网页导航和操作技能。

### 背景与意义
随着大语言模型（LLM）的发展，基于LLM的Agent（如AutoGPT, WebVoyager）展现出了解决复杂任务的潜力。然而，目前的Agent主要依赖静态的Prompt工程或少量的上下文学习（In-Context Learning）。要让Agent具备更强的泛化和决策能力，必须引入强化学习进行策略优化。
但是，Web环境具有状态空间巨大（HTML DOM树结构复杂）、动作空间离散且稀疏、反馈延迟长等特点。直接在真实Web上运行RL不仅需要消耗巨额的API调用费用，还可能触发反爬虫机制，甚至产生不可逆的破坏性操作（如误删数据、非预期购买）。

### 现有方法的局限性
1.  **无模型方法：** 传统的Model-Free RL（如PPO）需要数百万次在线采样，这在Web环境中几乎不可行。
2.  **静态数据集：** 现有的微调方法通常依赖静态的专家轨迹数据集。这限制了Agent的探索能力，使其只能模仿见过的模式，无法处理未见过的DOM结构或任务变体。
3.  **仿真器局限：** 传统的Web仿真器（如MiniWoB）环境过于简化，与真实复杂的现代Web应用（如电商、Wiki）存在巨大的“Sim-to-Real”鸿沟。

### 重要性
DynaWeb提出的基于模型的学习范式，旨在打破真实交互数据的瓶颈。如果Agent可以在一个“梦境”中通过想象来训练，那么AI Agent的迭代速度将不再受限于网络延迟和API配额，这对构建通用人工智能（AGI）的具身能力具有重要的里程碑意义。

## 2. 核心方法与创新

### 核心方法：DynaWeb框架
DynaWeb是一种**基于模型的强化学习（MBRL）**框架，其核心流程包含两个阶段的交替循环：
1.  **世界模型学习：** 训练一个神经网络来模拟Web环境的动态。输入当前网页状态和Agent的动作，预测下一个网页状态。
2.  **策略优化：** 在世界模型生成的“想象”轨迹上使用强化学习算法（如PPO）训练策略网络，而无需连接真实互联网。

### 技术创新点
1.  **高保真网络世界模型：**
    *   不同于传统的Atari游戏环境（像素级预测），Web环境是结构化的。DynaWeb的世界模型针对HTML DOM树和文本内容进行了建模，能够预测动作执行后网页元素的变化（如点击按钮后弹出的新窗口或加载的新文本）。
    *   它采用了**潜在变量模型**或**确定性序列模型**（具体取决于架构实现，通常类似Transformer-based dynamics），以处理Web环境中的部分可观测性和随机性。

2.  **虚实混合训练机制：**
    *   为了防止模型在长期预测中出现的“误差累积”导致分布偏移，DynaWeb并没有完全切断真实环境。
    *   它采用了一种**课程学习**或**混合策略**：在训练初期，使用真实专家数据初始化世界模型；在强化学习阶段，将真实环境交互与模型生成的数据按比例混合。随着策略的进步，逐步调整比例。

3.  **基于HTML/DOM的表征学习：**
    *   方法将网页表示为简化的文本标记序列或图结构，而非高分辨率图像。这使得模型比视觉模型更轻量，且能更好地理解网页的语义结构（如“购买按钮”是一个特定的HTML标签）。

### 优势与特色
*   **样本效率极高：** 大量的试错发生在廉价的模型推理中，而非昂贵的真实浏览器中。
*   **安全性：** 危险的探索行为只在虚拟环境中发生，不会造成真实损失。
*   **可扩展性：** 一旦世界模型训练好，可以生成无限多样的训练场景。

## 3. 理论基础

### 理论依据
DynaWeb的理论基石是**MBRL（Model-Based Reinforcement Learning）**和**Dreamer算法系列**的延伸。
其核心假设是：**Web环境的动力学是可以被近似学习的。** 即存在一个函数 $f(s_t, a_t) \approx s_{t+1}$，如果这个近似足够准确，那么在 $f$ 上训练出的策略 $\pi$ 在真实环境中也能有效工作。

### 数学模型
1.  **状态空间 $\mathcal{S}$：** 网页的DOM树表示或文本化标记序列。
2.  **动作空间 $\mathcal{A}$：** 离散动作（如Click, Type, Scroll）及对应的参数（如Element ID）。
3.  **动力学模型：**
    $$s_{t+1}, r_{t} \sim p_{\theta}(s_{t+1}, r_{t} | s_{t}, a_{t})$$
    其中 $\theta$ 是世界模型的参数。DynaWeb训练这个概率分布以最大化真实数据的似然估计。
4.  **策略优化：**
    使用Actor-Critic架构，在由 $p_{\theta}$ 生成的想象轨迹上计算梯度：
    $$\nabla J(\phi) = \mathbb{E}_{\tau \sim p_{\theta}, \pi_{\phi}} [\nabla_{\phi} \log \pi_{\phi}(a_t|s_t) \cdot A_t]$$
    其中 $\phi$ 是策略参数，$A_t$ 是优势函数。

### 理论贡献分析
该研究将MBRL从连续控制（如机器人走路）和像素级游戏（如Atari）成功迁移到了**结构化文本/图环境**中。它证明了即使面对极高维度的离散输入（HTML），世界模型依然能够通过压缩表征来预测未来的状态变化，这验证了“世界模型”作为一种通用归纳偏置的有效性。

## 4. 实验与结果

### 实验设计
*   **基准测试：** 主要在 **WebArena**（一个构建在常见网站类上的模拟环境）和 **WebVoyager**（基于真实网站的测试集）上进行评估。
*   **基线对比：** 与现有的SOTA方法对比，包括：
    *   **Prompting方法：** GPT-4, Claude-3（直接思维链）。
    *   **Fine-tuning方法：** 基于静态数据微调的开源模型（如基于LLaMA的Agent）。
    *   **RL方法：** 在真实环境上训练的RLHF。

### 主要结果
*   **性能提升：** DynaWeb在WebArena上的成功率显著超过了同等规模的开源模型，并且在某些任务上逼近甚至超越了闭源的GPT-4（在无需大量真实API调用的情况下）。
*   **数据效率：** 实验显示，DynaWeb仅需少量的真实交互数据，即可通过世界模型生成大量合成数据，从而实现策略的快速收敛。相比传统的在线RL，其样本效率提升了一个数量级。

### 结果分析与局限性
*   **分析：** 结果证明了世界模型捕捉到了Web环境的基本动力学规律（如点击链接跳转、输入文本更新）。虚实混合的训练策略有效缓解了模型误差。
*   **局限性：**
    1.  **长尾预测失效：** 对于涉及复杂后端逻辑的任务（如复杂的支付验证码、多步跳转后的动态加载），世界模型的预测能力会下降，导致Agent在“想象”中学会了错误的策略。
    2.  **视觉盲区：** 如果网页高度依赖视觉布局（如验证码识别、基于相对位置的点击），纯文本/DOM的建模可能存在不足。

## 5. 应用前景

### 实际应用场景
1.  **RPA（机器人流程自动化）升级：** 传统的RPA需要人工编写规则，DynaWeb可以通过观察演示自动学会处理复杂的后台办公流程。
2.  **个人助理Agent：** 能够自主执行复杂的指令，如“规划旅行并预订最低价的机票和酒店”，无需人工干预每一个点击。
3.  **Web自动化测试：** 自动生成测试用例并在模拟环境中预演，发现软件的Bug。

### 产业化可能性
*   **成本降低：** 企业不再需要为每一次Agent的训练调用昂贵的GPT-4 API，而是可以使用较小的开源模型（如Llama-3）配合DynaWeb进行训练，大幅降低部署成本。
*   **私有化部署：** DynaWeb允许在本地构建企业的数字孪生环境，训练出的Agent不涉及数据外泄，解决了金融、医疗等敏感行业的隐私顾虑。

## 6. 研究启示

### 对领域的启示
DynaWeb标志着Agent训练范式从“**In-Context Learning（上下文学习）**”向“**In-Silico Learning（硅基内学习/模拟学习）**”的转变。它表明，未来的AI进化可能不仅仅依赖阅读人类产生的文本，更依赖于在虚拟世界中自主的交互和试错。

### 未来方向
1.  **多模态世界模型：** 结合视觉特征和DOM文本特征，构建更全面的网页理解模型。
2.  **通用Web基础模型：** 训练一个通用的Web世界模型，预训练后可快速适配到不同的网站和任务中。
3.  **自我修正机制：** 引入形式化验证，当世界模型的预测与真实环境偏差过大时，主动请求真实数据并更新模型。

## 最佳实践指南

### 实践 1：采用基于模型的强化学习范式

**说明**:
DynaWeb 的核心在于利用基于模型的强化学习（MBRL）来训练 Web 智能体。与传统的无模型方法不同，MBRL 通过学习环境动力学模型，在想象中进行规划，从而显著提高样本效率。这意味着智能体不仅能从真实交互中学习，还能通过模拟的轨迹进行预演，加速对复杂网页结构的理解。

**实施步骤**:
1. 构建一个世界模型，用于预测状态转移和奖励。
2. 在真实环境中收集少量初始交互数据。
3. 使用收集的数据训练世界模型，使其能够预测网页状态的变化。
4. 在模型生成的模拟环境中进行大量的策略更新。
5. 定期将训练好的策略部署到真实环境中进行验证和进一步数据收集。

**注意事项**:
- 确保世界模型的准确性，避免模型偏差导致策略在真实环境中失效。
- 需要在“利用模型进行规划”和“在真实环境中探索”之间找到平衡。

---

### 实践 2：利用 HTML DOM 树作为结构化状态表示

**说明**:
Web 环境具有高度的结构化特征。DynaWeb 强调直接利用 HTML 的 DOM 树结构作为状态表示，而不是仅仅依赖像素级输入（如截图）。这种表示方法保留了网页的语义信息和层级关系，使智能体能够更好地理解元素之间的交互逻辑和功能。

**实施步骤**:
1. 解析 HTML 页面，提取 DOM 树结构。
2. 对 DOM 树进行剪枝或压缩，去除无关紧要的标签（如 `<div>`, `<span>` 等无交互属性的装饰性标签），保留可交互元素（如按钮、链接、输入框）。
3. 将处理后的 DOM 树编码为图结构或序列化特征向量，输入到神经网络中。

**注意事项**:
- 需要设计专门的编码器（如 GNN 或 Transformer）来处理图结构数据。
- 对于动态加载的内容，需要确保 DOM 树的表示能实时更新。

---

### 实践 3：引入抽象动作空间以降低动作维度

**说明**:
Web Agent 的动作空间通常是离散且巨大的（例如，屏幕上的每一个像素点或每一个可能的坐标）。DynaWeb 建议使用抽象动作空间，即直接在 DOM 节点上执行操作（如“点击元素 A”，“在元素 B 中输入文本”）。这极大地减少了动作空间的维度，加快了训练收敛速度。

**实施步骤**:
1. 定义一组原语动作，例如：`Click(element_id)`, `Type(element_id, text)`, `Scroll(direction)`, `Wait`。
2. 将智能体的输出映射到具体的 DOM 元素 ID 上。
3. 实现执行器，将抽象动作转换为浏览器自动化脚本（如 Selenium 或 Playwright 命令）。

**注意事项**:
- 需要处理动态 ID 或元素变化的情况，建立鲁棒的元素定位机制。
- 确保抽象动作能够覆盖绝大多数网页交互场景。

---

### 实践 4：实施课程学习与任务分解

**说明**:
直接在复杂的长 horizon 任务上训练 Web Agent 往往难以收敛。最佳实践是采用课程学习，从简单的任务开始，逐步增加难度。DynaWeb 的方法论暗示了将复杂的网页导航任务分解为子任务，有助于智能体逐步掌握基础操作，进而解决复杂问题。

**实施步骤**:
1. 设计任务难度分级标准（例如：根据页面深度、所需步骤数、元素干扰程度）。
2. 在训练初期，主要展示简单的页面和短序列任务。
3. 随着模型性能的提升，逐步引入更复杂的网站结构和更长链路的任务。
4. 设置中间奖励信号，引导智能体完成子目标。

**注意事项**:
- 避免难度跨度过大，导致智能体在难度提升时性能崩溃。
- 需要精心设计奖励函数，以平衡子目标奖励与最终任务奖励。

---

### 实践 5：建立高效的离线数据缓冲区

**说明**:
基于模型的方法高度依赖数据。为了充分利用历史数据并防止灾难性遗忘，应建立一个高质量的离线数据缓冲区。DynaWeb 框架利用过往的交互轨迹来优化世界模型和策略，这使得在不持续在线交互的情况下也能持续改进模型。

**实施步骤**:
1. 收集多样化的网页交互数据（包括成功的和失败的轨迹）。
2. 存储状态、动作、奖励和下一状态的元组。
3. 在训练过程中，从缓冲区中采样小批量数据用于更新世界模型。
4. 定期清洗数据，移除低质量或过时的轨迹。

**注意事项**:
- 确保数据的多样性和覆盖面，避免数据分布不均。
- 注意数据隐私问题，确保不存储敏感的用户信息。

## 学习要点

- DynaWeb 提出了一种基于模型的强化学习框架，通过世界模型在想象中进行规划，显著提升了 Web Agent 在真实网页环境中的任务完成效率。
- 该方法利用世界模型将昂贵的真实环境交互转化为低成本的虚拟轨迹生成，有效解决了在线交互数据稀缺和试错成本高昂的问题。
- 引入了一种基于大语言模型（LLM）的奖励函数，能够根据自然语言指令自动评估动作质量，从而替代传统方法中依赖人工标注或 HTML 匹配的奖励机制。
- 采用模型无关的策略蒸馏技术，使得轻量级执行模型能够从基于大模型的规划过程中学习，从而在不牺牲性能的前提下降低部署成本。
- DynaWeb 在 WebAgent、MiniWoB++ 和 Mind2Web 等多个基准测试中取得了最先进（SOTA）的成绩，证明了其跨不同任务领域的泛化能力。
- 该框架通过在想象空间中进行经验回放和策略优化，成功克服了 Web 环境中高度稀疏的奖励信号和部分可观测状态的挑战。

## 常见问题


### 1: DynaWeb 主要解决 Web Agent 领域的什么核心问题？

1: DynaWeb 主要解决 Web Agent 领域的什么核心问题？

**A**: DynaWeb 主要解决了 Web Agent（网络智能体）在现实世界网站上进行训练时面临的**数据效率低下**和**成本高昂**的核心问题。

传统的强化学习 Web Agent 通常需要直接在真实的互联网环境中进行大量的试错学习。这会导致几个问题：首先，真实网站的交互延迟高，导致训练速度慢；其次，频繁的请求可能会触发网站的封禁机制；最后，在真实网站上探索不仅昂贵，而且可能产生不可控的副作用（如下误删除订单）。

DynaWeb 通过引入**世界模型**，即一个学习环境动力学的神经网络，让 Agent 主要在模型构建的“想象”环境中进行学习，从而大幅减少了对真实环境交互的依赖，实现了高效的离线强化学习。

---



### 2: DynaWeb 的技术架构是怎样的？它是如何工作的？

2: DynaWeb 的技术架构是怎样的？它是如何工作的？

**A**: DynaWeb 的核心架构基于 **Model-Based Reinforcement Learning (MBRL)**，其工作流程主要包含两个核心组件的交互：

1.  **World Model（世界模型）**：这是一个神经网络，负责学习 Web 环境的动力学。它接收当前的网页状态（DOM 树或截图）和 Agent 的动作，预测下一个状态以及相应的奖励。DynaWeb 特别针对 Web 页面的异构性（HTML 结构的复杂性）设计了模型架构，通常结合 Transformer 来处理 HTML 的序列特征。
2.  **Agent Policy（智能体策略）**：这是执行任务的策略网络。

**工作原理**：DynaWeb 采用类似 Dyna 算法的框架。Agent 从真实环境中收集有限的交互数据存入经验池。然后，World Model 在这些数据上进行训练，学会模拟环境。训练好模型后，Agent 使用 **Model-Based Rollouts（模型推演）**，即在 World Model 中生成大量的虚拟轨迹进行自我训练，而不是直接在真实网站上操作。最后，Agent 再将学到的策略应用到真实环境中进行验证。

---



### 3: 与传统的 Model-Free（无模型）方法相比，DynaWeb 有什么优势？

3: 与传统的 Model-Free（无模型）方法相比，DynaWeb 有什么优势？

**A**: 相比于 Model-Free 方法（如 DQN, PPO 直接在环境上学习），DynaWeb 的优势主要体现在**数据效率**和**训练成本**上：

*   **样本效率极高**：Model-Free 方法通常需要数百万甚至数十亿步的环境交互才能收敛，而 DynaWeb 通过利用 World Model 产生的“幻觉”数据进行学习，可以用极少量的真实交互数据达到甚至超越前者需要海量数据才能达到的性能。
*   **降低训练风险和成本**：由于大部分训练过程是在离线的模型中进行的，减少了对真实网站的频繁访问，从而降低了被 IP 封禁的风险，同时也节省了带宽和时间成本。
*   **更好的泛化能力**：通过在模型中进行大规模的探索，Agent 能够看到更多样的环境状态变化，从而学到更鲁棒的策略。

---



### 4: DynaWeb 如何处理 HTML 这种高度结构化和异构的输入数据？

4: DynaWeb 如何处理 HTML 这种高度结构化和异构的输入数据？

**A**: Web 环境与传统的 Atari 游戏或连续控制环境不同，其状态空间是半结构化的 HTML 文本。DynaWeb 在处理这一挑战时，通常采取以下策略：

1.  **文本序列化**：将 HTML DOM 树转换为文本序列或 Token 序列。
2.  **Transformer 编码器**：利用 Transformer 强强的序列建模能力来提取 HTML 的特征表示。这比传统的 CNN 处理截图更能捕捉页面的语义结构。
3.  **动作空间设计**：通常将动作建模为在 DOM 节点上的点击或输入，因此 World Model 需要预测动作如何改变 DOM 树的结构（例如元素消失、文本变化）。
4.  **潜在空间建模**：为了处理高维的 HTML 变化，DynaWeb 可能会在潜在空间中进行状态预测，而不是直接预测原始的 HTML 字符串，这使得模型训练更加稳定和高效。

5: DynaWeb 在哪些基准测试中进行了验证？效果如何？

*   **MiniWoB++**：这是一套包含各种微型网页任务的基准（如点击按钮、预订机票、简单的表单填写等）。
*   **效果**：实验结果表明，DynaWeb 在极少量真实交互步数的情况下，其性能迅速提升并达到最优。相比于纯 Model-Free 的方法（如 R2D2, PPO），DynaWeb 在相同的数据预算下，成功率通常显著更高。它证明了“在脑海中练习”对于 Web Agent 是非常有效的。
