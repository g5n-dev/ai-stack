## 导语

针对自动化特征发现中依赖人工经验且缺乏语义关联的瓶颈，本文提出了 FAMOSE 框架。该方法采用 ReAct 逻辑，通过迭代式推理与工具调用自动生成并筛选特征，在摘要中展示了其在多个数据集上的性能提升。然而，其具体的计算开销及对复杂噪声场景的鲁棒性，尚无法从摘要确认。该研究为构建具备自主推理能力的特征工程工具提供了新思路。

## 摘要

本文介绍了 **FAMOSE**（Feature AugMentation and Optimal Selection agEnt），这是一种利用 **ReAct 范式**结合大语言模型（LLM）来解决机器学习中**自动化特征工程**难题的新型智能体框架。

**核心背景：**
特征工程是机器学习的关键瓶颈，特别是在表格数据处理中，从巨大的特征空间中寻找最优特征通常需要大量领域专业知识。

**FAMOSE 的创新点：**
据作者所知，FAMOSE 是首个将基于智能体的 ReAct 框架应用于自动化特征工程的系统。它能够自主地探索、生成和优化特征，并在架构中集成了特征选择和评估工具，适用于回归和分类任务。

**性能表现：**
实验结果表明，FAMOSE 达到了顶尖水平：
*   **分类任务：** 在大规模数据集（超过 1 万条实例）上表现优异，ROC-AUC 平均提升 0.23%。
*   **回归任务：** 达到了目前的最优水平，平均 RMSE 降低 2.0%。
*   **鲁棒性：** 相比其他算法，FAMOSE 对错误具有更强的鲁棒性。

**成功原因：**
FAMOSE 的强大性能归功于 ReAct 机制。它允许 LLM 通过迭代的发现和评估步骤，在上下文窗口中记录哪些特征有效、哪些无效。这类似于“少样本提示”，从而引导 LLM 发明出更优质、更具创新性的特征。

**结论：**
该工作证明了 AI 智能体在解决需要高度创造性方案的问题（如特征工程）方面具有显著成效。

# 技术分析：FAMOSE —— 基于 ReAct 范式的自动化特征发现

## 1. 研究背景与问题

### 核心问题
本研究旨在解决机器学习流程中计算成本较高且依赖人工经验的环节——**特征工程**。具体而言，是如何在没有人工干预的情况下，从原始表格数据中自动构造出能够提升模型性能的高阶特征。

### 研究背景与意义
特征工程通常被视为机器学习中的关键步骤。尽管深度学习在图像和文本领域通过表示学习实现了特征提取的自动化，但在结构化数据领域，结合领域知识的手工特征（如“单位面积价格”、“过去30天的波动率”等）往往对模型表现有显著影响。然而，这个过程高度依赖专家经验，且随着数据维度的增加，特征空间的搜索复杂度呈指数级增长。

### 现有方法的局限性
现有的自动化特征工程（AFE）工具主要存在以下局限：
1.  **基于规则的盲目性**：传统工具（如 FeatureTools）主要依赖预定义的数学变换（加减乘除、聚合等）和暴力搜索。这种方式缺乏对数据语义的深层理解，容易产生大量无效特征，且计算资源消耗较大。
2.  **缺乏迭代优化**：大多数 AFE 工具采用“一次性生成”模式，缺乏根据模型反馈进行特征修正和再生的反思机制。
3.  **泛化能力受限**：针对特定数据集优化的特征往往难以直接迁移到同类任务中。

### 应用价值
解决这一问题有助于降低机器学习模型开发的门槛。通过自动化的特征发现，数据科学家可以从重复性的特征构造工作中释放出来，更多关注业务逻辑定义，同时提高构建 ML 模型的效率。

## 2. 核心方法与创新

### 核心方法：FAMOSE 框架
FAMOSE（Feature AugMentation and Optimal Selection agEnt）是一个基于 **ReAct（Reasoning + Acting）** 范式的智能体框架。它将特征工程视为一个**序列决策过程**。

其工作流程包含以下循环：
1.  **Thought（推理）**：LLM 分析当前数据集的统计特性、已有的特征列表以及模型反馈（如特征重要性），规划下一步的变换操作（例如：“由于数据呈现长尾分布，尝试对数变换”）。
2.  **Action（行动）**：调用 Python 解释器或特征生成工具执行代码，生成新特征。
3.  **Observation（观察）**：评估新特征对模型性能的贡献（通过验证集评分）。
4.  **Update（更新）**：将有效的特征和失败的尝试记录在“上下文记忆”中，用于指导后续的生成。

### 技术创新点
1.  **ReAct 范式的应用**：该系统将 ReAct 智能体引入特征工程任务。这使得 LLM 在该框架中不仅是代码生成器，还承担了特征工程师的规划角色。
2.  **上下文记忆与少样本学习**：FAMOSE 将历史上有效的特征模式存储在上下文窗口中。随着迭代进行，LLM 能够参考“什么特征有效”的历史记录，从而模仿并改进生成策略。
3.  **自主探索与评估闭环**：系统集成了特征选择工具，能够自动剔除冗余特征，保留最优子集，缓解了特征生成过程中的维度灾难问题。

### 方法的特性
*   **语义感知**：相比传统的暴力组合，LLM 能够解析列名含义（如“价格”和“重量”），从而构造出“每千克价格”等具有物理意义的特征。
*   **鲁棒性**：实验表明，FAMOSE 对数据中的噪声和错误具有一定的容忍度，归功于其不断验证特征有效性的机制。

## 3. 理论基础

### 理论依据
FAMOSE 的核心理论支撑主要来自两个方面：
1.  **强化学习与规划**：ReAct 本质上是一种无模型的规划过程。它假设在巨大的特征搜索空间中，通过“状态-行动-奖励”的反馈循环，智能体可以逐步逼近较优的特征构造策略。
2.  **程序合成**：将特征工程视为程序合成问题。LLM 作为概率模型，根据输入（数据描述）和输出（性能指标），合成符合特定语法的特征变换程序。

### 算法逻辑
虽然没有显式的数学公式推导，但其背后的逻辑可以抽象为寻找函数 $f^*$：
$$ f^* = \mathop{\arg\max}_{f \in \mathcal{F}} \mathbb{E}[\text{Score}(Model(X, f(X)), Y)] $$
其中 $\mathcal{F}$ 是由 LLM 生成的所有可能的特征变换函数空间。FAMOSE 通过迭代式的试错，试图在有限的计算资源内找到该函数的一个近似解。

## 研究最佳实践

## 最佳实践指南

### 实践 1：采用 ReAct 框架构建特征发现循环

**说明**: FAMOSE 的核心在于结合推理和行动。不要仅依赖单一的模型生成特征，而是建立一个包含“观察-思考-行动”的循环机制。这意味着代理在生成特征代码之前，应先分析数据分布和模型反馈，在执行代码后根据结果（如特征重要性、性能提升）进行反思和修正。

**实施步骤**:
1. 设计提示词，强制 LLM 在生成代码前先输出对当前数据状态的“思考”过程。
2. 建立反馈机制，将特征工程的结果（如验证集 AUC 变化）作为“观察”输入回给代理。
3. 允许代理基于负面反馈进行多轮自我修正，而不是一次生成即止。

**注意事项**: 避免跳过“思考”步骤直接生成代码，这会导致大量无效或冗余特征的生成。

---

### 实践 2：实施严格的代码沙箱与安全执行

**说明**: 自动化特征发现涉及 LLM 生成并执行可执行代码（如 Python）。为了防止恶意代码或不安全操作破坏生产环境或数据泄露，必须在隔离的沙箱环境中运行生成的代码。

**实施步骤**:
1. 使用 Docker 容器或受限的 Python 执行环境来运行 LLM 生成的特征转换脚本。
2. 限制可用库的范围，仅包含数据处理和科学计算库（如 Pandas, NumPy, Scikit-learn），屏蔽系统级操作。
3. 设置超时和内存限制，防止因生成的死循环或内存溢出代码导致系统崩溃。

**注意事项**: 绝不要在本地或生产环境直接运行未经审计的 LLM 生成代码。

---

### 实践 3：利用进化算法进行特征空间搜索

**说明**: FAMOSE 方法通常涉及从大量候选特征中选择最优组合。采用进化算法策略，通过保留高性能特征并变异生成新特征，可以逐步优化特征子集，避免盲目搜索。

**实施步骤**:
1. 初始化一个包含基础特征的种群。
2. 定义适应度函数，通常为特征在验证集上的预测性能（如 SHAP 值或信息量）。
3. 执行选择、交叉和变异操作：保留表现好的特征，组合它们，或对其进行微调（例如改变分箱边界或数学运算符）。

**注意事项**: 设定最大迭代次数或性能阈值，防止进化过程无限运行消耗资源。

---

### 实践 4：建立基于数据漂移的动态特征触发机制

**说明**: 特征的有效性随时间变化。最佳实践不仅是静态发现特征，而是让系统具备监控数据分布的能力。当检测到特征分布漂移或预测性能下降时，自动触发新的特征发现流程。

**实施步骤**:
1. 部署监控服务，定期计算生产数据与训练数据之间的 KL 散度或 PSI。
2. 设定告警阈值，当关键特征发生漂移时自动调用 FAMOSE 代理。
3. 让代理针对新数据生成替代特征或调整现有特征的参数。

**注意事项**: 区分概念漂移和数据漂移，确保仅在特征失效时触发重构，避免不必要的计算开销。

---

### 实践 5：强制执行特征可解释性与业务逻辑验证

**说明**: LLM 可能会生成数学上有效但业务逻辑荒谬的特征（例如将“客户ID”与“当前时间”相乘）。必须在自动化流程中加入人工或规则层面的验证关卡。

**实施步骤**:
1. 定义特征类型的白名单或黑名单规则（例如：禁止使用 PII 敏感数据直接作为特征）。
2. 要求 LLM 在生成特征时附带“业务含义解释”，并由简单的规则过滤器检查合理性。
3. 对于高影响力特征，引入人工审核环节，确认其符合业务常识。


---

### 实践 6：优化提示词策略以减少冗余特征

**说明**: LLM 倾向于生成大量相似的特征（如各种对数变换的变体）。通过精心设计的提示词工程，引导代理专注于生成多样性高、互补性强的特征。

**实施步骤**:
1. 在提示词中明确要求生成“与现有特征相关性低”的新特征。
2. 提供现有特征列表作为上下文，要求代理分析并避免重复。
3. 指导代理尝试不同的特征工程类别（时序、聚合、统计、交互），而不是局限于单一类型。

**注意事项**: 定期对生成的特征池进行去重和相关性分析，移除高相关性的冗余特征。

## 学习要点

- FAMOSE 首次将大语言模型（LLM）的 ReAct（推理+行动）范式引入自动化特征工程，通过迭代循环“思考-行动-观察”来动态生成和优化特征，而非依赖静态模板。
