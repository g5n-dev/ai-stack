## 导语

针对网页智能体在真实互联网环境中训练面临的低效与安全挑战，本文提出了 DynaWeb 这一基于模型的强化学习框架。该方法通过训练“网页世界模型”构建合成环境，使智能体能利用生成的交互轨迹及真实专家数据进行高效的“想象式”训练。实验结果显示，该框架在 WebArena 等基准测试中显著提升了现有开源模型的性能，但摘要未明确披露其在复杂长链路任务中的具体泛化边界。

## 摘要

以下是对该内容的简洁总结：

**DynaWeb：基于模型的网页智能体强化学习框架**

**背景与挑战**
随着大型语言模型（LLM）和强化学习（RL）的发展，自主网页智能体正朝着通用AI助手的方向迈进。然而，现有的训练方法面临巨大挑战：直接与实时互联网交互不仅效率低下、成本高昂，还存在安全风险。

**解决方案：DynaWeb框架**
为了解决上述问题，本文提出了**DynaWeb**，这是一种基于模型的强化学习（MBRL）新框架。DynaWeb的核心思路是训练一个“网页世界模型”，该模型能够根据智能体的动作预测自然的网页表示。这个模型作为一个合成环境，允许智能体策略在其中进行“想象”——即生成海量的交互轨迹，从而实现高效的在线强化学习训练。

**技术特点**
除了生成策略轨迹外，DynaWeb还结合了训练数据中的真实专家轨迹。在训练过程中，这些真实轨迹与在线策略轨迹被随机混合，以提高训练的稳定性和样本效率。

**实验成果**
在具有挑战性的WebArena和WebVoyager基准测试中，实验结果表明，DynaWeb显著且持续地提升了现有最先进的开源网页智能体模型的性能。

**结论**
这项研究证明了通过“想象”来训练网页智能体的可行性，为扩展在线智能体强化学习提供了一种可扩展且高效的途径。

## 评论

### **DynaWeb: Model-Based Reinforcement Learning of Web Agents 论文深度评价**

**综述**
DynaWeb 旨在解决网页智能体训练中数据获取成本高和在线交互效率低的问题。该研究提出了一种基于模型的强化学习（MBRL）框架，通过构建网页世界模型，使智能体能够在离线模拟环境中进行策略优化。以下是对该方法学术价值与技术局限性的客观剖析。

---

#### **1. 研究创新性**

*   **核心主张：** 针对无模型强化学习依赖大量在线试错的问题，DynaWeb 引入世界模型机制，利用历史动作与 HTML DOM 快照预测未来状态，通过内部模拟生成训练数据，从而减少对真实环境的交互需求。
*   **技术实现：** 论文设计了基于 Transformer 的动力学模型，利用潜在空间中的策略推演来替代部分真实浏览器的渲染与执行过程。
*   **学术评价：** 该研究实现了从“在线交互”向“离线规划”的范式转换，探索了将结构化文本（HTML）作为世界模型输入的可行性。
*   **局限性与挑战：**
    *   **累积误差：** 世界模型在多步预测后的误差会随时间步长累积。对于包含高度动态内容（如实时数据流）或复杂客户端逻辑（如 Canvas 渲染）的页面，模型的预测准确性会显著下降。
    *   **模态缺失：** 当前模型主要依赖 DOM 文本，缺乏对视觉样式（CSS）和像素级信息的深度建模，这在处理视觉密集型任务时可能成为瓶颈。

#### **2. 理论贡献**

*   **核心主张：** 论文证明了在高维语义空间中，基于 DOM 的结构化表示比原始像素更适合作为强化学习的状态空间。
*   **学术评价：** 该工作补充了结构化世界模型的理论研究，利用 HTML 的树状结构作为归纳偏置，在理论上提高了样本效率。它探索了符号（DOM 树）与亚符号（神经网络嵌入）结合的建模方式。
*   **局限性与挑战：**
    *   **状态完备性假设：** 理论模型假设 DOM 文本包含了完成任务所需的全部必要信息。然而，现代 Web 应用中大量关键信息隐含在视觉渲染中（如特定颜色、位置布局），仅靠文本解析可能导致语义丢失。
    *   **泛化边界：** 模型对未见过的 DOM 结构或非标准 Web 框架的泛化能力尚未得到充分验证。

#### **3. 实验验证**

*   **实验结果：** 在 WebShop 和 MiniWoB 等基准测试中，DynaWeb 在有限的交互预算下表现优于现有的无模型基线（如 ReAct）。
*   **学术评价：** 实验表明该方法在受控的模拟环境中具有数据效率优势。然而，基准测试环境的结构相对规整和静态，可能无法完全反映真实互联网的复杂性。
*   **局限性与挑战：**
    *   **Sim-to-Real 鸿沟：** 实验主要集中在模拟环境。真实网站存在网络延迟、反爬虫机制及非确定性 DOM 变化，这些因素均未在训练数据中体现，可能导致策略在部署时失效。
    *   **评估维度单一：** 目前的评估主要关注任务成功率，缺乏对模型鲁棒性及长期预测误差的定量分析。

#### **4. 应用前景**

*   **适用场景：** 该框架为在交互成本受限的场景下训练网页智能体提供了一种可行的技术路径，特别是在 DOM 结构相对稳定的任务中。
*   **现实挑战：** 在实际部署中，系统仍需处理真实环境的不可预测性。单纯依赖离线训练的模型可能难以应对复杂的 Web 动态，未来的应用方向可能需要结合在线微调或混合架构设计。

# DynaWeb: 基于模型的网页智能体强化学习——深入分析报告

## 1. 研究背景与问题

### 核心问题
本研究致力于解决自主网页智能体在训练过程中面临的**“样本效率低下”**与**“交互成本高昂”**这一核心矛盾。具体而言，如何在不依赖大规模实时互联网交互的情况下，利用有限的专家数据，通过强化学习训练出具有高泛化能力的网页操作策略。

### 背景与意义
随着大语言模型（LLM）的爆发，基于LLM的智能体被视为迈向通用人工智能（AGI）的关键步骤。网页智能体作为最直接的应用载体，能够自动执行订票、电商操作、信息检索等复杂任务，具有极高的商业价值和社会意义。
然而，现有的网页智能体训练范式正处于一个瓶颈期：从“有监督微调（SFT）”向“强化学习（RL）”过渡时，传统的RL需要智能体在真实环境中进行海量试错。对于Web环境而言，这意味着巨大的API调用成本、时间消耗以及潜在的安全风险（如误操作购买商品）。

### 现有方法的局限性
1.  **无模型强化学习的低效性**：现有的如ReAct等基于Prompting的方法，或者直接在真实环境运行的RL算法，每一步都需要渲染网页、解析HTML并获取反馈，训练速度极慢且成本不可控。
2.  **离线数据的匮乏**：虽然存在一些专家轨迹数据，但静态的数据无法覆盖长尾场景和动态变化的网页结构，导致智能体泛化能力不足。
3.  **幻觉与环境不匹配**：单纯的LLM生成容易产生幻觉，即执行了在当前网页状态下无法执行的动作。

### 问题重要性
解决这一问题不仅能够大幅降低网页智能体的训练门槛，使其从“富人的游戏”变为普及化的技术，更重要的是，它验证了**世界模型**在复杂半结构化环境（Web）中的有效性。这为未来在物理世界或其他数字世界中训练具身智能体提供了重要的范式参考。

## 2. 核心方法与创新

### 核心方法：DynaWeb框架
DynaWeb提出了一种**基于模型的强化学习（MBRL）**框架，其核心包含两个组件：
1.  **网页世界模型**：这是一个学习型模型，旨在模拟Web环境的动态。它接受当前的网页状态和智能体的动作为输入，预测下一个网页状态。这使得智能体可以在“脑海”中推演动作的后果。
2.  **想象式策略优化**：利用训练好的世界模型生成合成轨迹，智能体在这些合成轨迹上进行策略学习，相当于在虚拟环境中进行“思维体操”。

### 技术创新点
1.  **表示学习与解耦**：DynaWeb并没有直接预测原始的HTML代码（这极其困难且高噪），而是学习预测网页的**隐式表示**。这种解耦降低了世界模型的训练难度。
2.  **混合数据流策略**：在训练策略时，DynaWeb创新性地将**真实专家轨迹**与**模型生成的想象轨迹**进行随机混合。这种做法既保留了真实数据的准确性，又利用了合成数据的多样性。
3.  **端到端的MBRL适配**：将传统的MBRL（通常用于连续控制或Atari游戏）成功迁移到高度离散、文本密集的Web Agent领域，解决了状态空间巨大和动作空间离散的挑战。

### 优势与特色
- **高样本效率**：通过“想象”产生数据，减少了对昂贵真实交互的依赖。
- **安全性**：在合成环境中训练，避免了智能体在训练初期对真实网站造成破坏。
- **可扩展性**：世界模型一旦训练好，可以无限生成数据，支持策略的大规模迭代。

## 3. 理论基础

### 理论依据
DynaWeb的理论根基主要建立在**基于模型的强化学习（MBRL）**和**系统辨识**理论之上。
- **MBRL理论**：MBRL的核心思想是将强化学习问题分解为“学习模型”和“规划/优化”。理论上，如果世界模型足够准确，利用模型生成的数据进行策略训练，其效果上限可以逼近在真实环境中无限交互的结果。
- **想象力**：借用认知心理学的概念，智能体通过内部模型模拟未来，这种“反事实”推理能力是高级智能的标志。

### 算法设计
数学上，DynaWeb试图学习一个转移函数 $T_{\psi}$：
$$ S_{t+1} \sim T_{\psi}(S_t, A_t) $$
其中 $S_t$ 是网页的隐状态表示，$A_t$ 是动作。
策略网络 $\pi_{\theta}$ 则通过最大化由真实数据和模型生成数据混合构成的回报来更新：
$$ J(\theta) = \mathbb{E}_{\tau \sim \beta_{real} + \beta_{model}} [\sum r(s_t, a_t)] $$

### 理论贡献
该研究在理论上并未提出全新的数学定理，但其贡献在于**验证了MBRL在非像素、离散符号领域的有效性**。传统的世界模型多用于连续控制或像素预测（如Dreamer系列），DynaWeb证明了在HTML这种树状结构、文本密集的复杂环境中，构建隐式世界模型是可行的。

## 4. 实验与结果

### 实验设计
- **基准测试**：主要在**WebArena**（一个构建在常见网站上的模拟环境）和**WebVoyager**（基于真实网站的基准）上进行评估。
- **基线对比**：与当前最先进的（SOTA）开源Agent进行对比，包括基于Prompting的方法（如ReAct, CoT）和经过微调的模型。
- **评估指标**：任务成功率。

### 主要结果
- **显著提升**：DynaWeb在WebArena上相比现有的微调方法（如仅使用SFT数据）取得了显著的性能提升。实验表明，随着合成数据比例的增加，模型性能持续上升，证明了“想象”带来的价值。
- **数据效率**：达到相同性能水平，DynaWeb所需的真实交互步数远少于Model-Free方法。

### 局限性分析
- **世界模型的误差累积**：在长链任务中，世界模型的预测偏差会逐渐累积，导致生成的轨迹偏离真实分布，影响策略训练。
- **评估环境的封闭性**：WebArena虽然是模拟环境，但仍比真实互联网简单。模型在处理极其复杂的验证码、动态加载内容或未知网站类型时，可能仍表现不佳。

## 5. 应用前景

### 实际应用场景
1.  **个人助理**：自动执行复杂的跨网站操作，如“规划旅行并预订最低价机票和酒店”。
2.  **RPA（机器人流程自动化）**：企业级自动化办公，处理表单填写、数据抓取等重复性工作。
3.  **无障碍访问**：帮助视障用户通过自然语言指令操作网页。

### 产业化可能性
DynaWeb架构具有很高的产业化潜力。由于它降低了对真实API调用的依赖，企业可以构建内部的“网页世界模型”，在本地沙箱中快速迭代Agent，而无需担心在公网上产生高昂的费用或触发安全封禁。

### 未来方向
- **多模态扩展**：目前的模型主要基于文本HTML，未来将融入视觉截图信息，处理验证码和复杂的图形界面。
- **个性化世界模型**：为不同领域的网站（如电商、社交）训练专门的世界模型，提高预测精度。

## 6. 研究启示

### 对领域的启示
DynaWeb的研究表明，**Agent的训练范式正在从“在线探索”转向“离线想象”**。这与人类学习的方式非常相似——我们不需要真的去跳崖才知道危险，我们可以通过模拟（思考）来学习。这为解决RL数据稀缺问题提供了明确的方向。

### 需进一步探索的问题
1.  **模型的分布外（OOD）泛化**：当Agent遇到世界模型训练数据中未见过的全新网页结构时，预测会失效。如何提高世界模型的泛化能力？
2.  **奖励函数的设计**：实验中仍依赖基于HTML的奖励（如成功文本匹配），如何设计更通用的、基于视觉或语义的奖励信号？

## 8. 相关工作对比

| 维度 | 传统Prompting (e.g., ReAct) | 离线强化学习 | DynaWeb (本文) |
| :--- | :--- | :--- | :--- |
| **训练方式** | 仅推理时交互，无训练 | 仅使用历史静态数据 | 使用世界模型生成动态数据 |
| **交互成本** | 高（每次推理都需在线） | 低（训练时不交互） | **极低**（大部分交互在虚拟模型中） |

| **创新性评估** | 基线方法 | 传统范式 | **SOTA水平**，引入了动态模拟 |

**地位分析**：DynaWeb目前处于该领域的领先地位，特别是在开源社区。它填补了“低成本训练高性能Web Agent”的空白，是目前少数几个将MBRL成功落地于复杂Web任务的工作之一。

## 9. 研究哲学：可证伪性与边界

### 关键假设与归纳偏置
- **假设**：网页状态的转移逻辑是可以通过历史数据学习到的，且这种逻辑在隐空间中是平滑且可预测的。
- **归纳偏置**：模型假设下一个网页状态主要依赖于当前的HTML文本内容和动作，而非不可见的后台服务器状态。

### 失败条件分析
DynaWeb在以下情况下最可能失败：
1.  **高度对抗性环境**：如果网页包含恶意陷阱或反爬虫机制，世界模型无法预测这些非确定性的行为。
2.  **时间敏感任务**：例如抢票或秒杀，世界模型无法模拟真实网络延迟和并发竞争。
3.  **多模态强依赖**：如果任务的关键信息完全包含在复杂的图像（如滑块验证码、特定图表）中，仅基于HTML的世界模型将失效。

### 事实与推断
- **经验事实**：在WebArena基准测试中，加入想象数据确实提升了成功率。
- **理论推断**：作者推断这种方法可以无限扩展以解决更复杂的任务。但这尚未被完全证实，因为随着任务复杂度增加，世界模型的误差可能会成为瓶颈。

### 方法与理解的推进

## 最佳实践指南

### 实践 1：构建基于DOM树的分层状态表示

**说明**: 
DynaWeb 的核心优势在于利用网页的层次化结构。最佳实践是不要将网页截图作为扁平的像素输入，而是解析 HTML DOM 树。通过这种方式，代理可以理解元素的层级关系（如父级、子级、兄弟级），从而更准确地定位交互元素并理解页面布局，这对于处理复杂或长页面尤为重要。

**实施步骤**:
1. 使用浏览器自动化工具（如 Playwright 或 Selenium）获取页面的 DOM 树结构。
2. 对 DOM 树进行修剪，去除无关紧要的脚本或样式标签，保留交互元素（按钮、输入框）。
3. 将处理后的 DOM 树转换为图结构或序列化 tokens 输入到模型中。

**注意事项**: 
- 在处理动态加载内容时，需确保 DOM 树获取的时机与页面渲染完成状态同步。
- 对于 DOM 树过深的情况，应设置最大深度限制以控制计算开销。

---

### 实践 2：实施世界模型与策略模型的解耦训练

**说明**: 
DynaWeb 强调“想象”与“行动”的分离。最佳实践是分别训练世界模型和策略模型。世界模型负责预测环境动态（即点击某个按钮后页面会变成什么样），而策略模型负责根据预测做出决策。这种解耦允许代理在虚拟环境中进行大量的试错，而无需频繁消耗真实浏览器的资源。

**实施步骤**:
1. 收集真实环境中的交互数据（状态、动作、下一状态、奖励）。
2. 训练世界模型以最小化对下一状态预测的误差。
3. 冻结世界模型参数，使用其生成的“想象”轨迹来训练策略模型。

**注意事项**: 
- 世界模型的准确性至关重要。如果世界模型预测偏差过大，策略模型会在错误的虚拟环境中学习，导致性能下降。
- 需定期使用真实数据更新世界模型，以防止分布漂移。

---

### 实践 3：利用模型想象能力进行数据增强

**说明**: 
真实的网页交互数据获取成本高且速度慢。最佳实践是利用训练好的世界模型生成“想象”的轨迹。通过在模型内部进行“回滚”和“前瞻”，可以生成合成数据来扩充训练集。这有助于提高代理对罕见场景的泛化能力，并加速收敛。

**实施步骤**:
1. 在训练循环中，混合使用真实环境数据和世界模型生成的虚拟数据。
2. 对于高成本或高风险的操作步骤，优先在虚拟环境中进行预演。
3. 设置阈值，仅当世界模型对预测结果的置信度较高时，才将该预测数据用于策略更新。

**注意事项**: 
- 虚拟数据与真实数据的比例需要精心调整，过多的低质量虚拟数据可能会引入噪声。
- 确保生成的虚拟状态在视觉和语义上符合逻辑。

---

### 实践 4：定义紧凑且语义化的动作空间

**说明**: 
网页上的动作空间通常是巨大的（所有可能的坐标和文本输入）。最佳实践是基于 DOM 元素定义动作空间，而不是基于像素坐标。动作应表示为对特定元素的操作（如 `click(button_12)` 或 `type(input_5, "search"`），并结合元素的语义属性（如 ID、XPath、文本内容）来增强可解释性。

**实施步骤**:
1. 编写动作提取器，从 DOM 树中识别所有可交互元素并建立索引。
2. 定义基础动作类型：Click, Type, Scroll, Wait。
3. 将动作表示为 `(元素标识符, 动作类型, 参数)` 的元组形式输入模型。

**注意事项**: 
- 处理动态变化的元素 ID 时，应优先使用稳定的 XPath 或 CSS 选择器。
- 对于 iframe 或 shadow DOM 中的元素，需要特殊处理以确保动作能正确执行。

### 实践 5：引入多模态输入以增强视觉感知

**说明**: 
虽然 DOM 树提供了结构信息，但某些任务依赖视觉线索（如识别验证码、判断图片颜色或布局风格）。最佳实践是采用多模态方法，结合 DOM 的文本特征和页面截图的视觉特征，使代理能够同时理解“代码结构”和“视觉外观”。

**实施步骤**:
1. 使用视觉编码器（如 ResNet 或 ViT）处理页面截图，提取视觉特征向量。
2. 使用文本编码器（如 BERT 或 GPT）处理 DOM 树的文本内容和标签。
3. 在特征融合层将视觉特征和文本特征对齐，作为策略网络的输入。

**注意事项**: 
- 多模态输入会显著增加计算量和推理延迟，需权衡性能与速度。
- 确保视觉特征与 DOM 元素之间的空间对齐是准确的，避免视觉特征错位。

## 学习要点

- DynaWeb 提出了一种基于模型的强化学习框架，通过世界模型在想象空间中进行规划，显著提升了网页智能体的数据效率和泛化能力。
- 该方法引入了基于 HTML 的 Transformer 架构作为世界模型，能够有效预测环境动态并生成高质量的合成轨迹用于策略训练。
- DynaWeb 利用“模型强化数据”策略，通过世界模型生成的幻觉数据与真实数据混合训练，解决了真实网页交互数据稀缺的瓶颈。
- 该架构将决策过程解耦为离线世界模型学习和在线策略优化，使得智能体能够在不依赖实时环境交互的情况下进行大规模试错。
- 实验表明，DynaWeb 在 MiniWoB++ 等基准测试中取得了最先进（SOTA）的性能，证明了基于模型的方法在网页任务中的优越性。
- 该研究验证了将视觉语言模型（VLM）作为世界模型应用于复杂网页导航任务的可行性，为构建自主智能体提供了新的技术范式。

## 常见问题


### 1: DynaWeb 的核心目标是什么，它主要解决了 Web Agent 领域的什么痛点？

1: DynaWeb 的核心目标是什么，它主要解决了 Web Agent 领域的什么痛点？

**A**: DynaWeb 的核心目标是训练能够熟练完成复杂网页任务的智能体。它主要解决了 Web Agent 开发中的两个关键痛点：**数据稀缺**和**环境交互的高成本**。

在传统的强化学习（RL）训练中，Agent 需要在真实的浏览器环境中进行海量的试错，这不仅耗时耗力，而且容易因为频繁的无效操作导致环境崩溃或被网站封禁。DynaWeb 通过引入“基于模型的强化学习”，构建了一个世界模型来模拟真实的网页环境。这使得 Agent 可以在“想象”中进行大量的离线训练，从而显著减少了对真实网页交互的依赖，提高了学习效率。

---



### 2: DynaWeb 的工作原理是什么？它是如何利用“世界模型”的？

2: DynaWeb 的工作原理是什么？它是如何利用“世界模型”的？

**A**: DynaWeb 的工作原理基于 Dyna 架构（一种经典的 MBRL 框架），结合了**环境模型**与**基于模型的策略优化**。其具体流程如下：

1.  **真实交互与数据收集**：Agent 首先在真实的 Web 环境中进行少量的交互，收集真实的轨迹数据（状态、动作、奖励）。
2.  **世界模型训练**：利用收集到的数据训练一个世界模型。该模型能够根据当前的历史状态和动作，预测下一个 DOM 状态以及相应的奖励。这个模型本质上是一个“网页模拟器”。
3.  **想象中的强化学习**：一旦世界模型训练完成，Agent 就不再需要频繁访问真实网页。它可以在世界模型生成的虚拟环境中生成大量的模拟经验，并使用这些模拟数据来更新其策略。
4.  **迭代优化**：Agent 不断在真实环境和模拟环境之间切换，利用真实数据修正模型偏差，利用模拟数据快速提升策略能力。

---



### 3: Web 环境的 HTML DOM 结构非常复杂且动态，DynaWeb 是如何对这些状态进行建模的？

3: Web 环境的 HTML DOM 结构非常复杂且动态，DynaWeb 是如何对这些状态进行建模的？

**A**: 确实，直接对原始 HTML 进行建模非常困难。DynaWeb 采用了一种高效的**基于文本的表示方法**，并结合了 Transformer 架构来处理状态。

具体来说，它将网页 DOM 树转换为一种简化的文本序列，通常包含 HTML 标签、属性（如 id, class）以及文本内容。为了处理这种高维度的序列数据，DynaWeb 的世界模型通常采用类似 GPT 的 Transformer 解码器结构。这种结构能够捕捉 DOM 树中的长距离依赖关系，从而更准确地预测页面在执行动作后的变化。相比于传统的图像建模或图神经网络，这种方法在处理网页文本结构时表现出了更好的效果和效率。

---



### 4: 相比于传统的无模型强化学习，DynaWeb 有哪些具体的优势？

4: 相比于传统的无模型强化学习，DynaWeb 有哪些具体的优势？

**A**: 相比于传统的无模型方法，DynaWeb 的优势主要体现在**样本效率**和**训练稳定性**上：

1.  **更高的样本效率**：传统的 RL（如 DQN 或 PPO）需要数百万次的真实交互才能收敛。DynaWeb 通过世界模型生成的“幻觉”数据进行学习，可以将对真实环境的交互需求降低一个数量级。
2.  **更安全的探索**：在真实网站上盲目探索可能会导致不可逆的操作（如误删数据、下单购买等）。DynaWeb 允许 Agent 在模拟器中先进行高风险的探索，只有在策略成熟后才接触真实环境。
3.  **利用离线数据**：DynaWeb 可以利用过去收集的静态数据集进行预训练，而不需要一直在线运行，这使得资源的利用更加充分。

---



### 5: DynaWeb 在实验中的表现如何？它在哪些基准测试上进行了验证？

5: DynaWeb 在实验中的表现如何？它在哪些基准测试上进行了验证？

**A**: 根据论文报告，DynaWeb 在多个标准的 Web Agent 基准测试中均表现出色，显著优于现有的基线方法。

实验主要在 **MiniWoB++** 和 **WebShop** 等数据集上进行。结果显示，DynaWeb 在达到相同任务成功率的情况下，所需的真实环境步数远少于基于 PPO 或 IMPALA 的方法。特别是在复杂的任务上，DynaWeb 展现出了更强的泛化能力和对长序列任务的处理能力。这证明了基于模型的方法在处理具有复杂状态空间的 Web 导航任务时具有巨大的潜力。

---



### 6: DynaWeb 目前存在哪些局限性或挑战？

6: DynaWeb 目前存在哪些局限性或挑战？

**A**: 尽管 DynaWeb 表现优异，但它仍面临一些挑战：

1.  **模型复合误差**：世界模型是基于真实数据训练的近似模型。当 Agent 在模型中进行多步预测时，预测的误差会逐渐累积，导致模型生成的“虚拟网页”与真实情况出现偏差，进而影响策略的质量。
2.  **复杂动态内容的处理**：虽然基于 Transformer 的模型能处理文本，但对于高度动态的网页（如大量 JavaScript 动画、Canvas 绘图或复杂的即时加载内容），静态的 HTML 表示可能无法完全捕捉其变化，导致世界模型的预测不够准确。
3.  **计算开销**：训练一个高精度的 Transformer 世界模型需要大量的计算资源，这在一定程度上抵消了部分因减少真实交互而节省的成本
