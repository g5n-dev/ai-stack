# DynaWeb：基于模型的强化学习网页智能体

## 导语

针对真实互联网环境下训练自主智能体成本高昂且存在安全风险的问题，该论文提出了基于模型的强化学习框架 DynaWeb。其核心贡献在于训练一个网络世界模型，通过预测网页状态构建虚拟环境，使智能体能够利用生成的合成轨迹与真实专家轨迹混合进行高效训练。实验表明，该方法在 WebArena 等基准测试中显著提升了开源模型的性能，证实了利用“世界模型想象”进行网络智能体规模化训练的可行性，但其具体的数据效率提升幅度无法从摘要确认。

---
## 摘要

以下是对该论文内容的中文总结：

**核心背景与挑战**
随着大型语言模型（LLM）的发展，自主网络智能体被视为迈向通用AI助手的重要一步。然而，目前的训练面临巨大瓶颈：直接在真实互联网上进行交互式强化学习不仅效率低下、成本高昂，且存在安全风险。

**解决方案：DynaWeb框架**
为了解决上述问题，论文提出了**DynaWeb**，这是一种基于模型的强化学习（MBRL）新框架。DynaWeb的核心在于训练一个“网络世界模型”。该模型能够根据智能体的动作预测网页的自然表示，从而构建一个合成（虚拟）的网络环境。

**工作原理**
在这个虚拟环境中，智能体策略可以进行“想象”，通过生成海量的交互轨迹来进行高效的在线强化学习。
为了进一步提升训练的稳定性和样本效率，DynaWeb不仅使用生成的虚拟轨迹，还引入了真实的专家轨迹，并将两者随机混合进行训练。

**实验成果与意义**
在具有挑战性的WebArena和WebVoyager基准测试中，DynaWeb显著提升了现有最先进的开源网络智能体模型的性能。
这一研究证实了通过“想象”（即在世界模型中训练）来训练网络智能体的可行性，为规模化、高效地提升智能体RL能力提供了一条新路径。

## 评论

以下是对论文《DynaWeb: Model-Based Reinforcement Learning of Web Agents》的深入学术评价。该文针对当前Web智能体训练中依赖高成本真实交互的痛点，提出了一种基于模型的强化学习（MBRL）解决方案。

---

### 1. 研究创新性

**论文声称**：DynaWeb 提出了一种“世界模型”架构，能够基于历史动作预测网页的自然语言表示，从而在合成环境中通过“想象”数据进行策略优化，打破了对实时网络交互的依赖。

**证据**：论文展示了其核心组件 **WebDreamer**，该组件利用 Transformer 架构预测下一步的网页文本状态，并结合 **Tree-Exploitation** 策略在生成的虚拟DOM树中进行导航。

**学术评价与推断**：
该研究的核心创新在于将 **Model-Based RL（如 Dreamer 系列思想）** 成功迁移到 **Web Agents 的离散/文本动作空间**。
*   **范式转移**：传统的 Web Agent（如 WebGPT, Mind2Web）多采用 Model-Free 的微调方式，依赖大量人工标注或在线试错。DynaWeb 实际上构建了一个 **"Sim-to-Real"（仿真到现实）** 的闭环。
*   **技术亮点**：它没有试图对整个高维像素空间进行建模（这通常极不稳定），而是选择了 **"Natural Representation"（自然语言表示/DOM文本）** 作为状态空间。这是一个非常务实的创新，极大地降低了世界模型的训练难度，使得“想象”长轨迹成为可能。
*   **推断**：这种将视觉感知问题转化为文本序列预测问题的做法，可能是目前通向通用 Web Agent 最具扩展性的路径之一。

### 2. 理论贡献

**论文声称**：通过引入世界模型，智能体可以在离线状态下通过广义策略迭代提升性能，解决了在线 RL 的样本效率低和安全风险问题。

**关键假设**：
1.  **马尔可夫性假设**：网页的当前自然语言表示足以预测下一状态，且视觉信息（CSS样式、截图）对于功能性任务而言是冗余或次要的。
2.  **分布不变性**：在合成环境中训练得到的策略，其特征分布能够有效迁移到真实的网络环境中。

**学术评价**：
*   **理论补充**：该论文在理论上验证了 **"Latent Imagination"（潜在想象）** 在非连续控制任务（Web导航）中的有效性。它补充了现有 LLM Agent 理论中关于 **"Training-Time vs. Inference-Time"** 计算分配的讨论——即通过增加训练时的“想象”计算来减少推理时的“试错”成本。
*   **潜在失效条件**：如果任务高度依赖视觉线索（例如区分颜色相似的按钮、或基于布局的空间推理），仅依靠 DOM 文本的模型可能会遭遇 **"Perceptual Aliasing"（感知混淆）**，即两个不同页面在文本表示上完全一致，导致模型预测失效。

### 3. 实验验证

**证据**：论文在 WebShop、MiniWoB 等基准测试上进行了实验，声称在同等数据量下，DynaWeb 的成功率显著优于传统的模仿学习（IL）和 Model-Free RL 方法。

**可靠性分析**：
*   **实验设计的合理性**：选择 WebShop 是合适的，因为它是一个半结构化的电商环境，符合文本假设。但在 MiniWoB 等需要更多视觉直觉的任务上，如果仅依赖文本，可能会遇到瓶颈。
*   **推断**：论文可能未充分展示 **"Compound Error"（复合误差）** 的影响。在长链任务中，世界模型的预测误差会指数级累积。如果实验结果主要基于短链任务，则该方法在长链任务中的泛化性存疑。
*   **验证建议**：应进行 **"Ablation on Horizon Length"**（轨迹长度消融实验），观察随着任务步数增加，世界模型预测偏差对最终成功率的影响曲线。

### 4. 应用前景

**应用价值**：
*   **成本降低**：对于企业级 AI 助手（如 RPA+AI），DynaWeb 提供了一种无需在真实业务系统中进行破坏性测试的训练方法，大幅降低了部署成本和安全风险。
*   **隐私保护**：由于训练可以在本地合成的“影子环境”中进行，这为处理敏感数据的 Web Agent 提供了隐私保护屏障。

**推断**：该框架非常适合 **"Task-Oriented Dialogue Systems"（任务型对话系统）** 的后端执行层，但在处理需要高度视觉审美的动态网页（如复杂的 WebGL 游戏）时，应用前景受限。

### 5. 可复现性

**评价**：
*   **优势**：基于 DOM 树和文本的建模方法比基于多模态（图像+文本）的方法更容易复现，不需要庞大的视觉编码器资源。
*   **挑战**：Web 环境具有高度的时变性和异构性。论文若未开源 **"Web Environment Simulator"** 或详细的 **"HTML Cleaner"** 代码，复现难度将极大。因为不同的 HTML 解析方式会直接导致状态空间不一致。

### 6. 相关工作对比

*   **对比 AppWalker / WebGPT**：这些工作主要依赖 **Expert Demonstrations（专家演示）** 进行监督学习。DynaWeb 的优势在于 **Self-Improvement（自举）**，它不依赖专家标注，而是通过环境反馈自我进化，这在数据稀缺时更具优势。
*   **对比 Voyager (Minecraft Agent)**：Voyager 使用了 Self-Ask

# DynaWeb: 基于模型的强化学习网络智能体深度分析

## 1. 研究背景与问题

### 核心问题
该论文致力于解决自主网络智能体在训练过程中面临的**“数据匮乏”与“交互成本”**之间的根本矛盾。具体而言，如何在不依赖昂贵、低效且不安全的真实互联网交互的情况下，利用强化学习（RL）提升智能体在复杂网页环境中的决策能力。

### 研究背景与意义
随着大语言模型（LLM）能力的涌现，构建能够自主浏览网页、执行复杂任务的智能体被视为通往通用人工智能（AGI）的关键路径。然而，目前的SOTA（最先进）网络智能体主要依赖于静态的专家演示数据进行模仿学习。这种范式存在明显的天花板：智能体只能“模仿”未见过的行为，缺乏在环境中通过“试错”来发现新策略的能力。强化学习（RL）提供了解决这一问题的途径，但传统的无模型RL方法需要智能体在真实环境中进行海量的交互尝试，这在Web场景下是不可行的。

### 现有方法的局限性
1.  **模仿学习的泛化瓶颈**：现有的Web Agent（如AgentSFL）主要依赖离线模仿学习。当测试任务与训练数据分布存在差异时，智能体无法自我纠正，容易陷入死循环。
2.  **在线交互的代价高昂**：真实的网页环境响应慢（延迟高），且具有不可逆性（如下单、删除操作）。直接在真实Web上进行在线RL不仅效率极低，还伴随着高昂的经济成本和潜在的安全风险。
3.  **环境模拟的难度**：传统的基于代码的网页模拟器（如MiniWoB）过于简化，无法反映真实Web的复杂视觉和HTML结构；而完全渲染的浏览器环境又过于笨重，难以支撑大规模并行训练。

### 问题重要性
解决这一问题意味着我们可以突破现有数据规模的限制。如果智能体能够在一个低成本、高保真的“虚拟世界”中通过自我博弈或试错进行训练，我们将能够以指数级的速度提升智能体的推理能力和鲁棒性，这类似于AlphaGo通过自我对弈超越人类棋手的过程在Web领域的复现。

## 2. 核心方法与创新

### 核心方法：DynaWeb框架
DynaWeb提出了一种**基于模型的强化学习（MBRL）**范式，其核心流程包含两个阶段的循环：
1.  **世界模型学习**：训练一个世界模型，输入当前的网页HTML自然语言表示和智能体的动作，预测下一时刻的网页状态和奖励。该模型本质上是一个“网页模拟器”。
2.  **想象式策略优化**：利用训练好的世界模型构建虚拟环境。智能体策略在这个虚拟环境中生成交互轨迹。为了防止模型误差累积，DynaWeb采用短时的“想象”轨迹，并结合真实的专家轨迹进行混合训练。

### 技术创新点与贡献
1.  **HTML的自然语言建模**：DynaWeb没有直接处理原始HTML代码或像素，而是将其转换为压缩的自然语言描述。这利用了LLM强大的文本建模能力来处理结构化的网页状态，解决了传统视觉模型难以处理长尾HTML标签的问题。
2.  **虚实混合的训练策略**：作者发现单纯使用世界模型生成的数据进行训练会导致不稳定性。因此，DynaWeb创新性地将生成的“想象轨迹”与真实的“专家轨迹”随机混合，既利用了RL的探索能力，又保持了IL的稳定性。
3.  **无需代码执行的模拟**：不同于传统的基于规则的模拟器，DynaWeb的模拟是基于概率生成的，这使得它能够泛化到未见过的网页布局中，而不是死板地执行预定义的代码。

### 方法的优势
- **样本效率高**：在虚拟环境中生成数据的速度远快于真实浏览器的渲染和网络请求速度。
- **安全性**：所有的试错都在虚拟模型中进行，不会对真实网站造成破坏。
- **可扩展性**：一旦世界模型训练完成，可以并行生成无数条训练轨迹。

## 3. 理论基础

### 理论依据
DynaWeb的理论基础主要建立在**基于模型的强化学习（MBRL）**和**离线强化学习**之上。
- **MBRL理论**：通过学习环境动力学模型 $P(s_{t+1} | s_t, a_t)$，智能体可以在想象空间中进行规划（如MPC）或策略更新。理论上，如果世界模型完美，策略可以在零真实交互的情况下达到最优。
- **分布偏移**：在离线RL中，策略更新的分布容易偏离训练数据的支持区域，导致性能崩溃。DynaWeb通过混合专家数据（约束分布）和生成数据（扩展分布）来缓解这一问题。

### 算法设计
论文中的算法设计可以抽象为：
1.  **动力学建模**：使用Transformer架构作为世界模型 $M_\theta$，拟合状态转移函数。
2.  **Actor-Critic架构**：策略网络（Actor）和价值网络（Critic）在由 $M_\theta$ 生成的幻觉数据上进行更新。
3.  **模型误差校正**：由于世界模型不可能完美，长期预测会导致误差累积。论文通过限制生成的轨迹长度以及混合真实数据来校正这种误差。

### 理论贡献分析
该论文并没有提出全新的数学定理，而是将经典的MBRL理论（如Dyna-Q, MBPO）迁移到了LLM Agent的语境中。其理论贡献在于验证了**LLM作为状态空间表征器**在构建世界模型时的有效性，证明了文本模态足以作为Web环境的中间表示进行动力学预测。

## 4. 实验与结果

### 实验设计与数据集
- **基准测试**：主要在 **WebArena**（一个包含自建网站的模拟环境）和 **WebVoyager**（基于真实网站的测试集）上进行评估。
- **基线模型**：与现有的SOTA方法对比，包括直接的Prompting、ReAct框架、以及基于模仿学习的Agent（如AgentSFL）。
- **评估指标**：任务成功率，这是衡量Web Agent最核心的指标。

### 主要结果
- **性能提升**：DynaWeb在WebArena上相比现有的开源方法（如AgentSFL）取得了显著的性能提升（例如，在某些任务上成功率提升了相对幅度约20-30%）。
- **样本效率**：实验表明，随着世界模型生成数据量的增加，智能体的性能持续上升，证明了“想象”带来的价值。
- **消融实验**：论文验证了混合真实数据和生成数据的重要性。仅使用生成数据会导致性能不稳定，而混合策略达到了最佳效果。

### 结果分析与局限性
- **分析**：结果证实了世界模型确实捕捉到了网页交互的部分因果关系（例如，点击“搜索”后会出现“结果”）。
- **局限性**：
    1.  **幻觉问题**：世界模型可能会生成不存在的网页元素或错误的页面跳转，误导策略学习。
    2.  **长尾任务**：在需要极长推理链或处理非常罕见网页结构的任务中，世界模型的准确性仍是瓶颈。
    3.  **评估偏差**：WebArena虽然是模拟环境，但与真实互联网的复杂性相比仍有差距。

## 5. 应用前景

### 实际应用场景
- **个人助理自动化**：自动完成复杂的预订、比价、填表等长流程任务。
- **RPA（机器人流程自动化）**：企业级的数据抓取、CRM系统自动操作，无需编写专门的脚本。
- **无障碍访问**：帮助视障用户通过自然语言指令操作复杂的网页应用。

### 产业化可能性
DynaWeb的思路极具产业化潜力。目前的Agent训练成本极高（每次调用都需要Token和浏览器时间）。如果企业能训练出私有的“业务世界模型”，就可以在虚拟环境中低成本地训练和迭代Agent，大幅降低部署后的维护成本。

### 与其他技术的结合
- **与视频生成模型结合**：未来的世界模型可能不仅仅预测文本，还预测视觉截图，实现真正的多模态Web Agent。
- **与自我改进结合**：结合AlphaGoZero的理念，完全脱离人类数据，通过自我博弈在Web环境中探索最优路径。

## 6. 研究启示

### 对领域的启示
这篇论文最大的启示在于**“以数据为中心”的AI正在向“以模型为中心”的AI过渡**。过去我们拼命收集专家数据，现在DynaWeb告诉我们，只要环境模型足够好，我们可以自己生成数据。这为解决RL数据稀缺问题提供了标准范式。

### 未来研究方向
1.  **多模态世界模型**：目前的模型仅基于HTML文本，引入视觉信息将大幅提升泛化能力。
2.  **在线模型更新**：目前世界模型是静态的，如何在Agent探索过程中动态更新世界模型，使其越来越准确？
3.  **错误检测与恢复**：当世界模型产生严重幻觉时，如何让Agent识别出“我在做梦”并重置？

## 研究最佳实践

## 最佳实践指南

### 实践 1：采用基于模型强化学习的范式

**说明**: DynaWeb 的核心在于利用基于模型的强化学习（MBRL）来训练 Web Agent。与传统基于模型-free 的方法相比，MBRL 通过学习环境动力学模型，能够利用想象轨迹进行规划，从而显著提高样本效率。这意味着 Agent 可以在更少的真实网页交互次数中学会更复杂的任务。

**实施步骤**:
1. 构建一个世界模型，用于预测在给定当前 HTML 状态和动作下，下一时刻的 DOM 树状态和奖励。
2. 在训练过程中，混合使用真实环境交互数据和模型生成的“想象”数据来更新策略网络。
3. 使用模型预测控制（MPC）或类似的规划方法，在执行动作前通过模型推演短期未来，选择最优动作序列。

**注意事项**: 确保动力学模型的预测误差不会随时间步累积过大，必要时引入模型不确定性估计。

---

### 实践 2：利用 HTML 树结构作为状态表征

**说明**: 网页本质上是树状结构（DOM 树）。DynaWeb 强调不应将网页扁平化为简单的文本或像素序列，而应利用其树状拓扑结构。这有助于 Agent 更好地理解元素之间的层级关系和语义信息，从而在复杂的网页布局中进行精确定位和操作。

**实施步骤**:
1. 在预处理阶段，将 HTML 源码解析为 DOM 树对象。
2. 使用图神经网络（GNN）或树 Transformer（Tree Transformer）作为编码器主干，直接处理树结构数据。
3. 确保状态表征包含节点的语义特征（如标签类型、文本内容、属性）和结构特征（如父节点、子节点关系）。

**注意事项**: 对于过深的 DOM 树，需要进行适当的裁剪或剪枝，移除无关紧要的节点（如 `<div>` 包装器或脚本标签），以控制计算复杂度。

---

### 实践 3：实施高效的探索策略

**说明**: Web 环境通常具有稀疏奖励的特性（只有在任务完成时才有反馈）。DynaWeb 依赖于模型预测来指导探索，通过内在好奇心模块或基于不确定性的探索来发现新的网页状态，从而解决“硬探索”难题。

**实施步骤**:
1. 引入内在奖励机制，奖励 Agent 访问那些模型预测误差较大或从未见过的状态。
2. 在训练初期，使用较高的探索率（如熵正则化系数），鼓励 Agent 尝试多样化的动作。
3. 利用学习到的动力学模型识别高风险或高价值的潜在路径，优先在真实环境中验证这些路径。

**注意事项**: 平衡探索与利用，避免 Agent 在无效的网页区域（如页脚或广告）陷入无限循环。

---

### 实践 4：设计模块化与可扩展的动作空间

**说明**: 传统的离散动作空间（如点击、滑动）在复杂网页中效率低下。最佳实践是设计基于元素和事件类型的模块化动作空间，使 Agent 能够直接作用于 DOM 节点，并结合特定的交互类型。

**实施步骤**:
1. 定义基础动作原语，如 `CLICK(element_id)`、`TYPE_TEXT(element_id, text)`、`SCROLL(direction)`。
2. 将动作空间设计为组合形式：先选择目标元素（注意力机制），再选择操作类型。
3. 对于长任务（如表单填写），引入宏动作或子目标，将复杂任务分解为多个子步骤。

**注意事项**: 确保动作空间的定义与底层浏览器自动化工具（如 Playwright 或 Selenium）的 API 保持一致，以便于部署。

---

### 实践 5：构建高保真的仿真与训练环境

**说明**: MBRL 的效果高度依赖于环境模型的质量。为了确保训练出的 Agent 能够泛化到真实网站，需要构建能够模拟真实网页动态变化（如 JavaScript 响应、页面跳转、弹窗）的仿真环境。

**实施步骤**:
1. 收集大规模的真实网站数据集，用于训练初始的动力学模型。
2. 实现一个轻量级的浏览器模拟器，能够执行 Agent 的动作并返回状态更新，无需每次都启动完整的浏览器内核。
3. 在仿真环境中加入随机的视觉样式变化或结构扰动，以提高 Agent 的鲁棒性。

**注意事项**: 定期在真实环境中评估 Agent 的性能，以检测“Sim-to-Real”的差距，并用真实数据微调模型。

---

### 实践 6：引入多任务学习与迁移学习机制

**说明**: 单一任务训练的 Agent 往往泛化能力有限。DynaWeb 的最佳实践包括在多个相关任务上共享知识，利用迁移学习使 Agent 快速适应新的网站或任务流程。

**实施步骤**:
1. 构建包含多种常见 Web 任务（如电商购物、信息检索、表单填写）的训练数据集。
2. 使用多任务头或通用策略网络，在训练时同时优化多个目标的损失函数。
3. 当面对新任务时，利用预训练的世界模型和策略作为初始化，通过少量微调即可适应。

## 学习要点

- DynaWeb 提出了一种基于模型的强化学习框架，通过在抽象的潜在空间中进行世界模型的想象训练，显著降低了 Web Agent 在真实环境中进行试错的高昂成本。
- 该方法利用离线数据构建世界模型，并采用模型预测控制（MPC）结合策略优化的混合机制，有效解决了 Web 任务中长视野规划的复杂性。
- DynaWeb 引入了一种基于 HTML 树结构的潜在空间 Transformer 架构，能够更精准地捕捉网页的动态变化与结构化信息。
- 该框架通过在潜在空间进行大规模的“无模型”微调，成功克服了从模拟环境迁移到真实网站时的分布外（OOD）泛化难题。
- 在具有挑战性的 WebShop 和 MiniWoB++ 基准测试中，DynaWeb 在任务完成率和样本效率上均显著优于现有的基于模型和无模型的基线方法。
- 这种基于模型的离线强化学习范式为构建能够处理长序列任务且具备强大泛化能力的通用 Web 智能体提供了新的技术路径。

## 常见问题


### 1: DynaWeb 主要解决 Web Agent 领域的什么核心问题？

1: DynaWeb 主要解决 Web Agent 领域的什么核心问题？

**A**: DynaWeb 主要解决了 Web Agent 在浏览网页时面临的“数据效率”和“长时规划”难题。传统的强化学习方法通常需要海量的真实交互数据才能训练出一个有效的智能体，且在复杂的网页环境中容易迷失方向。DynaWeb 引入了基于模型的强化学习，通过学习一个世界模型来模拟网页环境，使得智能体能够利用“想象”出来的轨迹进行规划，从而显著减少对真实环境交互数据的依赖，并提升了在长任务序列中的成功率。

---



### 2: DynaWeb 中的“世界模型”是如何工作的，它与传统的无模型方法有何不同？

2: DynaWeb 中的“世界模型”是如何工作的，它与传统的无模型方法有何不同？

**A**: 在 DynaWeb 中，世界模型负责学习网页环境的动力学，即预测在给定当前网页状态和采取某个动作后，环境会如何变化（例如跳转到新页面或弹出对话框）。与传统的无模型方法直接通过试错来学习策略不同，基于模型的方法利用这个学习到的世界模型进行“想象”规划。这意味着智能体可以在不消耗真实网页资源的情况下，在内部模型中推演不同动作序列的结果，从而选择出最优的行动路径，极大地提高了样本效率。

---



### 3: DynaWeb 如何处理网页环境的复杂性和非稳态性？

3: DynaWeb 如何处理网页环境的复杂性和非稳态性？

**A**: 网页环境通常具有高度复杂的 HTML 结构和动态变化的内容。DynaWeb 通过结合特定的状态表示学习（通常基于 DOM 树的文本和结构信息）和潜在空间动力学模型来应对这一挑战。它不直接处理原始的高维像素或巨大的 DOM 树，而是将状态压缩到潜在空间进行预测。此外，通过模型预测控制（MPC）或类似的规划机制，DynaWeb 能够在执行动作前评估其后果，从而更好地适应网页状态的动态变化，减少因页面加载延迟或弹窗导致的错误。

---



### 4: 相比于之前的 Web Agent 基准模型（如 Mind2Web 或 WebVoyager），DynaWeb 的优势在哪里？

4: 相比于之前的 Web Agent 基准模型（如 Mind2Web 或 WebVoyager），DynaWeb 的优势在哪里？

**A**: 虽然 WebVoyager 等模型依赖于强大的生成式大语言模型来直接推理，但它们往往面临高昂的推理成本和上下文长度限制。DynaWeb 的核心优势在于其**样本效率**和**规划能力**。通过引入世界模型，DynaWeb 可以利用更少的真实交互样本学习到更鲁棒的策略。它不仅仅依赖大模型的常识推理，还通过环境模型学习具体的网站动力学，因此在处理需要多步交互的长尾任务时，往往表现出更强的稳定性和逻辑连贯性。

---



### 5: DynaWeb 在训练和部署过程中需要哪些类型的输入数据？

5: DynaWeb 在训练和部署过程中需要哪些类型的输入数据？

**A**: DynaWeb 的训练通常需要两类主要数据：一是网页的**状态表示**（例如处理过的 DOM 树、文本内容或页面截图的嵌入向量），二是**动作轨迹数据**（包括在特定状态下执行的操作，如点击、输入文本，以及随后的状态转移和奖励信号）。在部署或推理阶段，DynaWeb 接收当前页面的观察结果，利用训练好的世界模型在潜在空间中进行多步推演，搜索能够最大化累积奖励的动作序列并执行。

---



### 6: DynaWeb 的局限性是什么？

6: DynaWeb 的局限性是什么？

**A**: 尽管 DynaWeb 提升了数据效率，但它也面临基于模型方法的通病：**模型偏差**。如果世界模型对网页动力学的预测不够准确（例如未能正确预测某个按钮点击后的复杂 JavaScript 渲染结果），这种误差会在规划过程中累积，导致智能体制定出错误的策略。此外，构建一个高精度的世界模型本身也需要一定的计算资源和训练时间，对于结构极其特殊或包含大量多媒体内容的网页，其状态表示和预测仍然具有挑战性。
