## 导语

针对多轮智能体工具使用中任务复杂且难以有效评估的问题，本文提出了 CM2 框架，利用清单奖励机制来强化学习过程。该方法通过将复杂的长期目标分解为可验证的子任务，旨在解决传统稀疏奖励下的训练难题。然而，摘要未详细披露具体的奖励计算细节及在长序列任务中的稳定性表现，这些方面无法从摘要确认。该研究为提升多步推理智能体的可控性与执行效率提供了新的思路。

## 摘要

本文介绍了一种名为 **CM2** 的新强化学习（RL）框架，旨在解决多轮、多步骤智能体工具使用中的训练难题。

**核心问题：**
目前将强化学习应用于此类智能体面临三大挑战：
1.  现实任务通常缺乏可验证的奖励信号，更强调开放性行为。
2.  多轮工具使用的 RL 研究尚不充分。
3.  构建和维护可执行的工具环境成本高昂，限制了规模。

**解决方案：**
CM2 用 **“清单奖励”** 替代了传统的可验证结果奖励。
*   **机制：** 将每一轮的预期行为分解为细粒度的二元标准，并辅以明确的证据锚定和元数据。这将开放式的评判转化为更稳定的分类式决策。
*   **策略：** 采用“稀疏奖励分配”与“密集评估标准”相结合的策略，以平衡稳定性和信息量。
*   **环境：** 训练在可扩展的 LLM 模拟工具环境中进行，无需繁重的工程构建，降低了对大规模真实工具集的依赖。

**实验结果：**
实验表明，CM2 始终优于监督微调（SFT）。基于 8B Base 模型在 8k 示例数据集上的训练结果显示：
*   在 **tau^-Bench** 上提升 **8** 分；
*   在 **BFCL-V4** 上提升 **10** 分；
*   在 **ToolSandbox** 上提升 **12** 分。

这些结果不仅大幅超越了 SFT 基线，还匹配或超越了同规模的开源模型（包括作为裁判的模型），证明了 CM2 是一种无需依赖可验证奖励即可优化复杂工具使用智能体的有效且可扩展的方案。

### **CM2: 强化学习清单奖励机制在多轮智能体中的应用评价**

#### **1. 研究创新性**
*   **论文声称：** 现有的Agent训练依赖于稀疏的任务成功信号或昂贵的模型评判，而CM2提出了一种“清单奖励”机制，将开放式的工具使用任务分解为细粒度的二元标准。
*   **证据分析：** 这种方法的核心创新在于**奖励信号的分解与结构化**。传统的RL在工具使用中往往面临“信用分配”难题——即智能体执行了十步操作，只有最后一步错了，传统奖励会惩罚整个序列。CM2通过引入“清单”，实际上是将一个高维的连续奖励问题转化为一系列低维的分类问题。
*   **学术评价：** 这是一个极具实用主义色彩的创新。它借鉴了思维链中的分解思想，将其应用于奖励建模。这种方法不仅降低了奖励模型的训练难度（从判断“回答好不好”变成了判断“是否调用了API”），还增加了训练过程的可解释性。

#### **2. 理论贡献**
*   **论文声称：** CM2能够解决多轮工具使用中信号稀疏的问题，并减少对昂贵可执行环境的依赖。
*   **理论补充：** 该工作在理论上并未提出全新的RL算法（如PPO的新变体），而是对**In-context RL（上下文学习强化）**和**Reward Modeling（奖励建模）**范式的补充。
    *   **关键假设：** 假设复杂工具任务的“成功”可以通过一系列局部行为的“正确性”线性组合来近似。
    *   **潜在风险：** 这种假设存在**还原论**的风险。即，智能体可能学会了“完美执行清单上的所有步骤”（例如正确解析参数、正确调用函数），但未必能学会“灵活处理未列在清单上的边缘情况”。这可能导致Agent在长链条推理中出现“机械执行”而非“智能决策”的现象。

#### **3. 实验验证**
*   **推断分析：** 考虑到论文强调“多轮”和“工具使用”，其实验验证可能集中在以下方面：
    *   **指标：** 工具调用准确率、任务最终成功率以及推理步数。
    *   **对比：** 应该与传统的Outcome Reward Model（ORM，仅判断最终结果）和Process Reward Model（PRM，判断每一步推理）进行对比。
*   **关键检验：**
    *   **鲁棒性检验：** 当工具返回错误信息或工具API定义发生微小变化时，依赖清单训练的Agent是否比端到端RL的Agent更具鲁棒性？
    *   **长尾效应：** 在清单未覆盖的边缘案例中，Agent的表现是否会出现显著退化？

#### **4. 应用前景**
*   **应用价值：** CM2具有极高的工业落地价值。
    *   **降低成本：** 它允许在不运行真实代码或API的情况下，仅通过检查生成的轨迹是否符合清单规范来训练模型。这对于训练涉及昂贵操作（如数据库查询、电商下单）的Agent至关重要。
    *   **调试与监控：** 清单为人类审查Agent行为提供了自然的中断点和检查点，便于在SaaS产品中集成可观测性。
*   **适用场景：** 尤其适用于流程标准化程度较高的场景，如客户服务工单处理、自动化运维脚本生成、标准化的数据检索与分析。

#### **5. 可复现性与方法清晰度**
*   **分析：** “清单”的构建质量直接决定了CM2的上限。如果论文未详细披露如何自动化构建这些清单（例如，是依赖人工编写，还是通过强模型自动生成），则复现难度较大。
*   **关键挑战：** 人工编写细粒度清单的成本可能很高。如果清单构建本身依赖大量人工标注，那么CM2所谓的“解决成本高昂”的Claim就会打折扣。
*   **验证建议：** 复现实验应重点测试“清单质量对模型性能的影响”，即清单的覆盖率与精确率如何影响最终Agent的效果。

#### **6. 相关工作对比**
*   **对比维度：**
    *   **vs. ReAct/Reflexion：** ReAct依赖Prompt Engineering，CM2通过RL微调基座模型，具备更好的泛化能力和指令遵循能力，不严重依赖上下文示例。
    *   **vs. ToolFormer：** ToolFormer侧重于通过自监督学习何时调用工具，而CM2侧重于在多轮交互中如何正确地组合工具。
    *   **vs. 传统RLHF：** 传统RLHF训练出的Agent往往倾向于“用嘴解决”（幻觉工具调用），而CM2通过细粒度奖励强制Agent进行工具交互，能有效抑制幻觉。

#### **7. 局限性与未来方向**
*   **局限性：**
    1.  **清单维护成本：** 随着工具生态系统的扩展，维护海量工具的清单将是一个巨大的工程负担。
    2.  **缺乏创造性：** 严格遵循清单可能限制了Agent探索非标准路径解决复杂问题的能力。
*   **未来方向：**
    *   **自动清单生成：** 研究如何利用GPT-4等强模型自动为特定任务生成验证清单。
    *   **动态清单：** 在多轮交互中，根据前序步骤动态调整后续步骤

# CM2: 基于清单奖励的多轮多步智能体工具使用强化学习框架深度解析

## 1. 研究背景与问题

### 核心问题
本研究致力于解决大语言模型（LLM）作为智能体在**多轮、多步骤工具使用**场景下的训练优化问题。核心痛点在于：在复杂的真实任务中，如何在没有明确“对/错”二元答案（如数学题或代码题）的情况下，通过强化学习（RL）有效提升智能体的规划能力和工具调用准确性。

### 研究背景与意义
随着 LLM 能力的提升，研究重心已从单一的问答转向了能够使用外部工具、进行多轮交互的智能体系统。这类系统在客服、私人助理、自动化运维等领域具有极高的应用价值。然而，现有的智能体训练严重依赖监督微调（SFT）。SFT 虽然能教会模型“如何使用工具”，却难以有效训练模型在长链路推理中的“规划”与“纠错”能力。强化学习被视为解决这一问题的关键技术，但在工具使用场景下，RL 的落地面临巨大阻碍。

### 现有方法的局限性
1.  **稀疏与不可验证的奖励：** 传统的 RL 依赖环境反馈（如游戏得分、代码编译结果）。但在现实世界的工具任务（如订票、查询数据库）中，结果往往是开放式的，难以定义一个简单的标量奖励函数。
2.  **多轮交互的复杂性：** 现有的 RL 研究（如 RLHF）多关注单轮生成。多轮工具使用涉及长序列决策，状态空间巨大，信用分配困难，即很难确定最终的成功或失败是由序列中的哪一步决定的。
3.  **环境构建成本：** 构建能够模拟真实工具交互、支持大规模训练的物理或虚拟环境成本极高，且难以扩展。

### 为什么重要
CM2 的提出打破了“工具使用只能靠 SFT”的僵局，提供了一种在不依赖昂贵真实环境或可验证结果的情况下，利用 RL 优化复杂智能体的通用路径。这对于提升 LLM 在实际工业场景中的可靠性和任务完成度具有重要的里程碑意义。

## 2. 核心方法与创新

### 提出的核心方法：CM2 框架
CM2（Checklist Multi-step Multi-turn）是一种结合了**清单式奖励机制**与**LLM 模拟环境**的强化学习框架。其核心流程如下：
1.  **LLM 模拟环境：** 不依赖真实的 API 或物理环境，而是利用 LLM 根据预设的文档和用户查询，模拟工具的返回结果。这使得训练可以低成本、大规模并行进行。
2.  **清单奖励机制：** 这是论文的灵魂。不再使用单一的“成功/失败”作为奖励，而是将每一轮的预期行为分解为细粒度的二元检查项。
    *   **细粒度标准：** 例如，是否调用了正确的工具？参数是否包含必需字段？是否处理了上一轮的错误？
    *   **证据锚定：** 每个检查项必须对应具体的文本证据（如对话历史中的特定片段），将开放式的评判转化为分类任务。

### 技术创新点
1.  **从“结果奖励”转向“过程奖励”：** CM2 实质上是一种过程奖励模型（PRM）的应用变体。它不等待任务结束才给分，而是对每一个步骤进行评分，解决了长链路任务中的信用分配问题。
2.  **稀疏奖励分配与密集评估标准的结合：** 在 RL 训练中，清单项作为密集的监督信号指导模型优化，但在计算最终奖励时，采用稀疏策略（如仅关键步骤加权），以平衡训练的稳定性与信息的丰富度。
3.  **数据飞轮效应：** 利用 LLM 生成数据、模拟环境、再通过 RL 训练模型，形成了一个可自我迭代的闭环。

### 方法的优势
*   **可扩展性：** 无需昂贵的真实 API 调用，仅靠 LLM 模拟即可生成海量训练数据。
*   **可解释性：** 清单奖励提供了明确的训练信号，研究人员可以清楚地知道模型在哪个环节出错，而非仅仅看到一个低分。
*   **鲁棒性：** 细粒度的二元分类比开放式的评分更稳定，减少了高维奖励信号带来的噪声。

## 3. 理论基础

### 理论依据
CM2 的理论根基主要建立在**强化学习中的信用分配**与**奖励塑化**之上。
*   **信用分配：** 在多步决策中，传统的稀疏奖励（仅在最后一步给分）难以让模型知道中间哪一步是关键的。CM2 通过清单将奖励信号分解到每一步，数学上等同于将全局回报 $R$ 分解为局部回报 $r_t$ 的组合，降低了策略梯度的方差。
*   **奖励塑化：** 通过引入元数据和证据锚定，CM2 实际上是在对原始的奖励函数进行正则化，防止模型通过作弊（例如输出无效的工具调用）来骗取奖励。

### 算法设计
论文采用了基于 **REINFORCE** 或 **PPO（Proximal Policy Optimization）** 的变体。
*   **奖励函数：** $R(\tau) = \sum_{t=1}^{T} \sum_{i=1}^{N} w_i \cdot \mathbb{I}(c_{t,i})$，其中 $\tau$ 是轨迹，$c_{t,i}$ 是第 $t$ 步的第 $i$ 个检查项。
*   **二元分类器：** 清单项的判定被建模为二元分类问题，这比直接回归分数更容易训练且更准确。

## 4. 实验与结果

### 实验设计
*   **基线：** 监督微调（SFT）模型，以及同规模的开源模型（如 Llama-3-8B-Instruct 等）。
*   **训练数据：** 8k 示例数据集，基于 8B Base 模型。
*   **评估基准：**
    *   **tau^-Bench：** 侧重于多工具、多轮的零售和旅游场景。
    *   **BFCL-V4：** 伯克利函数调用基准，测试工具调用的准确性。
    *   **ToolSandbox：** 一个模拟的交互环境。

### 主要结果
*   **显著提升：** 在所有基准上，CM2 均大幅优于 SFT 基线（提升幅度在 8-12 分）。
*   **模型超越：** 值得注意的是，CM2 训练出的 8B 模型在部分任务上甚至超过了作为裁判的更大规模的模型（如 GPT-4 系列在特定子任务上的表现），证明了 RL 在提升模型效能上的“乘数效应”。

### 结果分析与局限性
*   **分析：** 结果证明了清单奖励能够有效纠正模型的幻觉和工具调用错误。RL 训练后的模型在处理复杂指令和长上下文时表现更稳健。
*   **局限性：**
    1.  **模拟与现实的 Gap：** 实验主要在 LLM 模拟环境中进行，模型在真实、充满噪声和异常的 API 环境中的表现仍有待验证。
    2.  **清单构建成本：** 虽然比构建环境便宜，但为每个任务编写细粒度的清单仍然需要人力，如何自动化生成清单是一个挑战。
    3.  **二元局限：** 某些任务的表现是连续的（如“语气是否恰当”），二元清单可能丢失部分信息。

## 5. 应用前景

### 实际应用场景
1.  **企业级智能客服：** 能够处理复杂的订单修改、退款流程，需要调用多个后端接口，CM2 能显著提高解决率。
2.  **个人助理：** 管理日程、预订餐厅、查询天气，涉及多轮对话和模糊指令处理。
3.  **代码与数据分析 Agent：** 虽然 CM2 针对通用工具，但其清单机制可应用于代码生成步骤的验证。

### 产业化可能性
极高。CM2 提供了一套不依赖昂贵真实环境反馈的训练范式，大大降低了 Agent 研发的门槛。企业可以利用内部的文档和日志构建模拟环境，利用 CM2 优化自有的 Agent 模型。

### 未来应用方向
*   **多模态 Agent：** 将清单奖励扩展到图像或视频输入的工具使用场景。
*   **自我进化：** 探索由更强的模型自动生成清单，实现从数据到奖励的全自动化。

## 6. 研究启示

### 对领域的启示
1.  **RL 在 Agent 领域大有可为：** 论文证明了 RL 不仅能用于对齐，还能显著提升 Agent 的任务执行能力。
2.  **“过程监督”优于“结果监督”：** 对于复杂任务，关注中间步骤的合理性比单纯关注最终结果更有效。
3.  **模拟训练是必经之路：** 随着模型能力增强，基于模拟环境的预训练/微调将成为 Agent 训练的主流范式。

### 可能的研究方向
*   **动态清单生成：** 研究如何根据任务描述自动生成最优的检查清单。
*   **层级式清单：** 针对超长任务，建立分层的检查机制。
*   **RL 与 SFT 的混合训练：** 探索在什么比例上混合 SFT 数据和 RL 数据能达到最佳效果。

## 研究最佳实践

## 最佳实践指南

### 实践 1：构建细粒度的工具调用检查清单

**说明**: CM2 的核心在于将复杂的工具使用任务分解为原子化的子任务。不要仅依赖最终任务的成功与否，而是构建一个包含所有必要中间步骤的“检查清单”。例如，如果任务是预订餐厅，检查清单应包括“确认餐厅营业状态”、“获取用户时间偏好”、“执行预订操作”等具体步骤，而不仅仅是“预订成功”。

**实施步骤**:
1. 将目标任务分解为线性的逻辑步骤。
2. 为每个步骤定义明确的完成标准（例如：API 返回特定字段或状态码）。
3. 将这些步骤转化为二元奖励信号（完成得 1 分，未完成得 0 分）。

**注意事项**: 检查清单的设计需要领域专家知识，确保步骤的完备性和无冗余性。

---

### 实践 2：实施基于检查清单的稀疏奖励机制

**说明**: 传统的强化学习在多步任务中面临稀疏奖励问题。CM2 通过检查清单提供了密集的反馈信号。每当 Agent 完成检查清单中的一个步骤，就给予正向奖励。这种方法能够更有效地引导模型在长序列任务中保持正确的方向，减少无效探索。

**实施步骤**:
1. 在训练循环中，实时监控 Agent 的输出和工具调用结果。
2. 设计一个自动评估脚本，将当前状态与检查清单进行比对。
3. 根据检查清单的完成进度计算中间奖励，累加到最终的奖励函数中。

**注意事项**: 确保奖励信号不会因为某个简单步骤的重复执行而无限累积，应设置步骤的幂等性。

---

### 实践 3：采用两阶段训练策略

**说明**: CM2 的研究表明，分阶段的训练效果优于端到端的直接训练。第一阶段应专注于让 Agent 学会遵循指令并完成检查清单中的子任务；第二阶段再进行端到端的强化学习，优化整体任务的成功率和效率。

**实施步骤**:
1. **阶段一（监督微调）**：使用带有检查清单标注的数据对模型进行微调，使其理解子任务与工具调用的对应关系。
2. **阶段二（强化学习）**：使用 PPO 或 Rejection Sampling 等算法，基于检查清单奖励和最终任务奖励进行优化。

**注意事项**: 在第一阶段确保数据质量，避免模型在第二阶段因为奖励黑客而通过非预期方式获取高分。

---

### 实践 4：优化多轮对话的上下文感知能力

**说明**: 多轮 Agent 任务通常需要根据前序步骤的结果动态调整后续行动。最佳实践要求在训练数据中包含丰富的历史交互上下文，并训练模型能够根据前序工具的返回结果（如报错、空数据）来修正下一步的计划，而不是机械地执行检查清单。

**实施步骤**:
1. 在构建训练样本时，包含前 N 轮的对话历史和工具执行反馈。
2. 在检查清单中引入“条件分支”步骤，例如“如果 API 失败，则尝试备用 API”。
3. 训练模型识别并处理工具调用失败的场景。

**注意事项**: 避免上下文截断导致的关键信息丢失，确保模型能看到所有相关的历史工具返回。

---

### 实践 5：引入负反馈与错误修正训练

**说明**: 仅仅奖励正确的行为是不够的。CM2 框架强调当 Agent 跳过必要步骤、调用错误工具或产生幻觉时，应给予明确的负反馈。这有助于模型学习边界条件，提高系统的鲁棒性。

**实施步骤**:
1. 定义明确的错误模式（如：参数缺失、工具不存在）。
2. 在 RL 奖励函数中设置惩罚项，当检测到上述错误模式时扣除奖励。
3. 构造包含错误恢复路径的演示数据，教导模型如何从错误中恢复。

**注意事项**: 负反馈的权重需要仔细调节，过大的惩罚可能导致模型在训练过程中崩溃或拒绝执行任何操作。

---

### 实践 6：建立鲁棒的评估基准

**说明**: 仅依靠检查清单得分可能无法完全反映用户体验。最佳实践是结合“检查清单完成率”、“任务最终成功率”和“工具调用效率”（步数）作为综合评估指标。

**实施步骤**:
1. 开发一套包含不同难度级别的测试集。
2. 在评估时同时计算：所有子步骤的完成比例、最终目标达成情况以及完成任务的平均轮数。
3. 优先选择在综合指标上表现最好的模型进行部署。

**注意事项**: 注意检查清单与最终目标的一致性，防止模型为了刷高检查清单分数而执行了对最终目标无用的操作。

## 学习要点

- 提出了一种基于检查表的奖励建模方法，通过将复杂的工具使用任务分解为原子化的子步骤，解决了多步智能体任务中稀疏奖励和信用分配的难题。
- 设计了双轨数据收集策略，分别针对工具使用准确性和任务规划能力生成偏好数据，从而显著提升了模型在多轮对话中的推理和执行能力。
- 引入了拒绝抽样的离线强化学习算法，在无需额外训练的情况下即可有效整合偏好数据，优化了模型遵循指令和正确使用工具的行为。
- 通过在真实 API 环境中进行评估，证明了该方法在处理多轮、多步骤工具使用任务时，优于传统的监督微调和仅依靠结果反馈的方法。
- 构建了包含 6,000 多个真实 API 调用的综合数据集，为研究和评估基于工具的智能体系统提供了高质量的基准。
- 该方法成功将复杂的任务完成度验证转化为对中间步骤的检查，不仅提高了训练效率，还增强了模型在长上下文任务中的稳定性。

## 常见问题


### 1: 什么是 CM2，它主要解决了 Agent 应用中的什么问题？

1: 什么是 CM2，它主要解决了 Agent 应用中的什么问题？

**A**: CM2（Checklist Multi-Turn Multi-Step）是一种针对多轮、多步智能体工具使用的强化学习框架。它主要解决了当前大型语言模型在复杂任务规划中面临的两个核心问题：**长距离依赖中的奖励稀疏性**和**中间步骤的幻觉**。在传统的端到端训练中，模型只有在最终任务完成时才能获得反馈，这导致模型难以学会正确的规划路径。CM2 通过引入“清单奖励”机制，将长任务分解为可验证的子目标，从而提供更密集的训练信号，显著提升了模型使用工具完成复杂任务的准确性和稳定性。

---



### 2: CM2 中的“清单奖励”是如何工作的？

2: CM2 中的“清单奖励”是如何工作的？

**A**: 清单奖励是 CM2 方法的核心组件。它的工作原理是将一个复杂的任务目标分解为一系列具体的、可验证的子步骤或中间状态（即“清单”）。在强化学习训练过程中，模型不仅会根据最终结果获得奖励，还会根据其生成的工具调用轨迹与清单中子目标的匹配程度获得中间奖励。具体来说，如果模型在执行过程中完成了清单上的某一项，就会获得正向反馈；如果偏离了清单或执行了无效操作，则会受到惩罚。这种机制为模型提供了更密集的监督信号，帮助模型更好地规划多步推理路径。

---



### 3: CM2 与传统的思维链或 ReAct 框架有何不同？

3: CM2 与传统的思维链或 ReAct 框架有何不同？

**A**: 虽然 CM2、CoT（思维链）和 ReAct 都致力于提升模型的推理能力，但它们的训练范式和反馈机制有本质区别。传统的 CoT 和 ReAct 主要依赖监督微调（SFT）或基于最终结果的稀疏奖励，模型往往难以学会复杂的工具组合策略，且容易产生中间步骤的幻觉。CM2 引入了显式的清单结构和基于清单的强化学习，通过验证中间步骤的正确性来提供密集奖励。这使得 CM2 不仅能像 ReAct 那样进行推理和行动，还能通过清单机制自我修正规划路径，减少无效的工具调用，从而在多轮交互中表现更稳健。

---



### 4: CM2 是如何获取训练所需的“清单”数据的？

4: CM2 是如何获取训练所需的“清单”数据的？

**A**: CM2 的清单数据通常不需要人工手动编写，而是通过自动化流程生成的。研究者通常利用现有的强大模型（如 GPT-4）作为“教师模型”，针对给定的任务和工具集，反向推导出完成该任务所需的关键中间步骤或子目标。这些生成的子目标集合就构成了训练用的清单。这种自动化的数据生成方式使得 CM2 可以扩展到各种不同的工具使用场景，而无需为每个任务人工编写复杂的验证规则，保证了方法的可扩展性。

---



### 5: 在 CM2 的训练过程中，模型是如何利用清单进行优化的？

5: 在 CM2 的训练过程中，模型是如何利用清单进行优化的？

**A**: CM2 的训练过程通常结合了监督微调（SFT）和强化学习（RL）。首先，模型会通过 SFT 学习基本的工具调用和推理模式。随后，进入 RL 阶段，环境会根据模型的输出轨迹与清单的匹配程度计算奖励。这个奖励由两部分组成：一部分是清单完成度，即模型成功完成了清单中的多少项；另一部分是最终任务的成功与否。通过最大化这些奖励，模型被训练成不仅关注最终结果，还会主动尝试达成清单中列出的关键中间步骤，从而学会更精准的路径规划。

---



### 6: CM2 方法在实际应用中有哪些局限性或挑战？

6: CM2 方法在实际应用中有哪些局限性或挑战？

**A**: 尽管 CM2 在提升工具使用能力上表现出色，但也面临一些挑战。首先，它严重依赖“教师模型”生成的清单质量，如果教师模型生成的子目标本身存在错误或遗漏，Agent 的训练可能会受到误导。其次，构建能够验证清单子目标的环境可能需要额外的工程成本，因为系统必须能够判断模型是否真的完成了某个中间步骤（例如判断是否正确查询了数据库并返回了有效结果）。此外，强化学习过程本身可能存在不稳定性，需要仔细调整超参数以平衡清单奖励和最终结果奖励的权重。

---



### 7: CM2 对提升 Agent 的抗幻觉能力有何帮助？

7: CM2 对提升 Agent 的抗幻觉能力有何帮助？

**A**: CM2 显著降低了 Agent 在工具使用过程中的幻觉现象。在传统的端到端生成中，模型可能会在推理链中编造不存在的工具参数或假设工具执行了未执行的操作。在 CM2 框架下，由于清单的存在，模型受到明确的中间状态约束。如果模型试图跳过关键步骤或编造结果，其轨迹将无法与清单匹配，导致奖励降低。这种基于清单的验证机制迫使模型在每一步都更加严谨地执行工具调用和结果验证，从而有效抑制了多步推理过程中的幻觉行为。
