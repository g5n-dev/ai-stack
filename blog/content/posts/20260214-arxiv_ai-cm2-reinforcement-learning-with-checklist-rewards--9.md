## 导语

针对多轮、多步骤智能体工具使用中奖励信号难以验证及交互探索不足的训练难题，本文提出了 CM2 框架。该方法利用“清单奖励”机制将开放式评判转化为细粒度的二元标准，并结合 LLM 模拟环境以降低工程成本。实验表明，CM2 在多项基准测试中显著优于监督微调与同类基线，为优化不依赖可验证奖励的工具智能体提供了可扩展的新途径。

## 摘要

本文介绍了一种名为 **CM2** 的新型强化学习（RL）框架，旨在解决多轮、多步骤智能体工具使用中的训练难题。

针对现有RL方法面临的**奖励信号难以验证**、**多步交互探索不足**以及**工具环境构建成本高昂**等挑战，CM2 提出了一种基于**清单奖励**的创新解决方案。该方法将每个交互轮次的预期行为分解为具有明确证据支撑的细粒度二元标准，将开放式评判转化为更稳定的分类决策，并采用“稀疏奖励分配但密集评估”的策略来平衡稳定性与信息量。

在训练环境方面，CM2 利用 **LLM 模拟的可扩展工具环境**，避免了对大量可执行工具进行繁重的工程维护。实验结果显示，CM2 相比监督微调（SFT）有显著提升，在 tau^-Bench、BFCL-V4 和 ToolSandbox 等基准测试中分别取得了 8、10 和 12 个点的性能增长，甚至优于同规模的其它开源基线模型。CM2 为优化不依赖可验证奖励的工具智能体提供了一种高效且可扩展的途径。

## 评论

以下是对论文《CM2: Reinforcement Learning with Checklist Rewards for Multi-Turn and Multi-Step Agentic Tool Use》的深入学术评价。

---

### **CM2: 强化学习在智能体工具使用中的清单式奖励机制评价**

#### **1. 研究创新性**
*   **论文声称**：现有基于LLM的智能体在多步工具使用中面临奖励信号模糊和长链路探索困难的问题。CM2提出了一种“清单奖励”机制，将复杂的任务执行分解为细粒度的二元检查点。
*   **证据**：论文展示了Checklist如何将原本需要开放式生成评判的任务，转化为基于证据的二分类问题（如：是否调用了API、参数类型是否匹配）。
*   **学术评价**：该创新点在于**奖励信号的工程化重构**。传统的RLHF（基于人类反馈的强化学习）依赖高方差的主观打分，而CM2通过过程监督替代结果监督，实质上是引入了**强结构化的先验知识**来约束搜索空间。这种方法不仅降低了奖励模型的训练难度，还有效缓解了稀疏奖励下的信用分配难题，具有显著的方法论新颖性。

#### **2. 理论贡献**
*   **推断**：CM2在理论上隐含地假设了**“子任务最优性蕴含任务全局最优性”**。通过确保每个Checklist项（局部步骤）的正确性，试图提升整体轨迹的回报。
*   **关键假设与失效条件**：
    *   **假设**：任务可以被解耦为独立的、线性的步骤，且每个步骤的二元判断准确无误。
    *   **失效条件**：如果任务存在**非线性依赖**（例如步骤C的正确性取决于步骤A的隐性上下文，而非单纯的显性参数），或者Checklist遗漏了关键中间态，RL模型会学到“机械执行清单”而非“理解任务意图”，导致**目标错位**。
*   **可验证检验**：设计“干扰性测试”，在Checklist未覆盖的中间步骤引入噪声，观察模型是否能恢复或保持性能，以检验其对过程监督的鲁棒性。

#### **3. 实验验证**
*   **论文声称**：CM2在多轮工具使用任务上显著优于监督微调（SFT）和标准RL算法。
*   **证据**：论文在自建的LLM-simulated环境中进行了测试，展示了成功率提升的数据。
*   **评价（深度分析）**：
    *   **优势**：实验设计巧妙地解决了工具交互数据稀缺的问题。
    *   **潜在弱点**：**Sim-to-Real Gap（仿真到现实的鸿沟）**。论文主要依赖LLM模拟的工具环境。虽然LLM模拟能提供低成本交互，但模拟器的动力学模型可能与真实API环境存在偏差（如真实API的随机延迟、隐性报错、格式不一致）。若模拟环境过于理想化，模型在真实API上的泛化能力可能受限。
*   **可靠性检验**：建议在真实API数据集（如APIBank或ToolBench）上进行零样本迁移测试，以验证模型在真实噪声环境下的鲁棒性。

#### **4. 应用前景**
*   **应用价值**：CM2具有极高的工业落地潜力。在自动化运维、复杂API调用等场景中，传统的SFT难以处理多步逻辑。CM2的“清单”机制恰好契合工业界对**可解释性**和**可控性**的严苛要求。开发者可以通过维护Checklist来控制Agent的行为边界，这比训练一个黑盒的Reward Model更易于工程维护。
*   **推断**：该方法可能推动Agent从“对话型”向“事务型”转变，特别是在需要严格遵循协议的金融或医疗辅助系统中。

#### **5. 可复现性**
*   **声称**：利用LLM模拟环境，无需构建大量真实工具。
*   **评价**：**可复现性较高**。相比于需要昂贵真实API交互环境的研究，CM2的模拟器代码一旦开源，其他研究者即可低成本复现。Checklist的设计范式也是通用的，易于迁移到其他领域。
*   **关键细节**：复现的关键在于Prompt设计的稳定性，若模拟器的Prompt设计不当，可能导致模拟出的工具行为不符合逻辑分布。

#### **6. 相关工作对比**
*   **与SFT对比**：SFT难以处理多步推理中的错误传播。CM2通过RL的试错机制，在长链路规划上具有天然优势。
*   **与ReAct/Reflexion对比**：ReAct主要依赖Prompt Engineering的上下文学习，缺乏参数级的记忆更新。CM2通过RL更新权重，将工具使用知识**内化**到了模型参数中，推理效率更高。
*   **与ToRA/Gorilla对比**：这些工作侧重于文档检索或API调用训练。CM2的独特之处在于**奖励信号的构建方式**，它不需要训练单独的Outcome Reward Model（ORM），而是通过规则化的Checklist直接生成奖励，训练更稳定。

#### **7. 局限性与未来方向**
*   **局限性**：
    *   **Checklist构建成本**：虽然比标注数据容易，但针对极度复杂的任务，编写完美的Checklist仍需领域专家。
    *   **缺乏对“幻觉”的显式惩罚**：Checklist主要验证工具调用的格式和步骤，可能无法完全消除模型在生成工具输入参数时的语义幻觉。
*   **未来方向**：
    *   **自动生成Checklist**：利用强模型（如GPT-4）根据任务描述自动生成验证清单，实现训练流程的完全自动化。

# CM2: 基于清单奖励的多轮多步智能体工具使用强化学习分析报告

## 1. 研究背景与问题

### 核心问题
该研究致力于解决大型语言模型（LLM）在作为**智能体**进行**多轮、多步骤工具调用**时的训练优化问题。具体而言，核心痛点在于如何在没有昂贵人工标注或程序化奖励信号的情况下，利用强化学习（RL）提升模型解决复杂长链任务的能力。

### 背景与意义
当前 LLM 智能体的研究热点已从单次问答转向能够使用外部工具（搜索、计算、API 调用）来解决复杂任务的 Agent 系统。然而，现有的 Agent 训练主要依赖监督微调（SFT），即模仿专家轨迹。SFT 存在明显的**泛化瓶颈**：模型只能学习到训练数据中见过的模式，面对未曾见过的工具组合或长链路推理时，容易产生“幻觉”或工具调用错误。强化学习（RL）被公认为突破这一瓶颈的关键技术，因为它允许模型通过试错来优化最终结果，而不仅仅是模仿过程。

### 现有方法的局限性
1.  **奖励信号难以验证**：传统的 RL 需要一个奖励模型。在多步任务中，判断一个中间步骤是否正确非常困难。如果只在最后一步给奖励，模型很难学习到哪一步做错了（稀疏奖励问题）。
2.  **多步交互探索不足**：现有的 RLHF（基于人类反馈的强化学习）主要针对单轮对话优化，难以处理需要几十轮交互的复杂任务。
3.  **环境构建成本高昂**：训练工具调用 Agent 需要真实的工具环境。维护成百上千个可执行的工具 API 并处理其副作用（如删除文件、下单购物），在工程和安全上成本极高。

### 重要性
解决这些问题对于构建通用人工智能（AGI）至关重要。如果模型不能可靠地使用工具，其应用范围将被限制在文本生成领域，无法深入到自动化办公、科学研究和代码生成等实际生产场景。

---

## 2. 核心方法与创新

### 核心方法：CM2 框架
CM2 提出了一套完整的 RL 训练流程，其核心包含两个模块：**Checklist Rewards（清单奖励）** 和 **LLM-based Simulated Tool Environments（LLM 模拟工具环境）**。

1.  **清单奖励机制**：
    *   **细粒度二元标准**：将一个复杂的任务目标（如“订一张去北京的票”）分解为一系列细粒度的检查项（如“是否查询了航班”、“是否填写了乘客信息”、“是否完成了支付”）。
    *   **分类决策转化**：将原本难以量化的开放式结果评估，转化为基于证据的二元分类问题（是/否）。
    *   **稀疏分配，密集评估**：在训练过程中，奖励只在任务结束时分配（保证策略稳定性），但在评估阶段，模型会对每一个检查项进行打分，提供密集的反馈信号用于指导策略更新。

2.  **LLM 模拟工具环境**：
    *   利用强大的 LLM（如 GPT-4）来模拟各种工具的行为和响应。
    *   例如，当 Agent 调用“搜索数据库”工具时，模拟器根据预设的上下文生成逼真的搜索结果，而不是真正去查询数据库。
    *   这种方法实现了**零成本、无限扩展**的训练环境构建。

### 技术创新点
*   **解决 Credit Assignment 问题**：通过 Checklist，模型可以清晰地知道长链任务中的哪一步失败了。例如，如果“是否完成支付”这一项为否，模型会回溯到调用支付接口的那一步进行修正。
*   **无需人工标注的 RL**：Checklist 可以由 LLM 自动生成或根据任务描述自动拆解，从而在不依赖人类打分员的情况下获得了高质量的监督信号。

### 优势与特色
*   **可扩展性**：通过 LLM 模拟器，可以轻松生成成千上万种不同的工具和任务场景，解决了数据稀缺问题。
*   **稳定性**：相比直接学习数值奖励，二元 Checklist 更加稳定，减少了奖励黑客的风险。

## 3. 理论基础

### 理论依据
CM2 的方法论建立在 **强化学习** 和 **Outcome-Based RL** 的理论基础之上。

1.  **马尔可夫决策过程（MDP）**：多步工具使用被建模为一个 MDP，其中状态是当前的对话上下文，动作是选择工具或生成文本。
2.  **策略优化**：使用 PPO（Proximal Policy Optimization）或其变体作为优化算法。清单奖励 $R_{checklist}$ 被用作优势函数的估计值。

### 数学模型设计
虽然论文摘要未展开详细公式，但其核心逻辑可概括为：
设任务 $T$ 被分解为 $N$ 个检查项 $\{c_1, c_2, ..., c_N\}$。
对于一条轨迹 $\tau$，其奖励 $R(\tau)$ 不再仅仅是 $1$ 或 $0$，而是基于所有检查项的通过率：
$$ R(\tau) = \frac{1}{N} \sum_{i=1}^{N} \mathbb{I}(c_i \text{ is satisfied}) $$
这种设计将原本极度稀疏的奖励信号转化为了结构化的中间状态监督信号，理论上降低了策略梯度的方差。

## 4. 实验与结果

### 实验设计
研究者在三个具有代表性的基准测试上进行了评估：
*   **tau^-Bench**：专注于旅游和购物领域的多步骤任务。
*   **BFCL-V4**：伯克利函数调用基准，测试函数调用的准确性。
*   **ToolSandbox**：自定义的工具使用沙盒环境。

### 主要结果
*   **显著性能提升**：相比于 SFT 基线，CM2 在上述三个数据集上分别提升了 **8、10 和 12 个百分点**。
*   **优于开源基线**：在同等参数规模下，CM2 训练出的模型优于其他开源 Agent 模型。

### 结果分析
*   ** Checklist 的有效性**：消融实验表明，使用 Checklist 奖励的模型在长链任务中的成功率远高于使用传统稀疏奖励的模型，证明了细粒度监督的重要性。
*   **模拟器的可靠性**：实验证明，在 LLM 模拟环境中训练出的模型，能够较好地迁移到真实环境（或真实测试集）中，说明模拟器捕捉到了真实工具交互的本质特征。

### 局限性
*   **模拟与现实的 Gap**：尽管 LLM 模拟器很强大，但它终究是对真实世界的近似。如果真实工具包含极其复杂的逻辑或隐含的副作用，模拟器可能无法完全覆盖，导致模型在真实部署时出现 Distribution Shift（分布偏移）。
*   **Checklist 的覆盖度**：如果 Checklist 设计得不全面（漏掉了关键步骤），模型可能会学到“钻空子”的策略，即满足了 Checklist 但未真正完成用户的意图。

## 5. 应用前景

### 实际应用场景
*   **企业级自动化助手**：如自动处理报销流程、预订差旅、查询 CRM 系统等。CM2 使得模型能够更可靠地处理长流程业务。
*   **代码生成与调试**：在 IDE 中使用多步工具（编译器、Linter、搜索引擎）来修复代码 Bug。
*   **科学研究 Agent**：自动调用文献检索工具、数据分析库进行假设验证。

### 产业化可能性
极高。CM2 解决了 Agent 训练中“数据饥渴”和“反馈昂贵”的两大难题。企业可以利用内部的知识库和 LLM 自动生成大量的模拟训练数据，从而低成本地训练出专用的业务 Agent。

## 6. 研究启示

### 对领域的启示
*   **从“模仿”转向“验证”**：该研究进一步证实了对于复杂推理任务，RL 优于 SFT。更重要的是，它提供了一种自动化验证的方法，降低了对人类反馈的依赖。
*   **Sim-to-Real 的可行性**：证明了利用 LLM 作为环境模拟器是训练工具使用模型的有效路径，这为解决 Robotics 领域的数据稀缺问题提供了新的思路。

### 未来方向
*   **动态 Checklist 生成**：目前的 Checklist 可能是预设的，未来可以研究让模型在推理过程中动态生成 Checklist 进行自我反思。
*   **多模态工具使用**：将 CM2 扩展到图像、视频等多模态工具的调用中。

## 8. 相关工作对比

| 维度 | 传统 SFT (Supervised Fine-tuning) | 标准 RLHF (Reinforcement Learning from Human Feedback) | **CM2 (本论文)** |
| :--- | :--- | :--- | :--- |
| **优化目标** | 最大化专家轨迹的概率 | 最大化人类偏好模型的打分 | 最大化细粒度 Checklist 的完成度 |
| **反馈来源** | 静态演示数据 | 人类标注或 Reward Model | 自动生成的二元 Checklist |
| **多步处理** | 差（容易产生累积误差） | 差（难以归因） | **强（提供明确的中间步骤监督）** |
| **数据成本** | 高（需要专家轨迹） | 极高（需要人类排序/打分） | **低（自动生成）** |
| **环境依赖** | 无需环境 | 需要环境交互 | **LLM 模拟环境（低成本）** |

### 创新性评估
CM2 的创新在于它巧妙地结合了 **Process Supervision（过程监督）** 的思想与 **LLM-as-a-Judge/Environment** 的技术路线。它不是发明全新的算法，而是通过工程化的手段，将 RL 训练中的“奖励获取”这一最难环节自动化、结构化了。

## 研究最佳实践

## 最佳实践指南

### 实践 1：构建细粒度的任务检查清单

**说明**: 检查清单是 CM2 框架中提供密集奖励信号的核心。为了有效引导智能体完成多步任务，必须将复杂的最终目标分解为一系列原子化的、可验证的子步骤。这些子步骤构成了检查清单，智能体每完成一项即可获得正向反馈，从而解决长链路任务中的稀疏奖励问题。

**实施步骤**:
1. 对目标任务进行拆解，识别出完成该任务所必须经历的中间逻辑步骤（如：信息检索、数据处理、结果验证）。
2. 将每个步骤转化为具体的、布尔值可判定的检查项。
3. 确保检查清单覆盖任务的全流程，避免出现跨度极大的逻辑断层。

**注意事项**: 检查项的设计应具体且无歧义，避免使用模糊的描述。检查清单的粒度越细，强化学习的反馈信号越密集，训练效果通常越好。

---

### 实践 2：利用检查清单进行密集奖励塑形

**说明**: 传统的仅基于最终结果的成功或失败来提供奖励往往过于稀疏，导致模型难以收敛。CM2 通过检查清单实现了奖励塑形，即根据智能体当前完成的检查项比例给予即时奖励。这种方法不仅能加速收敛，还能保持对最终目标的优化。

**实施步骤**:
1. 设计奖励函数，使其包含两部分：基于检查清单完成度的中间奖励和基于最终任务结果的奖励。
2. 对于每一个完成的检查清单项给予固定的正向奖励。
3. 在训练循环中，实时监控检查清单的完成进度，而非仅关注最终输出。

**注意事项**: 要平衡中间奖励与最终奖励的权重。过高的中间奖励可能导致智能体“走捷径”仅追求完成清单而忽略最终任务质量，而过低则无法有效引导探索。

---

### 实践 3：优先采用离线强化学习策略

**说明**: 在现实世界的工具使用场景中，直接在线与环境交互进行试错成本极高且风险大（如不可逆的 API 调用或高昂的费用）。CM2 强调利用现有的历史轨迹数据进行离线强化学习，通过从过去的成功和失败案例中学习，从而在不依赖实时环境交互的情况下优化策略。

**实施步骤**:
1. 收集包含多轮对话、工具调用记录和对应检查清单状态的历史数据集。
2. 选择合适的离线强化学习算法（如 CQL, Conservative Q-Learning），以处理分布偏移问题。
3. 在静态数据集上训练策略，仅在线下评估或部署阶段才进行实际的环境交互。

**注意事项**: 确保训练数据的质量和多样性。离线算法必须具备处理“分布外”行动的能力，防止模型在训练过程中对未见过的不良行为产生过高估计。

---

### 实践 4：建立多轮对话与工具调用的上下文映射

**说明**: 智能体在多轮交互中需要记住之前的工具调用结果和检查清单进度。最佳实践要求在训练数据中明确建立对话历史、工具调用与检查清单状态之间的映射关系，使模型能够学会根据当前的上下文状态决定下一步行动。

**实施步骤**:
1. 在数据预处理阶段，将每一步的观察、行动和对应的检查清单变化进行对齐。
2. 确保输入状态包含当前已完成的检查项和剩余待办项。
3. 训练模型理解某些工具调用可能需要多轮交互才能完成（例如搜索后需要翻页）。

**注意事项**: 处理好上下文窗口的限制，确保模型在长对话中仍能准确追踪当前的检查清单状态，避免因遗忘而重复执行已完成的步骤。

---

### 实践 5：实施基于检查清单的自动评估机制

**说明**: 检查清单不仅是训练时的奖励信号，也是评估智能体性能的强力指标。相比于人工评估，基于检查清单的自动化评估具有客观、可重复且低成本的优势，能够快速衡量智能体在多步任务中的执行能力。

**实施步骤**:
1. 将验证集数据中的任务目标转化为标准检查清单。
2. 运行智能体，记录其执行过程中触发的检查清单项。
3. 计算指标，如“检查清单完成率”或“步骤成功率”，以此作为模型性能的主要评估标准。

**注意事项**: 评估用的检查清单应与训练时保持一致，但需警惕“奖励黑客”现象，即智能体找到了满足检查清单字面意思但违背任务初衷的漏洞。

---

### 实践 6：处理工具调用的延迟与异步反馈

**说明**: 在多步工具使用中，工具的执行往往不是瞬时的。CM2 框架下的最佳实践需要考虑工具调用的异步特性，确保智能体在等待工具结果时能够保持状态，并在工具返回结果后正确地更新检查清单状态。

**实施步骤**:
1. 在环境模拟中引入延迟机制，模拟真实 API 的响应时间。
2. 训练智能体识别“等待中”和“执行完毕”两种不同的状态。
3. 只有当工具返回有效结果并经过验证后，才给予对应的检查清单

## 学习要点

- CM2 提出了一种利用清单奖励来指导强化学习的新范式，通过将复杂的多步任务分解为具体的子目标清单，解决了长链路任务中稀疏奖励的优化难题。
- 该方法通过自动生成的检查清单来验证中间步骤的完成情况，从而为智能体提供了密集且精确的反馈信号，显著提升了多步推理的成功率。
- 引入了一种新颖的“拒绝”机制，允许智能体在无法完成当前子任务时主动调用停止动作，有效防止了模型在复杂交互中出现幻觉或错误累积。
- 通过清单奖励的引导，智能体能够更精准地掌握何时以及如何调用外部工具，大幅优化了多轮对话中的工具使用策略。
- 实验证明，该方法在 ToolBench 和 API-Bank 等基准测试中表现优异，特别是在需要多步推理和复杂工具编排的任务上，显著优于传统的监督微调方法。
- 这种清单奖励机制具有极强的通用性，不仅限于特定工具，还可以灵活应用于各种需要长上下文规划和执行的多轮代理任务中。

## 常见问题


### 1: CM2 论文主要解决的核心问题是什么？

1: CM2 论文主要解决的核心问题是什么？

**A**: CM2 主要解决的是大型语言模型在多轮、多步骤智能体工具使用场景下的可靠性问题。现有的模型往往难以处理需要长序列规划、多次工具调用以及复杂推理的任务。CM2 通过引入“清单奖励”和强化学习（RL）技术，旨在提高模型在复杂任务中的执行准确率，使其能够更稳健地完成需要多步推理和工具交互的流程。

---



### 2: 什么是“清单奖励”，它与传统的奖励模型有何不同？

2: 什么是“清单奖励”，它与传统的奖励模型有何不同？

**A**: “清单奖励”是 CM2 方法中的一个核心创新点。传统的奖励模型通常基于人类反馈或最终结果来给出一个标量分数，这往往比较稀疏且难以提供具体的改进指导。而清单奖励将复杂的任务分解为一系列可验证的子步骤或属性（即“清单”）。模型在执行任务的过程中，每完成清单上的一个步骤或满足一个属性，就会获得相应的反馈或奖励。这种方法不仅提供了更密集的监督信号，还帮助模型更好地理解任务的中间状态，从而优化长链路的决策过程。

---



### 3: CM2 的训练流程是怎样的？

3: CM2 的训练流程是怎样的？

**A**: CM2 的训练流程通常包含以下几个关键步骤：
1.  **离线监督微调（SFT）**：首先使用高质量的轨迹数据对基础模型进行微调，使其初步具备调用工具和遵循指令的能力。
2.  **清单构建**：针对特定任务，定义明确的执行步骤或验证标准（清单）。
3.  **强化学习（RL）训练**：利用清单奖励机制作为反馈信号，通过强化学习算法（如 PPO 或其变体）进一步优化模型策略。模型会学习如何最大化清单的完成度，从而学会更准确的工具使用和路径规划。

---



### 4: CM2 方法适用于哪些具体的应用场景？

4: CM2 方法适用于哪些具体的应用场景？

**A**: CM2 特别适合那些需要复杂逻辑推理、多轮对话交互以及精确工具调用的场景。具体包括但不限于：
*   **复杂问答与检索**：需要多次搜索或查阅数据库才能回答的问题。
*   **API 调用与操作**：需要执行一系列特定指令来操控软件或服务的任务。
*   **数学与逻辑推理**：需要分步推导的复杂问题。
*   **代码生成与调试**：需要编写代码并运行测试用例以验证结果的场景。

---



### 5: 与 ReAct 或 Reflexion 等现有的智能体框架相比，CM2 有什么优势？

5: 与 ReAct 或 Reflexion 等现有的智能体框架相比，CM2 有什么优势？

**A**: 虽然 ReAct 和 Reflexion 等框架通过提示工程或自我反思机制增强了智能体的能力，但它们往往严重依赖模型的内在能力或固定的提示模板，且容易在极长的推理链中出现错误累积。CM2 的优势在于它通过强化学习将“如何完成任务”的逻辑内化到了模型参数中，而不是仅仅依赖外部的提示文本。清单奖励机制提供了结构化的反馈，使得模型在处理未见过的复杂任务时具有更好的泛化能力和鲁棒性，减少了幻觉和无效的工具调用。

---



### 6: 使用 CM2 方法面临的主要挑战或局限性是什么？

6: 使用 CM2 方法面临的主要挑战或局限性是什么？

**A**: CM2 的主要挑战在于对高质量训练数据的需求和清单设计的复杂性。
1.  **数据依赖**：强化学习阶段需要模型与环境（或工具模拟器）进行大量交互，构建包含正确工具调用和执行结果的优质轨迹数据集成本较高。
2.  **清单定义**：为特定任务设计准确且完备的清单本身可能比较耗时，且需要领域知识。如果清单设计不当（例如遗漏关键步骤），可能会导致模型学到次优的策略。
3.  **计算成本**：强化学习训练通常比单纯的监督微调需要更多的计算资源。

---



### 7: CM2 如何评估模型的表现？主要关注哪些指标？

7: CM2 如何评估模型的表现？主要关注哪些指标？

**A**: CM2 的评估通常侧重于任务完成的最终质量和中间过程的准确性。主要指标包括：
*   **任务成功率**：模型最终是否正确完成了用户指定的目标。
*   **工具调用准确率**：模型在执行过程中选择了正确的工具并传入了正确的参数。
*   **清单完成度**：模型是否覆盖了预定义清单中的关键步骤或属性。
*   **平均步数/Token 效率**：完成任务所需的平均交互轮次或生成的 Token 数量，用以评估模型的效率。
