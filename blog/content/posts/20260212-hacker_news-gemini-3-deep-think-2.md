class ConversationMemory:
    """
    实现对话记忆功能，保持上下文连贯性
    """
    def __init__(self):
        # 存储对话历史，每条记录包含角色和内容
        self.history = []
        # 设置最大记忆长度
        self.max_history = 5
    
    def add_message(self, role: str, content: str):
        """添加新的对话记录"""
        self.history.append({
            "role": role,
            "content": content,
            "timestamp": len(self.history) + 1
        })
        # 保持记忆长度在限制内
        if len(self.history) > self.max_history:
            self.history.pop(0)
    
    def get_context(self) -> str:
        """获取格式化的对话上下文"""
        context = []
        for msg in self.history:
            role = "用户" if msg["role"] == "user" else "AI"
            context.append(f"{role}: {msg['content']}")
        return "\n".join(context)
    
    def clear_history(self):
        """清空对话历史"""
        self.history = []

# 测试
if __name__ == "__main__":
    mem = ConversationMemory()
    mem.add_message("user", "你好，我叫Alice")
    mem.add_message("assistant", "你好Alice，很高兴认识你")
    mem.add_message("user", "我的爱好是编程")
    
    print("当前对话上下文：")
    print(mem.get_context())

## 最佳实践指南

### 实践 1：构建结构化的提示词工程

**说明**: Gemini 3 Deep Think 模型具备极强的上下文理解能力，但为了获得最精准的“深度思考”结果，输入的提示词不能是简单的碎片化问题。需要采用结构化的提示词框架，明确界定背景、约束条件、期望的输出格式以及具体的任务目标。

**实施步骤**:
1. 采用“角色设定 + 任务背景 + 详细指令 + 边界条件 + 输出示例”的五段式结构。
2. 明确告知模型“请一步步思考”或“请展示推理过程”，以激活模型的深度分析链。
3. 将复杂的任务拆解为子任务，并在提示词中明确列出逻辑顺序。

**注意事项**: 避免歧义性词汇，指令需具备明确的指向性。

---

### 实践 2：利用“思维链”引导复杂逻辑推理

**说明**: 针对数学、编程或逻辑分析类任务，直接要求答案可能导致模型跳过关键步骤。最佳实践是强制模型展示其完整的推理过程，这不仅提高了最终答案的准确性，也便于人工核查其逻辑路径。

**实施步骤**:
1. 在提示词中添加指令：“请逐步解释你的推理逻辑，并在得出结论前展示每一步的验证过程。”
2. 如果模型出错，针对具体的推理步骤进行纠正，而不是直接要求重给答案。
3. 使用“让我们一步步思考”作为标准的前缀触发器。

**注意事项**: 确保推理过程与最终结论的一致性，警惕模型在长链条推理中出现的逻辑断裂。

---

### 实践 3：实施迭代式验证与自我修正

**说明**: Gemini 3 Deep Think 具备自我反思的能力。在生成初版内容后，不应直接采用，而应将其作为反馈循环的起点，要求模型进行自我批判或根据外部标准进行修正。

**实施步骤**:
1. 生成初稿后，追加提示词：“请批判性地审查上述回答，指出潜在的逻辑漏洞或不准确之处，并重新生成改进后的版本。”
2. 设定具体的评估维度（如：代码效率、文本安全性、事实准确性），要求模型按维度打分。
3. 对比多次迭代的结果，选择最稳健的版本。

**注意事项**: 避免陷入无限修正循环，设定明确的迭代次数上限（通常为 2-3 轮）。

---

### 实践 4：精细化的上下文窗口管理

**说明**: 虽然模型支持长上下文，但将大量无关信息填入上下文窗口会引入噪声，干扰模型的注意力机制。最佳实践是根据当前任务动态裁剪上下文，仅保留最相关的信息片段。

**实施步骤**:
1. 在处理长文档或代码库时，先进行语义检索或摘要，提取与当前提问最相关的段落。
2. 使用“系统指令”固定全局背景，使用“用户指令”传递具体的临时变量。
3. 定期清理对话历史中的冗余轮次，保留核心上下文即可。

**注意事项**: 注意“迷失中间”现象，即模型容易忽略长上下文中间部分的信息，关键信息应尽量放在提示词的开头或结尾。

---

### 实践 5：建立安全护栏与输出格式约束

**说明**: 为了确保模型输出的内容符合企业合规要求或特定技术规范，必须在提示词层面建立严格的约束机制，防止模型产生幻觉或不符合格式的输出。

**实施步骤**:
1. 在系统提示词中明确列出“负面约束”，例如：“不要编造事实，如果不知道请直接回答不知道”。
2. 强制要求输出特定的数据格式（如 JSON, XML, Markdown 表格），以便于后续程序自动化处理。
3. 对于敏感话题，设置预处理指令，要求模型遵循中立、客观的立场。

**注意事项**: 格式约束可能会略微影响生成速度，需权衡格式严格度与生成效率。

---

### 实践 6：多模态数据的协同处理

**说明**: Gemini 3 Deep Think 原生支持多模态输入。最佳实践不仅仅是将文本和图片混合输入，而是利用模型对视觉信息的深度理解能力，进行跨模态的联合推理。

**实施步骤**:
1. 在分析图表或截图时，要求模型结合视觉特征和文本背景进行综合分析，而非仅描述图片内容。
2. 对于代码任务，可以将架构图与代码片段同时输入，要求模型检查代码是否符合架构设计。
3. 利用视频帧分析能力，提取视频中的关键时序信息进行逻辑推演。

**注意事项**: 确保输入的图像或视频清晰度足够，模糊的视觉输入会显著降低推理质量。

---

### 实践 7：性能监控与延迟优化

**说明**: “深度思考”模式通常涉及更多的计算量和推理时间，导致延迟增加。在产品级应用中，必须建立监控机制，平衡思考深度与响应速度。

**实施步骤**:
1. 为 API 调用设置合理的超时时间，并实施异步处理机制，避免阻塞主线程。
2. A/B 测试对比“快速模式”与“深度思考模式”的输出
