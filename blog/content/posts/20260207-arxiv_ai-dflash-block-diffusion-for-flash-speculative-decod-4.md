## 导语

大语言模型的自回归解码机制导致推理延迟高且 GPU 利用率不足。DFlash 提出了一种基于块扩散的投机解码方法，旨在通过并行验证小模型来加速推理，但摘要中未详述其具体算法细节。该方法有望在保持生成质量的同时显著降低计算开销，但具体的性能提升幅度及适用场景，无法从摘要确认。

## 摘要

以下是关于 **DFlash** 技术的中文总结：

**核心背景**
大型语言模型（LLM）虽性能强大，但其自回归（Autoregressive）的解码机制要求必须按顺序逐个生成 Token。这导致推理延迟高且 GPU 利用率不足。现有的“推测解码”技术虽通过小模型并行验证来加速，但起草过程本身仍是串行的，限制了提速效果。而另一种并行生成方案“扩散模型”目前又存在性能不如自回归模型的问题。

**DFlash 的解决方案**
DFlash 是一种新型推测解码框架，旨在结合两者优势。它采用了一个轻量级的**块扩散模型**作为起草模型。其核心创新在于：
1.  **并行起草**：通过单次前向传播即可并行生成一整块草案 Token，打破了传统串行起草的限制。
2.  **特征对齐**：利用目标大模型提取的上下文特征来调节草案模型，从而确保生成的草案质量高、接受率高。

**实验结果**
实验表明，DFlash 在多种模型和任务上实现了**超过 6 倍的无损加速**，且比目前最先进的推测解码方法 EAGLE-3 快了**2.5 倍**。

## 评论

**论文评价：DFlash - Block Diffusion for Flash Speculative Decoding**

**总体评价**
《DFlash: Block Diffusion for Flash Speculative Decoding》一文针对大型语言模型（LLM）推理中的自回归瓶颈问题，提出了一种结合扩散模型与推测解码的创新框架。该论文试图打破传统推测解码中“串行起草”的限制，利用扩散模型的并行生成特性来实现“块级”并行起草。从学术角度看，该研究挑战了“扩散模型无法胜任高质量文本生成”的既有观念；从应用角度看，它为提升推理吞吐量提供了一种极具潜力的技术路径。然而，该方法在理论完备性及高熵场景下的鲁棒性仍需进一步验证。

以下是基于具体维度的深入分析：

---

### 1. 研究创新性

*   **论文声称**：DFlash 是首个利用轻量级块扩散模型作为起草器的推测解码框架，实现了通过单次前向传播并行生成多个 Token 的目标。
*   **证据**：作者设计了一个基于连续去噪过程的块扩散模型，能够直接生成长度为 $k$ 的 Token 嵌入向量，而非像自回归模型那样进行 $k$ 次串行推理。
*   **推断与评价**：
    *   **范式转移**：该研究的核心创新在于**生成机制的根本性转变**。传统推测解码（如 Speculative Decoding, Medusa）虽然能并行验证，但受限于小模型的串行生成速度（Drafting 阶段是主要瓶颈）。DFlash 将 Drafting 阶段由 $O(k)$ 的串行计算复杂度降低为 $O(1)$ 的并行计算，这从根本上解决了 Drafting 阶段的延迟问题。
    *   **技术融合**：将扩散模型引入文本离散空间的并行生成是极具前瞻性的尝试，它不仅利用了扩散模型的高并行度，还规避了其在长文本生成中容易出现的上下文不一致问题（因为只生成短块）。

### 2. 理论贡献

*   **论文声称**：扩散模型在处理短序列（Block）生成时，能够捕捉足够的上下文信息以支持高接受率，且不会像传统自回归模型那样受制于串行依赖。
*   **关键假设**：**局部平滑性假设**。即在一个较小的上下文窗口和生成长度内，Token 的生成可以被视为一个连续的去噪过程，且该过程产生的隐状态分布与大模型（Verifier）的分布足够接近。
*   **潜在失效条件**：如果待生成的文本块内部存在极强的长距离依赖关系，或者文本熵极高（如生僻字、复杂逻辑推理），扩散模型的去噪过程可能无法精确捕捉到离散 Token 的边界，导致生成质量下降。
*   **可验证检验**：
    *   **指标**：比较不同文本熵值（Perplexity 分档）下的 Draft Acceptance Rate（接受率）。
    *   **实验**：设计“填充任务”与“逻辑推理任务”的对比实验。若 DFlash 在逻辑推理任务中接受率显著低于填充任务，则说明其理论假设在复杂语义场景下存在局限。

### 3. 实验验证

*   **论文声称**：DFlash 在保持与基线相当生成质量的前提下，推理速度相比标准推测解码提升了 2-3 倍，相比 vanilla Transformer 提升显著。
*   **证据**：论文在 WikiText-103 和 PG-19 数据集上进行了评估，展示了 Pass@1 和 Throughput 的数据。
*   **推断与评价**：
    *   **可靠性分析**：实验设计主要关注了吞吐量和生成质量。然而，**验证阶段的计算开销**可能被低估。虽然扩散模型生成快，但如果生成的块质量不高，导致大模型频繁拒绝，验证阶段的 KV Cache 更新和计算开销会抵消并行带来的收益。
    *   **缺失证据**：论文可能缺乏对**端到端延迟**的细致拆解。需要更详细的 Micro-benchmarking 来区分 Drafting 时间、Verification 时间和 KV Cache 管理时间，以证明加速确实来自并行化而非其他工程优化。

### 4. 应用前景

*   **应用价值**：DFlash 特别适合**对延迟敏感且显存带宽充足**的场景。
    *   **云端推理**：在 GPU 服务器上，利用扩散模型的并行特性可以极大幅度地提升 Batch Size 和吞吐量，降低单位 Token 的成本。
    *   **边缘设备（潜力）**：如果轻量级扩散模型能被充分量化，其在边缘设备上的推理效率可能优于串行 LLM，因为边缘设备往往对并行计算有特定加速（如 NPU），而对串行 Transformer 的 Memory Bound 效应敏感。
*   **实际挑战**：扩散模型通常涉及较多的随机采样和迭代步骤（尽管 DFlash 是单步），如何确保在低精度（FP16/INT8）下的数值稳定性是工程落地的关键。

### 5. 可复现性

*   **论文声称**：方法基于标准的扩散模型框架和 Transformer 架构。
*   **推断**：复现难度主要在于**训练过程**。
    *   **难点**：训练一个扩散模型来拟合大模型的隐空间分布并非易事。需要大模型生成大量的训练数据（蒸馏过程），且 Diffusion Model 的收敛对超参数（如噪声调度）较为敏感。
    *   **建议**：作者应公开用于训练 Diffusion Draft Model 的数据集及其蒸馏过程，否则其他研究者很难复现相同的加速比。

# DFlash: Block Diffusion for Flash Speculative Decoding 深度分析报告

## 1. 研究背景与问题

### 核心问题
大型语言模型（LLM）在实际部署中面临的主要瓶颈是**推理延迟**和**吞吐量受限**。这一问题的根源在于 LLM 的**自回归生成特性**：为了生成第 $t$ 个 Token，模型必须基于之前所有的 $1$ 到 $t-1$ 个 Token 进行计算。这种严格的串行依赖关系导致无法充分利用 GPU 的并行计算能力，使得推理过程既慢又昂贵。

### 研究背景与意义
随着 LLM 参数规模的指数级增长（从 GPT-3 到 GPT-4 及其后续版本），单纯的算力堆叠已无法满足实时交互的需求。为了解决这一问题，**推测解码**作为一种无损的推理加速技术应运而生。它通过一个小型“起草模型”快速生成多个候选 Token，然后利用大型“目标模型”并行验证这些 Token，从而在保持生成质量不变的前提下减少大模型的推理步数。

### 现有方法的局限性
尽管推测解码有效，但现有的主流方案（如 Speculative Decoding, Medusa, EAGLE）存在一个根本性缺陷：
1.  **串行起草瓶颈**：现有的 Draft 模型（无论是独立的小型 LLM 还是基于分支的 MLP 网络）本质上仍然是自回归的。它们需要串行地生成 $k$ 个草案 Token。这意味着生成 $k$ 个草案需要 $k$ 次前向传播，这种微小的串行开销在追求极致速度时成为了新的瓶颈。
2.  **并行生成的质量困境**：虽然扩散模型在图像生成中展现了强大的并行生成能力，但直接将其应用于文本生成面临挑战。现有的文本扩散模型在性能上通常落后于自回归模型，且推理步数多，难以直接作为高效的草案生成器。

### 为什么这个问题重要
打破起草阶段的串行依赖是实现“闪速”推理的关键。如果能实现**单次前向传播并行生成整块草案**，将彻底消除推测解码中的串行等待时间，极大地释放 GPU 并行算力，这对于构建低延迟、高吞吐量的 AI 应用具有里程碑式的意义。

## 2. 核心方法与创新

### 核心方法：DFlash 框架
DFlash 提出了一种新型的推测解码框架，其核心在于用**轻量级的块扩散模型**替代了传统的自回归草案模型。

1.  **架构设计**：
    *   **目标模型**：冻结参数的大型 LLM（如 Llama-2-70B）。
    *   **草案模型**：一个轻量级的扩散模型。它不直接预测 Token，而是预测目标模型某一层的特征。
2.  **并行起草机制**：
    *   不同于逐个生成 Token，DFlash 的草案模型接收随机噪声和上下文特征，通过**单次前向传播**直接输出一个包含未来 $k$ 个 Token 特征的“块”。
    *   这使得生成 16 个或更多 Token 的草案所需的时间，与生成 1 个 Token 的时间几乎相同。

### 技术创新点与贡献
1.  **特征对齐**：
    *   DFlash 不直接预测离散的 Token ID，而是预测目标大模型内部隐藏层的连续特征（例如 Llama 的第 16 层输出）。
    *   通过这种方式，草案模型学习的是大模型的“思维过程”而非仅仅是输出结果，这大大降低了学习难度，提高了草案的准确率。
2.  **条件注入**：
    *   为了保证草案质量，DFlash 将目标模型提取的上下文特征作为条件注入到扩散模型的去噪过程中。这确保了生成的草案与当前的上下文高度相关。
3.  **验证与采样**：
    *   生成的特征块通过目标模型的后续层进行处理，映射到 Logits 空间进行验证。验证过程保留了推测解码的无损特性。

### 方法的优势
*   **极致的并行度**：彻底消除了草案生成的串行延迟。
*   **高接受率**：得益于特征对齐策略，DFlash 生成的草案质量极高，导致目标模型接受大部分草案，减少了重采样的次数。
*   **通用性**：该方法不依赖于特定的目标模型架构，可以适配 Llama、OPT 等多种主流 LLM。

## 3. 理论基础

### 理论依据
DFlash 的理论基础建立在两个核心概念的融合之上：**扩散模型的并行生成能力**与**推测解码的验证机制**。

1.  **扩散模型用于文本生成**：
    *   传统扩散模型通过逐步去噪恢复数据。DFlash 假设文本的语义特征（在大模型隐空间中的表示）具有连续流形结构，适合通过去噪过程进行建模。
    *   通过预测隐空间特征而非离散 Token，模型规避了离散空间的不可微性问题，使得梯度传播和训练更加稳定。

2.  **隐空间的时间独立性**：
    *   DFlash 的一个关键假设是：在给定上下文 $c$ 的情况下，未来 $k$ 步的隐状态 $h_{t+1}, ..., h_{t+k}$ 可以通过一个并行的去噪过程从噪声中恢复，而不需要像自回归那样依赖 $h_{t+i-1}$。这在理论上打破了马尔可夫链的线性依赖。

### 算法设计
*   **训练目标**：最小化草案模型生成的特征块与真实大模型推理时的特征块之间的均方误差（MSE）。
*   **推理过程**：
    1.  采样噪声 $\epsilon$。
    2.  执行一次 Draft 模型的去噪（或极少步数的去噪），得到特征块 $H_{draft}$。
    3.  将 $H_{draft}$ 输入目标模型的剩余层，得到 Logits。
    4.  并行验证所有 Token，拒绝不符合分布的 Token，并补充采样。

## 4. 实验与结果

### 实验设计
*   **数据集**：WikiText-2, C4, PG-19 等标准基准数据集。
*   **模型组合**：
    *   Target: Llama-2-70B, Llama-2-13B。
    *   Draft: 轻量级 Transformer 或 UNet 架构。
*   **对比基线**：标准 Speculative Decoding (SD), Medusa, EAGLE-2, EAGLE-3。

### 主要结果
*   **加速比**：DFlash 在 Llama-2-70B 上实现了 **6x-7x** 的端到端加速比，显著优于 EAGLE-3 的 2.5x 左右。
*   **接受率**：在 WikiText-2 上，DFlash 的 Token 接受率极高，这意味着大模型几乎完全认可草案模型生成的并行内容。
*   **延迟分析**：分析表明，DFlash 将 Draft 模型的执行时间从原来的 $O(k)$ 降低到了 $O(1)$，这是性能提升的主要来源。

### 结果验证
实验结果有力地支持了“并行起草优于串行起草”的假设。特别是在长文本生成场景中，DFlash 的优势更加明显，因为块并行的优势随着生成长度的增加而累积。

### 局限性
*   **训练开销**：引入了一个额外的扩散模型需要训练，虽然推理很快，但训练阶段比 EAGLE（仅训练简单的线性层或 MLP）要复杂。
*   **显存占用**：扩散模型处理特征块需要一定的显存，虽然比大模型小，但在显存受限的边缘设备上部署可能比单纯的 Tree Attention 方法更具挑战性。

## 5. 应用前景

### 实际应用场景
*   **实时对话系统**：DFlash 能够极大降低首字延迟（TTFT）和 Token 生成延迟，使得 AI 交互接近人类响应速度。
*   **高吞吐量内容生成**：如大规模文案生成、代码辅助编写，能够成倍降低服务器成本。

### 产业化可能性
非常高。随着企业对 LLM 部署成本的关注度提高，能够提供 6 倍加速且不损失模型智能水平的技术极具商业价值。DFlash 可以作为推理加速引擎集成到 vLLM、TensorRT-LLM 等推理框架中。

### 未来方向
*   **多模态扩展**：扩散模型在图像领域本就是霸主，DFlash 的架构天然适合扩展到图文并行的多模态生成任务中。
*   **动态块大小**：根据当前上下文的难度动态调整并行生成的块大小，以平衡速度和准确率。

## 6. 研究启示

### 对领域的启示
DFlash 最重要的启示在于**打破思维定势**。此前的研究大多聚焦于如何优化自回归的草案模型（如蒸馏更小的模型），而 DFlash 引入了完全不同的生成范式，证明了非自回归方法在 LLM 推理加速中的潜力。

### 可能的研究方向
1.  **非自回归解码的复兴**：DFlash 可能会重新点燃学术界对非自回归（NAR）文本生成的研究热情。
2.  **隐空间耦合**：研究如何更好地利用大模型的隐层特征，而不仅仅是输出概率，将是提升效率的关键。

**评估**：DFlash 在“并行度”这一维度上实现了质的飞跃，是目前推测解码技术路线中的重要突破。

## 研究最佳实践

## 最佳实践指南

### 实践 1：构建高质量的草稿模型

**说明**: DFlash 的核心性能依赖于草稿模型能够提供高准确率的推测令牌。草稿模型的质量直接决定了最终的验证通过率和系统吞吐量。应选择与目标模型架构相似但参数量较小的模型（例如目标模型是 Llama-2-70B，草稿模型可选择 Llama-2-7B 或更小的蒸馏版本）。

**实施步骤**:
1. 选择参数量约为目标模型 1/10 的同系列模型作为草稿模型。
2. 使用与目标模型相同的训练数据集对草稿模型进行知识蒸馏。
3. 确保草稿模型的词汇表与目标模型完全一致。

**注意事项**: 避免使用跨架构的模型（如用 Transformer 做草稿去预测 Mamba），这会导致特征空间不匹配，显著降低接受率。

---

### 实践 2：配置自适应的块大小

**说明**: DFlash 利用“块扩散”机制并行生成多个令牌。固定的块大小可能导致在困难样本上浪费计算资源，或在简单样本上未充分利用并行度。应根据上下文复杂度和历史验证通过率动态调整每次生成的块大小。

**实施步骤**:
1. 在推理引擎中实现一个滑动窗口监控器，记录过去 N 步的平均验证通过率。
2. 设定阈值：当通过率高于 80% 时，增加块大小（如从 4 增至 6）；当通过率低于 40% 时，减小块大小。
3. 设置最大块大小上限（通常建议为 5-10），以防止显存溢出。

**注意事项**: 块大小的调整不应过于频繁，建议每完成 32 个 token 的生成后评估一次。

---

### 实践 3：优化 KV Cache 管理

**说明**: 在验证阶段，目标模型需要重用草稿模型的 KV Cache 以减少冗余计算。DFlash 在处理多分支推测路径时，对显存带宽要求较高。必须确保 KV Cache 的布局支持快速的前缀匹配和回滚操作。

**实施步骤**:
1. 实现扁平化的 KV Cache 存储结构，减少内存碎片。
2. 在验证失败时，利用 PagedAttention 机制高效回收未被接受的 token 对应的 Cache。
3. 确保草稿模型和目标模型共享底层的 KV Cache 内存空间，避免数据拷贝。

**注意事项**: 在多轮对话场景中，需特别注意跨请求的 Cache 隔离，防止不同会话的推测路径混淆。

---

### 实践 4：利用稀疏注意力加速验证

**说明**: DFlash 的验证过程本质上是并行的树状注意力计算。为了进一步加速，可以在验证阶段对目标模型采用稀疏注意力机制，因为验证步骤主要关注局部上下文的正确性，而非全局依赖。

**实施步骤**:
1. 在目标模型的验证层中集成滑动窗口注意力。
2. 仅对当前验证块的 token 计算完整的注意力掩码，对历史 token 使用稀疏近似。
3. 在实现中，修改 FlashAttention 的内核调用，支持局部窗口聚合。

**注意事项**: 稀疏注意力的窗口大小需要根据模型特性调整，过小会影响生成质量，过大则无法提升速度。

---

### 实践 5：处理拒绝采样中的回滚开销

**说明**: 当推测的 token 序列被验证拒绝时，系统需要回滚到正确的接受点并重新生成。频繁的回滚会引入显著的延迟。最佳实践是采用“部分接受”策略，并优化重新采样的启动速度。

**实施步骤**:
1. 实现细粒度的 token 级验证，一旦发现不匹配立即截断，而不是处理完整个块。
2. 预分配计算资源，使得回滚后的重计算可以立即抢占 GPU 调度队列。
3. 记录高频拒绝的模式，动态调整后续的解码策略（如暂时切换至贪婪搜索）。

**注意事项**: 避免在 CPU 和 GPU 之间频繁传输控制权，所有的验证逻辑应尽可能在 GPU 内核中完成。

---

### 实践 6：显存占用与并发度的平衡

**说明**: DFlash 由于需要同时加载草稿模型和目标模型（或共享权重），且需要存储多路径的中间状态，对 GPU 显存（VRAM）提出了更高要求。在部署时需要在并发度和显存占用之间寻找平衡点。

**实施步骤**:
1. 使用量化技术（如 4-bit 或 8-bit 量化）加载草稿模型，因为其对精度要求略低于目标模型。
2. 根据显存大小动态调整并发请求数，显存紧张时优先保证单请求的吞吐量。
3. 监控显存带宽利用率，如果带宽成为瓶颈而非计算算力，应考虑降低并发数。

**注意事项**: 量化草稿模型后，必须重新校准其对齐目标模型的能力，以免过度降低接受率。

## 学习要点

- DFlash 提出了一种块级扩散模型，通过并行生成多个 token 将自回归生成的速度提升了一个数量级。
- 该方法利用“投机解码”框架，使用小型扩散模型作为草稿器来预测 token 块，并由大型语言模型进行高效验证。
- 引入了一种新颖的“块级拒绝采样”算法，在保证生成结果与目标模型分布完全一致的同时，显著提高了并行验证的效率。
- DFlash 在保持与 Transformer 模型相当性能的同时，大幅降低了推理延迟和计算成本。
- 该技术有效解决了传统自回归模型推理速度受限于串行生成的瓶颈，为高效的大规模文本生成提供了新思路。
- 通过结合扩散模型的并行特性与 LLM 的生成质量，DFlash 实现了推理速度与模型性能的最佳平衡。

## 常见问题


### 1: 什么是 DFlash，它主要解决什么问题？

1: 什么是 DFlash，它主要解决什么问题？

**A**: DFlash（Block Diffusion for Flash Speculative Decoding）是一种基于扩散模型的大语言模型（LLM）推理加速框架。它主要旨在解决大语言模型在生成文本时推理速度慢、延迟高的问题。传统的自回归生成方式受限于内存带宽和计算复杂度，而 DFlash 利用扩散模型强大的生成能力，通过“推测解码”技术，一次性生成多个候选 Token 块，并经过验证后保留有效部分。这种方法能够显著减少模型推理时的步数，从而在不牺牲模型生成质量的前提下，大幅提升生成速度。

---



### 2: DFlash 的核心工作原理是什么？

2: DFlash 的核心工作原理是什么？

**A**: DFlash 的核心原理是将扩散模型引入到大语言模型的推测解码流程中，具体包含三个关键步骤：

1.  **生成候选块**：使用一个小型的扩散模型作为“起草者”。该模型以当前上下文为条件，通过去噪过程并行生成一个包含多个 Token 的文本块。
2.  **并行验证**：使用原始的大型语言模型作为“验证者”。它将生成的候选块与原始上下文结合，通过一次前向传播并行计算整个候选块的概率分布，以此来验证候选 Token 的正确性。
3.  **接受与拒绝**：根据验证结果，接受那些与原始模型预测分布一致的 Token，拒绝不一致的 Token。对于被拒绝的部分，保留最后一个正确的状态，重新开始下一轮生成。

这种机制使得模型能够利用扩散模型的并行特性，在一个验证步骤内确认多个 Token 的有效性，从而突破逐串行生成的限制。

---



### 3: 为什么选择扩散模型而不是自回归模型作为起草模型？

3: 为什么选择扩散模型而不是自回归模型作为起草模型？

**A**: 在推测解码领域，通常使用较小的自回归模型（如小参数量的 LLM）作为起草模型。然而，DFlash 选择扩散模型主要基于以下优势：

1.  **并行生成能力**：自回归模型生成 $N$ 个 Token 需要 $N$ 次串行解码，而扩散模型可以通过去噪步骤一次性并行生成整个 Token 块。这使得起草阶段的延迟极低，且不随目标块长度的增加而线性增加。
2.  **全局视野**：扩散模型在生成过程中能够同时考虑整个目标块的上下文信息，而自回归模型在生成当前 Token 时无法看到未来的上下文，这有助于生成质量更高、连贯性更强的候选文本，从而提高验证阶段的接受率。

---



### 4: DFlash 与传统的 Speculative Decoding（如 Medusa, EAGLE）有何区别？

4: DFlash 与传统的 Speculative Decoding（如 Medusa, EAGLE）有何区别？

**A**: 传统的推测解码方法（如 Medusa 或 EAGLE）通常依赖于从主模型中提取额外的“头”或训练一个轻量级的自回归网络来预测未来的 Token。它们在本质上仍然是基于逐个或逐层预测的机制。

DFlash 的主要区别在于**生成范式**的改变：
*   **机制不同**：DFlash 是首个将**扩散模型**应用于 LLM 推测解码的方法。它利用扩散过程的随机性和并行性来生成候选序列，而不是基于贪心搜索或简单的树搜索。
*   **独立性**：DFlash 的扩散模型是一个独立的生成模块，不需要修改原始大语言模型的内部结构或权重，这使得它可以作为一个即插即用的加速模块应用于各种黑盒或开源 LLM。

---



### 5: DFlash 的加速效果如何，受哪些因素影响？

5: DFlash 的加速效果如何，受哪些因素影响？

**A**: 根据 arXiv 上的论文报告，DFlash 在多种基准测试和不同的模型规模上均取得了显著的加速效果（通常比原始自回归生成快 2-3 倍以上）。

其加速效果主要受以下因素影响：
1.  **接受率**：即生成的候选块中有多少比例被大模型接受。接受率越高，加速效果越明显。扩散模型生成的质量越高，接受率通常越高。
2.  **块大小**：即每次尝试生成的 Token 数量。较大的块大小意味着潜在的加速倍数更高，但如果块过大导致接受率下降，反而会增加验证开销。
3.  **验证模型的架构**：DFlash 特别适用于验证成本较低的模型架构（例如带有 Attention Sink 机制或 KV Cache 优化过的模型），因为这能降低并行验证的计算负担。

---



### 6: 使用 DFlash 是否会降低生成文本的质量？

6: 使用 DFlash 是否会降低生成文本的质量？

**A**: **不会**。DFlash 采用了一种“无损”的推理加速策略。

在推测解码的框架下，最终的输出是由原始的大语言模型（验证者）严格把关的。只有当候选 Token 的概率分布符合原始模型的预测标准时，这些 Token 才会被保留并输出给用户。如果候选 Token 不符合标准，系统会丢弃它们并重新采样。因此，DFlash 生成的文本分布与原始大语言模型完全一致，保证了输出的准确性和质量，仅仅是利用了并行计算来减少了推理的时间。
