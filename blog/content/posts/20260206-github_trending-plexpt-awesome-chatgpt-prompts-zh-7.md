## 3. 技术实现细节

**关键算法或技术方案**
虽然仓库本身不含传统代码算法，但其背后的 Prompt Engineering 遵循特定的技术范式：
- **Few-Shot Prompting（少样本提示）**：部分 Prompt 包含具体的输入输出示例，引导模型模仿特定的格式和逻辑。
- **Chain of Thought（思维链）**：部分复杂的 Prompt 会显式要求模型“一步步思考”，通过引导推理过程来提高复杂任务的准确性。
- **Delimiters（定界符）使用**：规范使用三引号、井号等定界符来区分指令和输入内容，有效防止 Prompt 注入攻击。

- **Contributing.md**：定义了贡献指南，规范了 Prompt 的提交格式，确保了代码库（文本库）的整洁和一致性。
- **GitHub Actions**：虽然未显式提及，但此类仓库通常配置了 Lint Action（如 Markdown Linter）来自动检查格式错误。

**数据流与交互逻辑**
1. **检索**：用户在 GitHub 页面上通过浏览器搜索功能（Ctrl+F）查找特定角色。
2. **复制**：用户手动复制 Prompt 文本。

# 示例1：从GitHub Trending获取热门仓库信息
import requests
from bs4 import BeautifulSoup

def get_github_trending_repos(language='python', since='daily'):
    """
    获取GitHub Trending上指定语言的热门仓库
    :param language: 编程语言，如'python', 'javascript'
    :param since: 时间范围，'daily', 'weekly', 'monthly'
    :return: 包含仓库信息的列表
    """
    url = f"https://github.com/trending/{language}?since={since}"
    headers = {'User-Agent': 'Mozilla/5.0'}
    
    try:
        response = requests.get(url, headers=headers)
        response.raise_for_status()
        soup = BeautifulSoup(response.text, 'html.parser')
        
        repos = []
        for article in soup.select('article.Box-row'):
            repo_info = {
                'name': article.select_one('h2 a').text.strip().replace('\n', '').replace(' ', ''),
                'url': "https://github.com" + article.select_one('h2 a')['href'],
                'description': article.select_one('p').text.strip() if article.select_one('p') else '无描述',
                'stars': article.select_one('a[href$="/stargazers"]').text.strip(),
                'forks': article.select_one('a[href$="/network/members"]').text.strip() if article.select_one('a[href$="/network/members"]') else '0'
            }
            repos.append(repo_info)
        
        return repos
    except Exception as e:
        print(f"获取失败: {e}")
        return []

## 最佳实践

## 提示词工程最佳实践指南

### 1. 明确角色定位

**核心价值**：赋予AI具体的专家身份，以锁定回答的专业度与语境。

**操作要点**：
*   **定义身份**：使用“你是一位[领域]专家”的句式。
*   **细化背景**：指定工作年限、专精方向（如“专注于后端高并发架构”）。
*   **风格设定**：明确沟通口吻（如“客观严谨”、“通俗易懂”）。

> **反例**：你是一个聪明的人。
> **正例**：你是一位拥有10年经验的Python后端工程师，擅长性能优化。

---

### 2. 结构化任务描述

**核心价值**：将复杂任务拆解为逻辑步骤，防止AI遗漏关键环节。

**操作要点**：
*   **分步指引**：使用有序列表（1. 2. 3.）明确执行顺序。
*   **任务拆解**：将大任务分解为“分析”、“草拟”、“润色”等子阶段。
*   **逻辑关联**：说明步骤间的依赖关系（如“在完成X的基础上，进行Y”）。

---

### 3. 补全上下文信息

**核心价值**：提供背景信息，消除歧义，提高回答的相关性。

**操作要点**：
*   **背景阐述**：简要说明项目现状或问题来源。
*   **受众定义**：明确阅读者是谁（如“面向非技术背景的产品经理”）。
*   **资源引用**：提供相关的参考资料、数据或前文摘要。

---

### 4. 规范输出格式

**核心价值**：强制要求特定格式，减少后期整理工作量。

**操作要点**：
*   **明确形式**：直接指定“Markdown表格”、“JSON代码块”或“无序列表”。
*   **结构模板**：提供具体的结构示例（如“请按：问题-原因-解决方案 的三段式输出”）。
*   **字段要求**：若为表格，需指定列名；若为代码，需指定语言类型。

---

### 5. 设定约束条件

**核心价值**：通过限制条件，精准控制输出的边界与质量。

**操作要点**：
*   **负面约束**：明确列出“不要做什么”（如“不要使用行业黑话”、“不要包含前言”）。
*   **优先级**：当存在冲突要求时，指定优先遵循的原则。

---

### 6. 迭代优化提示词

**核心价值**：通过A/B测试与反馈循环，持续逼近最佳效果。

**操作要点**：
*   **变量控制**：每次仅修改一个要素（如角色、格式或约束），以便定位问题。
*   **复盘对比**：分析失败案例的共性，针对性补强上下文或修正指令。
*   **版本管理**：记录有效的提示词版本，便于复用。

---

### 7. 利用少样本示例

**核心价值**：通过提供“输入-输出”样例，实现零样本或少样本学习，大幅提升模仿准确度。

**操作要点**：
*   **典型示范**：给出1-3个具有代表性的输入及期望输出。
*   **格式对齐**：确保示例的格式与最终要求完全一致。
*   **复杂度适中**：示例应涵盖核心逻辑，但避免过于冗长，消耗过多Token。

## 实践建议

以下是基于该仓库内容的 5-7 条实践建议：

**1. 采用“角色设定 + 任务描述 + 约束条件”的提示词结构**
不要直接抛出问题，而是先定义 ChatGPT 的身份。例如，与其说“帮我写段代码”，不如说“你是一位拥有 10 年经验的资深 Python 架构师。请帮我编写一个爬虫脚本，要求代码符合 PEP8 规范，并包含详细的错误处理机制。”这种结构能显著提高输出结果的专业度和准确率。

**2. 在提示词中提供“少量样本”进行引导**
如果你需要特定的输出格式（如 JSON、特定的表格样式或特定的语调），在提示词中给出 1-2 个具体的示例。这被称为 Few-Shot Prompting，能让模型迅速理解你的预期格式，减少反复修改的时间。

**3. 迭代优化提示词，而非一次定型**
如果第一次的回答不尽如人意，不要直接放弃。将 ChatGPT 的回答作为反馈，告诉它“这个回答太啰嗦了，请精简”或“请使用更专业的术语”。通过多轮对话逐步修正模型的理解，通常能获得比一次性写出复杂提示词更好的效果。

**4. 善用“思维链”技巧处理复杂逻辑**
对于数学、编程或逻辑推理类问题，在提示词末尾加上“请一步步思考”或“让我们一步步来解决这个问题”。这能强迫模型展示推理过程，从而大幅降低逻辑错误的发生率。

**5. 警惕“幻觉”现象，始终要求提供依据**
