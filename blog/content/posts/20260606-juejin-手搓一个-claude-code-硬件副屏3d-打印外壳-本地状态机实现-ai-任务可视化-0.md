## 摘要

#### 背景与目标
在使用 Claude Code 执行长时间任务时，AI 有时会“偷懒”，导致效率下降。为了实时感知任务状态，作者设计了一款实体 mini 副屏，用红绿灯直观展示 AI 的工作状态，从而促使其保持活跃。

#### 硬件方案
- **外壳**：采用 3D 打印制作紧凑外壳，适配常见 ESP32/Arduino 等开发板，便于放置在桌面或笔记本侧面。
- **显示**：使用三色 LED（红、黄、绿）或小型 OLED，分别对应“空闲/错误”“运行中”“完成”。
- **供电**：通过 USB‑C 供电，支持即插即用。

#### 软件实现
- **本地状态机**：在副屏微控制器上实现轻量状态机，接收来自 Claude Code 的状态信息（如 `idle`、`running`、`done`），并驱动对应 LED。
- **通信方式**：利用串口或网络（MQTT/WebSocket）将 Claude Code 的任务进度推送至副屏，保证低延迟、可靠传输。
- **可扩展**：状态机预留多种触发条件（如超时、错误率），后续可加入声音或震动提醒。

#### 使用效果
- **可视化**：红绿灯直观显示任务当前阶段，用户一眼即可判断 AI 是否在正常工作。
- **激励**：灯光颜色变化形成即时反馈，促使 AI 保持高效运行，降低“偷懒”概率。
- **成本低**：3D 打印外壳与普通电子元件相结合，整体材料成本约在 30–50 元。

#### 小结
通过 3D 打印外壳配合本地状态机，作者成功打造了一款低成本、实时的硬件副屏，实现了对 Claude Code 任务的可视化监控，显著提升了长时间任务的执行效率。

## 评论

#### 中心观点

这篇项目展示了开发者通过物理反馈机制监控 AI 编程工具的尝试，其核心思路值得肯定，但在技术实现与问题本质之间存在一定偏差。

#### 事实陈述

Claude Code 是 Anthropic 推出的命令行编程工具，能够根据自然语言描述执行代码修改、文件创建等任务。作者使用 3D 打印制作外壳，搭建本地状态机读取 Claude Code 的输出日志，并将任务状态映射为红、绿、黄三色灯光。项目中使用的技术栈包括 ESP32/Arduino 硬件平台、状态机逻辑以及 3D 建模与打印。

#### 作者观点

作者认为 AI 在执行长任务时存在"偷懒"现象，理由是任务进度停滞或输出质量下降。通过实体副屏提供实时状态反馈，可以"把 AI 牛马卷起来"，暗示物理可视化能够激励 AI 提升表现。

#### 技术推断

然而，Claude Code 的任务执行由远程 AI 模型控制，本地状态机只能反映输出频率和内容特征，无法向模型传递额外信号。红绿灯的变化本质上服务于人类观察者，而非 AI 本身。如果存在"偷懒"现象，其根源在于模型推理策略、token 限制或上下文窗口管理，而非缺少物理反馈。因此，该副屏更接近一种开发者仪式感工具，而非真正干预 AI 行为的手段。

#### 边界条件

该方案的有效性取决于具体场景。对于需要持续监控、运行时间较长的批量任务，状态可视化能帮助开发者快速判断任务是否卡顿或正常进行，减少反复检查终端的频率。但对于短时交互或需要即时交互修正的场景，实体副屏的实际帮助有限。

#### 实践启发

从项目本身看，作者展现了将软件行为映射到物理世界的硬件思维，这种能力在嵌入式开发和物联网场景中有广泛用途。如果目标明确为改善 AI 表现，更实际的优化方向包括：调整 prompt 结构、设置合理的任务分解粒度、以及利用厂商提供的任务监控 API。这些手段从模型侧入手，而非依赖外部观察。

- 通过低成本硬件（如 ESP32/STM32）和常见显示模组快速搭建 AI 任务的硬件副屏。
- 使用 3D 打印技术定制外壳，实现结构强度与外观的统一，提升产品化程度。
- 设计本地状态机实现任务状态的实时跟踪，保证状态切换的可靠性与错误恢复。
- 采用轻量级通信协议（UART、I2C、MQTT）实现主机与副屏的低延迟数据交互。
- 将 AI 任务拆解为离散的步骤并以图形化方式展示，提升开发者的可视化体验。
- 本地处理降低对云服务的依赖，提高响应速度并保障数据隐私。
- 采用模块化软硬件架构，便于后续功能扩展和跨平台移植。
