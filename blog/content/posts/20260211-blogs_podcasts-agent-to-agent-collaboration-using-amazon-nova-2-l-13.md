## 摘要/简介

This post walks through how agent-to-agent collaboration on Amazon Bedrock works in practice, using Amazon Nova 2 Lite for planning and Amazon Nova Act for browser interaction, to turn a fragile single-agent setup into a predictable multi-agent system.

---
## 导语

随着任务复杂度的提升，单一智能体往往难以兼顾全局规划与精准执行，这促使开发者转向多智能体协作架构。本文将深入探讨如何在 Amazon Bedrock 环境中，利用 Amazon Nova 2 Lite 负责规划，并结合 Amazon Nova Act 处理浏览器交互。通过这种分工协作，读者可以了解如何将脆弱的单体系统改造为稳定、可预测的多智能体工作流，从而有效解决复杂场景下的自动化难题。

## 摘要

这篇文章介绍了如何在 Amazon Bedrock 平台上，利用 **Amazon Nova 2 Lite** 和 **Amazon Nova Act** 两个模型，构建一个更稳定、可预测的多智能体协作系统。

以下是核心内容的总结：

**1. 背景与挑战**
文章首先指出了“脆弱的单智能体”模式的局限性。当仅使用单一模型处理复杂任务（如网页浏览、数据分析）时，往往会因为上下文过长、功能耦合度过高或缺乏纠错机制而导致失败。

**2. 解决方案：多智能体协作**
为了解决上述问题，文章提出了将任务拆解，由两个专门的角色（Agent）协同工作：
*   **规划者：** 负责高层逻辑。它不直接执行浏览器操作，而是负责将用户的宏大目标拆解为具体的步骤，并指导执行者。
*   **执行者：** 负责底层操作。它具备浏览器交互能力，根据规划者的指令执行具体的点击、输入和提取数据等操作。

**3. 实际运作流程**
文章通过一个具体案例（如查询比赛结果并总结）展示了工作流：
1.  **用户提问：** 用户提供一个复杂指令。
2.  **规划：** Amazon Nova 2 Lite 分析任务，制定计划并生成第一道指令发给执行者。
3.  **执行与反馈：** Amazon Nova Act 控制浏览器执行操作，并将结果（如网页截图或文本）反馈给规划者。
4.  **迭代：** 规划者根据反馈判断任务是否完成，或生成下一步指令，直到任务达成。

**4. 核心优势**
*   **可预测性：** 通过明确的分工（Llama 3.1 70B 通常用于规划，而 Nova Act 用于执行），系统行为更加可控，减少了单模型“幻觉”或操作失误带来的风险。
*   **容错性：** 如果执行步骤出错，规划者可以分析错误并重试，而不是直接导致整个任务失败。
*   **高效性：** 不同的模型针对其擅长的工作进行了优化（轻量级模型用于逻辑规划，功能型模型用于工具使用），降低了成本并提高了响应速度。

**总结**
该文章展示了如何利用 Amazon Bedrock 上的最新模型组合，通过**“思考”与“行动”分离**的架构，将原本脆弱的单智能体系统升级为结构

## 评论

### 中心观点
文章主张通过将认知规划任务与执行操作任务解耦，利用 Amazon Nova 2 Lite（规划者）和 Amazon Nova Act（执行者）构建多智能体系统，从而将脆弱的单体架构转化为可预测、高可靠性的自动化工作流。

### 支撑理由与边界条件分析

**1. 专业化分工带来的系统鲁棒性**
*   **事实陈述**：文章指出了单智能体模式在处理复杂任务时的“脆弱性”，即同一个模型既要负责逻辑推理又要负责工具调用，容易导致上下文过载或幻觉。
*   **作者观点**：采用“规划者-执行者”架构，Nova 2 Lite 负责将高层意图拆解为具体步骤，Nova Act 专注于浏览器环境的交互。这种基于角色的分离符合软件工程中的“单一职责原则”，能有效降低单一模型的认知负荷。
*   **实际案例**：在处理“预订机票并添加到日历”这类涉及多步骤、多网页跳转的任务时，专门的 Act 模型能更精准地识别 DOM 结构变化，而 Lite 模型则负责维持任务目标的连贯性。

**2. 模型能力的差异化匹配**
*   **事实陈述**：Amazon Nova Act 针对浏览器交互进行了专门优化（如解释 HTML/CSS），而 Nova 2 Lite 则侧重于逻辑推理与指令生成。
*   **你的推断**：这种组合暗示了未来 Agent 开发的趋势——不再是盲目追求单一“全知全能”的超大模型，而是追求“小模型组成的专家网络”。通过针对特定工作负载（如浏览器自动化）微调出的专用模型，在特定领域的表现往往优于通用大模型，且成本更低、延迟更小。

**3. 可观测性与调试的便利性**
*   **作者观点**：多智能体系统天然具有更好的可观测性。当任务失败时，开发者可以明确区分是“计划错了”（Lite 的问题）还是“操作没点到”（Act 的问题）。
*   **你的推断**：这对于企业级落地至关重要。在单智能体黑盒中，排查错误往往需要检查整个上下文窗口；而在分离式架构中，可以针对失败的环节单独替换模型或调整 Prompt，极大地降低了运维成本。

**反例与边界条件**

1.  **边界条件：简单任务的效率折损**
    *   **你的推断**：对于极简任务（如“查询当前天气”），双智能体架构引入了额外的网络往返开销和模型切换成本。单智能体直接生成函数调用可能比“Lite 规划 -> Act 执行”快 2-3 倍。因此，该架构并不适用于所有轻量级场景，存在过度设计的风险。

2.  **边界条件：上下文窗口的碎片化**
    *   **事实陈述**：在多 Agent 协作中，Agent 之间的通信通常需要将前一个 Agent 的输出压缩或总结后传递给下一个。
    *   **你的推断**：如果 Nova Act 在浏览器中捕获了大量非结构化的网页文本，将其全部回传给 Lite 进行下一步规划可能会导致上下文溢出或关键信息被稀释。如何设计 Agent 之间的“信息压缩协议”是该架构成败的关键，文章可能低估了这一技术难点。

## 技术分析

# 多智能体系统技术架构分析

## 1. 架构设计原理

**设计模式**
该方案采用了**职责分离**的设计模式，将单一的端到端智能体架构拆分为规划与执行两个独立的逻辑单元。这种架构旨在解决单一模型在处理复杂、非确定性任务（如浏览器交互）时的稳定性瓶颈。

**角色分工**
*   **规划层**：利用 **Amazon Nova 2 Lite** 模型承担任务拆解与逻辑推理职能。该层负责将高层意图转化为可执行的子步骤序列。
*   **执行层**：利用 **Amazon Nova Act** 模型承担具体操作职能。该层专注于处理视觉输入（如网页截图）并生成具体的交互指令。

**架构优势**
*   **认知与执行解耦**：将逻辑推理负载与环境交互负载隔离，避免了单一模型在同时处理复杂规划和精细动作时的性能冲突。
*   **容错机制**：规划层可以监控执行层的反馈。当执行层操作失败时，规划层能够基于当前状态重新生成指令，而非直接导致任务流中断。

## 2. 核心技术机制

**技术组件**
*   **Multi-Agent Orchestration（多智能体编排）**：通过中心化逻辑（通常为 Python 脚本或工作流引擎）管理智能体间的消息传递与状态流转。
*   **Vision-Action Loop（视觉-动作循环）**：执行层通过接收环境状态的视觉表征（截图）来决策下一步物理操作，形成闭环控制。
*   **State Management（状态管理）**：在非状态环境（如浏览器）中维护上下文记忆，确保执行层具备必要的任务背景。

**工作流逻辑**
1.  **任务分发**：用户指令输入至规划层，生成结构化的子任务列表。
2.  **指令执行**：编排层将当前子任务及上下文传递给执行层。执行层分析视觉输入，输出具体操作参数。
3.  **状态验证**：环境更新后，执行层将结果反馈回规划层。
4.  **迭代修正**：规划层评估反馈结果，决定继续执行下一步、重试或终止任务。

## 3. 挑战与应对

**关键难点**
*   **上下文窗口限制**：执行层仅能感知当前时刻的视觉状态，缺乏全局历史视野。
*   **错误累积**：单次执行的偏差可能在多步任务中被放大。

**工程化解决方案**
*   **记忆注入**：在调用执行层时，由规划层显式注入“当前目标”和“历史摘要”信息，弥补感知缺陷。
*   **强制中断机制**：在编排层设定最大重试次数或超时阈值，防止系统陷入无限循环或死锁状态。

## 最佳实践

## 最佳实践：构建多智能体系统

### 实践 1：基于模型特性明确智能体角色分工

**说明**:
Amazon Nova 2 Lite 和 Amazon Nova Act 针对不同的计算场景设计。Nova 2 Lite 适合处理文本生成、摘要和快速推理任务，具有较低的延迟；Nova Act 则更适合处理需要深度逻辑、工具调用或复杂决策的任务。最佳实践是利用这种互补性，让 Lite 充当“协调者”或“预处理者”，Act 充当“执行者”或“解决者”。

**实施步骤**:
1.  **定义工作流**：绘制任务流程图，明确哪些节点需要高速吞吐，哪些节点需要深度推理。
2.  **分配角色**：
    *   使用 **Nova 2 Lite** 处理：数据清洗、初步摘要、对话管理、信息检索。
    *   使用 **Nova Act** 处理：复杂逻辑推理、代码生成、API 调用编排、最终决策制定。
3.  **构建路由层**：建立一个轻量级路由机制，根据任务复杂度自动将请求分发给相应的模型。

**注意事项**:
避免让“重”模型处理简单的重复性任务，这会增加成本和延迟。同时，确保路由逻辑足够简单，以免引入额外的瓶颈。

---

### 实践 2：建立标准化的通信协议与消息格式

**说明**:
在多智能体协作中，Agent 之间的信息交换效率至关重要。非结构化的自然语言对话可能导致信息传递丢失或误解。最佳实践是定义一套严格的消息架构，确保 Lite（负责收集信息）和 Act（负责处理信息）能够无缝对接。

**实施步骤**:
1.  **定义消息结构**：创建包含 `sender`（发送者）、`receiver`（接收者）、`context`（上下文）、`payload`（具体数据）和 `timestamp` 的标准 JSON 格式。
2.  **实施中间件**：在 Agent 之间构建一个消息队列或总线服务，负责验证消息格式和转发。
3.  **上下文压缩**：利用 Nova 2 Lite 的摘要能力，在将历史对话传递给 Nova Act 之前，对冗长的上下文进行压缩，仅保留关键决策信息。

**注意事项**:
消息格式应具备版本控制能力，以便在不破坏现有系统的情况下进行迭代升级。

---

### 实践 3：实施“监督者”模式以优化成本与延迟

**说明**:
并非所有任务都需要高性能模型介入。最佳实践是采用“监督者”架构，由一个轻量级 Agent（使用 Nova 2 Lite）作为中央调度器，负责评估任务难度。只有当 Lite 无法解决或置信度不足时，才将任务升级给高性能 Agent（使用 Nova Act）。

**实施步骤**:
1.  **初始化调度器**：部署一个基于 Nova 2 Lite 的 Controller Agent。
2.  **设置评估阈值**：在 Prompt 中定义评估标准，让 Controller 判断任务是否属于“复杂/未知”类别。
3.  **执行路由逻辑**：
    *   简单任务 -> Controller 直接处理并返回。
    *   复杂任务 -> Controller 将任务封装并转发给 Worker Agent（Nova Act）。
4.  **结果整合**：Controller 接收 Worker 的结果，并转换为用户友好的格式输出。

**注意事项**:
这种模式有助于降低 API 调用成本，但需要精心设计 Prompt 以防止 Lite 模型误判任务难度。

---

### 实践 4：设计独立的工具调用沙箱环境

**说明**:
多智能体系统通常涉及与外部世界交互（如查询数据库、发送邮件）。Nova Act 可能被赋予执行这些操作的权限。为了安全起见，必须将不同权限级别的 Agent 隔离。Lite Agent 应仅拥有只读权限，而 Act Agent 的操作权限应受到严格审计。

**实施步骤**:
1.  **权限分级**：为 Lite 和 Act 分配不同的 IAM 角色或 API 密钥。
2.  **工具封装**：将底层 API 封装为标准化函数，并在函数描述中明确副作用（例如：“此操作将扣款”）。
3.  **人工确认环**：对于高风险操作（如删除数据、发送邮件），在 Act Agent 生成函数调用参数后，增加一个必须由 Lite Agent 或人工确认的步骤。

**注意事项**:
绝对不要允许 Agent 直接执行任意代码或命令。所有外部调用必须通过预定义的、经过严格测试的接口进行。

## 学习要点

- Amazon Nova Act 具备突破性的浏览器操控能力，能够直接驱动 Chrome 浏览器执行点击、输入和导航等操作，从而实现无需编写代码即可自动化处理 Web 任务。
- 通过将具备推理能力的 Nova 2 Lite 与具备行动能力的 Nova Act 组合，可以构建高效的“规划-执行”多智能体协作系统，实现复杂工作流的自动化。
- Nova Act 能够利用浏览器的无头模式和开发者工具，以极低的延迟完成页面交互，这为构建高性能的自主智能体提供了技术基础。
- 多智能体协作模式允许将复杂的业务逻辑拆解，由一个智能体负责高层决策与任务分发，另一个智能体专注于具体执行，从而显著提升系统的可扩展性。
- 该技术栈展示了从传统的“API 调用”向“自主 UI 交互”的转变，使智能体能够像人类一样操作现有的软件界面，极大降低了集成成本。
- 利用此类多智能体系统，企业可以快速自动化处理繁琐的在线工作流程（如数据抓取或表单填写），从而显著提高运营效率。
