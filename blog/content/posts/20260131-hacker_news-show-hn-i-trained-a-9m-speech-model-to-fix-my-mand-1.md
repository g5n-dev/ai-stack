# 示例1：拼音转带调符号（解决声调可视化问题）
def pinyin_with_tone(text):
    """
    将带数字声调的拼音转换为带声调符号的拼音
    例如: 'ni3 hao3' -> 'nǐ hǎo'
    """
    tone_map = {
        'a': ['ā', 'á', 'ǎ', 'à', 'a'],
        'e': ['ē', 'é', 'ě', 'è', 'e'],
        'i': ['ī', 'í', 'ǐ', 'ì', 'i'],
        'o': ['ō', 'ó', 'ǒ', 'ò', 'o'],
        'u': ['ū', 'ú', 'ǔ', 'ù', 'u'],
        'ü': ['ǖ', 'ǘ', 'ǚ', 'ǜ', 'ü'],
        'v': ['ǖ', 'ǘ', 'ǚ', 'ǜ', 'ü']  # 处理v代替ü的情况
    }
    
    # 声调优先级规则: a > o > e > i/u > ü
    priority = ['a', 'o', 'e', 'i', 'u', 'ü']
    
    result = []
    for word in text.split():
        if not word[-1].isdigit():
            result.append(word)
            continue
            
        tone_num = int(word[-1])
        base = word[:-1]
        
        # 找到需要标注声调的元音
        target_char = None
        for char in priority:
            if char in base:
                target_char = char
                break
                
        if target_char:
            # 替换为带声调的字符
            new_char = tone_map[target_char][tone_num - 1]
            base = base.replace(target_char, new_char, 1)
        
        result.append(base)
    
    return ' '.join(result)

# 测试
print(pinyin_with_tone("ni3 hao3 ma1"))  # 输出: nǐ hǎo mā
print(pinyin_with_tone("zhong1 guo2"))   # 输出: zhōng guó
```

def check_tone_accuracy(user_pinyin, correct_pinyin):
    """
    比较用户拼音声调与正确拼音声调的差异
    返回: (正确率, 错误列表)
    """
    user_tones = []
    correct_tones = []
    errors = []
    
    # 提取声调数字
    for word in user_pinyin.split():
        if word[-1].isdigit():
            user_tones.append(int(word[-1]))
    
    for word in correct_pinyin.split():
        if word[-1].isdigit():
            correct_tones.append(int(word[-1]))
    
    # 比较声调
    for i in range(min(len(user_tones), len(correct_tones))):
        if user_tones[i] != correct_tones[i]:
            errors.append(f"第{i+1}个字: 应该是{correct_tones[i]}声，你读的是{user_tones[i]}声")
    
    accuracy = (len(correct_tones) - len(errors)) / len(correct_tones) * 100 if correct_tones else 0
    return accuracy, errors

# 测试
user = "ni3 hao2"  # 用户发音
correct = "ni3 hao3"  # 正确发音
score, mistakes = check_tone_accuracy(user, correct)
print(f"声调准确率: {score:.1f}%")
print("错误详情:", mistakes)
```

### 实践 1：构建轻量级且针对性的模型架构

**说明**:
针对声调修正这一具体任务，并不总是需要数十亿参数的超大模型。通过使用参数量较小（如9M）的架构，可以在保持核心功能（修正声调）的同时，极大地降低推理延迟和部署成本。小模型更容易在边缘设备（如手机、本地浏览器）上运行，适合实时辅助语言学习。

**实施步骤**:
1.  **选择架构**: 选用适合音频处理的高效架构，如 DistilHuBERT 或精简版的 Conformer，这些模型在保留关键特征提取能力的同时大幅减少了参数量。
2.  **任务裁剪**: 专注于单一任务（如声调分类或声调转换），避免多任务学习带来的额外计算开销。
3.  **知识蒸馏**: 如果有更大的教师模型，利用知识蒸馏技术训练小模型，使其性能接近大模型但体积更小。

**注意事项**: 确保小模型在训练过程中没有严重的欠拟合，监控验证集上的准确率是否达到可用标准。

---

### 实践 2：利用合成数据进行针对性微调

**说明**:
高质量的声调标注数据稀缺且昂贵。利用现有的高质量TTS（文本转语音）引擎合成带有标准声调的音频，或者通过修改自然语音的音高来生成“错误声调”与“正确声调”的配对数据，可以快速构建大规模训练集。这种方法能确保模型学习到明确的声调特征差异。

**实施步骤**:
1.  **数据生成**: 使用TTS工具生成包含标准普通话四声的音频库。
2.  **数据扰动**: 对音频进行音高调整，模拟外国人学习中文时常见的声调错误（如将二声读成三声），构建“错误-正确”配对数据。
3.  **混合训练**: 将合成数据与真实的人类录音数据混合使用，在提高数据量的同时保留自然语音的语感。

**注意事项**: 合成数据与真实数据的分布可能存在差异，需仔细评估模型在真实场景下的泛化能力，避免模型只学会处理合成语音的特征。

---

### 实践 3：实施基于音素对齐的细粒度评估

**说明**:
传统的语音评估指标（如WER）主要关注字词对错，容易忽略声调错误。为了准确衡量模型修正声调的能力，必须实施基于音素或声调级别的对齐评估。这能帮助开发者精确定位模型是在哪个音节或声调转换上出现了问题。

**实施步骤**:
1.  **强制对齐**: 使用蒙特卡洛采样或强制对齐工具（如Montreal Forced Aligner）将音频与文本对齐，确定每个音素的起止时间。
2.  **声调提取**: 提取每个音节对应的基频曲线，将其量化为标准的四声。
3.  **对比分析**: 计算模型输出音频的声调与标准声调的一致性，生成混淆矩阵，分析模型对特定声调（如三声变调）的处理能力。

**注意事项**: 汉语的三声（上声）在语流中会发生变调，评估系统需要具备处理连读变调的逻辑，否则会产生误判。

---

### 实践 4：建立端到端的实时反馈管线

**说明**:
语言学习工具的价值在于即时反馈。构建一个低延迟的音频处理管线，使得用户在说完一句话后，能立即听到修正后的发音或看到可视化的声调曲线。这要求模型优化和工程部署紧密结合。

**实施步骤**:
1.  **流式处理**: 设计支持流式输入的推理引擎，无需等待用户说完整个句子即可开始处理。
2.  **模型量化**: 对训练好的模型进行量化（如INT8量化），减少内存占用并提高推理速度。
3.  **可视化界面**: 开发前端界面，实时绘制用户音频的基频曲线与标准曲线的对比图，直观展示声调差异。

**注意事项**: 在移动端或Web端部署时，需考虑浏览器兼容性和电池消耗，避免过度占用CPU资源导致UI卡顿。

---

### 实践 5：关注上下文相关的声调变化

**说明**:
汉语声调并非孤立存在，会受到前后字声调的影响（如“一”和“不”的变调，以及三声连读时的变调）。一个好的声调模型不能仅根据单字判断，而必须具备上下文感知能力，才能生成自然、地道的修正语音。

**实施步骤**:
1.  **上下文窗口**: 在训练模型时，输入不仅包含目标音节，还应包含前后各1-2个音节的音频或文本特征。
2.  **变调规则集成**: 在数据预处理阶段或后处理阶段，显式地应用汉语变调规则，或者通过大量语料让模型隐式学习这些规则。
3.  **韵律自然度**: 除了声调高低，还要关注句子的韵律和重音，避免修正后的声调听起来像机器人。

**注意事项**: 过度纠正可能导致语流不自然，模型应学会区分
