- LangServe 和 LangSmith 分别提供了模型服务的部署能力与开发调试的可观测性，完善了从原型开发到生产上线的全生命周期支持。

1: LangChain 是什么，它主要解决了什么问题？

### 2: LangChain 中的 Chain（链）和 Agent（代理）有什么区别？

2: LangChain 中的 Chain（链）和 Agent（代理）有什么区别？

**A**: 这是理解 LangChain 架构的核心，两者的主要区别在于确定性和灵活性：

*   **Chain（链）**：
    *   **确定性流程**：Chain 是预定义的操作序列。开发者明确规定了第一步做什么、第二步做什么。
    *   **适用场景**：适用于逻辑固定、步骤明确的任务，例如：获取用户输入 -> 调用 LLM 总结 -> 翻译成英文 -> 输出。
*   **Agent（代理）**：
    *   **动态决策**：Agent 不遵循固定的路径。它接收用户目标，由 LLM 决定下一步采取什么行动（Action），甚至决定何时结束任务。
    *   **适用场景**：适用于未知路径或需要推理的复杂任务，例如：“帮我查一下现在的天气，如果下雨就建议带伞，否则建议涂防晒霜”。Agent 会先判断需要查天气，再根据结果生成建议。

3: 如何理解 LangChain 中的 Prompt Template（提示词模板）？

其核心功能包括：

### 4: 在 LangChain 中，什么是“索引”和“检索器”，它们在 RAG 中扮演什么角色？

4: 在 LangChain 中，什么是“索引”和“检索器”，它们在 RAG 中扮演什么角色？

**A**: 在构建 RAG（检索增强生成）应用时，这两个概念至关重要：

*   **索引**：这是数据准备阶段的过程。指将非结构化数据（如文本文件）加载、切分、转化为向量嵌入，并存储到向量数据库中的全过程。目的是让数据变成 LLM 可以高效搜索的格式。
*   **检索器**：这是数据查询阶段的接口。它的作用是根据用户的查询，从索引好的数据中找到最相关的文档片段，并将其作为上下文传递给 LLM。

简单来说，**索引是“存”的过程，检索器是“取”的过程**。LangChain 提供了标准接口，使得可以轻松切换不同的底层向量数据库（如 ChromaDB, Pinecone, FAISS）而不需要修改上层业务代码。
