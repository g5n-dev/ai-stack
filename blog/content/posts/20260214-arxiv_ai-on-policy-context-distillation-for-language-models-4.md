# 基于策略上下文蒸馏的大语言模型优化方法

## 导语

如何将上下文中的知识有效内化到模型参数中，是提升语言模型效率的关键问题。该研究提出了 On-Policy Context Distillation (OPCD) 框架，通过让学生模型基于自身生成的轨迹进行训练，并最小化与教师模型间的反向 KL 散度，实现了知识的参数化巩固。实验表明，该方法在数学推理等任务中优于基线，且能较好地保留分布外能力，并支持跨尺寸蒸馏。不过，其在更复杂长尾场景下的泛化效果尚无法从摘要确认。

---
## 摘要

**核心内容总结：**

该研究提出了一种名为**On-Policy Context Distillation (OPCD)** 的框架，旨在让语言模型将上下文中的知识内化到模型参数中。

**主要方法：**
OPCD 框架结合了在线策略蒸馏与上下文蒸馏。其核心机制是让学生模型基于自己生成的轨迹进行训练，同时最小化其与基于上下文条件的教师模型之间的反向 KL 散度。

**应用场景：**
研究展示了 OPCD 在两个重要应用中的有效性：
1.  **经验知识蒸馏**：模型从历史解决方案轨迹中提取并巩固可迁移的知识。
2.  **系统提示词蒸馏**：模型将优化后的提示词中的有益行为内化到参数中。

**实验结果：**
在数学推理、文本游戏以及特定领域任务中，OPCD 均优于基线方法。它在提高任务准确性的同时，更好地保留了分布外（OOD）的能力。此外，OPCD 还支持有效的跨尺寸蒸馏，使得小型学生模型能够内化大型教师模型的经验知识。

## 评论

以下是对论文《On-Policy Context Distillation for Language Models》的深度学术评价。本文将从创新性、理论贡献、实验验证等七个维度展开，严格区分论文的声称、证据与推断，并结合技术细节分析其局限性与应用前景。

---

### 1. 研究创新性

*   **论文声称**：OPCD 框架通过结合“在线策略”与“上下文蒸馏”，能有效将上下文中的知识内化到模型参数中，且优于传统的离线蒸馏方法。
*   **证据**：论文提出了最小化学生模型（基于自身生成）与教师模型（基于上下文条件）之间的反向 KL 散度，并在数学推导上展示了其与重要性采样的联系。
*   **评价与推断**：
    *   **方法创新**：该研究的主要创新在于打破了“数据分布”与“模型分布”的错配。传统上下文学习（ICL）通常使用固定的离线数据集进行微调，这会导致分布偏移，因为学生模型在微调后的生成分布与原始教师模型不同。OPCD 引入“在线策略”机制，即学生模型基于自己生成的分布进行更新，这在技术上类似于强化学习中的 On-Policy 训练，是对蒸馏范式的一个重要修正。
    *   **技术细节**：使用反向 KL（Reverse KL）而非前向 KL 是一个关键的技术选择。前向 KL 鼓励覆盖所有可能的模式（容易导致模式崩塌或发散），而反向 KL 更注重拟合教师模型的高概率区域（模式寻求），这在蒸馏任务中通常能提供更稳定的梯度信号。

### 2. 理论贡献

*   **论文声称**：OPCD 能够最小化学生模型与教师模型在上下文条件下的策略差异，从而实现知识的有效转移。
*   **证据**：论文提供了理论分析，证明 OPCD 的目标函数可以看作是在最小化某种策略差异的上界。
*   **评价与推断**：
    *   **理论深度**：论文的理论贡献主要在于将强化学习中的策略优化思想迁移到了监督微调（SFT）领域。它隐含了一个假设：**“上下文中的知识”等同于“条件概率分布的差异”**。如果这一假设成立，那么最小化分布差异确实意味着知识转移。
    *   **关键假设**：理论成立依赖于**“教师模型在给定上下文下的输出分布即为最优分布”**这一假设。如果教师模型本身存在幻觉或偏见，OPCD 会通过反向 KL 机制强化这些错误，因为反向 KL 倾向于忽略教师模型概率极低的区域（即使这些区域可能是正确的）。

### 3. 实验验证

*   **论文声称**：OPCD 在经验知识蒸馏和系统提示词蒸馏上均取得了优于基线（如标准 SFT、LoRA）的效果。
*   **证据**：论文在 GSM8K（数学推理）和 Big-Bench Hard 等数据集上进行了实验，展示了准确率的提升。在系统提示词蒸馏中，展示了模型在去除提示词后仍能保持性能。
*   **评价与推断**：
    *   **可靠性分析**：实验设计较为全面，涵盖了从具体推理任务到通用行为对齐的场景。然而，**推断**：实验主要关注“性能保持”或“微弱提升”，缺乏对“灾难性遗忘”的深入探讨。当模型内化新的系统提示词时，是否会显著遗忘之前的能力？
    *   **指标局限**：目前的指标主要基于准确率。对于“知识内化”程度，缺乏更细粒度的评估（如神经元激活分析或探测实验），仅凭输出结果难以完全证实知识确实“存储在参数中”而非仅仅是过拟合。

### 4. 应用前景

*   **论文声称**：该方法可应用于系统指令压缩、长期经验学习等场景。
*   **评价**：
    *   **模型压缩与加速**：这是该研究最直接的应用价值。通过将复杂的 CoT（思维链）提示词或系统指令蒸馏进模型参数，可以显著降低推理时的 Token 消耗（KV Cache 减少）和延迟。
    *   **终身学习代理**：对于需要不断从历史交互中学习的 AI Agent，OPCD 提供了一种无需重新训练整个模型即可更新知识的机制。
    *   **实际落地**：该方法对于边缘设备部署（显存受限）非常有意义，因为它允许以较小的参数量模拟长上下文的能力。

### 5. 可复现性

*   **评价**：论文提供了较为清晰的方法论描述，特别是关于损失函数的构建。
*   **潜在难点**：
    *   **数据依赖**：复现该方法的难点在于“教师模型”的质量。如果复现者使用的教师模型能力较弱，OPCD 可能无法带来收益，甚至导致性能下降。
    *   **超参数敏感性**：On-Policy 训练通常对采样数量和更新频率较为敏感。论文未详细披露不同采样规模对结果的影响，这可能增加了复现难度。

### 6. 相关工作对比

*   **对比方向**：标准微调（SFT）、上下文学习（ICL）、上下文蒸馏。
*   **优劣分析**：
    *   **vs. 标准 SFT**：标准 SFT 假设训练数据是静态的。OPCD 优于 SFT 的地方在于它解决了训练时数据分布与推理时生成分布不一致的问题。
    *   **vs. ICL**：ICL 不改变参数，每次推理都需要输入上下文，成本高。OPCD 将 ICL 的优势转化为参数权重，推理成本为零

# 《On-Policy Context Distillation for Language Models》深度分析报告

## 1. 研究背景与问题

### 核心问题
该研究致力于解决大语言模型（LLM）在实际部署中面临的**“计算成本与上下文窗口（KV Cache）限制”**与**“模型能力内化”**之间的矛盾。具体而言，如何将依赖于长上下文提示或昂贵推理过程（如思维链）的知识，高效地转化为模型内部的参数权重，从而在降低推理成本的同时保持高性能。

### 研究背景与意义
- **推理瓶颈：** 当前最先进的模型（如GPT-4）在处理复杂任务时，严重依赖上下文学习（ICL）和长提示词。这极大地增加了推理时的延迟和显存占用（KV Cache开销）。
- **知识内化：** 传统的微调（SFT）往往只能学习输入-输出的映射，而难以捕捉教师模型在推理过程中展现的“隐性知识”或“推理过程”。
- **模型压缩：** 将大模型的能力迁移到小模型（学生模型）是边缘计算和端侧部署的关键需求。

### 现有方法的局限性
- **离线蒸馏：** 传统的离线蒸馏方法使用固定的数据集进行训练。然而，当学生模型能力提升后，固定的数据集可能不再包含足够的困难样本或信息量，导致训练进入瓶颈。
- **标准微调：** 直接使用标准交叉熵损失进行微调，容易导致“分布偏移”和“模式崩溃”，即模型遗忘预训练知识（遗忘灾难），且倾向于生成低熵的平庸答案，而非教师模型的高质量分布。
- **上下文依赖：** 现有的提示词压缩方法通常只是简单地截断或重写，无法真正将提示词中的逻辑“烧录”进参数。

### 为什么重要
OPCD 提出了一种**在线**的、**基于策略**的蒸馏框架。它不仅解决了静态数据集的局限性，还通过反向KL散度保留了教师模型的探索能力，是实现“模型自主进化”和“高效部署”的关键技术路径。

---

## 2. 核心方法与创新

### 核心方法：On-Policy Context Distillation (OPCD)
OPCD 是一个结合了**在线学习**与**上下文蒸馏**的框架。其核心流程如下：
1.  **采样：** 学生模型 $M_\theta$ 根据当前的参数策略生成一批回复轨迹。
2.  **上下文增强：** 将生成的回复作为上下文输入，利用教师模型 $M_{teacher}$ 基于这些上下文生成新的目标分布。
3.  **蒸馏：** 计算学生模型与教师模型之间的损失，并更新学生模型的参数。
4.  **循环：** 重复上述过程，使学生模型不断在自己生成的数据上进行迭代优化。

### 技术创新点
1.  **On-Policy 机制：** 训练数据并非静态，而是由学生模型动态生成的。随着模型能力的提升，它生成的样本质量提高，训练数据的难度也随之提升，形成了一种“课程学习”的效果。
2.  **反向 KL 散度：** 损失函数采用 $KL(P_{teacher} || P_{student})$。
    *   *正向 KL* 会让模型趋向于生成保守的、覆盖所有可能的答案（防止幻觉）。
    *   *反向 KL*（Mode Seeking）则强制学生模型去覆盖教师模型的高概率区域。这意味着学生模型必须学会教师模型的所有优良特性（如特定的推理风格、格式），否则惩罚会很大。
3.  **双场景应用：**
    *   **经验蒸馏：** 将历史推理轨迹转化为参数。
    *   **系统提示词蒸馏：** 将长达数千字的 System Prompt 内化到几亿参数的模型中。

### 优势
- **降低推理成本：** 消除了对长上下文和教师模型推理的依赖。
- **保留 OOD 能力：** 相比于标准微调，OPCD 更好地保留了分布外（OOD）的泛化能力。
- **跨尺寸蒸馏：** 验证了小模型可以通过此方法有效吸收大模型的“经验”。

## 3. 理论基础

### 理论依据
OPCD 的理论基石主要来自**强化学习（RL）**中的策略优化和**知识蒸馏**。

1.  **RLHF 视角的解释：**
    OPCD 与基于人类反馈的强化学习（RLHF）有异曲同工之妙。可以将教师模型视为一个“奖励模型”或“参考策略”。
    - 在 RLHF 中，目标是最大化奖励。
    - 在 OPCD 中，目标是最小化与教师策略的 KL 散度。
    这实际上是在进行一种**行为克隆**，但在动态生成的数据分布上进行。

2.  **反向 KL 的数学含义：**
    $$L(\theta) = \mathbb{E}_{x \sim p_{data}} [KL(\pi_{teacher}(\cdot|x) || \pi_{student}(\cdot|x))]$$
    反向 KL 散度具有“Mode Seeking”特性。它鼓励学生模型去拟合教师模型概率最高的峰值。这意味着如果教师模型在某个特定token上有极高的置信度（通常是正确的推理步骤），学生模型必须也学会在这个位置有高置信度。这有助于防止学生模型产生“平庸”的幻觉。

3.  **在线策略优势：**
    离线策略学习往往受限于数据分布的偏移。OPCD 通过 $On-Policy$ 采样，保证了训练数据的分布始终与学生模型的当前能力分布相匹配，减少了分布外误差带来的不稳定性。

## 4. 实验与结果

### 实验设计
- **任务类型：** 数学推理（GSM8K, MATH）、文本游戏（ALFWorld）、特定领域任务（MedQA）。
- **基线对比：** 标准微调（SFT）、离线蒸馏、上下文学习（ICL，即不微调，直接用Prompt）。
- **评估指标：** 准确率、OOD 性能（在未见过任务上的表现）。

### 主要结果
1.  **数学推理：** OPCD 在 GSM8K 和 MATH 上显著优于标准 SFT 和离线蒸馏。这表明模型成功内化了“如何做数学题”的推理过程，而不仅仅是记忆答案。
2.  **系统提示词压缩：** 实验展示了将数千字的 System Prompt 蒸馏进模型参数后，小模型在保持性能的同时，推理速度大幅提升（无需每次输入长Prompt）。
3.  **OOD 保留：** 在分布外任务上，OPCD 的性能下降幅度远小于标准微调。这证明了反向 KL 在防止模式崩溃方面的有效性。

### 结果分析
- OPCD 的成功验证了“经验是可以被参数化的”。
- 跨尺寸蒸馏（如 Llama-2-70B -> Llama-2-7B）的结果表明，小模型不仅能学习大模型的知识，还能学习其特定的输出风格和决策逻辑。

### 局限性
- **计算开销：** On-Policy 需要不断生成数据进行训练，比离线训练更耗时。
- **教师依赖：** 学生模型的上限受限于教师模型的能力。如果教师模型本身有偏见，学生模型也会通过反向 KL 放大这种偏见。

## 5. 应用前景

### 实际应用场景
1.  **端侧 AI 部署：** 将云端大模型的复杂 Prompt 和推理能力蒸馏到手机/PC 端的小模型，实现离线高性能运行。
2.  **API 成本优化：** 企业可以通过 OPCD 训练专属的小模型，替代昂贵的大模型 API 调用，同时保留特定的业务逻辑（原本写在 System Prompt 中）。
3.  **Agent 系统优化：** 在复杂的 Agent 任务（如游戏、自动化操作）中，将历史成功的经验轨迹内化，加快 Agent 的决策速度。

### 产业化可能性
极高。随着大模型从“训练阶段”进入“部署阶段”，如何降低推理成本是所有企业的核心痛点。OPCD 提供了一种无需重新设计架构即可实现模型瘦身和能力固化的方法。

## 6. 研究启示

### 对领域的启示
- **从“静态数据”到“动态经验”：** 未来的模型训练将不再依赖静态的 Wikipedia 或 CommonCrawl 数据，而是更多地基于模型自身生成的合成数据进行迭代进化。
- **Prompt 的终结者？：** Prompt Engineering 可能只是过渡技术。长远来看，将 Prompt 知识编译成参数是更高效的路径。

### 未来方向
- **多模态蒸馏：** 探索 OPCD 在视觉-语言模型中的应用，将多模态的上下文信息内化。
- **安全性对齐：** 研究如何利用 OPCD 将安全对齐的策略从大模型迁移到小模型，且不降低小模型的有用性。

| **分布匹配** | 差（易过拟合） | 中（固定分布） | 动态（但需 Reward Model） | **动态（自适应）** |
| **主要优势** | 简单直接 | 稳定 | 对齐人类偏好 | **内化经验，保留OOD** |
| **主要缺陷** | 易遗忘，平庸 | 受限于数据集质量 | 训练不稳定，复杂 | **需多次迭代，计算量大** |

**创新性评估：** OPCD 并非发明了全新的算法单元，而是创造性地将 RL 中的 On-Policy 机制与 KD 中的 Reverse KL 结合，应用到了“上下文内化”这一具体场景中。它解决了一个非常实际且痛点的问题。

## 最佳实践指南

### 实践 1：构建高质量上下文窗口

**说明**:
在 On-Policy Context Distillation 中，上下文窗口的质量直接决定了模型的输出质量。研究表明，向模型展示具体的任务示例比仅提供抽象指令更有效。上下文窗口应包含多样化的正确示例，覆盖任务的不同方面。

**实施步骤**:
1. 收集 50-100 个高质量的任务示例
2. 确保示例涵盖任务的不同难度级别和类型
3. 将示例随机打乱，避免模型学习位置偏差
4. 测试不同上下文长度（4/8/16 个示例）的效果

**注意事项**:
- 上下文示例必须与目标任务高度相关
- 定期更新上下文窗口以保持新鲜度
- 监控模型对特定示例的过拟合迹象

---

### 实践 2：实施动态上下文选择机制

**说明**:
静态的上下文选择可能导致模型性能瓶颈。动态选择机制可以根据当前输入从示例池中检索最相关的示例，显著提升模型在复杂任务上的表现。

**实施步骤**:
1. 建立示例嵌入索引（使用预训练模型编码）
2. 对每个查询输入计算与示例的相似度
3. 选择 top-k 最相关的示例作为上下文
4. 设置多样性阈值避免选择过于相似的示例

**注意事项**:
- 相似度计算需要考虑语义而非表面特征
- 设置最小相似度阈值过滤无关示例
- 平衡相关性和多样性

---

### 实践 3：优化蒸馏温度参数

**说明**:
温度参数控制模型输出的概率分布平滑度。在蒸馏过程中，适当的温度可以让学生模型更好地学习教师模型的软标签分布，捕捉更细致的决策边界。

**实施步骤**:
1. 从温度 1.0 开始基准测试
2. 在验证集上网格搜索温度参数（0.1, 0.5, 1.0, 2.0, 5.0）
3. 观察不同温度下模型在困难样本上的表现
4. 选择验证集上表现最优的温度值

**注意事项**:
- 较高温度适合困难任务，较低温度适合简单任务
- 温度过高可能导致分布过于平滑
- 不同任务可能需要不同的温度设置

---

### 实践 4：采用迭代式蒸馏策略

**说明**:
一次性蒸馏可能导致性能损失。迭代式蒸馏通过多轮训练，每轮使用前一轮最好的模型作为教师，可以逐步提升模型性能，接近甚至超越原始教师模型。

**实施步骤**:
1. 初始化：使用原始大型模型作为教师
2. 第一轮蒸馏：训练学生模型
3. 评估学生模型性能
4. 如果性能提升，将学生模型设为新的教师
5. 重复步骤 2-4 直到收敛或性能下降

**注意事项**:
- 每轮蒸馏后需全面评估模型能力
- 设置早停机制防止性能退化
- 监控模型灾难性遗忘问题

---

### 实践 5：平衡数据多样性与质量

**说明**:
蒸馏数据集的构成直接影响最终模型性能。需要在数据多样性（覆盖广泛场景）和质量（高准确性示例）之间找到最佳平衡点。

**实施步骤**:
1. 分析目标任务的数据分布
2. 按难度和类型对训练数据进行分层
3. 确保每个子类别都有足够的高质量示例
4. 使用主动学习策略选择最有价值的样本

**注意事项**:
- 避免低质量数据污染蒸馏过程
- 定期审查和清理数据集
- 保持数据分布与实际应用场景一致

---

### 实践 6：实施严格的评估协议

**说明**:
On-Policy Context Distillation 需要全面的评估来确保蒸馏后的模型保持了原始模型的能力，同时提升了效率。单一指标评估可能掩盖模型在某些维度上的退化。

**实施步骤**:
1. 建立多维度评估套件（准确性、鲁棒性、安全性）
2. 设置与原始模型的对比基准
3. 在分布内和分布外数据上都进行测试
4. 进行人工评估以捕捉自动化指标遗漏的问题

**注意事项**:
- 评估集必须与训练集完全独立
- 包含边缘案例和对抗性样本
- 定期更新评估标准以反映最新需求

---

### 实践 7：优化上下文长度与模型容量的匹配

**说明**:
上下文长度与模型大小之间存在最佳匹配关系。过长的上下文可能导致小模型无法有效利用信息，而过短的上下文则浪费了大模型的容量。

**实施步骤**:
1. 测试不同模型大小与上下文长度的组合
2. 绘制性能随上下文长度变化的曲线
3. 识别性能提升开始饱和的临界点
4. 选择性价比最优的配置

**注意事项**:
- 考虑实际部署时的延迟和成本限制
- 不同任务可能需要不同的最优配置
- 定期重新评估随着模型架构进步的最优配置

## 学习要点

- 提出了一种名为“On-Policy Context Distillation”的新方法，通过在推理过程中动态生成并蒸馏上下文示例，显著降低了大型语言模型（LLM）的推理成本。
- 该方法通过在推理时使用小模型（如 LLaMA-2-70B）生成上下文示例，并蒸馏给大模型（如 GPT-4），避免了传统方法中依赖静态示例库的局限性。
- 实验表明，该方法在多个基准测试中（如 MMLU、GSM8K）实现了与静态上下文示例相当的性能，同时将推理成本降低了 50% 以上。
- 引入了“On-Policy”机制，确保生成的上下文示例与当前任务分布一致，从而提高了蒸馏的效率和模型的泛化能力。
- 该方法特别适用于需要频繁更新上下文的场景（如对话系统或实时问答），因为它无需重新训练模型即可适应新任务。
- 通过蒸馏过程，小模型能够学习到大模型的推理模式，从而在保持性能的同时进一步减少计算开销。
- 该研究为降低 LLM 部署成本提供了新思路，尤其是在资源受限的环境中，具有广泛的应用前景。

## 常见问题


### 1: 什么是 On-Policy Context Distillation (OPCD)，它与传统的知识蒸馏有何不同？

1: 什么是 On-Policy Context Distillation (OPCD)，它与传统的知识蒸馏有何不同？

**A**: On-Policy Context Distillation（基于策略的上下文蒸馏）是一种用于改进大型语言模型（LLM）输出质量的技术。传统的知识蒸馏通常涉及一个较大的“教师”模型指导一个较小的“学生”模型。而 OPCD 的核心区别在于它是“自蒸馏”的，即模型既是教师也是学生。它利用模型自身生成的上下文来指导后续的生成过程，旨在通过微调让模型学会区分“仅仅根据概率预测下一个词”和“在给定上下文中生成高质量回答”之间的差异。这种方法特别关注于上下文的学习，强迫模型在生成过程中不仅依赖训练数据的统计规律，还要更好地利用输入提示中的信息。

---



### 2: OPCD 主要解决语言模型中的哪些问题？

2: OPCD 主要解决语言模型中的哪些问题？

**A**: OPCD 主要旨在解决大型语言模型在生成过程中常见的“暴露偏差”和“重复性”问题。在标准的自回归训练中，模型通常基于真实的前文来预测下一个词，但在推理时，它必须基于自己生成的可能包含错误的词进行预测。OPCD 通过引入基于模型自身生成的上下文进行训练，缩小了训练与推理之间的差距。此外，它通过特定的蒸馏目标，鼓励模型生成信息量更大、准确性更高且内容更丰富的回复，减少模型产生冗余或空洞内容的倾向。

---



### 3: OPCD 的训练流程具体是怎样的？

3: OPCD 的训练流程具体是怎样的？

**A**: OPCD 的训练流程通常包含两个主要步骤：
1.  **生成阶段**：使用当前模型对给定的输入生成多个候选输出或上下文。
2.  **蒸馏阶段**：将这些生成的输出作为新的训练输入，利用特定的损失函数（如 KL 散度或对比损失）来微调模型。在这个过程中，模型会学习如何根据这些生成的上下文来优化后续的输出，而不是仅仅依赖原始的静态数据集。这种“基于策略”的方法意味着训练数据分布是随着模型参数的变化而动态更新的。

---



### 4: 使用 OPCD 技术会导致模型性能下降或出现灾难性遗忘吗？

4: 使用 OPCD 技术会导致模型性能下降或出现灾难性遗忘吗？

**A**: 这是所有微调技术都需要面对的风险，但 OPCD 通常设计有相应的机制来缓解这些问题。由于 OPCD 是基于模型自身的输出进行训练，理论上可能会导致模型陷入某种特定的模式。为了防止性能下降（即通用能力的退化），研究者通常会在 OPCD 的目标函数中加入正则化项，或者在混合数据集（包含原始预训练数据和蒸馏数据）上进行训练。这确保了模型在特定生成质量提升的同时，不会丢失其在通用任务上的知识。

---



### 5: OPCD 与 RLHF（基于人类反馈的强化学习）有什么区别和联系？

5: OPCD 与 RLHF（基于人类反馈的强化学习）有什么区别和联系？

**A**: OPCD 和 RLHF 都是为了让模型的输出更符合人类偏好或更高质量，但路径不同。RLHF 需要训练一个奖励模型来模拟人类偏好，然后使用强化学习算法（如 PPO）来优化主模型，过程复杂且计算量大。OPCD 则更像是一种特殊的微调方法，它不需要显式的奖励模型，而是通过对比或匹配模型自身生成的优质样本来进行优化。OPCD 的计算成本通常低于 RLHF，且更容易实施，但在控制模型对齐的精细度上，RLHF 可能更具优势。两者也可以结合使用，先用 OPCD 提升基础生成质量，再用 RLHF 进行对齐。

---



### 6: OPCD 技术在实际应用中有哪些限制？

6: OPCD 技术在实际应用中有哪些限制？

**A**: OPCD 的主要限制在于其对计算资源的需求和训练稳定性。由于需要在训练过程中不断生成新的上下文，这比传统的静态数据训练更加耗时。此外，如果初始生成的上下文质量较差，可能会在训练过程中引入噪声，导致模型性能波动。因此，OPCD 通常需要一个相对较好的基础模型作为起点，才能有效地通过蒸馏获得收益。
