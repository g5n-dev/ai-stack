# 示例1：批量处理文本数据
def process_text_data(text_list):
    """
    批量处理文本数据：去除空白、统一小写、过滤空字符串
    :param text_list: 原始文本列表
    :return: 处理后的文本列表
    """
    processed = []
    for text in text_list:
        # 去除首尾空白字符并转为小写
        clean_text = text.strip().lower()
        # 过滤空字符串
        if clean_text:
            processed.append(clean_text)
    return processed

# 测试数据
raw_texts = ["  Hello World  ", "Python", "", "  Data Science  "]
print(process_text_data(raw_texts))  # 输出: ['hello world', 'python', 'data science']

def generate_log_file(log_messages, filename="app.log"):
    """
    将日志消息写入文件，每条记录带时间戳
    :param log_messages: 日志消息列表

# 示例3：计算文件哈希值（用于校验文件完整性）
def calculate_file_hash(filepath, algorithm="md5"):
    """
    计算文件的哈希值
    :param filepath: 文件路径
    :param algorithm: 哈希算法（支持md5/sha1/sha256）
    :return: 十六进制哈希字符串
    """
    import hashlib
    
    # 根据算法选择哈希对象
    hash_obj = hashlib.new(algorithm)
    
    try:
        with open(filepath, "rb") as f:
            # 分块读取文件（适合大文件）
            for chunk in iter(lambda: f.read(4096), b""):
                hash_obj.update(chunk)
        return hash_obj.hexdigest()
    except FileNotFoundError:
        return "文件不存在"

## 最佳实践指南

### 实践 1：构建高上下文感知的开发环境

**说明**: Qwen3-Coder-Next 模型通常拥有较大的上下文窗口，能够处理长文件和跨文件的依赖关系。最佳实践是充分利用这一特性，将整个项目结构或相关的多个文件一次性输入，而不是仅仅截取代码片段。这有助于模型理解全局变量、类继承关系以及模块间的交互，从而生成更连贯、无冲突的代码。

**实施步骤**:
1. 在构建 Prompt 时，首先提供项目的目录结构树。
2. 将被修改文件及其直接依赖（如导入的库、基类、配置文件）的内容填充到上下文中。
3. 明确指示模型在特定的文件和行号处进行修改，以保持上下文关联。

**注意事项**: 注意 Token 消耗速度，确保上下文长度未超过模型的最大处理限制，必要时可压缩非关键代码的注释或空白行。

---

### 实践 2：采用结构化的提示词工程

**说明**: 随意提问往往只能得到通用甚至错误的代码。为了获得高质量的输出，必须使用结构化的提示词。这包括定义角色、明确任务、指定技术栈、约束条件以及输出格式。结构化的指令能显著减少模型产生幻觉或不遵循语法规范的概率。

**实施步骤**:
1. **角色定义**: 以 "你是一位资深的高级软件工程师" 或 "你是一位专注于 {语言} 的专家" 开头。
2. **任务描述**: 使用祈使句清晰描述需求，例如 "请重构以下函数以提高其可读性和性能"。
3. **约束条件**: 明确限制，例如 "不要使用任何外部库" 或 "必须符合 PEP8 规范"。
4. **输出格式**: 要求特定格式，如 "请仅返回修改后的代码块，不要包含解释文字"。

**注意事项**: 避免在提示词中包含矛盾或模糊的指令，这会降低模型推理的准确性。

---

### 实践 3：实施迭代式优化与自我修正

**说明**: 第一次生成的代码往往不是完美的。最佳实践包括利用模型的对话能力进行迭代。让模型检查其生成的代码是否存在逻辑漏洞、安全漏洞（如 SQL 注入）或性能瓶颈，并要求其进行自我修正。这种 "反思-修正" 的循环能显著提升代码质量。

**实施步骤**:
1. 生成初版代码后，追加提示词："请检查上述代码中是否存在潜在的错误或安全风险"。
2. 要求模型进行单元测试编写："请为上述代码编写详细的单元测试用例，覆盖边界条件"。
3. 根据测试反馈或人工审查意见，要求模型："请根据第 X 行报错信息修复代码"。

**注意事项**: 在要求模型自我修正时，最好提供具体的报错日志或不符合预期的行为描述，而非笼统地说"代码不对"。

---

### 实践 4：利用思维链 进行复杂逻辑推理

**说明**: 对于复杂的算法实现或系统架构设计，直接生成代码可能会跳过关键步骤。利用思维链技术，要求模型在编写代码之前先进行逻辑分析或编写伪代码。这能帮助模型理清思路，减少逻辑错误，特别是在处理复杂数据结构转换时。

**实施步骤**:
1. 在提问中加入 "Let's think step by step" 或 "请先分析解题思路，再编写代码"。
2. 要求模型先列出实现步骤的编号列表。
3. 确认步骤无误后，再要求模型 "基于上述步骤，生成具体的实现代码"。

**注意事项**: 思维链会增加 Token 消耗，仅在处理高复杂度任务时使用，简单任务可直接生成代码以提高效率。

---

### 实践 5：建立严格的安全与隐私审查机制

**说明**: AI 模型可能会生成包含安全漏洞的代码，或在无意中泄露敏感数据。最佳实践要求将 AI 生成的代码视为 "未经审查的代码"，必须经过静态分析和人工审查才能合并到主分支。

**实施步骤**:
1. 配置本地或云端的安全扫描工具（如 Snyk, SonarQube），对 AI 生成的代码进行自动扫描。
2. 绝对不要将包含 API 密钥、密码或个人身份信息（PII）的敏感数据发送给模型。
3. 建立代码审查流程，确保由资深工程师验证 AI 生成逻辑的正确性。

**注意事项**: 警惕 "幻觉" 导致的引用不存在的库或方法，务必在隔离环境中运行并测试生成的代码。
