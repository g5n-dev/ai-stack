# 示例1：自动化批量重命名文件
import os
import re

def batch_rename_files(directory, prefix):
    """
    批量重命名指定目录下的文件，添加统一前缀并按序号编号
    :param directory: 目标文件夹路径
    :param prefix: 文件名前缀
    """
    # 获取目录下所有文件并按名称排序
    files = sorted([f for f in os.listdir(directory) if os.path.isfile(os.path.join(directory, f))])
    
    for index, filename in enumerate(files, start=1):
        # 获取文件扩展名
        ext = os.path.splitext(filename)[1]
        # 构造新文件名
        new_name = f"{prefix}_{index:03d}{ext}"
        # 重命名操作
        os.rename(
            os.path.join(directory, filename),
            os.path.join(directory, new_name)
        )
        print(f"已重命名: {filename} -> {new_name}")

# 使用示例

import requests
import time
from datetime import datetime

def monitor_stock_price(symbol, interval=60):
    """
    实时监控指定股票的价格变化
    :param symbol: 股票代码 (如: AAPL)
    :param interval: 检查间隔(秒)
    """
    print(f"开始监控 {symbol} 股票价格...")
    while True:
        try:
            # 使用免费的Yahoo Finance API
            url = f"https://query1.finance.yahoo.com/v8/finance/chart/{symbol}"
            response = requests.get(url, headers={'User-Agent': 'Mozilla/5.0'})
            data = response.json()
            
            # 解析价格数据
            price = data['chart']['result'][0]['meta']['regularMarketPrice']
            timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
            
            print(f"[{timestamp}] {symbol} 当前价格: ${price:.2f}")
            time.sleep(interval)
            
        except Exception as e:
            print(f"获取数据失败: {e}")
            time.sleep(interval)

## 最佳实践指南

### 实践 1：构建高精度的上下文环境

**说明**: Qwen3-Coder-Next 在处理代码任务时，对上下文信息的依赖度极高。仅仅提供简单的代码片段往往导致模型理解偏差。高精度的上下文意味着不仅要包含出错的代码，还应包含相关的依赖库版本、具体的报错信息、预期的输入输出示例以及项目目录结构。这有助于模型建立完整的“心智模型”，从而生成更准确的解决方案。

**实施步骤**:
1. 收集报错日志或复现步骤，将其粘贴在提示词中。
2. 使用 `tree` 命令或手动列出关键文件的目录结构，帮助模型理解文件间的依赖关系。
3. 在提问中明确指出所使用的编程语言版本及关键框架版本（如 Python 3.9, PyTorch 2.0）。
4. 提供最小可复现代码，去除无关的业务逻辑，聚焦核心问题。

**注意事项**: 避免一次性粘贴数万行的超长日志，应先进行精简，保留关键堆栈信息。

---

### 实践 2：采用结构化的提示词工程

**说明**: 结构化的提示词能显著降低模型的认知负荷。通过明确的角色定义、任务拆解和输出格式要求，可以引导模型按照特定的逻辑路径进行推理。对于 Qwen3-Coder-Next，使用 Markdown 或 XML 标签来分隔不同的指令部分，能有效提升代码生成的准确率和可读性。

**实施步骤**:
1. 定义角色：例如“你是一位拥有 10 年经验的资深后端工程师”。
2. 明确任务：使用“# 任务”或“### Objective”标签清晰描述需求。
3. 约束条件：明确指出“不要使用任何已废弃的 API”或“代码必须符合 PEP8 规范”。
4. 指定输出格式：要求“请以 JSON 格式返回结果”或“请输出完整的可直接运行的 Python 脚本”。

**注意事项**: 保持指令的简洁性，避免在结构化标签中填充过多的废话，以免干扰模型对核心指令的关注。

---

### 实践 3：利用思维链技术处理复杂逻辑

**说明**: 对于算法设计、架构重构或复杂的 Bug 修复，直接要求模型生成代码可能会出现逻辑跳跃。利用思维链技术，强制模型先进行“思考”，逐步分析问题成因、评估不同方案的优劣，再编写代码。这能显著减少代码中的逻辑漏洞。

**实施步骤**:
1. 在提示词中添加指令：“请先逐步分析这个问题，不要直接写代码。”
2. 要求模型列出解题思路：“请在给出最终答案前，先列出 3 种可能的解决方案并对比其优缺点。”
3. 确认思路无误后，跟进指令：“基于上述第二种方案，请生成具体的实现代码。”

**注意事项**: 思维链会消耗更多的输出 Token，需根据任务的复杂程度灵活使用，简单的语法补全无需此步骤。

### 实践 4：实施迭代式代码审查与优化

**说明**: 模型生成的初版代码往往不是最优解，可能存在安全隐患、性能瓶颈或边界条件未处理的情况。将 Qwen3-Coder-Next 视为结对编程伙伴，通过多轮交互进行代码审查和重构，是获取高质量代码的关键。

**实施步骤**:
1. 获取初版代码后，不要直接复制使用，而是发起第二轮提问：“请检查上述代码是否存在 SQL 注入风险”或“请优化该段代码的时间复杂度”。
2. 要求代码解释：“请逐行解释这段代码的核心逻辑，并说明为什么选择这种数据结构。”
3. 请求单元测试：“请为这段代码生成包含边界条件的 Pytest 单元测试用例。”

**注意事项**: 在审查过程中，重点检查模型是否使用了不安全的函数（如 `eval`）或是否存在硬编码的敏感信息。
