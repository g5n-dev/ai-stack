## 导语

在大语言模型推理过程中，如何高效分配计算资源以平衡性能与成本，一直是测试时扩展领域的核心挑战。现有TTS策略多依赖手工设计，限制了推理模式的多样性探索。该研究提出AutoTTS框架，通过构建可控的发现环境并引入宽度-深度TTS形式化，实现TTS策略的自动优化。实验结果表明，该方法在数学推理任务上以更低计算成本取得与强基线相当或更优的准确率，且发现的策略具备跨基准迁移能力。该工作的自动化思路或许能为测试时计算分配的研究提供新的设计范式。

## 摘要

#### 背景
测试时扩展（TTS）通过在推理阶段分配额外计算提升大语言模型性能，但现有 TTS 策略多为手工设计，仅探索少量推理模式，导致计算资源分配空间未被充分挖掘。

#### 方法
我们提出 **AutoTTS**，将 TTS 策略的设计从手工调优转向环境驱动的自动发现。关键步骤包括：
1. **构建可控制的发现环境**：使控制空间可遍历，并提供廉价、频繁的反馈信号。
2. **宽度‑深度 TTS 形式化**：把 TTS 控制器视为对已有推理轨迹和探测信号的综合器，控制器可决定分支、继续、探测、剪枝或停止，且评估时不需再次调用 LLM。
3. **β 参数化**：通过参数化降低搜索维度，提升可操作性。
4. **细粒度执行追踪**：帮助 Agent 诊断失败原因，提高发现效率。

#### 实验结果
在数学推理基准上，AutoTTS 发现的策略在保持精度的同时显著降低计算成本，整体准确率‑成本权衡优于强手工基线。发现策略能够跨基准和模型规模迁移。

#### 成本与资源
整个发现过程仅花费 39.9 美元、约 160 分钟。代码与数据将在 GitHub 开源（https://github.com/zhengkid/AutoTTS）。

#### 核心方法
##### 可控制的发现环境
- **环境特征**（摘要）：构建可遍历的控制空间，并提供廉价、频繁的反馈信号，使 Agent 能够在少量试错中快速评估策略效果。

##### 宽度‑深度 TTS 形式化
- **控制器角色**（摘要）：将 TTS 控制器视为对已有推理轨迹和探测信号的综合器，控制器可决定分支、继续、探测、剪枝或停止。
- **评估方式**（摘要）：评估过程不需再次调用 LLM，直接基于已有的执行追踪计算收益。

##### β 参数化
- **目的**（摘要）：通过参数化降低搜索维度，使策略空间更易遍历，提升可操作性。

##### 细粒度执行追踪
- **功能**（摘要）：记录每一步的中间状态与成本，帮助 Agent 诊断失败原因，提升发现效率。

#### 理论基础
- **推断**：控制器本质上是基于强化学习的策略网络，输入为轨迹特征与探测信号，输出为动作分布；β 参数化将连续的动作空间映射为离散决策，降低策略梯度估计方差。
- **推断**：细粒度追踪相当于为每个分支提供“价值估算”，形成类似蒙特卡洛树搜索的价值回传机制，从而在无外部奖励的情况下实现自我改进。
