import requests

def transcribe_audio_file(audio_path, api_key):
    """
    将本地音频文件转录为文本
    :param audio_path: 音频文件路径
    :param api_key: Voxtral API密钥
    :return: 转录文本
    """
    url = "https://api.voxtral.com/v2/transcribe"
    headers = {"Authorization": f"Bearer {api_key}"}
    
    with open(audio_path, "rb") as audio_file:
        files = {"file": audio_file}
        response = requests.post(url, headers=headers, files=files)
    
    return response.json()["text"]

# 示例2：实时语音流转录
import pyaudio
import requests

def transcribe_stream(api_key, language="zh-CN"):
    """
    实时转录麦克风输入的语音流
    :param api_key: Voxtral API密钥
    :param language: 语言代码，默认中文
    """
    url = "https://api.voxtral.com/v2/transcribe/stream"
    headers = {"Authorization": f"Bearer {api_key}"}
    
    audio = pyaudio.PyAudio()
    stream = audio.open(format=pyaudio.paInt16,
                       channels=1,
                       rate=16000,
                       input=True,
                       frames_per_buffer=1024)
    
    print("开始录音... (按Ctrl+C停止)")
    try:
        while True:
            data = stream.read(1024)
            response = requests.post(url, headers=headers, data=data,
                                   params={"language": language})
            if response.json().get("text"):
                print(response.json()["text"])
    except KeyboardInterrupt:
        stream.stop_stream()
        stream.close()
        audio.terminate()

# 使用示例
# transcribe_stream("your_api_key")

# 示例3：带时间戳的转录结果处理
def process_transcript_with_timestamps(transcript_json):
    """
    处理带时间戳的转录结果
    :param transcript_json: API返回的完整JSON响应
    :return: 格式化后的文本段落
    """
    segments = transcript_json["segments"]
    formatted_text = []
    
    for seg in segments:
        start_time = seg["start"] / 1000  # 转换为秒
        end_time = seg["end"] / 1000
        text = seg["text"]
        
        formatted_text.append(
            f"[{start_time:.1f}s-{end_time:.1f}s] {text}"
        )
    
    return "\n".join(formatted_text)

## 最佳实践指南

### 实践 1：音频源质量优化

**说明**: 音频输入的质量直接决定了转录的准确率。高质量的音频源可以显著减少错误识别和遗漏。Voxtral Transcribe 2 对背景噪音和重叠说话较为敏感，因此优化输入信号至关重要。

**实施步骤**:
1. 使用高信噪比（SNR）的录音设备，尽量避免环境噪音。
2. 在录音软件中启用降噪功能或后期进行音频预处理（如去除静音段）。
3. 确保采样率设置合理（建议 44.1kHz 或 48kHz），并使用单声道（Mono）以减少文件体积和处理时间。

**注意事项**: 避免使用过度压缩的低码率音频格式（如低于 64kbps 的 MP3），推荐使用 WAV 或 FLAC 格式以保留更多细节。

---

### 实践 2：精准的领域模型选择

**说明**: Voxtral Transcribe 2 可能针对不同场景（如通用会议、医疗、法律、技术）提供了不同的模型权重或词汇库。选择与内容匹配的模型能大幅提升专业术语的识别率。

**实施步骤**:
1. 在处理任务前，分析音频内容的所属领域。
2. 在 API 请求或界面设置中，指定对应的 `model_type` 或 `domain` 参数。
3. 如果是混合场景，尝试使用“通用”模型，或分段处理不同领域的内容。

**注意事项**: 切勿为了追求速度而始终使用默认的轻量级模型，对于关键业务文档，应优先使用高精度模型。

---

### 实践 3：自定义词汇与热词注入

**说明**: 即使是最好的通用模型也无法覆盖所有专有名词、产品名称或特定行话。通过提供自定义词汇表，可以强制引擎优先匹配特定词汇。

**实施步骤**:
1. 整理一份包含关键术语的清单，包括正确的拼写和常见的同音字变体。
2. 利用 API 的 `custom_vocabulary` 或 `boosting_words` 功能上传该清单。
3. 为特定词汇设置权重值，确保在发音模糊时优先选择该词汇。

**注意事项**: 词汇表不宜过长，建议控制在 500-1000 个高频核心词汇以内，以免影响整体识别速度。

---

### 实践 4：说话人分离与标点策略

**说明**: 对于会议记录或访谈记录，区分不同的说话人（Diarization）和正确的标点符号是提升可读性的关键。

**实施步骤**:
1. 在配置中启用 `speaker_diarization` 选项。
2. 设置预期的说话人数量上限，以帮助算法更快收敛。
3. 确保开启自动标点功能，并检查是否支持根据语境调整标点风格（如列表式 vs 叙述式）。

**注意事项**: 说话人分离在音频质量较差或说话人声音相似时准确率会下降，后期需进行人工校对。

---

### 实践 5：利用时间戳进行后期校对

**说明**: 转录文本不可避免地会存在错误。利用精确到词或句级别的时间戳，可以极大地加速人工审核和修正的过程。

**实施步骤**:
1. 请求 API 返回带时间戳的 JSON 或 TTML 格式结果。
2. 使用支持音频波形同步显示的文本编辑器打开结果。
3. 点击错误文本即可跳转至对应音频位置进行快速修正。

**注意事项**: 存储包含时间戳的数据会占用更多数据库空间，建议仅在审核阶段保留，归档时视情况决定是否精简。

---

### 实践 6：异步处理与长音频分段

**说明**: 直接上传长音频文件可能导致请求超时或处理阻塞。采用异步任务队列和合理的分段策略能提高系统的健壮性和吞吐量。

**实施步骤**:
1. 将超过 1 小时的音频文件按逻辑（如章节或静音段）切割成 10-30 分钟的片段。
2. 使用 Voxtral 的异步 API 提交任务，并注册回调 URL 以接收完成通知。
3. 在所有片段处理完成后，通过时间戳顺序将文本合并。

**注意事项**: 切割点应尽量选择在静音处，以免切断单词导致拼接处语义不完整。

---

### 实践 7：隐私保护与数据合规

**说明**: 音频数据往往包含敏感信息。在数据传输和处理过程中，必须确保符合 GDPR 或其他数据保护法规。

**实施步骤**:
1. 确认 Voxtral Transcribe 2 的数据处理协议，明确音频是否会被用于模型训练。
2. 在传输过程中使用 TLS/SSL 加密。
3. 对于高度敏感数据，考虑在本地部署或使用支持即时删除数据的云端配置（设置 `delete_after_processing` 标志）。

**注意事项**: 始终在客户端对敏感个人信息（如身份证号、电话号码）进行脱敏处理后再发送给转录服务。
