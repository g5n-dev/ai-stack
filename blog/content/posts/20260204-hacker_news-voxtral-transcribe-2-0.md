# 示例1：音频文件转写
import requests

def transcribe_audio_file(audio_path, api_key):
    """
    将本地音频文件发送给Voxtral Transcribe 2进行转写
    :param audio_path: 音频文件路径
    :param api_key: Voxtral API密钥
    :return: 转写结果JSON
    """
    # API端点
    url = "https://api.voxtral.com/v2/transcribe"
    
    # 准备请求头和文件
    headers = {"Authorization": f"Bearer {api_key}"}
    files = {"audio": open(audio_path, "rb")}
    
    # 发送POST请求
    response = requests.post(url, headers=headers, files=files)
    
    # 检查响应状态
    if response.status_code == 200:
        return response.json()
    else:
        raise Exception(f"转写失败: {response.text}")

import asyncio
import websockets

async def transcribe_stream(audio_stream, api_key):
    """
    实时转写音频流数据
    :param audio_stream: 音频流数据生成器
    :param api_key: Voxtral API密钥
    """
    uri = "wss://api.voxtral.com/v2/transcribe/stream"
    
    async with websockets.connect(uri) as websocket:
        # 发送认证信息
        await websocket.send(f"Bearer {api_key}")
        
        # 持续发送音频数据
        async for chunk in audio_stream:
            await websocket.send(chunk)
            
            # 接收并处理转写结果
            result = await websocket.recv()
            print("实时转写:", result)

# 示例3：带语言检测的转写
def transcribe_with_detection(audio_path, api_key):
    """
    自动检测音频语言并进行转写
    :param audio_path: 音频文件路径
    :param api_key: Voxtral API密钥
    :return: 包含语言检测结果的转写数据
    """
    url = "https://api.voxtral.com/v2/transcribe"
    headers = {
        "Authorization": f"Bearer {api_key}",
        "X-Detect-Language": "true"  # 启用语言检测
    }
    
    with open(audio_path, "rb") as audio:
        response = requests.post(
            url,
            headers=headers,
            files={"audio": audio},
            params={"detect_language": True}
        )
    
    data = response.json()
    return {
        "text": data["text"],
        "detected_language": data["language"],
        "confidence": data["confidence"]
    }

## 最佳实践指南

### 实践 1：优化音频输入质量

**说明**: 音频质量是决定转录准确率的最关键因素。Voxtral Transcribe 2 虽然具备降噪能力，但清晰的原始音频能显著降低错误率，尤其是在处理专业术语或多人对话时。

**实施步骤**:
1. 使用采样率至少为 16kHz 的音频文件（推荐 44.1kHz 或 48kHz）。
2. 在录音阶段尽量减少背景噪音和回声。
3. 如果是实时麦克风输入，请使用高质量的定向麦克风。

**注意事项**: 避免使用过度压缩的低码率音频格式（如低于 32kbps 的 MP3），推荐使用 WAV 或 FLAC 等无损格式作为输入源。

---

### 实践 2：合理利用领域模型选择

**说明**: Voxtral Transcribe 2 可能包含针对不同场景（如通用会议、医疗、法律、技术）优化的模型。选择与内容匹配的特定领域模型，可以大幅提高专业词汇的识别精度。

**实施步骤**:
1. 在配置 API 或界面设置时，检查可用的模型列表。
2. 根据音频内容类型（例如：技术访谈 vs 日常闲聊）选择对应的领域模型。
3. 如果内容混合了多个领域，选择通用模型作为基准。

**注意事项**: 特定领域模型对非该领域的词汇识别率可能会下降，请确保内容与模型匹配。

---

### 实践 3：正确配置说话人分离

**说明**: 对于包含两名或以上说话者的会议记录，启用说话人分离功能至关重要。这有助于后续区分发言人并整理对话结构。

**实施步骤**:
1. 在请求参数中启用 `diarization` 或类似功能开关。
2. 如果可能，预先提供说话人数量的大致范围，以辅助算法分组。
3. 利用 API 返回的时间戳信息来校验说话人切换的准确性。

**注意事项**: 说话人分离会增加处理延迟和计算资源消耗。如果是单人演讲，请务必关闭此功能以提高处理速度。

---

### 实践 4：利用自定义词汇表

**说明**: 即使是最先进的模型也难以识别特定组织名称、新造词或缩写。通过上传自定义词汇表或热词，可以强制修正这些专有名词的拼写。

**实施步骤**:
1. 整理一份文档中常见的专有名词列表。
2. 按照平台要求的格式（如 JSON 或 CSV）准备词汇表及其可能的发音提示。
3. 在发起转录请求时附加上下词汇表参数。

**注意事项**: 词汇表不宜过大，通常限制在几百个词以内，且应避免包含常见拼写错误的词汇，以免干扰正常识别逻辑。

---

### 实践 5：处理流式与非流式转录的权衡

**说明**: 根据应用场景选择合适的转录模式。实时字幕需要流式传输，而离线文档归档则适合批量处理。

**实施步骤**:
1. 对于实时场景，使用 WebSocket 或流式 API，并设置适当的延迟缓冲区。
2. 对于离线文件，使用完整的异步 API 以获得最高的准确率。
3. 在流式模式下，实现最终的文本修正逻辑，因为流式结果的中间词可能会随着后续上下文的出现而改变。

**注意事项**: 流式转录通常比非流式转录消耗更多的网络带宽，且最终结果需要等待音频流结束后才能完全确定。

---

### 实践 6：建立置信度评分过滤机制
