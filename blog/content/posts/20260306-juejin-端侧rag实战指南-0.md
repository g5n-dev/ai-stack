- 为解决端侧上下文窗口限制，应优先选用支持长文本的轻量级模型（如 Gemma、Phi-3 或 Qwen-1.8B），并实施严格的上下文长度截断策略。

### 1: 什么是端侧 RAG，它与云端 RAG 有什么本质区别？

1: 什么是端侧 RAG，它与云端 RAG 有什么本质区别？

**A**: 端侧 RAG（Retrieval-Augmented Generation）是指将检索增强生成的整个流程或核心流程运行在用户本地设备（如手机、PC、边缘计算盒子）上，而不是依赖远程服务器。其本质区别主要在于**数据隐私、网络依赖和成本结构**。

1.  **数据隐私与安全**：端侧 RAG 的所有数据（用户查询、知识库内容、生成的回答）均不出设备，彻底消除了数据上传云端带来的泄露风险，非常适合金融、医疗或个人隐私敏感场景。
2.  **网络依赖**：端侧方案完全离线运行，不依赖网络环境，响应速度无网络延迟，且在弱网或飞行模式下依然可用。
3.  **运行成本**：云端 RAG 需要持续支付 API 调用费用或 GPU 服务器租赁费用；端侧 RAG 主要利用用户设备的闲置算力（NPU/CPU），虽然初期模型适配有成本，但大规模部署后的边际成本几乎为零。
4.  **性能限制**：端侧受限于设备的内存和算力，通常需要使用经过量化的小型模型（如 1B-7B 参数量）和轻量级向量数据库。

### 2: 在端侧设备上部署 RAG 流程，主要的硬件瓶颈是什么？如何解决？

2: 在端侧设备上部署 RAG 流程，主要的硬件瓶颈是什么？如何解决？

**A**: 端侧 RAG 的主要硬件瓶颈是 **内存（RAM）大小** 和 **推理算力**。

1.  **内存瓶颈**：大语言模型（LLM）加载到内存中需要占用大量空间。例如，一个 4-bit 量化的 7B 模型大约需要 4-5GB 内存。如果设备内存只有 8GB，除去系统和应用占用，留给模型和向量库的空间非常紧张。
    *   *解决方案*：使用更小的模型（如 Gemma 2B, Qwen 1.5B 或 Phi-3 Mini），或采用更高的量化等级（如 4-bit 或甚至 2-bit 量化）。同时，向量数据库也需控制索引大小，及时清理未使用的缓存。
2.  **算力瓶颈**：嵌入模型和 LLM 的推理速度直接影响响应延迟。如果仅依赖 CPU 推理，速度可能较慢。
    *   *解决方案*：利用端侧 NPU（神经网络处理单元）或 GPU 加速推理（如通过 Metal 在苹果芯片上，或通过 OpenVINO、MNN 等推理框架）。选择对端侧推理友好的模型架构（如 Flat 架构而非 MoE）。
