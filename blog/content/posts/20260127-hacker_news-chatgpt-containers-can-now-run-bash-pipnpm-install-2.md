## 最佳实践指南

### ✅ 实践 1：严格的依赖管理与版本锁定

**说明**:
由于容器环境具有临时性，每次会话结束后环境会被重置。为了确保代码的可复现性和避免版本冲突，必须精确管理 `pip` 或 `npm` 的依赖版本。

**实施步骤**:
1. 在安装包时，明确指定版本号，例如 `pip install pandas==2.0.3`。
2. 如果使用 `requirements.txt` 或 `package.json`，确保文件内容经过审查。
3. 安装完成后，使用 `pip list` 或 `npm list` 验证已安装的版本是否符合预期。

**注意事项**: 
避免使用 `pip install package_name --upgrade`，这可能导致不可预测的破坏性更新。

---

### ✅ 实践 2：安全地处理敏感信息

**说明**:
切勿在 Bash 命令或下载脚本中硬编码 API 密钥、密码或私钥。虽然是在容器中运行，但为了培养安全意识并防止信息泄露，应始终使用环境变量。

**实施步骤**:
1. 使用 `export` 命令设置临时环境变量，例如 `export API_KEY="your_key"`。
2. 在 Python 或 Node.js 代码中通过 `os.getenv` 或 `process.env` 读取变量。
3. 如果使用 `curl` 或 `wget` 下载受保护文件，利用 `-H` 参数传递 Header 而非在 URL 中拼接凭证。

**注意事项**: 
即使在测试环境中，也不要将包含凭证的命令输出到日志中。

---

### ✅ 实践 3：验证下载文件的完整性与安全性

**说明**:
使用 `wget` 或 `curl` 下载文件时，必须验证来源的可信度，并尽可能检查文件的校验和，以防止恶意软件注入或下载损坏的数据。

**实施步骤**:
1. 仅从官方源或可信的 CDN 下载文件。
2. 如果提供方提供了 SHA256 或 MD5 校验和，下载后运行 `sha256sum filename` 进行比对。
3. 下载后，使用 `file filename` 或 `head filename` 快速检查文件类型和内容是否符合预期。

**注意事项**: 
绝对不要运行来源不明的 `.sh` 或 `.exe` 脚本。

---

### ✅ 实践 4：控制包安装的体积与层级

**说明**:
容器可能有存储空间限制。安装过多的包或下载不必要的大文件会导致环境臃肿，甚至触发存储限制导致会话中断。

**实施步骤**:
1. 仅安装当前任务所需的最小依赖集，避免全家桶式安装（如 `apt-get install xxx` 而非 `apt-get install xxx*`）。
2. 下载大文件前，先使用 `curl -I` 检查文件大小 (`Content-Length`)，确认空间足够。
3. 如果下载了压缩包，使用完毕后使用 `rm` 命令清理原始压缩文件以释放空间。

**注意事项**: 
定期使用 `df -h` 检查磁盘使用情况，保持环境轻量化。

---

### ✅ 实践 5：实施有效的错误捕获与日志记录

**说明**:
在 Bash 或代码执行过程中，如果静默失败，调试将变得非常困难。必须显式地处理错误输出。

**实施步骤**:
1. 在 Bash 脚本开头添加 `set -e`，确保任何命令失败时脚本立即停止。
2. 在 Python 代码中使用 `try...except` 块包裹网络请求和文件操作，并打印具体的 Traceback。
3. 将复杂的 Bash 命令输出重定向到日志文件，例如 `python script.py > output.log 2>&1`。

**注意事项**: 
不要忽略“非致命”错误，累积的小错误可能导致最终结果不可用。

---

### ✅ 实践 6：构建幂等的执行脚本

**说明**:
由于 ChatGPT 可能会被要求重复执行相似任务，脚本应当设计为可重复运行（幂等性），即多次运行结果一致，不会因为文件已存在或环境已配置而报错。

**实施步骤**:
1. 在创建文件或目录前检查是否存在，例如 Bash 中的 `mkdir -p folder`。
2. 在 `pip install` 时使用 `--no-deps` 或忽略已存在包的选项，或者在代码逻辑中捕获“已存在”的异常。
3. 设计工作流时，清理步骤应在开始之前进行，确保处于干净状态。

**注意事项**: 
避免假设环境总是处于初始状态。
