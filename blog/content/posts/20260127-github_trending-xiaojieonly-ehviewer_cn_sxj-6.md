## Key Features

### Content Browsing

  * Multi-mode gallery browsing (normal, favorites, subscriptions, watched, popular)
  * Advanced search with filters (category, rating, uploader, tags)

  * Tag system with translation support (10+ languages)

  * Cloud-synced favorites (10 categories)
  * Local favorites for offline access
  * Reading history with timestamps
  * Quick search templates for frequent queries

  * Multi-threaded parallel downloads with configurable worker count
  * Two-tier storage: temporary cache (40-640MB) and persistent storage

  * Domain fronting capability

## High-Level Architecture


**Architecture Description:**

EhViewer CN SXJ follows a layered architecture with clear separation of concerns:

  1. **Application Entry:** `SplashActivity` performs initialization, then launches `MainActivity` which hosts the scene-based navigation system.

  2. **Presentation Layer:** Uses a scene-fragment pattern where `MainActivity` extends `StageActivity` to manage a stack of `SceneFragment` instances. Each scene represents a distinct UI state (browsing, viewing, downloading).

  3. **Business Logic Layer:** Core operations are centralized in manager classes:

## 1. 技术架构深度剖析 🏗️

### 技术栈与架构模式
*   **混合语言栈**：该项目展示了 Android 开发的高级演进形态。
    *   **UI 层**：主要采用 **Java**，部分新模块迁移至 **Kotlin**（如 `UpdateDialog.kt`）。这表明项目正处于从 Java 向 Kotlin 现代化转型的阶段。
    *   **架构模式**：采用典型的 **MVVM (Model-View-ViewModel)** 或 **MVP** 变体。代码中包含 `EhApplication`（全局控制），以及大量的 UI 组件（`drawable`, `ui`），配合依赖注入或单例模式管理全局状态。
*   **底层核心技术**：
    *   **JNI / NDK**：`app/src/main/cpp` 目录揭示了其核心竞争力。通过 CMake 编译 C/C++ 代码，用于处理高性能的图像解码、缩放和色彩空间转换。
    *   **自定义图片加载引擎**：`UnikeryDrawable.java` 和 `ImageBitmapHelper.java` 表明它没有直接使用 Glide 或 Picasso 的默认实现，而是构建了一套**自定义的图片加载与渲染管线**，以满足对大图、长图的极速加载需求。

### 核心模块与设计
*   **图片管线**：这是项目的灵魂。它处理从网络流获取数据（可能涉及复杂的 EhViewer 网站协议解析），到内存缓存、磁盘缓存，最终通过 JNI 渲染到 Canvas 的全过程。
*   **Unikery 接口**：`UnikeryDrawable` 实现了一种“唯一性”接口。这是一种**资源管理锁**的设计，确保在 ListView 或 RecyclerView 快速滑动时，只有当前可见的 Item 占用图片解码资源，防止图片错位和内存溢出（OOM）。

### 架构优势
*   **极致的性能**：通过 JNI 将高频、高耗时的图像操作（如 JPEG/WebP 解码、缩放算法）下放至 C 层，绕过了 Java 层的 GC（垃圾回收）停顿和 Bitmap 分配限制（特别是在 Android 8.0 之前 Native Allocation 的限制）。
*   **内存控制**：针对“漫画”这一特殊场景（单页图片可能非常长或非常大），架构设计上极其重视内存复用和采样率计算。

## 2. 核心功能详细解读 🛠️

### 主要功能与场景
*   **高性能阅读器**：支持在线及本地压缩包（Zip/Rar）的直读，这是动漫图站应用的核心痛点。
*   **复杂的网络协议处理**：EhViewer 网站具有极其复杂的反爬虫机制、Cookie 管理和 HTTPS 混淆。该应用内置了高度定制化的 HTTP 客户端逻辑（可能基于 OkHttp 的深度魔改）。
*   **标签与元数据管理**：处理复杂的 Tag 系统和评分系统。

### 解决的关键问题
*   **OOM（内存溢出）崩溃**：这是 Android 图片应用的头号杀手。该项目通过 JNI 在 Native Heap 分配 Bitmap 内存（在部分 Android 版本上不计入 App 限定的内存峰值），极大地提高了加载超大图片的稳定性。
*   **滑动卡顿**：通过异步解码和视图复用优化，即使在大量图片流中也能保持 60fps。

### 与同类工具对比
*   **对比通用阅读器**：通用阅读器（如 Perfect Viewer）虽然格式支持广，但对特定网站（E-hentai 相关）的搜索、标签过滤、API 交互支持不佳。
*   **对比原版 EhViewer**：这个 Fork 版本（CN_SXJ）主要解决了**国内网络环境适配**、**Material Design 3 界面现代化**以及**长期维护更新**的问题。
