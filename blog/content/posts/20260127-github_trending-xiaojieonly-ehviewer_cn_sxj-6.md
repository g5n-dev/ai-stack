## Key Features

EhViewer CN SXJ provides comprehensive functionality for E-Hentai content consumption:

### Content Browsing

  * Multi-mode gallery browsing (normal, favorites, subscriptions, watched, popular)
  * Advanced search with filters (category, rating, uploader, tags)
  * Image search using uploaded photos
  * Tag system with translation support (10+ languages)
  * Content filtering and blacklist management



### Gallery Management

  * Cloud-synced favorites (10 categories)
  * Local favorites for offline access
  * Reading history with timestamps
  * Quick search templates for frequent queries



### Download System

  * Multi-threaded parallel downloads with configurable worker count
  * Two-tier storage: temporary cache (40-640MB) and persistent storage
  * Download queue with pause/resume/retry support
  * Archive download from H@H (Hentai@Home) servers
  * Label-based organization and filtering



### Reader Features

  * Multiple reading modes (left-to-right, right-to-left, vertical)
  * Zoom and pan controls
  * Page preloading for smooth reading
  * Reading progress tracking
  * Archive file support (.zip, .rar, .7z)



### Network Resilience

  * Four-tier DNS resolution strategy for censorship circumvention
  * Built-in IP addresses for E-Hentai domains
  * DNS-over-HTTPS support via Yandex DNS
  * Custom hosts database
  * Domain fronting capability
  * Proxy configuration support



### Localization

  * 10 supported languages: Chinese (Simplified/Traditional/Hong Kong), Japanese, Korean, English, German, Thai, French, Spanish
  * Tag translation database with community contributions

  1. **Application Entry:** `SplashActivity` performs initialization, then launches `MainActivity` which hosts the scene-based navigation system.

## 🚀 性能优化建议

## 性能优化建议

### 🚀 优化 1：图片加载与缓存机制优化

**说明**: Ehviewer 作为图片浏览应用，图片加载性能直接影响用户体验。当前可能存在图片解码效率低、缓存策略不完善或大图OOM（内存溢出）风险。

**实施方法**:
1. 使用 **Coil** 或 **Glide** 的高性能版本，并配置自定义的 `ImageDecoder` 以支持 WebP 等高压缩比格式。
2. 优化内存缓存策略，根据设备可用内存动态调整缓存大小（例如：使用 `LruCache`）。
3. 对超大分辨率图片进行**子采样**加载，避免全图加载导致内存飙升。
4. 实现更激进的磁盘缓存预加载机制，利用线程池提前预取下一页图片。

**预期效果**: 图片滑动流畅度提升 20%-30%，内存占用峰值降低 15%，大幅减少因内存不足导致的崩溃（OOM）。

---

### 🔄 优化 2：列表渲染性能提升

**说明**: 阅读列表和搜索结果页通常包含大量数据，若 RecyclerView 的布局层级过深或未开启相关优化，会导致滑动掉帧。

**实施方法**:
1. **减少布局层级**：将复杂的 XML 布局转换为 `<merge>` 标签或使用 **ConstraintLayout** 扁平化视图结构。
2. **增加 RecyclerView 缓存**：通过 `setItemViewCacheSize` 和 `setRecycledViewPool` 增加缓存池大小，复用 ViewHolder。
3. 使用 **DiffUtil** 代替 `notifyDataSetChanged()`，仅刷新发生变化的数据项。
4. 为列表项添加固定的高度（如果可能），避免昂贵的 `measure` 过程。

**预期效果**: 列表滑动帧率稳定在 60fps，数据处理时间减少 40%，UI 渲染更加丝滑。

---

### 🗄️ 优化 3：数据库查询与索引优化

**说明**: 应用内大量使用本地数据库存储元数据（标签、历史记录、收藏）。如果缺少索引或查询语句低效（如 N+1 查询问题），会导致页面加载卡顿。

**实施方法**:
1. 使用 Room 或 SQLCipher 的 **索引** 功能，为高频查询字段（如 `gid`, `tags`, `title`）建立索引。
2. 重构复杂查询语句，使用 `JOIN` 替代多次单独查询。
3. 对不需要实时同步的数据（如图片统计信息）采用 **异步加载** 或 **懒加载** 策略。
4. 定期在应用后台空闲时执行 `VACUUM` 操作，优化数据库文件大小。

**预期效果**: 本地搜索和详情页加载速度提升 50%+，数据库 I/O 阻塞主线程的风险降至最低。

---

### 🌐 优化 4：网络请求并发与连接池复用

**说明**: 获取画廊信息和图片元数据涉及大量网络请求。串行请求或未复用连接会显著增加加载延迟。

**实施方法**:
1. 配置 OkHttp 的 **连接池**，增加 `maxIdleConnections` 和 `keepAliveDuration`，减少握手开销。
2. 使用 **协程** 或 **RxJava** 实现并发请求控制，对 API 请求进行并行分发（例如同时获取详情和评论）。
3. 启用 HTTP/2 或 HTTP/3（QUIC）协议支持，利用多路复用减少队头阻塞。
4. 实现更智能的请求重试与回退机制（如重试时切换 DNS）。

**预期效果**: 网络请求总耗时减少 30%-40%，在弱网环境下的响应速度显著提升。
