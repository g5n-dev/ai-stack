## 导语

现有 Prompt Agent 方法通常将提示词优化视为序列决策问题，但严重依赖高质量的有监督奖励信号，而这在实际场景中往往难以获取。为此，论文提出了 UPA（Unsupervised Prompt Agent），利用基于树的搜索与选择机制，在无监督环境下自动优化提示词。该方法有望降低大模型应用对人工标注数据的依赖，不过其具体的泛化性能及计算开销，无法从摘要确认。

## 摘要

以下是关于 **UPA (Unsupervised Prompt Agent)** 的内容总结：

**核心问题**
现有的 Prompt Agent（提示词智能体）方法虽然通过将提示词优化视为序列决策问题取得了进展，但它们通常严重依赖**有监督的奖励信号**。然而，在实际应用场景中，这种高质量的监督信号往往难以获取。

**提出方案：UPA**
UPA 是一个**无监督的提示词智能体**，旨在不依赖任何外部监督反馈的情况下，实现结构化的提示词搜索与优选。

**主要方法与技术**
1.  **基于树的搜索**：UPA 利用大语言模型（LLM）生成细粒度且与顺序无关的成对比较结果，以此为指导，迭代构建一个不断演化的树结构来探索提示词空间。
2.  **两阶段框架（BTL模型）**：由于局部的成对比较无法直接提供一致的全局质量标准，UPA 基于 Bradley-Terry-Luce (BTL) 模型，将系统性的探索与最终选择解耦，分为两个阶段：
    *   **路径级贝叶斯聚合**：对局部比较结果进行聚合，在不确定性下过滤掉候选提示词。
    *   **全局锦标赛比较**：通过全局性的对比推断出提示词的潜在质量，从而识别出最优提示词。

**实验结果**
在多项任务上的实验表明，UPA 的性能始终优于现有的提示词优化方法。这证明了即使在**完全无监督**的设置下，基于智能体风格的优化策略依然非常有效。

## 评论

**论文评价：UPA: Unsupervised Prompt Agent via Tree-Based Search and Selection**

**总体评价**
该论文针对大模型提示词工程中“高质量监督信号稀缺”这一痛点，提出了UPA（Unsupervised Prompt Agent）框架。其核心贡献在于构建了一个完全脱离外部奖励模型或人工反馈的闭环优化系统。从学术角度看，该研究探索了LLM内在的“自我纠错”与“偏好对齐”能力；从应用角度看，它为低成本自动化提示词优化提供了可行的技术路径。然而，其“无监督”定义的严格性及推理成本仍是潜在的限制因素。

### 1. 研究创新性
*   **论文声称**：UPA 首次提出了基于树搜索的无监督提示词智能体，无需任何外部监督信号即可完成提示词的优化。
*   **证据**：论文提出了一种利用LLM自身生成成对比较结果来指导树搜索的方法，替代了传统的Reward Model。
*   **推断**：
    *   **方法创新**：将强化学习中的树搜索（如MCTS思想）迁移至Prompt优化领域，并结合LLM的生成能力进行“自我博弈”，这是对现有Prompt Engineering方法的重要补充。
    *   **视角转换**：传统方法（如APE, PPO）依赖“输入-输出”对的监督信号，UPA将其转化为“候选Prompt之间的相对优劣评估”，降低了对标注数据的依赖。
*   **关键假设与失效条件**：
    *   *假设*：LLM具备足够的推理能力，能够准确判断两个不同Prompt在语义上的优劣，且这种判断与下游任务的真实性能呈正相关。
    *   *失效条件*：对于极度复杂或需要深层领域知识的任务，LLM可能无法准确自我评估，导致“近朱者赤，近墨者黑”的错误收敛。
    *   *检验方式*：设计“LLM自我评估得分”与“真实下游任务指标（如Accuracy、BLEU）”的Spearman相关性实验，若相关性低（<0.5），则该方法失效。

### 2. 理论贡献
*   **论文声称**：UPA通过无监督的搜索与选择机制，实现了Prompt的结构化进化。
*   **证据**：论文构建了基于树的搜索空间，利用LLM生成比较结果作为剪枝和扩展的依据。
*   **推断**：
    *   **理论补充**：该工作在理论上支持了“LLM不仅是生成器，也是判别器”的观点。它隐含地利用了LLM内部蕴含的对齐偏好来优化输入，而非仅仅优化输出。
    *   **突破点**：突破了传统Prompt优化依赖“黑盒”反馈的局限，建立了一种“白盒”内省式的优化范式。
*   **局限性**：缺乏对树搜索收敛性的理论证明。在树结构中，如何保证全局最优解没有被错误的早期剪枝所排除，论文未给出数学上的边界分析。

### 3. 实验验证
*   **论文声称**：UPA在多个推理和生成任务上均取得了优于基线模型的表现。
*   **证据**：论文在Big-Bench Hard等数据集上进行了实验，对比了Manual Prompt、AutoPrompt及有监督的PromptAgent方法。
*   **推断**：
    *   **可靠性分析**：实验设计较为全面，涵盖了推理与常识任务。结果显示UPA在缺乏监督信号的情况下，逼近甚至超过了部分有监督方法，这有力地证明了其有效性。
    *   **潜在偏差**：实验可能主要集中在对LLM“友好”的任务上（如逻辑推理、文本改写），而在对精确性要求极高的任务（如代码生成、数学计算）中，无监督信号可能过于模糊。
*   **检验方式**：增加高精度要求的任务测试（如HumanEval代码通过率），并引入“置信度区间”分析，验证多次运行结果的稳定性。

# 1. 研究背景与问题

### 核心问题
该论文致力于解决大语言模型（LLM）应用中**提示词优化的自动化与通用化问题**。具体而言，它针对现有“提示词智能体”方法高度依赖**外部有监督奖励信号**（如人工标注、任务执行准确率、或基于特定日志的反馈）的痛点，提出了一个核心问题：**在完全没有外部监督信号的情况下，如何自动搜索并优化出高质量的提示词？**

### 问题的研究背景和意义
随着 LLM 能力的爆发，如何通过设计精准的提示词来激发模型的潜力成为了关键课题。然而，人工编写提示词成本高昂且不稳定。因此，自动提示词优化（APE, OPRO等）应运而生，并逐渐演化为基于智能体的序列决策问题。这一领域的意义在于降低 LLM 的使用门槛，实现 AI Agent 的自我进化。然而，现实场景中，获取高质量的监督信号（例如“这个提示词生成的代码是否通过了所有测试用例”）往往极其困难或昂贵，这限制了现有 APO 方法的泛化能力。

### 现有方法的局限性
现有的提示词优化方法（如 APE, Refiner, OPRO）大多采用**“生成-评估-反馈”**的闭环模式。它们的局限性主要体现在：
1.  **依赖外部奖励模型**：需要定义明确的奖励函数或拥有标注好的数据集来评估提示词的好坏。
2.  **任务特异性强**：针对数学题优化的提示词很难迁移到创意写作任务，因为奖励机制完全不同。
3.  **评估成本高昂**：在迭代过程中需要反复调用 LLM 进行推理以获取分数，计算资源消耗巨大。

### 为什么这个问题重要
解决这一问题标志着 LLM Agent 从“被动优化”向“自主探索”的跨越。如果 Agent 能够在缺乏明确“对错”标准的情况下，仅依靠模型自身的内省和比较能力来进化，那么它将具备更强的**零样本泛化能力**和**自适应性**。这对于构建通用人工智能（AGI）是一个重要的微观尝试。

# 2. 核心方法与创新

### 提出的核心方法：UPA (Unsupervised Prompt Agent)
UPA 提出了一个完全无监督的框架，将提示词优化过程分解为**基于树的搜索**和**基于模型的选择**两个核心环节。

1.  **基于树的搜索**：
    *   利用 LLM 生成当前提示词的变体（修改、重写）。
    *   利用 LLM 对生成的变体与父节点进行成对比较，判断哪个更好。
    *   构建一个演化的树结构，通过“探索与利用”策略在提示词空间中游走。

2.  **两阶段选择框架（解耦探索与选择）**：
    *   **路径级贝叶斯聚合**：在搜索过程中，利用贝叶斯方法聚合路径上的局部比较结果，过滤掉明显较差的分支，控制搜索树的规模。
    *   **全局锦标赛比较**：搜索结束后，基于 Bradley-Terry-Luce (BTL) 模型，对所有候选提示词进行全局建模，通过求解最大似然估计（MLE）找出潜在质量最高的提示词。

### 技术创新点和贡献
*   **完全去除外部奖励**：这是最大的创新。它证明了 LLM 本身具备判断“哪个提示词更好”的元认知能力，无需外部任务执行结果作为依据。
*   **细粒度与顺序无关的比较**：UPA 设计了特定的 Prompt 让 LLM 进行比较，这种比较被设计为细粒度的（关注具体措辞）且顺序无关的（避免位置偏差），提高了比较信号的信噪比。
*   **解耦策略**：将“如何探索更多可能性”与“如何确定最终答案”解耦。搜索阶段负责广度，选择阶段负责精度。这解决了局部比较可能存在的非传递性矛盾（即 A>B, B>C，但 C>A 的情况）。

### 方法的优势
*   **通用性强**：不依赖特定任务的奖励函数，可以跨任务迁移。
*   **资源效率相对较高**：相比于需要执行生成代码或复杂推理来获取奖励的方法，UPA 仅需要 LLM 输出比较结果，计算开销相对可控。
*   **鲁棒性**：通过 BTL 模型的全局聚合，能够容忍单次比较中的噪声和错误。

# 3. 理论基础

### 使用的理论基础或假设
UPA 的理论基石主要来自**博弈论**和**排序理论**：
1.  **Bradley-Terry-Luce (BTL) 模型**：这是用于描述成对比较结果的标准概率模型。假设每个对象（提示词）都有一个潜在的真实质量分数 $\theta_i$，对象 $i$ 优于对象 $j$ 的概率满足 Logistic 函数关系：
    $$P(i > j) = \frac{\sigma(\theta_i)}{\sigma(\theta_i) + \sigma(\theta_j)}$$
    其中 $\sigma$ 通常是恒等函数。
2.  **贝叶斯更新**：用于在搜索过程中维护候选提示词的后验分布，动态剪枝。

### 数学模型或算法设计
*   **局部比较矩阵**：构建一个非对称矩阵 $A$，其中 $A_{ij}$ 记录提示词 $i$ 优于 $j$ 的次数或概率。
*   **全局评分求解**：在搜索结束后，通过最大化以下对数似然函数来求解所有提示词的潜在分数 $\theta$：
    $$L(\theta) = \sum_{(i,j) \in \mathcal{D}} \log P(i > j)$$
    这通常通过最小二乘法或梯度下降求解。

### 理论贡献分析
论文的理论贡献在于证明了**“局部比较的聚合可以收敛于全局最优”**。在无监督设定下，虽然单次 LLM 的判断可能不可靠，但通过树状结构产生大量样本，并利用 BTL 模型进行统计推断，可以从 noisy 的比较中恢复出真实的排序。这为 LLM 的自我进化提供了一种统计学上的解释框架。

# 4. 实验与结果

### 实验设计和数据集
论文在多项 NLP 任务上进行了评估，涵盖了：
*   **推理任务**：GSM8K (数学), BBH (大模型打榜基准).
*   **知识问答**：TriviaQA.
*   **生成任务**：Creative Writing (创意写作).
*   **指令遵循**：IFEval.

对比基线包括：手动设计、CoT (思维链)、以及有监督的优化方法如 APE 和 TextGrad。

### 主要实验结果和指标
*   **性能优势**：UPA 在大多数零样本和少样本设置下，显著优于手动 Prompt 和其他自动优化方法。
*   **无监督有效性**：最关键的发现是，在没有 Ground Truth 的情况下，UPA 优化出的 Prompt 甚至接近或超过了依赖大量标注数据的有监督方法。
*   **收敛性**：实验展示了随着搜索步数的增加，Prompt 质量的提升曲线。

### 结果分析和验证
结果表明，LLM 确实具备一种“内在的判断力”，能够识别出更清晰、更逻辑严密的指令。BTL 模型有效地修正了树搜索过程中的随机游走偏差。

### 实验的局限性
*   **计算成本**：虽然比执行代码快，但构建搜索树和进行成对比较仍需大量的 API 调用。
*   **长上下文遗忘**：随着树深度的增加，LLM 可能会遗忘初始的优化目标。
*   **主观性偏差**：由于没有 Ground Truth，对于创意写作等开放任务，BTL 选出的“最优”可能符合模型偏好，但不一定符合人类审美。

# 5. 应用前景

### 实际应用场景
1.  **私有化部署模型的调优**：企业在没有高质量标注数据时，可利用 UPA 快速优化内部 RAG 系统的 Prompt。
2.  **自动化 Agent 编排**：在多 Agent 系统中，Agent 可以利用 UPA 动态调整其通信协议，无需人工干预。
3.  **教育辅助**：自动优化向学生解释复杂概念的 Prompt，使其更易懂。

### 产业化的可能性
极高。UPA 提供了一种“低成本、高通用”的优化手段，非常适合接入到现有的 LLM 开发平台（如 LangChain, AutoGPT）中作为标准插件。

### 与其他技术的结合
*   **RAG (检索增强生成)**：优化检索查询和重排序指令。
*   **Multi-Agent**：作为 Agent 之间的“协商机制”，自动达成最优的协作策略。

# 6. 研究启示

### 对该领域的启示
1.  **从“外部反馈”转向“内省”**：未来的 Agent 研究应更多关注模型自身的元认知能力，而非过度依赖外部环境反馈。
2.  **搜索算法的重要性**：提示词优化不仅仅是 NLP 问题，更是组合优化问题。MCTS、A* 等传统搜索算法与 LLM 的结合大有可为。

### 可能的研究方向
*   **多模态扩展**：将 UPA 应用于图像生成 Prompt 的优化。
*   **个性化 BTL**：根据不同用户的偏好调整 BTL 模型的权重，实现个性化的 Prompt 优化。
*   **记忆增强**：引入长期记忆机制，避免树搜索中的重复探索。

# 8. 相关工作对比

### 与同类研究的对比
*   **vs. APE (Automatic Prompt Engineering)**：APE 需要训练一个奖励模型或使用 LLM 生成输出样本并计算 ROUGE/BLEU 分数作为监督。UPA 完全抛弃了这些指标。
*   **vs. OPRO (Outlining Prompt Optimization)**：OPRE 同样将优化视为序列问题，但依赖“优化分数”作为反馈。UPA 用“成对比较”替代了“优化分数”。
*   **vs. Evoke (Refiner)**：Refiner 通过基于梯度的反馈改进 Prompt，依赖于可微分的输出或白盒模型。UPA 是黑盒优化。

### 创新性评估
UPA 的创新性在于**范式转移**。它证明了在没有标尺的情况下，通过相对比较依然可以建立绝对秩序。这在方法论上是一个重要的进步。

## 最佳实践指南

### 实践 1：构建高质量的蒙特卡洛树搜索（MCTS）反馈机制

**说明**:
UPA 的核心在于利用 MCTS 进行无监督的提示词优化。最佳实践要求建立一个基于模型自身输出的评估反馈循环，而不是依赖人工标注或地面真值。通过让模型充当“评论家”和“执行者”，利用 LLM 的生成能力来评估不同提示词分支的质量，从而在无需外部监督的情况下引导搜索向高提示词质量方向收敛。

**实施步骤**:
1. 设计一个通用的评估提示模板，要求 LLM 根据生成的回复质量（如连贯性、事实性）打分或提供偏好反馈。
2. 在 MCTS 的每一轮模拟中，使用当前节点提示词生成样本，并立即调用评估模块获取奖励信号。
3. 根据反馈奖励更新树节点的价值（Q值），优先选择高价值的节点进行扩展。

**注意事项**:
确保评估提示词具有足够的区分度，避免模型对所有生成的回复给出相似的分数，导致搜索无法区分优劣。

---

### 实践 2：设计有效的变异与进化策略

**说明**:
在树搜索过程中，节点的扩展依赖于对现有提示词的修改。实施时应建立一套结构化的“变异算子”，模仿遗传进化中的操作。这不仅包括简单的文本重写，还应包括语义层面的扩展和简化，以探索更广阔的提示词空间，避免陷入局部最优解。

**实施步骤**:
1. 定义一组操作算子，例如：语义重述、增加具体约束、添加思维链指令、风格迁移等。
2. 在 MCTS 的扩展阶段，随机选择或基于策略选择一种变异算子作用于父节点的提示词。
3. 限制变异的幅度，确保子代提示词保留父代的核心意图，同时引入新的指令特征。

**注意事项**:
变异操作不应过于激进，以免生成的提示词偏离原始任务意图；应保持“语义一致性”与“指令创新性”之间的平衡。

---

### 实践 3：实施温度采样与探索-利用平衡

**说明**:
在树搜索过程中，必须在利用已知的高分提示词和探索未知的潜在优秀提示词之间取得平衡。UPA 方法通常依赖 MCTS 的 Upper Confidence Bound (UCB) 算法或类似策略。最佳实践包括动态调整采样温度，在搜索初期鼓励高多样性（高温度），在后期侧重于收敛于最优解（低温度）。

**实施步骤**:
1. 配置 MCTS 的选择策略参数（如 $C_{puct}$），控制探索项的权重。
2. 在提示词生成阶段，根据搜索进度调整 LLM 的温度参数。初期使用较高温度（如 0.8-1.0）以产生多样化的变异。
3. 随着迭代次数增加，逐步降低温度（如 0.1-0.3），使生成的提示词更加确定和精细。

**注意事项**:
如果探索参数设置过低，算法会过早收敛于次优解；设置过高则会导致搜索效率低下，无法在有限预算内找到稳定的最优提示词。

---

### 实践 4：利用少样本上下文增强评估稳定性

**说明**:
由于 UPA 是无监督方法，评估模型的准确性至关重要。为了防止模型在自我评估过程中出现幻觉或不稳定的判断，最佳实践是在评估提示词中引入少样本示例。通过在评估请求中提供“好”与“坏”回复的具体案例，可以校准模型的判断标准，使其反馈信号更加可靠。

**实施步骤**:
1. 构建一个包含典型任务场景及对应高质量/低质量回复的参考数据集。
2. 在要求模型评估新生成的提示词效果时，在 Prompt 中包含 2-3 个上述参考示例。
3. 明确指示模型参考示例中的评分逻辑或偏好理由来对当前样本进行打分。

**注意事项**:
参考示例必须与目标任务领域相关，且需要定期审查示例的质量，以免引入偏差导致模型优化方向错误。

---

### 实践 5：建立迭代式的候选提示词库与去重机制

**说明**:
随着树搜索的进行，会产生大量的候选提示词。为了防止计算资源浪费在重复或高度相似的提示词上，需要建立一个动态管理的候选库。最佳实践包括使用语义去重技术（如基于 Embeddings 的余弦相似度）来过滤冗余节点，确保搜索树的健康生长和多样性。

**实施步骤**:
1. 为每一个生成的提示词计算向量嵌入。
2. 在将新提示词加入搜索队列或候选库之前，计算其与库中现有提示词的相似度。
3. 设定阈值（如余弦相似度 > 0.85），如果新提示词与现有提示词过于相似，则丢弃该分支或强制进行不同的变异。

**注意事项**:
去重阈值需要根据任务特性调整。对于需要精确指令的任务，阈值应较高（严格去重）；对于创造性任务，可适当放宽以允许微小的变体存在。

## 学习要点

- UPA 提出了一种无监督的提示词优化框架，能够在不依赖人类标注数据或更强模型（如 GPT-4）反馈的情况下，通过自我进化迭代自动生成高质量的提示词。
- 该方法采用树状搜索策略（结合蒙特卡洛树搜索），通过探索不同的提示词变体并利用无监督指标（如熵、多样性）来指导搜索方向，从而高效地找到最优解。
- 引入了基于实例选择和提示词生成的双重优化机制，通过从训练池中筛选最具代表性的样本并动态调整指令，显著提升了模型在下游任务上的表现。
- UPA 在推理任务上取得了与最先进的（SOTA）有监督提示方法相当甚至更好的性能，证明了无监督方法在降低成本和避免强模型依赖方面的巨大潜力。
- 该框架通过迭代式的“生成-评估-选择”循环，利用自身模型对候选提示词进行打分和排序，实现了完全自动化的提示词工程过程。
- 实验表明，UPA 在处理复杂推理任务（如算术和符号推理）时，能够有效克服传统提示词方法面临的幻觉问题和鲁棒性不足的挑战。

## 常见问题


### 1: 什么是 UPA (Unsupervised Prompt Agent)，它的主要功能是什么？

1: 什么是 UPA (Unsupervised Prompt Agent)，它的主要功能是什么？

**A**: UPA 是一种基于大语言模型（LLM）的智能体框架，旨在解决提示工程中的“如何让模型表现更好”这一核心问题。它的全称是“无监督提示代理”。其主要功能是在没有任何人工标注数据或人类反馈的情况下，自动地生成、优化和选择最佳的提示词。UPA 能够将一个简单的初始指令，通过树状搜索和迭代优化，转化为能够引导大模型产生高质量输出的复杂、精确的提示词。

---



### 2: UPA 与传统的提示工程方法（如手动调试或 AutoPrompt）有何区别？

2: UPA 与传统的提示工程方法（如手动调试或 AutoPrompt）有何区别？

**A**: 传统方法通常依赖人工经验进行反复试错，或者使用基于梯度的方法（如 AutoPrompt/Prefix-Tuning）来优化提示，这些方法往往计算成本高昂且需要可访问的模型梯度。UPA 的核心区别在于：
1.  **无监督性**：它不需要下游任务的标注数据集，也不需要人工标注的“黄金答案”作为奖励信号。
2.  **黑盒优化**：它将 LLM 视为黑盒，仅通过输入输出交互进行优化，不需要访问模型内部参数或梯度。
3.  **树状搜索**：不同于简单的线性迭代，UPA 使用树结构来探索不同的提示词变体，通过蒙特卡洛树搜索（MCST）等策略平衡探索与利用，从而更高效地找到全局最优解。

---



### 3: UPA 的工作流程是怎样的？

3: UPA 的工作流程是怎样的？

**A**: UPA 的工作流程主要包含四个循环阶段：
1.  **生成**：基于当前的提示词，LLM 生成多个新的候选变体。
2.  **评估**：使用一个无监督的评分机制（如基于熵的置信度评分或一致性评分）来评估这些候选提示词的质量，而不依赖真实标签。
3.  **选择**：根据评估分数，从候选者中选择表现最好的提示词。
4.  **参数更新**：利用树搜索算法（如 MCTS）更新搜索策略，决定下一步是继续优化当前分支（利用）还是尝试新的方向（探索）。这个过程不断重复，直到找到满意的提示词或达到计算预算上限。

---



### 4: UPA 如何在没有人工标注数据的情况下评估提示词的质量？

4: UPA 如何在没有人工标注数据的情况下评估提示词的质量？

**A**: 这是 UPA 最具创新性的部分。由于没有标准答案，UPA 使用**自一致性**和**不确定性**作为代理信号。
具体来说，它会用同一个提示词让 LLM 生成多个输出。如果这些输出高度一致（例如，在推理任务中得出了相同的结论，或者生成的文本熵值很低），则认为该提示词是“稳定”且“高质量”的。反之，如果输出杂乱无章，则说明提示词不够清晰。通过这种基于“置信度”的反馈，UPA 可以在无监督环境下筛选出有效的提示词。

---



### 5: UPA 适用于哪些类型的任务？

5: UPA 适用于哪些类型的任务？

**A**: UPA 特别适合那些难以获取大量高质量标注数据，或者任务定义较为复杂的场景。根据论文研究，它在以下任务中表现优异：
1.  **复杂推理任务**：如数学应用题（GSM8K）或符号推理，需要精确的指令引导模型进行逐步思考。
2.  **代码生成**：通过优化指令描述，提高生成代码的准确性和通过率。
3.  **知识密集型问答**：在缺乏特定领域示例的情况下，优化提示词以激发模型的内在知识。
简而言之，任何需要精细提示词以激发 LLM 潜力的场景，都是 UPA 的潜在应用领域。

---



### 6: 使用 UPA 进行提示词优化有什么局限性或成本吗？

6: 使用 UPA 进行提示词优化有什么局限性或成本吗？

**A**: 虽然 UPA 能够自动化提示工程，但也存在一些局限性：
1.  **计算成本较高**：由于需要进行树状搜索和多次迭代采样，UPA 需要调用 LLM 数十次甚至上百次。虽然它优化了最终的提示词，但搜索过程本身的 API 调用费用或时间成本是不可忽视的。
2.  **评估信号的偏差**：无监督的评估信号（如一致性）并不总是与真实的人类偏好完全对齐。有时候模型可能“自信地”给出了错误的答案，这可能会导致 UPA 误判提示词的质量。
3.  **依赖基础模型能力**：UPA 的效果上限取决于所使用的底层 LLM 的能力。如果基础模型本身无法理解任务，UPA 也很难“魔法般”地生成有效的提示词。
