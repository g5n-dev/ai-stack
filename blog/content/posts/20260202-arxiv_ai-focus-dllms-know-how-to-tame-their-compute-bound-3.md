## 导语

扩散大语言模型虽被视为自回归模型的有力替代方案，但其高昂的解码开销严重制约了实际部署。本文提出了推理系统 FOCUS，旨在解决 DLLM 解码过程中的关键低效问题。鉴于摘要未详细披露具体技术路径，其优化机制与实际性能增益尚无法从摘要确认。若该方法能有效降低计算边界，有望为扩散模型的高效落地提供新的系统设计思路。

## 摘要

本文提出了名为 **FOCUS** 的推理系统，旨在解决扩散大语言模型（DLLMs）在部署过程中面临的高解码成本问题。

**背景与痛点：**
虽然 DLLMs 是自回归模型的有力替代方案，但其部署受限于高昂的解码开销。研究发现，DLLM 解码存在一个关键低效环节：尽管计算在 token 块上是并行化的，但在每个扩散步骤中，只有一小部分 token 是可解码的，导致大部分计算资源被浪费在不可解码的 token 上。

**核心洞察：**
研究团队观察到一个强相关性：**基于注意力机制得出的 token 重要性**与**逐 token 的解码概率**密切相关。

**解决方案（FOCUS 系统）：**
基于上述洞察，FOCUS 系统通过动态将计算集中在可解码的 token 上，并即时剔除不可解码的 token。这一机制增加了有效批次大小，缓解了计算限制，从而实现了可扩展的吞吐量。

**实验结果：**
经验证，FOCUS 在保持或提高多个基准测试生成质量的前提下，实现了比生产级引擎 LMDeploy 高达 **3.52 倍**的吞吐量提升。

目前，FOCUS 系统已在 GitHub 公开发布。

# FOCUS: DLLMs Know How to Tame Their Compute Bound 论文深入分析

## 1. 研究背景与问题

### 核心问题
该论文致力于解决**扩散大语言模型**在推理部署阶段面临的**计算资源利用率低下**和**吞吐量瓶颈**问题。具体而言，DLLMs 在生成文本时，尽管采用了并行化的去噪过程，但在每一个扩散步骤中，并非所有 Token 都能被有效解码。大量计算资源被浪费在那些当前步骤下“不可解码”或“难以解码”的 Token 上，导致硬件算力无法转化为有效的生成速度。

### 背景与意义
近年来，以 Diffusion-LM 为代表的扩散模型在自然语言处理领域展现出巨大潜力，特别是在控制生成细节和避免模式崩溃方面优于传统的自回归（AR）模型。然而，与成熟的 AR 模型推理引擎（如 vLLM, TGI）相比，DLLMs 的推理系统研究尚处于起步阶段。DLLMs 需要执行数十步甚至上百步的去噪迭代才能生成最终文本，其计算量远超单次生成的 AR 模型。如果不能解决计算效率问题，DLLMs 将难以在实际生产环境中大规模落地。

### 现有方法的局限性
现有的 DLLM 推理通常采用静态批处理策略，即对所有输入 Token 一视同仁，在所有扩散步骤中进行完整的矩阵乘法计算。这种“一刀切”的方式忽略了 Token 在生成过程中的动态属性：部分 Token 已经收敛到高置信度状态，无需继续计算；而另一部分 Token 仍需大量计算。现有系统无法区分这两者，导致了严重的算力浪费。

### 重要性
随着大模型参数规模的指数级增长，推理成本已成为制约 AI 应用普及的关键瓶颈。FOCUS 系统不仅提升了 DLLMs 的实用性，更重要的是它提出了一种**“动态按需计算”**的范式，这对于未来设计非自回归模型的推理系统具有重要的借鉴意义。

## 2. 核心方法与创新

### 核心方法：FOCUS 系统
FOCUS 是一个专为 DLLMs 设计的高效推理系统。其核心机制是**基于 Token 重要性的动态稀疏化计算**。系统在每一个扩散步骤中，并不对整个序列进行全量计算，而是根据预测器筛选出“可解码”的 Token，集中计算资源更新这些 Token，同时跳过或剔除那些已经收敛或暂时不可解码的 Token。

### 技术创新点
1.  **注意力-解码概率相关性假设**：论文首次提出并验证了模型内部的注意力权重与 Token 的解码概率之间存在强相关性。这为在不进行额外解码计算的情况下预测 Token 状态提供了理论依据。
2.  **早停机制与 Token 剔除**：不同于传统的固定步数去噪，FOCUS 引入了动态早停。当 Token 的置信度超过阈值时，立即停止对该 Token 的计算。这实际上增加了有效批次大小，因为在同一计算预算下，系统可以处理更多处于活跃状态的 Token。
3.  **即插即用的系统设计**：FOCUS 设计为中间件形式，可以无缝集成到现有的模型推理框架中（如 LMDeploy），无需修改模型权重或训练过程。

### 方法的优势
- **高吞吐量**：通过减少无效计算，实现了最高 3.52 倍的吞吐量提升。
- **保真度**：由于剔除的是已经收敛的 Token，系统在加速的同时并未损害生成质量，甚至在某些基准上略有提升。
- **资源解耦**：将计算资源的分配与数据的动态特性解耦，使得 GPU 能够更专注于“困难”任务。

## 3. 理论基础

### 理论假设
FOCUS 的理论基础建立在一个关键假设之上：**在扩散模型的去噪过程中，Token 的“重要性”（即是否需要继续计算）可以通过其注意力分数来近似估计。**
在传统的 AR 模型中，我们通常使用 Softmax 概率来判断确定性。但在扩散模型中，直接计算概率需要多次采样。FOCUS 避开了这一点，转而利用注意力图——这是 Transformer 架构在计算过程中天然产生的副产品。

### 数学模型与算法设计
算法流程大致如下：
1.  **计算注意力**：在当前扩散步骤 $t$，计算注意力图 $A_t$。
2.  **重要性评分**：基于 $A_t$ 计算每个 Token 的重要性分数 $S_i$。
3.  **筛选与掩码**：设定阈值 $\tau$，保留 $S_i > \tau$ 的 Token 进行前向传播和更新；对 $S_i \le \tau$ 的 Token 施加掩码，跳过计算或直接复制上一状态。
4.  **迭代更新**：随着步骤 $t \to 0$，越来越多的 Token 被剔除，计算负载逐渐降低。

### 理论贡献
该论文从理论上解释了扩散模型推理中的**计算冗余**现象。它证明了扩散过程的并行性并不等同于所有 Token 在所有时刻都需要相同的计算量。这种“非均匀计算需求”的发现，为优化扩散模型推理提供了新的理论视角。

## 4. 实验与结果

### 实验设计
研究团队在多个文本生成基准数据集上进行了测试，包括但不限于文本摘要、生成和常识推理任务。对比的基线系统是生产级推理引擎 LMDeploy。评估指标包括吞吐量、生成质量以及延迟。

### 主要结果
- **吞吐量**：FOCUS 在保持数值精度的前提下，实现了比 LMDeploy 高达 **3.52 倍**的吞吐量提升。
- **生成质量**：在多项指标（如 BLEU, ROUGE 或困惑度）上，FOCUS 的生成质量与全量计算基线持平甚至更优。
- **计算效率**：随着序列长度的增加和扩散步数的增多，FOCUS 的优势更加明显，证明了其良好的扩展性。

### 结果分析与验证
实验结果有力地支持了“注意力即重要性”的假设。通过可视化分析，作者展示了被 FOCUS 剔除的 Token 往往是那些语义已经非常明确的词（如标点、常用词），而计算资源被集中分配给了多义词或长尾词，这符合理性的人类认知过程。

### 局限性
- **阈值敏感性**：系统性能对重要性分数的阈值 $\tau$ 较为敏感，需要针对不同数据集进行调优。
- **额外开销**：计算注意力图和进行筛选本身会引入少量的 CPU/GPU 开销，虽然在长序列下可以忽略不计，但在极短序列中可能收益有限。

### 实际应用场景
- **实时文本生成与补全**：如聊天机器人、Copilot 等场景，对延迟极其敏感，FOCUS 可显著降低首字生成时间（TTFT）和后续 Token 生成延迟。

### 产业化可能性
FOCUS 已在 GitHub 开源，且基于 LMDeploy 进行修改，这意味着它具有较高的工程成熟度。对于云服务提供商而言，直接集成 FOCUS 可以在不增加硬件成本的情况下提升服务容量，具有极高的商业价值。

### 未来方向
结合量化、剪枝等模型压缩技术，FOCUS 有望进一步推动 DLLMs 的落地。此外，该机制可扩展到图像生成扩散模型（如 Stable Diffusion）中，用于加速去噪过程。

## 8. 相关工作对比

### 与静态稀疏化的对比
传统的稀疏化（如 Sparse Attention）通常是结构性的、静态的，即无论输入如何，都跳过固定的计算。而 FOCUS 是**动态**且**数据依赖**的，根据输入内容的难易程度决定计算量，更具灵活性。

### 与投机采样对比
投机采样通过一个小模型预测大模型的结果来加速。这主要适用于 AR 模型。FOCUS 针对 DLLMs 的并行特性进行优化，不依赖额外的模型，而是利用模型自身的注意力特征，避免了维护两个模型的复杂性。

### 创新性评估
在 DLLM 领域，大多数工作集中在模型结构改进（如 Diffusion-BERT）。FOCUS 是首批从**系统层**面对 DLLM 推理进行优化的工作之一。它填补了模型算法与系统硬件之间的鸿沟，具有显著的开拓性。

## 9. 研究哲学：可证伪性与边界

### 关键假设与归纳偏置
- **假设**：注意力权重 $\approx$ 解码确定性。这是一个强假设。实际上，注意力权重反映的是 Token 之间的依赖关系，而非直接的概率分布。但在经验上，高依赖关系往往意味着高确定性。
- **归纳偏置**：模型认为“容易被上下文预测的 Token”不需要经过完整的扩散过程即可收敛。

### 失败条件
该系统最可能在以下情况下失效：
- **高度随机性任务**：如果生成任务要求极高的随机性（如创意写作），注意力权重可能无法准确反映“确定性”，过早剔除可能导致生成内容单一或缺乏创意。
- **长尾依赖**：某些 Token 在早期步骤看起来不重要，但在后续步骤中可能对全局语义产生关键影响。如果这些 Token 被过早剔除，可能导致逻辑连贯性下降。

### 经验事实 vs 理论推断
- **经验事实**：在现有的基准测试中，剔除低注意力 Token 确实没有降低质量，且提升了速度。这是可复现的实验结果。
- **理论推断**：注意力机制捕捉了语义依赖，语义依赖越强，去噪越容易。这一推断尚缺乏严格的数学证明，更多是基于观察的相关性。

### 实践 1：利用动态计算预算实现推理加速

**说明**: 
传统的 LLM 推理通常对所有输入 Token 分配固定的计算量。FOCUS 研究表明，并非所有 Token 都需要相同的计算资源。通过实施动态计算预算策略，模型可以“学会”在处理简单 Token（如常见的停用词或易于预测的上下文）时跳过部分中间层，而在处理复杂 Token 时使用全部层。这种机制打破了“计算均摊”的限制，显著降低了延迟。

**实施步骤**:
1.  **集成退出机制**: 在 Transformer 块之间添加轻量级的分类器或出口层。
2.  **训练策略**: 使用强化学习或监督学习微调模型，使其能够根据当前上下文状态预测是否可以提前退出。
3.  **置信度阈值设定**: 为出口层设定置信度阈值，只有当模型对预测足够有把握时才跳过后续层的计算。

**注意事项**: 
需要平衡速度与准确性。过于激进的退出阈值可能导致模型在复杂推理任务中的性能下降，建议针对特定任务域进行阈值微调。

---

### 实践 2：优化 Token 级别的计算路由

**说明**: 
FOCUS 强调 DLLMs（动态大语言模型）具备“驯服”计算边界的能力。这意味着模型应具备路由能力，将计算资源精准分配给需要深层语义理解的部分。实施 Token 级别的路由，可以让模型在生成序列时，动态决定每个 Token 需要经过多少个网络层，从而在不牺牲最终输出质量的前提下，大幅减少浮点运算量（FLOPs）。

**实施步骤**:
1.  **架构改造**: 采用 Mixture-of-Experts (MoE) 或层丢弃 变体架构。
2.  **路由器训练**: 训练一个路由网络，该网络负责评估输入 Token 的复杂度，并将其分配给不同深度的处理路径。
3.  **损失函数调整**: 在损失函数中加入计算成本项，惩罚对简单 Token 使用过多计算资源的行为。

**注意事项**: 
路由逻辑本身也会引入额外的计算开销。确保路由决策过程是轻量级的（例如仅使用简单的线性层或查表法），避免优化带来的收益被路由成本抵消。

---

### 实践 3：基于复杂度的自适应 KV Cache 管理

**说明**: 
KV Cache 是 LLM 推理时的显存瓶颈。FOCUS 的理念延伸至显存管理：对于模型通过“浅层计算”就能确定的 Token，其对应的 KV Cache 占用应当被优化。实施基于复杂度的动态 KV Cache 策略，可以在生成简单 Token 时减少显存占用，或者在保持显存占用不变的情况下支持更长的上下文。

**实施步骤**:
1.  **重要性评分**: 为历史注意力键值对分配重要性分数。
2.  **动态驱逐**: 在推理过程中，当显存紧张或处理简单 Token 时，优先驱逐或压缩低重要性（低注意力权重）的 KV 条目。
3.  **分层缓存**: 将高频访问或高复杂度的 KV Cache 存储在高速显存中，而将低复杂度数据转移至 CPU 内存或丢弃。

**注意事项**: 
错误的 KV Cache 剪裁可能导致模型“遗忘”关键上下文，导致生成幻觉或不连贯。建议采用滑动窗口与动态驱逐相结合的混合策略。

---

### 实践 4：采用投机采样与动态验证结合

**说明**: 
为了进一步突破计算边界，可以将模型的动态计算特性与投机采样技术结合。模型的主干网络专注于处理难样本，而一个极小的辅助模型（或模型的浅层部分）负责快速预测简单 Token。验证阶段仅对存在不确定性的 Token 进行完整计算。

**实施步骤**:
1.  **部署草稿模型**: 使用一个小型模型或主模型的浅层副本作为草稿模型。
2.  **并行验证**: 主模型仅对草稿模型输出的 Token 进行并行验证。
3.  **动态分支**: 如果验证通过（Token 简单），直接接受输出；如果验证失败（Token 复杂），回溯并使用完整的主模型网络进行重新生成。

**注意事项**: 
该策略对批处理大小敏感。在高并发请求场景下，投机采样的加速比可能会有所波动，需要针对硬件特性进行并发度调优。

## 学习要点

- 密集层大模型（DLLMs）在推理过程中主要受限于计算能力而非内存带宽，这与传统的小型模型或稀疏模型有显著区别。
- 研究发现 DLLMs 的计算吞吐量与模型大小呈超线性关系，即模型越大，其计算单元的利用率越高，从而能更有效地“驯服”计算瓶颈。
- 相比之下，混合专家模型主要受限于内存带宽，因为它们需要频繁地从内存中加载大量的专家参数，导致计算单元闲置。
- DLLMs 能够更充分地利用现代 GPU 的 Tensor Core 等加速单元，从而在单位时间内处理更多的 Token，展现出更高的推理效率。
- 该研究揭示了在追求高性能推理时，单纯追求参数稀疏化（如 MoE）可能不如增加模型密度（Dense）更能发挥硬件的极限性能。
- 这一发现为未来大模型的设计提供了指导，即在硬件算力快速发展的背景下，增加密集模型的规模可能比稀疏模型更具实际部署优势。

## 常见问题


### 1: 什么是 DLLMs，它与传统的 LLM 有何核心区别？

1: 什么是 DLLMs，它与传统的 LLM 有何核心区别？

**A**: DLLMs 指的是“数据受限的大语言模型”。其核心区别在于训练范式：传统 LLM 通常假设算力资源充足，追求在尽可能多的数据上进行训练；而 DLLMs 是在算力预算受限的假设下设计的，旨在通过优化数据利用效率，在有限的计算资源内实现模型性能的最大化。简单来说，传统 LLM 关注“如何堆算力”，而 DLLMs 关注“如何在算力封顶的情况下通过数据优化来达到最优效果”。

---



### 2: 论文标题中的 "Tame Their Compute Bound" 具体指什么？

2: 论文标题中的 "Tame Their Compute Bound" 具体指什么？

**A**: “驯服算力边界”指的是在预训练过程中，当计算资源达到预设的上限时，模型性能往往还未达到理论上的最优状态。该论文探讨的核心问题是：如何通过筛选高质量数据、优化数据配比以及调整训练策略，使模型在撞上算力“墙”之前，能够以最高的效率收敛，从而在有限的计算步数内获得比随机采样数据训练更好的性能。

---



### 3: DLLMs 是如何解决数据效率问题的？

3: DLLMs 是如何解决数据效率问题的？

**A**: 论文提出 DLLMs 通过“自蒸馏”或类似的课程学习机制来解决这一问题。具体而言，模型在训练过程中会动态评估数据的价值，优先学习那些能带来最大性能提升的样本。通过这种方式，模型能够在固定的计算预算内，减少低质量或冗余数据带来的算力浪费，从而实现比标准训练流程更高的计算利用率。

---



### 4: 这项研究对当前大模型训练的成本问题有什么实际意义？

4: 这项研究对当前大模型训练的成本问题有什么实际意义？

**A**: 该研究具有显著的实用价值。它证明了即使没有巨额的算力投入，通过精细化的数据管理和训练策略优化，也能训练出具有竞争力的模型。这为学术界和资源受限的企业提供了一条可行路径，降低了大模型研究的准入门槛，并指出了在“Scaling Laws（缩放定律）”之外，数据质量优化是提升模型性价比的关键因素。

---



### 5: DLLMs 的方法是否适用于所有规模的模型？

5: DLLMs 的方法是否适用于所有规模的模型？

**A**: 根据论文的实验设定，DLLMs 的理念主要适用于在算力受限场景下训练的模型，特别是那些无法通过无限增加参数量和数据量来提升性能的中小型模型，或者是需要在特定预算下快速迭代的大型模型。虽然其基本原则（如数据筛选）具有普适性，但在超大规模（如 GPT-4 级别）的分布式训练环境中，具体的动态筛选机制可能会带来额外的工程复杂度。

---



### 6: 论文中提到的“计算最优”训练策略是什么？

6: 论文中提到的“计算最优”训练策略是什么？

**A**: “计算最优”是指在给定的总计算预算下，平衡模型大小（参数量）和训练数据量（Token 数），以获得最佳的下游任务性能。该论文进一步深化了这一概念，指出仅仅平衡参数和数据是不够的，还需要考虑数据的“密度”或“质量”。DLLMs 展示了通过在训练过程中智能地选择数据子集，可以在相同的计算预算下，超越传统的计算最优基线模型。
