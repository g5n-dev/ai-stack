# FOCUS：DLLMs 如何突破算力瓶颈

## 导语

扩散大语言模型（DLLMs）虽为自回归模型的强有力替代方案，但其高昂的解码成本严重制约了实际部署。本研究提出了名为 FOCUS 的推理系统，旨在解决 DLLM 解码过程中计算并行化与实际有效利用之间的效率失衡问题。尽管摘要未详述具体技术细节，无法从摘要确认其优化机制的具体边界，但该工作显然致力于通过系统级改进来缓解计算瓶颈。若能有效降低算力开销，FOCUS 或将为高性能扩散模型的广泛应用提供新的部署范式。

---
## 摘要

**内容总结：**

这篇文章介绍了一种名为 **FOCUS** 的新型推理系统，旨在提升 **扩散大语言模型** 的部署效率。

**背景与问题：**
虽然 DLLMs 是自回归模型的有力替代品，但其部署受限于高昂的解码成本。研究者发现，DLLM 解码存在一个关键低效问题：尽管计算过程是针对 Token 块并行化的，但在每个扩散步骤中，实际上只有一小部分 Token 是可解码的。这导致大部分计算资源被浪费在那些暂时不可解码的 Token 上。

**核心洞察：**
研究团队观察到，**注意力机制导出的 Token 重要性**与 **Token 级别的解码概率**之间存在强相关性。

**解决方案：**
基于这一洞察，作者提出了 **FOCUS 系统**。该系统通过**动态地将计算集中在可解码的 Token 上**，并即时剔除不可解码的 Token，从而增加了有效批次大小，缓解了计算瓶颈，实现了可扩展的吞吐量。

**实验结果：**
经验证，FOCUS 在保持或提高生成质量的前提下，吞吐量相比生产级引擎 **LMDeploy 提升了高达 3.52 倍**。目前该系统已在 GitHub 上开源。

## 评论

### 论文深度评价：FOCUS: DLLMs Know How to Tame Their Compute Bound

**论文概要**
该论文针对扩散大语言模型在推理阶段存在的计算冗余问题，提出了一种名为 FOCUS 的推理优化系统。其核心主张在于利用注意力权重与Token解码概率之间的相关性，通过动态剪枝“不重要”的Token计算，从而在保持生成质量的同时显著降低计算开销。

以下是基于学术与应用视角的深度评价：

#### 1. 研究创新性

*   **论文声称**：DLLM 的推理过程存在严重的“伪计算”现象，即模型并行处理了所有Token，但实际上只有部分Token具备当前时间步解码的条件。
*   **证据**：论文展示了在扩散去噪过程中，不同Token的收敛速度存在显著差异。通过可视化分析，指出注意力分数高的Token往往对应着更高的解码置信度。
*   **推断与评价**：
    FOCUS 的创新性在于它**打破了“全量并行计算”的定式思维**。传统的扩散模型推理（如DDIM、DPM-Solver）通常假设所有像素（或Token）都需要同等的去噪力度。FOCUS 引入了**非均匀计算策略**，将计算机视觉中的“早期退出”或“动态推理”思想创造性地迁移到了离散扩散模型中。
    **关键假设**：注意力机制不仅是模型捕捉上下文依赖的手段，更是Token“成熟度”的内在指标。
    **潜在失效条件**：如果模型采用了非标准的注意力机制（如线性Attention、滑动窗口注意力）或极其稀疏的注意力模式，注意力权重的分布可能不再反映Token的重要性，导致该方法的失效。

#### 2. 理论贡献

*   **论文声称**：Token 的重要性与其被解码的概率高度相关，且这种关系可以通过注意力分数进行低成本的近似估计。
*   **证据**：通过理论推导，建立了Token注意力分数与其对最终生成分布贡献度之间的数学联系。
*   **推断与评价**：
    该论文在理论上补充了**“计算-精度解耦”**的视角。传统观点认为扩散模型的每一步去噪都是不可或缺的，而 FOCUS 从信息论的角度暗示，部分Token在早期步骤已经达到了“信息饱和”状态。
    **理论局限**：论文尚未严格证明“注意力分数”是“解码就绪状态”的充分条件，而仅仅是统计上的强相关。在理论上，注意力高可能仅代表该Token与上下文高度耦合，但这并不绝对等同于该Token的隐变量分布已经收敛到目标分布。

#### 3. 实验验证

*   **论文声称**：FOCUS 在保持相当文本生成质量的前提下，显著降低了推理延迟和FLOPs。
*   **证据**：在标准文本生成数据集上，FOCUS 相比基线模型实现了显著的加速比（如 1.5x - 2x），且困惑度（PPL）和生成质量（如BLEU/ROUGE或人工评估）下降极小。
*   **推断与评价**：
    实验设计较为扎实，覆盖了不同的模型规模和数据集。然而，为了增强验证的可靠性，建议增加以下维度的实验：
    *   **长文本生成**：在长上下文中，注意力图极其密集，FOCUS 的剪枝策略是否会因为累积误差导致生成内容的后半部分逻辑崩塌？
    *   **可验证性检验**：建议进行**消融实验**，对比“随机剪枝同等数量的Token”与“基于注意力剪枝”，以确证性能提升确实源于注意力机制的指导，而非仅仅是因为减少了计算量。

#### 4. 应用前景

*   **论文声称**：FOCUS 使得 DLLM 在资源受限环境下的部署成为可能。
*   **证据**：系统层面的评测显示显存占用和吞吐量的优化。
*   **推断与评价**：
    **应用价值极高**。随着扩散模型在多模态大模型（如Flux, Stable Diffusion 3）中的广泛应用，推理成本已成为主要瓶颈。FOCUS 提供了一种**模型无关**的优化插件思路。
    **实际挑战**：FOCUS 引入了额外的逻辑判断开销（计算注意力分数、决定是否跳过）。在硬件层面，GPU并不擅长处理这种动态的控制流。如果剪枝后的计算图不够规整，可能会导致GPU利用率的下降，从而抵消算法层面的收益。因此，**工程实现（如CUDA Kernel优化）**是其落地的关键。

#### 5. 可复现性

*   **论文声称**：方法清晰，仅需在推理循环中插入掩码逻辑。
*   **推断**：
    从方法论上看，复现难度中等。核心在于如何精确复现其重要性判定函数。
    **关键复现点**：需要明确具体的阈值设定策略。是使用固定阈值，还是动态百分位？这部分超参数的敏感性分析在论文中若未详细披露，会导致复现困难。

#### 6. 相关工作对比

*   **对比维度**：与自回归模型（LLM）的投机采样、以及传统扩散模型的采样加速器对比。
*   **优劣分析**：
    *   **优于传统扩散加速器**：传统的DPM-Solver等侧重于减少时间步，而FOCUS侧重于减少空间维度的计算，两者正交，具有叠加潜力。
    *   **对比LLM投机采样**：投机采样依赖一个小模型来预测大模型，而FOCUS是自引导的，不需要额外的辅助模型，部署更轻便。
    *   **劣势**：相比单纯的数学变换加速（如流匹配），FOCUS 需要修改模型的前向

# 论文深度分析报告：FOCUS 系统

## 1. 研究背景与问题

### 核心问题
该论文致力于解决**扩散大语言模型**在实际推理部署中面临的**计算效率低下**和**吞吐量瓶颈**问题。具体而言，DLLM 的解码过程需要执行数十次扩散步骤，而在每个步骤中，系统必须对整个序列的所有 Token 进行并行计算，但实际上只有极少数 Token 能够在当前步骤中被有效解码，导致大量算力浪费在“不可解码”的 Token 上。

### 背景与意义
近年来，以 Diffusion Transformer (DiT) 为代表的扩散模型在图像生成领域取得了巨大成功，研究者开始尝试将其范式迁移至语言建模，提出了 DLLMs。理论上，DLLMs 能够提供比自回归模型（如 GPT 系列）更好的模态对齐和样本质量。然而，在实际部署中，DLLM 的推理成本远高于传统的 LLM。这种高昂的计算成本阻碍了其在大规模生产环境中的应用。因此，如何在不牺牲生成质量的前提下，大幅提升 DLLM 的推理吞吐量，是连接理论研究与工业应用的关键。

### 现有方法的局限性
现有的推理引擎（如 vLLM, LMDeploy, TensorRT-LLM）主要针对自回归模型优化，其核心假设是“每个时间步解码一个 Token”。虽然这些系统也支持批处理和 KV Cache 优化，但它们将 DLLM 视为通用的 Transformer 块进行处理，忽略了扩散模型独特的**时间步冗余**特性。即，它们在每个扩散步骤中都对所有 Token 一视同仁地进行计算，没有识别出 Token 在不同步骤中的“成熟度”差异。

### 问题重要性
随着多模态大模型的发展，统一的生成范式至关重要。如果 DLLM 无法解决效率问题，它将很难取代或补充现有的自回归架构。FOCUS 系统的出现，首次从系统架构层面针对扩散模型的概率分布特性进行了优化，为 DLLM 的实用化提供了可能。

## 2. 核心方法与创新

### 核心方法：FOCUS 系统
FOCUS 是一种新型的推理系统，其核心思想是**“早退与动态聚焦”**。系统在推理过程中动态识别哪些 Token 已经“准备好”（即解码概率足够高），并仅对这些 Token 进行后续的精细化计算，同时跳过或大幅减少那些尚未准备好 Token 的计算。

### 技术创新点
1.  **Token 重要性预测：** FOCUS 利用注意力机制中的注意力分数作为 Token 重要性的代理指标。研究发现，注意力分数高的 Token 往往对应着更高的解码置信度。
2.  **动态计算屏蔽：** 基于预测的重要性，系统构建了一个动态掩码。在推理的早期步骤，大部分 Token 的计算被简化或跳过；随着扩散步数的增加，计算资源逐渐集中在模型尚未确定的困难 Token 上。
3.  **非均匀批次处理：** 传统的批处理中，所有 Token 获得相同的计算资源。FOCUS 打破了这一限制，允许同一个批次内的不同 Token 在不同的扩散步数“停止计算”，从而极大地释放了无效算力。

### 优势与特色
-   **保持模型精度：** FOCUS 不改变模型的权重，仅优化推理时的计算图，因此不会像模型剪枝或量化那样导致精度损失。
-   **通用性强：** 该方法不依赖于特定的模型架构细节，可广泛应用于基于 Diffusion 的语言模型。
-   **即插即用：** 作为一个中间层或优化插件，它可以集成到现有的推理框架中。

## 3. 理论基础

### 理论依据：注意力与置信度的相关性
该方法的基石在于一个经验观察：**注意力权重 $\alpha$ 与 Token 级别的解码概率 $P$ 之间存在强正相关关系**。
在扩散模型中，去噪过程可以看作是从高斯噪声中逐步恢复信号。当一个 Token 的特征趋于稳定时，它在自注意力层中与其他 Token 的交互模式也会趋于稳定。FOCUS 假设，如果某个 Token 对上下文的注意力分布非常集中（高熵低或特定权重大），说明模型已经对该 Token 有了明确的“构想”，此时可以提前终止该 Token 的扩散过程。

### 数学模型与算法
虽然论文摘要未详细展开数学公式，但其核心逻辑可概括为：
对于 Token $x_i$ 在扩散步 $t$：
1.  计算注意力图 $A_t$。
2.  提取重要性分数 $S_i = f(A_t)$。
3.  判决：若 $S_i > \tau$（阈值），则停止更新 $x_i$，直接输出当前预测值；否则继续计算。
这实际上将原本固定的 $T$ 步迭代，变成了变长迭代，每个 Token 的步数 $T_i \leq T$。

### 理论贡献
FOCUS 揭示了扩散模型推理中存在的**“计算冗余”与“认知不确定性”之间的联系**。它证明了可以通过模型内部状态（注意力）来推断外部状态（是否需要继续计算），这为未来的“自适应推理”系统提供了理论支撑。

## 4. 实验与结果

### 实验设计
研究团队选取了标准的文本生成基准数据集，并对比了 FOCUS 与当前最先进的推理引擎 LMDeploy 的性能。评估指标主要包括**吞吐量** 和**生成质量**。

### 主要结果
-   **吞吐量提升：** 在保持生成质量（Perplexity 和生成文本语义一致性）不变的前提下，FOCUS 实现了高达 **3.52 倍** 的吞吐量提升。
-   **有效批次大小增加：** 通过剔除无效计算，FOCUS 能够在相同的硬件显存和算力下，处理更多的有效请求。

### 结果分析与验证
结果表明，DLLM 的解码过程确实存在巨大的“尾部冗余”。在解码后期，大部分 Token 已经收敛，仅剩少量 Token 需要反复修正。FOCUS 成功地识别并剥离了这部分冗余。这种提升并非来自算力本身的优化，而是来自算力分配策略的优化。

### 局限性
-   **阈值敏感性：** 系统性能可能对重要性判断的阈值 $\tau$ 较为敏感，需要针对不同数据集进行调优。
-   **额外开销：** 计算注意力分数和进行掩码操作本身会引入轻微的计算开销，尽管相对于节省的算力而言是微不足道的，但在极短序列场景下收益可能递减。

## 5. 应用前景

### 实际应用场景
FOCUS 特别适合于**长文本生成**、**实时多模态对话**以及**资源受限的边缘设备部署**。在这些场景中，延迟和吞吐量是关键瓶颈。

### 产业化可能性
鉴于其显著的性能提升和开源策略，FOCUS 极有可能被集成到主流的 LLM 推理框架（如 vLLM 或 TensorRT-LLM）中，作为处理扩散类模型的标准后端。

### 未来方向
结合 **Speculative Decoding (投机采样)** 是一个极具前景的方向。既然 FOCUS 能够识别出哪些 Token 已经“准备好”，那么对于这些高置信度的 Token，可以进一步使用更小的 Draft Model 进行验证，从而实现双重加速。

---

## 6. 研究启示

### 对领域的启示
这项研究打破了“推理加速必须依赖模型压缩或硬件升级”的定式思维。它指出了**算法逻辑与系统调度协同设计**的重要性。对于扩散模型而言，时间维度的冗余是系统优化的蓝海。

### 后续研究方向
1.  **更早的终止机制：** 能否在更浅的层就判断出 Token 的重要性，从而节省每一层内的计算？
2.  **跨层/跨步复用：** 既然某些 Token 已经收敛，它们的中间表示是否可以在不同扩散步之间复用？
3.  **扩展至其他模态：** 这种基于注意力的动态剪枝是否可以迁移到图像生成模型（如 SDXL）中，以加速高分辨率图像的生成？

## 9. 研究哲学：可证伪性与边界

### 关键假设与先验
**假设：** 注意力分数是 Token 解码收敛度的充分统计量。
**归纳偏置：** 模型在生成过程中，对确定内容的注意力会更加“集中”或“模式化”，而对不确定内容的注意力会更加“分散”。
**风险：** 如果某些 Token 的生成需要“发散思维”才能涌现正确答案，那么基于注意力集中度的早退策略可能会错误地截断这种探索过程，导致模型陷入局部最优（生成平庸但错误的 Token）。

### 失败条件分析
该系统最可能在以下条件下失效：
1.  **高度创意或随机性要求高的任务：** 如诗歌创作，其中“不确定性”本身就是生成的一部分，过早截断可能导致风格单一。
2.  **长尾依赖严重的任务：** 某些 Token 在早期看起来不重要（注意力低），但对后文的逻辑至关重要。如果这些 Token 被过早“冻结”且质量不佳，会引发连锁错误。

### 事实与推断
-   **经验事实：** 在标准基准测试中，注意力与解码概率确实相关，且跳过计算确实加速了推理。
-   **理论推断：** 这种相关性是普遍存在的。
-   **验证方法：** 需要在更复杂的推理任务（如数学证明、代码生成）中进行大规模 A/B 测试，以验证 FOCUS 是否会因为“过早下结论”

## 最佳实践指南

### 实践 1：识别并突破计算瓶颈

**说明**:  
研究表明，大型语言模型（LLMs）的性能提升往往受限于计算资源而非模型架构本身。通过分析模型在不同计算规模下的表现，可以识别出计算瓶颈所在，并针对性地优化资源分配，从而突破性能瓶颈。

**实施步骤**:
1. 监控模型训练和推理过程中的计算资源使用情况（如GPU利用率、内存带宽等）。
2. 分析计算瓶颈是否由特定操作（如矩阵乘法、注意力计算）引起。
3. 优化瓶颈操作，例如通过更高效的算法或硬件加速。

**注意事项**:  
- 确保监控工具能够提供细粒度的性能数据。
- 优化过程中需权衡计算开销与模型性能。

---

### 实践 2：动态调整计算分配

**说明**:  
根据任务的复杂度和模型的需求动态调整计算资源的分配。例如，对于简单任务可以减少计算量，而对于复杂任务则分配更多资源，从而在保证性能的同时提高计算效率。

**实施步骤**:
1. 定义任务复杂度的评估指标（如输入长度、输出多样性）。
2. 设计动态计算分配策略，例如基于规则或学习的方法。
3. 在训练和推理中实施动态分配策略，并验证其效果。

**注意事项**:  
- 动态分配策略需与模型架构兼容。
- 避免频繁调整资源分配导致的开销过大。

---

### 实践 3：优化数据加载与预处理

**说明**:  
数据加载和预处理往往是计算密集型任务的瓶颈。通过优化数据管道（如并行加载、预取数据），可以显著减少等待时间，提高计算资源的利用率。

**实施步骤**:
1. 分析数据加载和预处理的性能瓶颈。
2. 实施并行数据加载和预处理（如使用多线程或GPU加速）。
3. 使用数据预取技术减少GPU空闲时间。

**注意事项**:  
- 确保数据预处理不会引入额外的延迟。
- 监控内存使用情况，避免内存溢出。

---

### 实践 4：利用稀疏化技术减少计算量

**说明**:  
稀疏化技术（如模型剪枝、稀疏注意力）可以显著减少计算量，同时保持模型性能。通过识别并去除冗余参数或操作，可以更高效地利用计算资源。

**实施步骤**:
1. 评估模型中冗余参数或操作的分布。
2. 选择合适的稀疏化方法（如结构化剪枝、非结构化剪枝）。
3. 实施稀疏化并验证模型性能。

**注意事项**:  
- 稀疏化可能影响模型精度，需在性能与效率之间权衡。
- 确保硬件支持稀疏计算加速。

---

### 实践 5：采用混合精度训练

**说明**:  
混合精度训练通过结合不同精度的数值表示（如FP16和FP32），可以减少内存占用和计算时间，同时保持模型稳定性。这是一种高效的计算资源利用方法。

**实施步骤**:
1. 确保硬件支持混合精度计算（如NVIDIA的Tensor Core）。
2. 在训练中使用自动混合精度（AMP）工具。
3. 调整损失缩放策略以避免数值下溢。

**注意事项**:  
- 混合精度可能导致数值不稳定，需谨慎调整超参数。
- 验证模型在混合精度下的收敛性和最终性能。

---

### 实践 6：实施模型并行化

**说明**:  
对于超大规模模型，单设备可能无法满足计算需求。模型并行化（如张量并行、流水线并行）可以将模型分布到多个设备上，从而突破单设备的计算限制。

**实施步骤**:
1. 分析模型结构和计算图，确定并行化策略。
2. 选择合适的并行化框架（如PyTorch Distributed、DeepSpeed）。
3. 实施并行化并优化通信开销。

**注意事项**:  
- 并行化可能引入通信开销，需优化通信策略。
- 确保负载均衡，避免设备空闲。

---

### 实践 7：持续监控与调优

**说明**:  
计算瓶颈可能随着模型规模、数据分布或硬件环境的变化而变化。建立持续监控和调优机制，可以确保模型始终在最优计算状态下运行。

**实施步骤**:
1. 部署性能监控工具，实时跟踪计算资源使用情况。
2. 定期分析性能数据，识别新的瓶颈。
3. 根据分析结果调整优化策略。

**注意事项**:  
- 监控工具需具备低开销，避免影响模型性能。
- 调优过程需谨慎，避免引入新的问题。

## 学习要点

- 密集大型语言模型（DLLMs）在推理过程中主要受限于计算能力而非内存带宽，这一发现挑战了以往认为内存带宽是主要瓶颈的传统观点。
- 研究提出了一种名为“计算感知解码”的新策略，通过动态调整模型计算负载来匹配硬件能力，从而显著提升推理吞吐量。
- 实验证明，通过智能跳过模型中的特定层或减少计算精度，可以在几乎不损失模型准确性的前提下大幅降低计算开销。
- 该研究揭示了不同硬件架构（如GPU、TPU）对DLLMs计算效率的影响差异，为针对特定硬件优化模型设计提供了理论依据。
- 研究团队开发了开源基准测试工具，用于系统评估DLLMs在不同计算约束下的实际性能表现。
- 研究指出，未来DLLMs的发展方向应更注重计算效率与模型性能的平衡，而非单纯追求模型规模的扩大。
- 该工作为实际部署大型语言模型提供了实用指导，特别是在资源受限环境中如何优化计算资源分配。

## 常见问题


### 1: 什么是 DLLMs，它与传统的 LLMs 有何核心区别？

1: 什么是 DLLMs，它与传统的 LLMs 有何核心区别？

**A**: DLLMs 指的是“动态大型语言模型”。其核心区别在于计算机制的自主性。传统的 LLMs 通常对所有输入 Token 使用相同的计算资源（即激活所有参数），这是一种静态的计算模式。而 DLLMs 引入了一种动态路由机制或早期退出机制，允许模型根据输入样本的复杂程度，决定使用多少计算资源。简单来说，对于简单的问题，模型只使用部分参数或较少的层数进行推理；对于复杂的问题，才调动全部算力。这使得 DLLMs 能够在保持高性能的同时，显著降低平均推理成本。

---



### 2: 论文标题中的 "Tame Their Compute Bound"（驯服其计算瓶颈）具体指什么？

2: 论文标题中的 "Tame Their Compute Bound"（驯服其计算瓶颈）具体指什么？

**A**: 这里的“计算瓶颈”指的是在推理过程中，模型受限于硬件计算能力（如 FLOPs）或内存带宽（Memory Bandwidth）而无法无限提升速度或降低成本的现象。“驯服”则意味着 DLLMs 通过一种自适应的策略，打破了模型必须进行全量计算的惯例。论文表明，DLLMs 能够识别出哪些任务不需要过多的计算量，从而主动“跳过”不必要的计算步骤。这种能力使得模型不再是被动地受限于硬件算力上限，而是通过智能分配算力，在有限的计算资源下实现了最优的吞吐量和效率。

---



### 3: DLLMs 是如何决定何时减少计算量的？其背后的机制是什么？

3: DLLMs 是如何决定何时减少计算量的？其背后的机制是什么？

**A**: DLLMs 通常依赖于一种被称为“置信度检测”或“难度评估”的机制。在模型逐层处理输入数据的过程中，中间层会输出对当前生成结果的置信度分数。如果中间层已经对预测结果有了极高的置信度（例如，预测下一个词的概率非常高），模型会判定该样本为“简单样本”，并触发早期退出机制，跳过后续的 Transformer 层。反之，如果置信度低，模型会继续进行计算。这种决策过程通常是端到端训练出来的，或者是通过强化学习策略优化的，旨在平衡准确率与延迟。

---



### 4: 使用 DLLMs 会牺牲模型的准确性吗？

4: 使用 DLLMs 会牺牲模型的准确性吗？

**A**: 根据 arxiv 上的相关研究，DLLMs 的设计目标就是在不牺牲（甚至极少牺牲）准确性的前提下提升效率。实验结果表明，通过合理的训练策略（如蒸馏、辅助损失函数），DLLMs 在处理大多数常见任务时，其准确率能够非常接近全量计算的 LLMs。在某些数据集上，通过动态分配计算资源，DLLMs 甚至能在总体计算量减少 30%-50% 的情况下，保持与基线模型相当的准确率。当然，在极端复杂的推理任务中，如果强制限制计算量，准确性可能会有轻微波动，但总体权衡是正向的。

---



### 5: DLLMs 对实际部署中的硬件利用率有什么影响？

5: DLLMs 对实际部署中的硬件利用率有什么影响？

**A**: DLLMs 能够显著改善硬件的利用率，特别是在处理大规模并发请求时。传统的 LLMs 往往受限于“内存墙”，即大部分时间花费在从显存中加载权重数据上，计算单元（GPU Tensor Cores）往往处于闲置或低效状态。DLLMs 通过减少部分样本的计算层数，直接减少了内存访问次数和计算量。这不仅降低了单个请求的延迟，还使得在相同的硬件环境下能够处理更多的用户请求，从而提高了整体的有效吞吐量。

---



### 6: DLLMs 技术目前面临哪些挑战或局限性？

6: DLLMs 技术目前面临哪些挑战或局限性？

**A**: 尽管 DLLMs 展示了巨大的潜力，但目前仍面临一些挑战。首先是训练难度，训练一个能够准确判断何时退出且保持高精度的动态路由模型比训练标准模型更复杂，往往需要复杂的课程学习或专门的优化器。其次是硬件实现的非标准化，目前的 GPU 和推理引擎（如 TensorRT、vLLM）主要针对静态图计算进行了高度优化，对于动态形状和动态层数的并行计算支持还不够完美，这可能导致实际加速比低于理论加速比。最后是尾延迟问题，为了保证极少数复杂样本的准确性，系统可能仍需预留处理长尾高延迟请求的能力。
