### 核心概念：什么是子代理？
在 Claude Code 中，**子代理** 是指主 AI 实例为了完成特定、复杂的任务而调用的辅助性 AI 实例。简单来说，就是“让 AI 去指挥另一个小 AI”专门处理某项工作。

### 为什么要用子代理？（解决痛点）
原文片段中提到的场景非常典型：
*   **问题现状**：主 Agent 花了 15 分钟探索代码库，虽然找到了内容，但随后“失忆”或上下文过载，导致最终未能满足你的请求。你被迫淹没在几百行日志中寻找报错原因。
*   **解决方案**：子代理可以将庞大的任务分解。主 Agent 负责宏观指挥，子代理负责微观执行（如只负责阅读日志或搜索文件），从而避免单一 AI 上下文过长导致的遗忘和混乱。

### 何时使用？
1.  **处理大量数据**：例如分析数千行日志文件、搜索庞大的代码库。
2.  **特定工具调用**：需要使用特定命令或脚本，且不想污染主上下文时。
3.  **并行任务**：需要同时进行多个独立操作时（尽管 Claude 主要为串行，但逻辑上可分离关注点）。

### 怎么用？
虽然具体命令参数在原文截断处未显示，但通常涉及在提示词中明确指定“使用子代理来...”，或者通过工具定义将特定功能剥离给子代理处理。

**一句话总结**：
当你的任务太复杂、日志太长，导致 Claude 开始“健忘”或迷失方向时，请使用**子代理**将任务切分，让专业的小 AI 去处理细节，从而提高准确性和可读性。

3.  **容错性与隔离**：一个子代理的失败（如无法解析特定文件）不会导致整个任务的崩溃，主代理可以进行重试或降级处理。

2.  **成本爆炸**：每个子代理的启动和交互都可能消耗昂贵的 Token。对于简单任务（如“总结这段文本”），使用子代理架构无异于“高射炮打蚊子”。

4: 子代理在执行任务时如果犯了错（例如改坏了代码），如何回滚或纠正？

**A**: 子代理虽然具备自我修正能力，但并非万无一失。处理错误的机制主要依赖**版本控制**和**人工干预**。

**纠正策略：**
1.  **依赖 Git**：这是最安全的网。在让子代理进行大规模修改前，确保当前工作区是干净的，或者提交了当前进度。如果子代理改乱了，直接使用 `git checkout .` 或 `git reset --hard` 回滚。
2.  **逐步确认**：虽然子代理可以自主运行，但在关键操作（如删除文件、数据库迁移）前，可以要求它"先列出计划，等待我批准后再执行"。

4.  **快照功能**：部分 IDE 集成环境可能提供会话快照，可以在子代理操作前保存状态。
