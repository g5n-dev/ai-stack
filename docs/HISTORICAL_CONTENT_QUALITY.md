# 历史文章质量修复报告

本报告记录 AI Stack 历史文章库的两阶段治理结果。处理原则是：只发布能够被现有证据支持的内容；来源不足时保留可解释的透明归档；不使用模型补写未知事实，不把来源节选包装成原文全文。

## 阶段一：结构治理与异常正文隔离

阶段一完成规范化 URL 去重、异常正文识别、结构修复和透明归档。旧报告中的 6,700、2,366 等数字属于阶段一盘点口径，不代表本次来源恢复后的最终文件数。阶段一建立了以下约束：

1. 同一规范化来源只保留一个稳定站内身份，重复路由通过 aliases 指向规范页。
2. 提示词泄漏、思维过程泄漏、标题独占、结构损坏或无法核验的正文不得继续以“完整文章”展示。
3. 透明归档保留来源入口、失败类型和时间，但不进入文章列表、Pagefind 搜索或知识图谱。
4. 标签、分类和场景只从 active 内容生成；空壳标题不会被扩写成事实。

### 发布边界

- ArXiv 公开摘要、GitHub/Hacker News 元数据和可核验描述按来源类型发布。
- Blogs / Podcasts 与掘金只发布最多 800 个字符的有界节选，并明确提示读者访问原始来源查看完整上下文。
- 最终来源快报的捕获模式为：abstract 571、metadata_only 799、excerpt 768。它们是证据支持的短卡片，不是原文全文恢复。
- `source_support=1.0` 仅表示当前展示字段被记录证据覆盖，不表示原文完整度为 100%。
- SHA-256 仅用于内容一致性校验和哈希绑定，不是数字签名、身份认证或来源可信证明。

## 事务与隐私边界

来源恢复使用独立计划摘要、明确变更上限、单独备份 ID 和执行前 Git HEAD。最终恢复事务：计划摘要为 `sha256:d6991736ad17b4a35c3046becec314f87d5d1b873e2b159f10695623418fe4ac`，执行 2,365 项；随后重复治理计划摘要为 `sha256:6dd67def63a455f20c721a938d45dde96f816517e198ed8238cf0e7dc7c65641`，执行 12 项。上述摘要是规范化内容的校验值，不是签名。

原始捕获、逐条审计、计划和备份均保存在仓库外的受限目录；仓库只提交脱敏后的代码、统计和派生资产，不提交 URL 清单、绝对本机路径、原始载荷或密钥。发布前规则扫描未发现敏感匹配；该结果是本次门禁的观测值，不是对未来数据的绝对保证。

## 验收门禁

每次历史数据变更都必须通过：

1. 恢复清单固定点检查：`planned_changes=0`、`issues=[]`、无待恢复项。
2. 内容质量清单：active quarantine 与结构 warning 均为 0。
3. 图谱资产校验：只从 active 内容生成，节点/边/搜索索引通过结构校验。
4. 趋势资产校验：哈希和文件清单可重复生成，二次生成无 diff。
5. Hugo、Pagefind 和渲染结果安全校验：透明归档可直达但不进入列表、搜索和图谱。
6. staged diff 安全扫描：不允许捕获审计、备份、绝对路径、凭据形态或未绑定的原始来源载荷进入提交。

最终质量清单、标签图谱和趋势索引必须与同一份 active/archived 语义一起提交；部署工作流不会在普通 push 上替代性地重新抓取历史来源。
