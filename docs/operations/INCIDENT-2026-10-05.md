## 根因

生产 `refresh` job 曾包含一步无条件的 Chromium 安装：

```
- name: Install crawler browser
  run: python3 -m playwright install --with-deps chromium
```

日志原文（run `41784410985`）：

```
BEWARE: your OS is not officially supported by Playwright; installing
dependencies for ubuntu26.04-x64 as a fallback.
Cannot install dependencies for ubuntu26.04-x64 with Playwright 1.57.0-beta-1764944708000!
ERROR: Playwright does not support chromium on ubuntu26.04-x64
Process completed with exit code 1.
```

失败链条：

```
runner OS 26.04
  → Playwright 1.57.0 不支持该镜像，浏览器安装退出 1
  → refresh 失败（第 6 步，尚未抓取任何内容）
  → validate / persist / build / deploy / production-verify / notify 全部 skipped
  → 没有 persist 提交，main 停止前进
  → 站点永远停留在 10-05 快照
```

**放大因素**：这步安装的浏览器对生产刷新毫无必要。`config/sources.yaml` 启用的
5 类来源（GitHub Trending、Hacker News、arXiv、掘金、博客/播客 RSS）全是
HTTP/RSS/API；Chromium 只服务于可选的本地 Twitter 爬虫（`crawler/twitter_crawler.py`）
和 CI 浏览器烟测（`tests/e2e/test_static_site.py`）。一个可选依赖被放在了发布关键路径上。

**为什么监控没能救回来**：监控本身工作正常——它每小时报一次、持续 30 天。
但告警只说「发布链中断 / 内容停滞」，#503 的排障指引固定指向 `validate` 阶段，
而真实失败在 `refresh` 的第 6 步；`monitoring.yml` 里那句误导性文案让每次人工排查
都从错误的阶段开始。此外 `tests/test_check_release_runs.py` 虽存在，却从未注册进
CI 测试清单，监控链路的回归保护形同虚设。

## 修复

1. **解除阻塞**：从 `deploy.yml` 的 `refresh` 中彻底移除浏览器安装步骤；生产刷新不再依赖任何浏览器。
2. **固定运行环境**：全部 7 个工作流、16 个 job 的 `runs-on` 从浮动的 `ubuntu-latest` 改为 `ubuntu-24.04`，见 [`runner-pinning.md`](./runner-pinning.md)。
3. **告警自诊断**：`scripts/check_release_runs.py` 现在通过 GitHub API 定位最近一次失败运行的首个失败 job 与失败步骤，直接写进告警正文；诊断查询失败时只记录、绝不掩盖已检出的故障。
4. **修正误导文案**：`monitoring.yml` 与排障手册不再预判断 `validate`，改为按首个失败 job 定位。
5. **固化教训**：新增 `tests/test_runner_pinning_contract.py`，禁止浮动 runner 标签、禁止生产 `refresh` 引入浏览器、禁止启用需浏览器的来源；并把监控链路测试注册进 CI。

## 预防性边界

| 边界 | 守卫 |
| --- | --- |
| 浮动 runner 标签 | 契约测试遍历所有 `*.yml`，逐一断言 `runs-on == ubuntu-24.04` |
| 生产路径引入浏览器 | 契约测试断言 `deploy.yml` 无 `playwright install`，且 `refresh` 步骤名不含 browser/chromium |
| 来源悄悄变成浏览器依赖 | 契约测试断言启用来源集合 ⊆ HTTP/RSS/API 白名单 |
| 新测试不进 CI | 契约测试断言两个测试文件都在 `ci.yml` 清单中 |
| 告警指错阶段 | `test_check_release_runs.py` 覆盖首个失败步骤定位与诊断降级 |
